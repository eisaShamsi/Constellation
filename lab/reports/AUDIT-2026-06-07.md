### Security (pre-existing)
- **[SA] `SecondScreenPage.svelte:55-62`** — second-screen Sky-View hover preview renders raw note content via `marked.parse()` with **no DOMPurify** → `<img onerror>`/`<script>` XSS. Fix: route through the sanitized `renderMarkdown` in `$lib/utils.ts`.
- **[SA] `tauri.conf.json:32`** — CSP `script-src` includes **`'unsafe-inline'`**, removing the defense-in-depth that would neutralize the above. No inline app scripts need it. Fix: drop `'unsafe-inline'` from script-src (keep on style-src).
- **[SIA] `search.rs:4767`** — property-filter **`pf.key` interpolated into SQL** unescaped (`json_extract(properties_json,'$.{}')`) — a `'` in the key breaks the literal → injection/query-break via the public search IPC. Fix: validate key against an identifier allowlist.

### Search correctness (pre-existing)
- **[SIA] `search.rs:4238`** — no-lexicon FTS5 fallback builds `format!("{}*", …)` stripping only `"` → special chars (`c++`, `(draft)`, `key:value`, bareword AND/OR) make an invalid MATCH → `prepare()` errors → **silent zero results**. Same at :6870/:6900. Fix: route through the existing `escape_fts_term`.
- **[SIA] `search.rs:4875`** — `mentions` filter does `LIKE` with the **raw** name, but `body_text` is stored Arabic-normalized → diacritic names never match. Fix: normalize the needle (pattern already exists at :7045).

### Type errors (svelte-check ERRORS — pre-existing, fast)
- **[AA/CQA] `store.ts:2481`** — `TIER_RANK: Record<LinkLifecycle,number>` omits **`'fresh'`** → svelte-check ERROR + NaN sort in `dedupeBySource`. Fix = the approved Option B in `project_link_lifecycle_dedupe_fix` (fresh:1, shift others). *(Two agents flagged this.)*
- **[AA/CQA] `PropertyEditor.svelte:236,252`** — `orderTaxonomyItems` walks a `HorizontalNode | VerticalNode` union → 2 svelte-check ERRORs. Fix: type over a shared union/base.

### Performance — vault-scaled (pre-existing, larger)
- **[PA] `SearchHub.svelte:515`** — search results render non-virtualized while backend limit defaults to 100,000 → a broad query in a 7,600-note Universe paints thousands of rows (each `{@html}` ×3). Fix: VirtualList and/or cap `req.limit`. Violates Perf Rule 3.
- **[PA] `FileTree.svelte:76`** — flat `universe_notes` library renders ~7,600 DOM nodes eagerly (no virtualization). Fix: window the flat root via VirtualList. Violates Perf Rule 3.

### Data freshness / offline (pre-existing)
- **[CFS] `NoteEditor.svelte:182-185`** — the live editor save path re-indexes (FTS) but **never re-embeds** → semantic search returns pre-edit results after a body edit. Fix: add the `semanticSearch`-gated `constellation_embed_notes` call (or route through `saveTabContent`).
- **[OGA] `semanticEngine.ts:12,47`** — Sky-View semantic links load `Xenova/all-MiniLM-L6-v2` via `@xenova/transformers` with no `allowRemoteModels=false` → **downloads from the HuggingFace CDN at runtime** (offline-guarantee violation). Fix: `env.allowRemoteModels=false` + local model path, or route to the Rust ONNX engine.
