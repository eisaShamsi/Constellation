## The 29, by family

### A · Concurrent writers can destroy each other's data (2)

| Site | What could be lost | Fix |
|---|---|---|
| `universe.rs:117` **APP-KILLER** | settings, session, collections, library list — written as a scrambled mix of two saves, then read as empty | pid+counter unique temp, matching `write_gate::atomic_write` |
| `libraries.rs:6753` | a file already in the trash, overwritten by a second delete of the same name | discriminate the gate's "already exists" refusal; **loop** the de-collide retry; never let copy+remove land on an occupied name |

`libraries.rs:6753` was the one fix in the sweep that a proof **rejected**. The first version
retried the collision exactly once, as the triage prescribed; the concurrency harness then failed
with a real sharing violation, because a fresh name can be taken again while you reach for it.
Under four concurrent deleters the pre-fix code lost **13 of 24 files**; a single retry still lost
some. Only the bounded loop passes, five runs out of five.

### D · A stale read written back over fresher bytes (5)

`store.ts:592` — `flushOutgoing` had no `isCascading` gate, so a departure mid-rename wrote the
pre-cascade body back and reverted the walker's link corrections. NoteEditor refuses at four
sites; the departure path was the fifth and it was open. ·
`+layout.svelte:6537` — `addTagToNote`'s closed-note branch, missing both guards `addLinkToNote`
carries. · `store.ts:4113` — `moveItem` had none of `renameItem`'s flush-before-cascade envelope,
so a move mid-typing could leave a stray copy carrying the newest words. ·
`store.ts:1727` — `loadTabHistoryEntry` flushed *before* the incoming disk read; every keystroke
typed during that read was discarded by the model re-seed. Now ordered like `openNoteTab`. ·
`+layout.svelte:6802` — `cascadeFreeze` was a shared boolean, so the first of two overlapping
renames lifted the read-only overlay while the second was still rewriting files. Now refcounted
(`markFreeze`/`clearFreeze`), the reactive twin of `cascadingLibraries`.

### E · The index diverges from disk (4)

`write_gate.rs:249` + `:250` — every gated note write woke the watcher into a full library
re-scan, because the containing directory was a separate unsuppressed key (`mark_with_parent`
existed and had zero callers — the LL-035 shape). · `canonical.rs:1311` — the first open of an
outside note writes its permanent identity to disk through the gate, and nothing told the index;
until the user edited that note, every identity-keyed lookup missed it. · `libraries.rs:2160` —
`collect_md_paths` re-indexed the notes sitting in `.trash`, so **deleted notes came back** in
search and link suggestions. · `search.rs:10247` — sky maintenance sat inside the INCOMING
stamp's `if let`, so on a fresh install every save skipped it and Sky View froze at stale values.

### F · Blocking the window, and leaked memory (5)

`libraries.rs:2234` and `libraries.rs:560` are now `#[tauri::command(async)]` — a whole-universe
folder walk and a slow note write no longer hold the IPC dispatch thread. ·
`store.ts:4187` and `SecondScreenPage.svelte:333` now dispose the models they drop
(`deleteWithSetting` filtered tabs without `closeNoteModel`; the peek pane and workspace restore
leaked one model per peeked note / per restore). · `cece/reliability.rs:199` swept every `.tmp`
it found, including the one a live `save` was writing through — so a correction silently did not
stick. Now only temps past an age floor are orphans (a re-lock would deadlock: the caller already
holds the non-reentrant `RELIABILITY_LOCK`).

### G · Malformed YAML from string concatenation (2)

`store.ts:490` (the "Save a copy" recovery title) and `+layout.svelte:4394` (the template merge)
both hand-built `key: value`. Measured with the repo's own parser before the fix:
`"Plan: phase two"` → 1 parse error and the title decodes as a MAP; `"#hashtag start"` → the value
decodes as NULL; `"- dash lead"` → 2 errors; `"[bracket]"` → decodes as an ARRAY. Both now use
`quoteIfNeeded` — which itself had a gap (it never quoted a leading `- `), found by the proof.

## Addendum — the Boss found the sweep's own Whole-Ecosystem violation

**2026-07-29, during Stage 1.** Test 2 as written asked the Boss to create two notes with the
same title. Constellation refuses that by design — collisions are caught universe-wide — and the
manual states it three lines above the paragraph this same sweep edited. The test was wrong.

Investigating the correct path exposed something worse than a bad test. The trash de-collide
concern has **two independent implementations**, and the sweep touched only one:

| Surface | Reached by | Pre-fix behaviour on a collision |
|---|---|---|
| `move_into_trash_folder` | **Delete** | fell through to copy+remove → **overwrote** the earlier trashed file |
| `move_to_trash` | the collision dialog's **Overwrite**, and the PJ-088 conflict-sidecar path | `?`-propagated → the Overwrite **failed**, citing a trash filename the user never chose and cannot see |

Both did an `exists()` pre-check outside the gate's lock followed by a single `gate_rename`; they
differed only in how badly they handled losing the race. This is the law's canonical shape
exactly — *fixed the site I saw, left its twin inconsistent* — committed **inside the sweep whose
report claimed the concern had been swept**.

**Fix.** One shared helper, `trash_move_decolliding`, plus the re-runnable `free_trash_name` it
loops on. Both call sites now go through it, so they cannot drift again. `move_to_trash` keeps its
no-fallback contract (its trash is always the note's own library root — same volume) and gains the
collision retry; `move_into_trash_folder` keeps its cross-device copy+remove fallback and now
re-resolves a free name before using it.

Two further proofs: `pj187_the_shared_trash_move_never_replaces_and_never_refuses` (five moves of
the same name all land, under five distinct names) and `pj187_free_trash_name_is_re_runnable` (the
search returns a *different* slot when re-run after its answer goes stale — the property the whole
fix rests on). Rust **1287 passed / 0 failed**.

**What this costs the report above.** Its "Whole-Ecosystem check" section listed three concerns as
swept. That check was run against the concerns I had already decided the fixes belonged to — it
never asked whether *trash de-collide* was itself a multi-surface concern, because the triage entry
named a single line. A per-concern grep is only as good as the concern's name.
