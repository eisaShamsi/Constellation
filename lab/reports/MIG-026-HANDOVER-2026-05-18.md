## 4. Architectural patterns to RESPECT

Patterns that emerged through the cascade and must not be broken
by Phase ι/κ/λ/μ work:

### 4.1 Chrome / semantic color split

`dome.ts` exports:
- `SEMANTIC_COLORS` — theme-AGNOSTIC categorical hues (stage hues,
  link types). DO NOT make these theme-aware.
- `ChromePalette` interface + `readChromePalette(el)` — theme-AWARE
  chrome (bg, strataRing, label colors, starFill, highlightedRing).
  Reads from `--background-primary` / `--text-normal` / etc. CSS
  vars set on `document.body` by `+layout.svelte`'s theme `$effect`.

Every canvas renderer in `anchor.ts` / `miniDome.ts` uses module-
level `let _chrome: ChromePalette` set at the top of the public
render function. `_chrome.bg`, `_chrome.strataRing`,
`_chrome.stratumLabel`, `_chrome.highlightedRing`, etc. — never
hardcoded hex.

**For Phase ι.2** (disclosure-layer UI): use the same CSS-var
pattern. The modal/popover background = `var(--background-secondary)`,
text = `var(--text-normal)`, etc. Inherits theme automatically.

### 4.2 Off-axis sector rotation

ANY sectoral tradition with cardinal-direction sector dividers
collides with the stratum labels on the +y axis. The fix is to
rotate by a half-wedge:
- 3 sectors (120° each): `+π/6` offset (Peirce, Habermas, Akan
  Wiredu)
- 4 sectors (90° each): `+π/4` offset (pramāṇa post-fix, masādir
  post-fix, Longino, Mencian, Sŏngnihak)
- 5 sectors (72° each): `+π/4` offset (Shāṭibī — chosen because
  the half-wedge `+π/5` puts a sector midpoint at -π/2)

**For user-defined traditions in Phase κ**: validate the offset
choice → warn if a divider lands within ±10° of -π/2 (vertical
axis collision risk).

### 4.3 Per-shape star size + opacity treatment

`SightV6.svelte::anchorStarRadiusBoostScreenPx` derives the boost
based on `tradition.shape`. The two-tier pattern:
- VERY-spread (+2 px): horizontal-bands, grid, binary-flow,
  relational, gradient, sectoral
- MODERATE-spread (+1.5 px): cyclic-flow, rings, ladder
- 0: nothing left

`anchor.ts::BODY_OPACITY_MULT = 1.0` (raised from 0.7 in §θ-fix-2).

**For Phase κ user-defined**: the same boost lookup applies to the
user-chosen shape. No special handling needed.

### 4.4 Mini-dome isolation (Concept Paper §11 invariant 6)

Mini-domes ALWAYS use `starsDefault` (default-Aristotelian
positions), never `stars` (tradition-remapped). This is the
invariant that prevents rhetorical pluralism — the user sees the
universe-baseline in mini-domes regardless of which tradition the
anchor is on.

**For Phase μ.1**: the channel-isolation test must iterate all
24 traditions and assert mini-dome star positions don't change
between traditions.

### 4.5 Default behavior conventions

- **Sectoral** (Peirce, Habermas, etc.): default-all-to-first-
  sector. Visually shows one populated wedge.
- **Spread shapes** (horizontal-bands, grid, ladder, relational,
  binary-flow): hash-bucket across all cells. Visually shows
  populated structure.
- **Rings** (Husserl, Ibn Rushd, PaRDeS, Maldonado-Torres): some
  use default-to-first (Husserl, Ibn Rushd, PaRDeS), some use
  hash-bucket (Maldonado-Torres). Per-tradition choice; not
  strictly consistent.

When Phase ι.1 manifests document each tradition's frontmatter,
make sure the manifest's "default behavior" line matches the
module's actual behavior.

If Eisa says "wrong target", "you're confused", "no", or

changed since the last approval, state the corrected
understanding, and wait for "proceed". Never pivot-and-power-

cascade but the rule applies).

### 4.7 Testing Instructions Rule
