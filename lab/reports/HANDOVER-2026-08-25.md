  redirected path — including a controlled experiment the Boss ran himself.
- A relative-path method that could only ever return 18 hits, whose "disagreement" with the
  content-id method I reported as a strength.
- Grepping the release binary for new UI strings, getting zero, and nearly reporting a failed
  build — the strings are compressed, so *known-shipping* strings also return zero.

**Before trusting any result, ask: if my method were wrong, would this look different?** If no, the
result is worthless. This is now the `findings-verifier`'s standing question and it belongs in
yours.

### Two traps that will bite you specifically

1. **`%APPDATA%` files may be sandbox shadows.** Any Constellation file read under `%APPDATA%` from
   a Claude session may be a frozen copy in the Claude Desktop MSIX container. Run
   `fsutil hardlink list "<path>"` before treating contents as fact; if the answer names
   `…\Packages\Claude_…\LocalCache\…`, it is a snapshot. Sibling files can pass through while one is
   shadowed — check the specific file. **`E:\` is not redirected.** This cost a Group-1 entry and a
   committed evidence bundle (`lab/reports/pj321-evidence-snapshot-2026-08-22/READ-THIS-FIRST.md`).
2. **`cargo build --release | tail` returns `tail`'s exit code.** Redirect to a file and check `$?`.
