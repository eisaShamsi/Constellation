## 1. What is 360.3D?

The 360.3D Inspector is the **synthesis surface of the Cognitive Engine for one note**. It is the only tool in Constellation that pivots from surveying the whole knowledge library to focusing entirely on a single note's situation.

The "360" is what the inspector reveals: the complete circumstance of a note across every dimension the Cognitive Engine measures. The "3D" is the multi-dimensionality of that view — not literal three-dimensional rendering, but the simultaneous overlay of multiple cognitive axes: connection, stratum, maturity, stage, provenance, lifecycle, and gap analysis.

The inspector answers exactly one question, deeply:

> **Where does THIS note stand in my Cognitive Knowledge?**

"Standing" has many senses. Position in the stratum hierarchy (intellectual altitude). Position in the maturity lifecycle (developmental state). Position in source chains (origin authority). Position in the connection network (centrality vs isolation). Position in the formalization journey (fleeting → synthesis). Position in time (when last reviewed). The inspector reveals all of these in one frame.

---

## 2. Why 360.3D exists

The other tools in Constellation are for **surveying** the library:

| Tool | What it surveys |
|---|---|
| Sky View | Relational network of every note + every link |
| Constellation Map | Hierarchical structural shape |
| Constellation Sight | Analytics-derived rankings (centrality, communities, structural gaps) |
| Index | Vocabulary pivot — terms across notes |
| OrgChart | Parent-child taxonomy |

Each one tells the user what their knowledge looks like as a whole.

The 360.3D Inspector is for **stopping**. The user opens it when they have decided that surveying is over for now, and they want to STAND with one specific note and see its complete situation. They are about to **develop, audit, extend, or evaluate** this single note — and they need to know where they are before they take the next step.

The moment of the inspector's value:

- **Before extending a note**: "What does it already connect to, and what haven't I traced?"
- **Before citing a note**: "Is this well-grounded? What's its provenance depth?"
- **Before promoting a note's stage**: "Does the connection density justify the formalization?"
- **Before declaring a note canonical**: "Have I tested this from all seven typed directions, or am I one-sided?"
- **After a long absence**: "Is this overdue for review? Has the maturity decayed?"
- **Before linking outward from a note**: "Where does this fit in the stratum hierarchy?"

## 3. The Cognitive Dimensions 360.3D Encodes

The `Note360View` shape carried by the IPC `get_360_view` aggregates every measurement the Cognitive Engine has taken for the note. Each is a different axis of "where it stands":

### 3.1 Stratum — intellectual altitude

The note's level in Constellation's 8-stratum hierarchy: Datum → Information → Proposition → Concept → Principle → Theory → Paradigm → Worldview. This is the primary VERTICAL position. A datum at L1 sits very differently from a worldview at L8. **This is the dimension Constellation alone measures**; no other PKM tool encodes a note's intellectual altitude as a first-class fact.

### 3.2 Maturity — lifecycle state

The note's developmental position: Seed → Sapling → Evergreen → Canonical → Wilting. This is the BIOLOGICAL position. Has this note grown into developed thinking, or is it raw or decaying?

### 3.3 Stage — formalization level

The note's commitment level: Fleeting → Literature → Permanent → Synthesis. This is INTENTIONAL position. Has the user formally committed this idea, or is it still a quick capture?

### 3.4 Provenance — source structure

Origin type (Received vs Discovered vs Mixed) plus trust depth (length of the derives-from chain to root). This is GENEALOGICAL position. Does the note descend from many sources, one source, or is it self-discovered?

### 3.5 Typed-link distribution — connection profile

Count of connections per typed direction (supports, contradicts, causes, derives-from, generalizes, exemplifies, part-of) plus untyped. This is RELATIONAL position. What kind of relationships does the note participate in, and which directions are unused?

### 3.6 Stratification of connections — where neighbors stand

For each connection, the stratum of the connected note. This shows how the note distributes across the library's vertical hierarchy. Are all my supports coming from low-stratum data, or do they span the full range?

### 3.7 Review pulse — temporal position

Last reviewed date and is-due-for-review flag. When was the note last touched intentionally?

### 3.8 Trail and lens membership — narrative + thematic position

Which trails this note is part of (sequenced narratives) and which lens groups it falls into.

### 3.9 Structural flags — network position

- **Orphan**: no inbound connections (isolated)
- **Single point of failure / Fragile**: high inbound but minimal derives-from (load-bearing on a thin foundation)
- **Blind spots**: count of unused typed-link directions
- **Tensions**: count of contradicts connections (active disagreement)

### 3.10 Word count — developmental size

Raw size signal. Combined with stratum, indicates whether developmental size matches intellectual altitude.

## 4. The Three Outputs of Reading 360.3D

A user reading the inspector should leave with three understandings:

### 4.1 POSITION — "where am I?"

The note's stratum, maturity, stage, and provenance. The user locates the note in the cognitive landscape.

### 4.2 CONNECTION PROFILE — "what surrounds me?"

The typed-direction distribution and the stratification of those connections. The user sees what kind of thinking has been done around this note.

### 4.3 ABSENCE — "what's missing?"

Gaps in typed directions. Strata that aren't reached. Fragility flags. Asymmetry warnings. **The inspector is most valuable when absence is read as eagerly as presence.** A blind-spots count of 5 is not a defect of the visualisation; it is the visualisation's core output.

---

## 5. Design Principles

Any 360.3D visualisation must satisfy:

**P1. Single-note focus.** The visualisation is about one note. Nothing else competes for attention.

**P2. All cognitive dimensions visible at once.** The user shouldn't need to switch panels to see different dimensions. Position, connections, and absence appear in a single frame.

**P3. Spatial position must carry semantic meaning.** Where a marker sits should reflect what that dimension means. Nothing is decorative.

**P4. Gaps are first-class.** The visualisation must surface what is ABSENT as readily as what is present. Empty regions are signals, not blank canvas.

**P5. Asymmetry must be visible at a glance.** A note with 15 supports and 0 contradicts is one-sided thinking. The inspector must make this readable without counting.

**P6. Stratification must be explicit.** Where a note sits VERTICALLY in the library hierarchy is the most distinctive Cognitive Engine dimension. The inspector should foreground it.

**P7. Click-to-navigate preserves focus.** Clicking a connection re-centres the inspector on that note, with a back stack walking the user's path.

**P8. Hover-only naming.** Names appear on hover so the visual stays clean for pattern reading. The geometry of cognitive position is what the user is supposed to see at a glance.

---

## 6. What 360.3D is NOT

- **Not a graph view.** Sky View is the graph. 360.3D is a position view.
- **Not a list of links.** Backlinks/Outgoing panels are link lists. 360.3D includes link counts but doesn't enumerate them as a list.
- **Not analytics.** Sight does centrality and community analytics across the library. 360.3D does not compute new metrics — it displays measurements already taken by the CE.
- **Not a hierarchy view.** OrgChart is the parent-child tree. 360.3D shows the note's stratum but doesn't navigate the full taxonomy.
- **Not a comparison view.** The inspector is about one note's standing in itself, not "how does this note compare to other notes." If the user wants comparison, they open another tool.
- **Not a narrative or trail player.** Trails has its own surface. 360.3D may show trail membership as a fact but doesn't play the trail.

## 7. The Visualisation Question

The original spherical / orbital / compass-position layout was inspired by the metaphor "the note as the core of a sphere with an atmosphere of dimensions surrounding it." After several rounds of iteration, that visualisation has been judged inadequate. The angular axis emphasises link TYPE (good), but its companion radial axis (depth-based rings, inherited from the compact widget) collapses for typical data because the IPC stamps every direct connection with `depth = 1`. The metaphor is sound; the geometry chosen to express it isn't load-bearing.

The next-generation 360.3D visualisation is open. It must satisfy the principles in §5. The current implementation will be set aside; a new visual model — chosen by the project owner from a clean-slate design — will replace it.

**Recommended starting axis**: stratum. It is the dimension Constellation alone measures, and it is most directly read as "where this note STANDS intellectually." A vertical layout that lets the user feel the note's altitude in the knowledge hierarchy (and the altitudes of its connections) addresses the core question more directly than any angular geometry can.

2. Are the ten cognitive dimensions in §3 the right set, or should any be added / removed?
3. Are the three outputs in §4 (Position / Connection Profile / Absence) the right framing?
4. Are the design principles in §5 the correct constraints?
5. Is the stratum-as-primary-axis recommendation in §7 the right starting point?

Owner answers shape the redesign. Once §1–§7 are confirmed, redesign proposals follow.
