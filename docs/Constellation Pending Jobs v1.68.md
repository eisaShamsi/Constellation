> - **Six surfaces scoped, not four.** The plan tables four; the Whole-Ecosystem sweep (7 angles, 64 agents, 57 candidates → **24 unique CONFIRMED**, each adversarially refuted first) found two more that matter: the **boot cold-start fan-out** — which submits one `ColdStart` per entry of the frontend's library list, and that list is the *recursive* set, so a federated universe re-offered every linked library on **every boot** — and **`library_attribution_backfill`**, an automatic boot pass that UPDATEs `note_meta.library_name`.
> - **No new loader.** `libraries::try_load_libraries` already existed with exactly the required contract ("absent is a FACT; unreadable is an unknown"), and `load_libraries`' own comment says its empty-on-failure return is only safe *because no write path uses it*. §8 makes six write paths take the strict twin.
> - **A typed `Foreign` submit outcome**, checked at the door and **before** the single-flight flag — deliberately distinct from `Blocked`, which means "not now" and is re-offered by the runner's drain, and which would therefore loop forever on a refusal that is "not ever, by this universe". The old registration check lived *inside* the worker, where a refusal would have set `last_error` and emitted `ok: false`, making an ordinary federated boot look like a failed repair.
> - **The exclusion set, kept even though today it is defensive.** §15 asked whether any cUniverse root is nested under an active root: **answered — no**, both federated parents on this machine declare siblings. Kept because narrowing the root LIST alone does not stop the walk *descending* into a nested child, and `universe_notes`' path IS the Universe root.
> - **Two mirrors removed rather than written**: `walk_exclusions` and `foreign_roots_of` are shared by production and test, so the test cannot keep passing after production changes. The `search.rs:338` mirror trap §1 deleted was not re-introduced in a test.

> ### 🔒 THE WIRING GUARD — because the behaviour tests could not be one
> The reproduction pins the *mechanism*; it cannot pin the *wiring*, because every entry point takes an `AppHandle` and this crate has **no Tauri test harness**. Reverting `try_load_libraries` → `load_all_libraries` at any call site would have left the whole suite green. §6's `ConvergeKey` token does not fit (a plain `&[LibraryInfo]` shared with a dozen legitimate read paths), so the invariant is asserted against the source. **RED proven twice, both observed**: revert the skip-set → the nesting test fails `left: 1, right: 0`; revert one call site → the guard fails naming the line.

> ### ☠️ A HIGH FOUND BY THE INSPECTION, FIXED IN THE SAME COMMIT
> `reconcile::run` had **no guard of any kind**. It runs on a spawned thread, computes its roots and orphan set from the universe active at start, then writes through `state.db` — which a universe **switch** replaces underneath it, so its re-adopt tail would index the **departed** universe's notes into the **newly-active** universe's index. Charter W2-9 through a second door, and a breach of Architect Invariant 10. §7 built `federation_generation_now`/`walk_may_proceed` for precisely this and wired only the bulk walk; the boot reconcile now takes the **same shared decision** at start, before each write phase, and per-iteration inside the removal and re-adopt loops.
>
> ### ⚖️ THE BOSS RULING THAT BOUNDED §8
> `validate_path_in_any_library`'s first branch is the **recursive** set, and its doc says so: *"including child universe libraries."* Editing a linked universe's note from the parent is **designed behaviour** — so the save path and every user-action write still put a row here. §8 closes the **automatic** doors; it cannot close that one without deciding where the write should go instead, and routing it nowhere would leave the edit findable in **no** index until that other universe is opened. **Boss-ruled 2026-08-07: ship §8 as scoped, file the rest → PJ-219.**

> - **PJ-221** — **APP-KILLER, `bases.rs:796` `format_yaml_value`.** A materially weaker quoter than the TS `quoteIfNeeded` it shadows: a Bases cell starting `- `, `|`, `>`, `%`, `@` or a backtick writes frontmatter that no longer parses, after which `composeFrontmatter`'s error branch **discards every later property edit on that note** — accepted, displayed, marked saved, never written. `&anchor`/`!tag` parse cleanly but null the value. > - **PJ-222** — `collect_md_paths` has **no library-boundary notion at all**. §8 filters its *output* in `run_cold_start` rather than fixing the collector, because its four other callers are folder-move paths with different semantics. Worth unifying behind the shared exclusion helper.
> - **PJ-223** — **one stray row disarms the cold-start recovery for a whole library.** Found on the Boss's live `Eisa Universe` during the §8 test: **2,096 `.md` on disk vs 1,890 indexed — 827 missing, 798 of them in `Constellation PKM`, a registered library.** His own boot log says *"825 orphan files (> cap 200) — skipping re-adopt."* **Proven pre-existing, not caused by §8 or by MIG-108**: the pre-unification snapshot MIG-108 itself took shows the identical `Constellation PKM: 1 row / 1890 total`. Root cause: the `only_if_unindexed` gate asks `SELECT COUNT(*) FROM note_meta WHERE library_name = ?1` and treats **any** non-zero as "already indexed" — so a single stray row makes a 799-note library look done, and the recovery that exists for exactly this gap can never fire. LL-027 / BUG-022 surviving inside its own guard. **This is the strongest existing argument for §9 (which would report it) and §11 (which would fix it).**
> - **PJ-224** — **the ordinary search box does not reach linked universes.** A plain word routes through `SearchHub.triggerSearch` → `universalSearch` → `execute_universal_search(conn, …)`, which queries the active universe's connection alone — no ATTACH, no federation. `federated_lexical_search_or_fallback` is reachable **only** from `constellation_search`'s advanced-syntax branches. So §8's stated premise — *"foreign notes stay searchable via the MIG-056 federated scatter-gather path"* — is true of that command and **false of the box the user types into**. §8 is unaffected (it removes nothing), but **§13 is gated on that premise and must not proceed until this is ruled on**: removing the duplicated copies would make those notes unfindable in ordinary use.
