# 笔记摘要

> *如果你写了摘要,Constellation 就用你的。只有在你没写时它才会写一段 — 即便如此,也从不写进你的文件。*

**笔记摘要**是一篇笔记的简短概要 — 几句话让你一眼就能知道这篇笔记讲的是什么。摘要由**笔记摘要生成器 (NSC)** 产生。今天它们出现在 **分类器** / **Source Review** 队列中每条笔记的标题下方,这样你无需打开卡片背后的笔记,就能决定如何对它进行分类。

本主题解释摘要来自哪里、那条始终优先采用*你的*文字而非机器文字的严格优先级顺序、生成的摘要是如何构建的,以及如何一次性为整个 Library 预先计算它们。

---

## 为什么有摘要

当你在处理一个数百张卡片的审阅队列时,仅凭标题往往不足以记起一篇笔记究竟说了什么。打开每篇笔记来唤醒记忆会打断你的节奏。标题下方的一眼摘要解决了这个问题:你读三句话,你记起这篇笔记,你做出判断,你继续前进。

但摘要也是一个小小的写作行为。如果你已经用自己的话提炼过一篇笔记 — 在 `summary:` 字段中或 `> [!summary]` callout 中 — 那么*那个*才是应该显示的摘要,而不是机器的猜测。因此 Constellation 关于摘要的第一条规则,是一条关于尊重你写作的规则:**你的优先。**

---

## 摘要来自哪里 — 优先级顺序

对于任意一篇笔记,Constellation 沿着这个列表逐项检查,在第一个存在的项处停下,以此挑选摘要:

1. **你的 frontmatter 摘要。** 如果笔记的属性中包含 `summary:`、`description:`、`abstract:` 或 `excerpt:` 字段(按此顺序检查),其文本会**完全按你所写**使用。
2. **你的摘要 callout。** 如果笔记正文中包含 `> [!summary]`、`> [!abstract]` 或 `> [!tldr]` callout,其文本会**完全按你所写**使用 — 包括变音符号和标点,逐字保留。
3. **生成的摘要。** 只有在上述两者你都没写时,Constellation 才会生成一段 — 通过读取笔记并抽取其最核心的句子(见下文)。
4. **开头文本回退。** 对于引擎无法切分成句子的笔记(例如,没有清晰句子标点的文字),它会显示笔记的开头几行,而不是排序后的摘要。

> **最重要的一条规则:** 第 1 步和第 2 步意味着你写的摘要*永远*不会被覆盖。如果你在一篇你以为已经写过摘要的笔记上看到了生成的摘要,那说明引擎没有在它查找的地方找到你的摘要 — 请检查你的 frontmatter 字段是否为上述四个名称之一,或你的 callout 是否为上述三种类型之一。

---

## 生成的摘要是如何构建的

当 Constellation 必须生成摘要时(因为你没写),它做的是**抽取式**摘要 — 它选择已经在你笔记中的句子,而不是发明新的散文。该方法是一种成熟的方法 (TextRank, Mihalcea & Tarau 2004):

1. **切分成句子。** 使用 Unicode 句子边界标准把笔记正文分段成句子,因此它跨语言和文字都能工作。
2. **读取每个句子的含义。** 用一个紧凑的设备端模型,把每个句子转化为一个小的数字「含义指纹」(嵌入)。
3. **按中心性排序。** 在含义上与最多*其他*句子相似的句子得分最高 — 这些句子最能代表整篇笔记。
4. **按顺序取前三句。** 排名最高的三个句子**按它们在笔记中出现的顺序**显示,这样摘要读起来自然,而不是顺序错乱。

很长的笔记会得到温和的处理 — 引擎会限制它扫描多少正文以及排序多少句子,所以摘要一篇庞大的笔记永远不会拖慢应用或冒崩溃的风险。

因为它是抽取式的,生成的摘要始终由你实际写下的句子构成。它绝不会把话塞进你嘴里。

---

## 摘要是只读的 — File-Over-App

Constellation **从不把生成的摘要写回你的笔记。** 你的 `.md` 文件才是真实来源;你在卡片上看到的摘要是即时计算的,并单独缓存,不会保存进文件的文本或 frontmatter。

这是有意为之的,它遵循 Constellation 的 *File-Over-App* 原则:应用是通往你文件的一扇窗,而不是一个悄悄改动它们的编辑器。如果你想让摘要*活在*笔记里,自己写一段(一个 `summary:` 字段或一个 `[!summary]` callout) — 然后,根据上面的优先级规则,Constellation 会显示你的并停止生成。

一切都在**你的设备上**计算。没有任何笔记文本会被发送到任何地方去做摘要。

---

## 摘要何时出现,以及它们如何填入

摘要出现在 **分类器** / **Source Review** 队列中每张卡片的笔记标题下方。

默认情况下它们**惰性而温和地**填入:当卡片滚动进入视野时,Constellation 一次计算几条摘要,并在 Library 分类扫描运行时暂停,这样两者绝不会争夺资源。这让应用保持响应迅速 — 你可能会短暂看到一张卡片先于其摘要出现,随后摘要在片刻后弹入。

如果你更想让每段摘要都提前准备好,请使用 **生成全部摘要**。

## 生成全部摘要 — 预先计算整个 Library

**生成全部摘要**按钮(在 **分类器** 头部)为**每条尚未拥有当前摘要的笔记**预先计算一段摘要,这样卡片会立即显示其摘要,而不是在你滚动时才填入。

**要使用它:**

1. 打开 **分类器**(左侧停靠栏中的层叠卡片图标)。
2. 点击头部中的 **生成全部摘要**。按钮变为 *正在生成笔记摘要…*。
3. 进度出现在窗口底部的**状态栏**中 — 运行期间你可以继续工作。
4. 要提前停止,使用状态栏进度条上的 **取消** 控件。部分运行没问题;下次它会从上次停下的地方接着来。

几点值得了解的事:

- 它**仅在你要求时**运行 — 它从不自行启动,所以它永远不会拖慢应用启动。
- 它**在后台**的一个单独线程上运行;键入和导航保持即时。
- 它是**可恢复的** — 如果你取消它,或在运行中途关闭应用,下次运行会从停下的地方继续,而不是重新开始。
- 它只计算**缺失或过期**的摘要 — 摘要已是当前的笔记会被跳过,所以第二次运行很快。

## 确保使用你自己的摘要

在卡片上,摘要出现在单个**摘要**标签下 — 卡片不会标注文本来自你还是来自引擎。决定这一点的是上面的优先级:如果一篇笔记有 frontmatter 字段之一或摘要 callout 之一,Constellation 就显示*那个*并从不生成一段。

所以如果一篇笔记显示的摘要读起来像是机器选的,那这篇笔记既没有 frontmatter 摘要也没有摘要 callout — 修复方法是添加一个:

- 给笔记的 frontmatter 添加一个 `summary:`(或 `description:` / `abstract:` / `excerpt:`)字段,**或者**
- 给正文添加一个 `> [!summary]`(或 `[!abstract]` / `[!tldr]`)callout。

下次计算那篇笔记的摘要时 — 当它的卡片下次加载时,或在你运行 **生成全部摘要** 之后 — 你的文字就会接管。

## 常见工作流程

**「一篇笔记显示了机器摘要,但我写过一段。」**
Constellation 没有在它查找的地方找到你的摘要。请确保你的 frontmatter 字段命名为 `summary`、`description`、`abstract` 或 `excerpt`,**或者** 你的 callout 是 `[!summary]`、`[!abstract]` 或 `[!tldr]`。然后重新打开分类器(或点击 *生成全部摘要*)以刷新。

**「我想让每张卡片在我一打开分类器时就显示其摘要。」**
点击一次 **生成全部摘要** 并让它跑完。在那之后,摘要就预先计算好了,会立即出现。

**「我想让摘要成为笔记本身的一部分,存在磁盘上。」**
自己写它 — 添加一个 `summary:` frontmatter 字段或一个 `> [!summary]` callout。然后 Constellation 会显示你的版本(并停止生成一段),你的文字就活在文件里,任何其他应用也能读到它。
