# Constellation 用户手册

**版本 0.1.0 | 2026年3月**

Constellation 是一款用于管理 Markdown 笔记库的个人知识管理（PKM）桌面应用程序。基于 Tauri v2、SvelteKit 和 Rust 构建，可在 Windows、macOS 和 Linux 上原生运行，并完整支持阿拉伯语和 RTL。

## 1. 入门指南

### 安装

从 [Constellation 发布页面](https://github.com/eisaShamsi/Constellation/releases) 下载最新安装程序：

- **Windows**：`.exe`（NSIS）或 `.msi` 安装程序
- **macOS**：`.dmg` 磁盘映像
- **Linux**：`.AppImage` 或 `.deb` 包

### 首次启动

首次打开 Constellation 时，**宇宙设置向导**将引导您完成以下步骤：

1. **选择语言** — 支持15种语言
2. **创建或导入库** — 指向现有的 Markdown 文件文件夹，或从零开始
3. **命名宇宙** — 宇宙是所有库的容器

### 界面概览

| 元素 | 说明 |
|------|------|
| **侧边栏（功能区）** | 导航按钮：文件树、搜索、星图视图、日历、模板、设置 |
| **文件树** | 浏览库中的笔记和文件夹 |
| **编辑器** | 阅读和编辑 Markdown 笔记 |
| **标签栏** | 以标签页方式打开多个笔记 |
| **状态栏** | 字数、字符数、阅读时间 |

## 2. 宇宙与库

### 什么是宇宙？

**宇宙**是容纳所有库的顶级容器。可以将其视为工作空间或库集合。

### 什么是库？

**库**是计算机上包含 Markdown（`.md`）文件的文件夹。您可以在一个宇宙中拥有多个库——例如，一个用于工作笔记，一个用于个人笔记。

### 管理库

- **添加库**：设置 > 库 > 添加库，或将文件夹拖入应用
- **移除库**：设置 > 库 > 点击库名旁的移除按钮
- **库设置**：每个库可以有自己的外观设置（字体、颜色）

### 同步与外部更改

Constellation 遵循 **File Over App**（文件优先于应用）——你的笔记就是磁盘上的纯 `.md` 文件，应用会持续监视它们的更改。如果在应用打开期间，某篇笔记从 Constellation *外部*被新增或修改——例如来自另一台设备的 Obsidian 同步、一次 `git pull`、某个云同步工具（iCloud / Syncthing / OneDrive），或是你直接丢进某个库文件夹里的文件——Constellation 都会在大约一秒内**自动**将其纳入，**无需重启**：

- 该笔记会出现在**文件树**中。
- 它会立即可在**星际跳转（快速打开）**（`Ctrl+O`）、**搜索**、**索引**、**反向链接**以及库的**笔记数量**中被找到——这些全都会自行更新。
- 如果你在应用外部重命名了某个文件夹，它里面的笔记仍能在新位置被找到，旧的条目也会被清理掉。
- 遇到大批量更改（一次拉取许多笔记的 `git pull`，或首次同步）时，索引会在后台建立——在搜索追赶进度的同时，打字始终保持即时。

你无需做任何操作：当文件在磁盘上发生变化时，Constellation 会让它的搜索索引与你的文件保持同步。*（一个细节：从应用**外部**重命名文件夹会重置这些笔记的复习计划与链接权重历史——笔记正文本身不受影响。在 Constellation **内部**重命名文件夹则会完整保留这一切。）*

**如果发生更改的笔记当前正在某个标签页中打开**，Constellation 会安全地将它更新到最新——你的工作绝不会被悄悄覆盖：

- 如果你在该笔记中**没有未保存的更改**，这篇打开的笔记会静默刷新以显示外部的编辑，这样你的下一次按键就会在新版本的基础上继续。*（此前，打开的笔记会一直显示旧的文本，而你的下一次按键可能会悄悄覆盖掉外部的编辑——现在这种情况不会再发生了。）*
- 如果在外部更改到来的同一时刻，你在该笔记中**确实有未保存的编辑**——这是一次真正的冲突——Constellation 绝不会触碰你未保存的工作。它会在编辑器中保留**你的**版本，把传入的外部版本写入该笔记旁边的一份**并列副本**（命名为 `<note>.conflict-<timestamp>.md.txt`，因此绝不会丢失任何内容），并显示一条横幅：*"对 {note} 的一次外部编辑已作为单独的副本保留——你的版本保持不变。"* 点击**显示副本**即可打开文件夹并定位到那份并列副本，如果你愿意，也可以手动合并。这份并列副本是一个惰性的 `.txt` 文件——它绝不会出现在你的侧边栏或搜索中，也绝不会触发另一次同步。

**合并两个版本。** 冲突横幅上还有一个 **合并…** 按钮。点击它会打开一个全屏的双栏视图——左侧是**你的版本**（可编辑），右侧并排显示**外部副本**（只读）——其中的差异会被高亮显示，相同的部分则被折叠收起。每一处差异旁边都有一个**复制到我的版本**按钮，可以把那处外部改动拉进你的版本；你也可以自由编辑左栏，手动把两者合二为一。完成后，**保存合并结果**会写入你调和好的那篇笔记，并把这份并列副本移入库的回收站（可恢复，绝不删除）；**取消**则什么都不会改变——两个版本都会原封不动地保持原样。Constellation 绝不会自动合并——如何调和，永远由你自己决定。

**如果被修改的笔记当时是关闭的**，重新打开时你会看到较新的文件。Constellation 会为你打开过的每篇笔记保留一份安全副本——保存失败时保护未保存内容的正是它——而在 0.1 版之前，这份副本可能压过在笔记关闭期间于别处被编辑的文件：你重新打开它，看到的是*旧*内容，而下一次切换标签页时，Constellation 就把旧版本写回、覆盖了较新的文件。悄无声息，并报告为保存成功。

> [!important] 已在 0.1 中修复
> 安全副本现在会记录它保存的是从未写入磁盘的内容，还是仅仅是已保存内容的一份拷贝。只有前者才能胜出。因此，在关闭期间被另一台设备、`git pull` 或任何同步工具修改过的笔记，打开时显示的是**较新的文件**——而未保存的内容仍与以往一样受到保护。
>
> 有一点值得知道：旧版本生成的副本没有这项标记，因此对某篇笔记而言，旧行为会一直持续到你下一次打开并关闭它为止。

### 如果你的笔记在 Constellation 关闭期间发生了更改

以上所讲的，都是**在 Constellation 运行期间**到来的更改。而一篇在应用*关闭*期间发生变化的笔记则是另一回事：当时没有任何东西在监视，因此搜索还不知道它。

Constellation 会在自己启动之后随即检查这件事。如果发现了什么，窗口顶部会出现一条**琥珀色横幅**，告诉你它发现了什么——例如*"Constellation 关闭期间磁盘上有 22篇笔记 发生变更，搜索可能不会显示其最新内容。"*——并且会另外说明，你的库中有多少笔记从未被加入搜索索引。它只会陈述确实为真的情况：数量为零的项目不会出现任何句子。你可以用 **✕** 关掉这条横幅，而且不会有任何东西在你背后被改动——它只是在告诉你，还没有修复任何东西。

**要修复它，请按横幅上的"立即修复"。** 同一项作业随时也可以从**设置 → 索引 → 索引修复 → 修复**启动。

这项修复做的事情是：重新读取自 Constellation 上次查看以来发生过变化的每一篇笔记，为它从未见过的笔记建立索引，并重建那些由你的笔记派生出来的视图（**外链**、**反向链接**、**星空视图数据**、**标签计数**以及**复习计划**）。**它绝不会写入你的笔记文件**——它只读取笔记，更新的是 Constellation 自己的索引。它在后台运行，因此你可以继续工作；进度会显示在窗口底部，并带有一个**取消**按钮，而取消之后，已经修复好的部分都会保留。

修复结束时，应用会**无需重启**地跟上最新状态——搜索能找到之前找不到的笔记，星图视图也会补全。随后，那条琥珀色横幅会*重新查看一遍*，而不是假定修复已经成功：如果已经没有什么要报告的，它就消失；如果还有，它会显示更小的数字。

**设置 → 索引**中还会在**上次修复**下保留上一次修复对自身的记录——重新读取了多少笔记、有多少没有变化、有多少失败，以及五个派生视图各自的一行说明。这份报告只在应用的本次运行期间存在；重启之后它就不再显示，直到你再次运行修复为止。

**你还可能看到另一条消息。** 如果一次修复被中断——最常见的原因是修复正在进行时关闭了 Constellation——剩下的重建工作会在下次启动时完成。这发生在窗口已经打开、可以使用*之后*，底部会出现一条消息说明它正在完成一次被中断的修复：*"正在完成中断的索引修复…"*。这不需要你采取任何行动；它耗时几秒钟，然后就会消失。早期版本是在应用仍在启动、尚不可用时做这件事的——大约三秒钟，屏幕上没有任何东西解释这段等待。

### 子宇宙

您可以在宇宙中嵌套宇宙。**子宇宙**是被父宇宙引用的另一个宇宙文件夹。子宇宙中的笔记会在星图视图中与您的笔记一同显示，跨库链接以虚线表示。

### 自动重新打开

Constellation 会记住您最后活跃的宇宙，并在启动时自动重新打开。如果宇宙已被移动或路径已更改，Constellation 会自动检测并修复路径。

### 可移动宇宙

Constellation 的宇宙完全可移动。您可以将宇宙文件夹移动到任何位置——不同的驱动器、U盘或另一台电脑——Constellation 在重新打开时会自动检测并修复所有内部路径。

移动宇宙的步骤：
1. 关闭 Constellation
2. 将宇宙文件夹移动或复制到新位置
3. 打开 Constellation → 显示欢迎界面（旧路径已失效）
4. 选择**打开现有宇宙**并指向新位置
5. 所有笔记和库立即显示——路径自动修复

宇宙文件夹结构遵循 Obsidian 模式：笔记直接存放在根文件夹中，配置存放在 `.constellation/` 中。

---


### 一个宇宙，一个位置

宇宙是**容纳其全部知识的一个文件夹**。每个库都住在其中——备份、同步或搬迁你的知识，就是处理一个文件夹。**带入库**会把现有的笔记文件夹（每次由你选择）复制或移动进宇宙；*复制*让原件原地不动，*移动*则把文件夹本身迁入。新库总是建在宇宙之内。

若你打开的宇宙仍有库在外面，Constellation 会提议**统一**：一个对话框列出每个外部库及其去向，每项可选移动/复制。在你点击**统一**之前，一切不动。移动前会在宇宙文件夹内保存经验证的备份；每一步都有记录——即使中途断电也会从停下的地方精确续行。笔记、链接、其历史与回顾计划都逐字节保留，并在完成前经过校验。而且宇宙**只有一个**回收站，在其根部。

## 3. 创建和编辑笔记

### 创建笔记

| 方法 | 操作 |
|------|------|
| **键盘** | `Ctrl+N` |
| **文件树** | 右键点击文件夹 > 新建笔记 |
| **任务控制** | `Ctrl+P` > "新建笔记" |

### 文件浏览器（文件树）

**文件浏览器**是侧边栏中浏览笔记和文件夹的地方——按你在磁盘上真实的目录结构呈现你的宇宙、各个库和它们的文件夹。除了打开笔记，它现在还把过去分散在别处的全部文件管理能力集中到了这一处：**筛选、排序、多选和批量操作**。

**按名称筛选。** 文件树顶部有一个筛选框。输入内容，文件树只保留**名称**匹配的笔记和文件夹。它会**搜索所有库**——即使某个库当前是折叠的，也会临时载入并展开以显示匹配项，清空筛选框后再恢复原来的折叠状态。这个筛选**只匹配名称，绝不匹配笔记正文**——要在笔记内容里搜索，请用搜索中枢（Search Hub，`Ctrl+Shift+F`）。

**排序。** 文件树顶部的排序菜单提供**八种顺序**：名称（A→Z / Z→A）、修改时间（最新 / 最旧）、创建时间（最新 / 最旧）、大小（最大 / 最小）。无论选哪一种，**文件夹始终排在前面**，笔记随后按所选顺序排列。

**多选。** 你可以一次选中多篇笔记或多个文件夹：

- **Ctrl+点击**（macOS 为 **⌘+点击**）——把某一行加入或移出选择集。
- **Shift+点击**——选中从上一个选中项到当前项之间的**整段范围**。
- **普通点击**——照常打开那篇笔记（不进入多选）。
- **Escape**——清空当前选择。

被选中的行会**高亮**显示，让你一眼看清选了哪些。

**批量操作栏。** 只要选中了至少一项，文件树底部就会出现一条**批量操作栏**，显示所选**数量**，并提供三个动作：

- **加标签** — 给所选的每一篇笔记添加一个标签。
- **移动** — 把所选项一并移动到你选定的文件夹。
- **删除** — 把所选项移入废纸篓（可恢复，绝不是永久删除）。

每个批量动作都走的是**与单篇笔记完全相同的安全受控流程**，因此重命名、链接更新等一切都会照常保持正确。**只读的子宇宙笔记会被自动跳过**——批量操作绝不会改动你无权修改的联邦（子宇宙）内容。

### 重新启动时标签页自动恢复

过去，关闭 Constellation 后应用不会记住您打开过哪些笔记——每次启动都是一片空白。现在，应用会记住您打开的标签页、哪个是活动标签页、窗口是否处于分屏状态，并在下次启动时自动恢复原样。您的书桌保持着离开时的模样。

- 这份记忆是**按宇宙分开保存**的，会在您打开、关闭或重新排列标签页约一秒后静默更新。即使应用崩溃或被强制结束，最多也只会丢失最后一秒的*标签页布局*——绝不会丢失笔记内容（内容安全由另一套更早的机制保障）。
- 应用关闭期间被移动或删除的笔记会被自动跳过，其余标签页照常恢复。
- 如需关闭此功能：**设置 > 编辑器 > 重新启动时恢复标签页**。关闭此选项也会删除已保存的会话——关闭即意味着*不再记忆*。
- 已命名的**工作区**不受影响：它们仍是您有意手动保存的快照。此功能只是滚动更新的"最近状态"。
- 已知限制：使用分屏视图时，分屏本身会恢复，但哪些标签页位于哪半边尚未被记住。

### 编辑器模式

Constellation 提供两种编辑器模式，可在**设置 > 编辑器 > 编辑器类型**中选择：

#### Markdown 编辑器（CodeMirror）

面向高级用户的默认编辑器，可直接编写 Markdown：

- **实时预览** — 输入时内联渲染格式
- **源码模式** — 显示原始 Markdown 语法
- **格式工具栏** — 选中文本时出现
- **斜杠命令** — 输入 `/` 快速插入
- **Wikilink 自动补全** — 输入 `[[` 链接笔记
- **多光标** — `Alt+Click` 或 `Ctrl+D`

#### 文档编辑器（TipTap）

带有可视化工具栏的所见即所得文字处理体验：

- 加粗、斜体、下划线、删除线、高亮
- 标题（H1～H3）、文本对齐
- 无序列表、有序列表、任务列表
- 引用块、代码块、水平线
- 表格（插入、添加/删除行列）
- 链接和图片

两种编辑器都保存为标准 Markdown 文件。您可以随时切换而不会丢失数据。

### 标注 (Callouts)

创建样式化的标注块，用于注释、警告、提示和其他说明：

```markdown
> [!note] 重要信息
> 标注内容写在这里。

> [!warning] 请注意
> 此操作无法撤消。

> [!tip]- 点击展开
> 可折叠的标注内容。
```

支持的类型：`note`、`tip`、`warning`、`danger`、`success`、`question`、`failure`、`bug`、`example`、`quote`、`abstract`。每种类型都有独特的颜色和图标。在类型后添加 `-` 使其可折叠（初始为折叠状态），或 `+`（初始为展开状态）。

#### 自定义标注——颜色、图标和您自己的类型

标注的颜色和图标都可以随您更改，您还可以创造自己的标注类型。打开样式设定器（停靠栏中的 🎨 按钮），选择「编辑器」类别，然后点击「标注」。中央会打开一个统一的标注管理器，每个标注占一行，显示它的颜色、图标和名称。

- 重新着色内置标注。点击该行上的颜色色块。会打开一个小调色板，里面有您保存过的颜色（点击即可应用），以及一个用于选取任意新颜色的「自定义…」选取器——您选取的颜色也会被加入调色板，方便下次使用。内置类型的颜色更改会在您于样式设定器中按下「保留／应用」时保存。
- 更改内置标注的图标。点击该行上的图标。会打开「表情符号与图标库」——可挑选任意表情符号或矢量图标。它会立即在所有位置以该标注的颜色生效。旁边会出现一个小小的 ↺，方便您单独还原该图标。
- 重置内置项。管理器顶部的「↺ 重置此元素」按钮会将所有内置标注的颜色和图标恢复为默认值。（您的自定义标注不受影响——请逐个移除它们。）
- 创建您自己的标注类型。分隔线下方是「添加」一行。输入一个名称（例如 Decision 或 فكرة）、一个触发词（您将要输入的 [!word]——支持任意语言，包括阿拉伯语），挑选一种颜色和一个图标，然后点击「添加」。现在在任意笔记中输入 > [!decision]（或 > [!فكرة]）就会渲染出您的标注。如果您在触发词后不输入标题，标注的标题栏会以粗体显示您该标注的名称。
- 编辑或移除自定义标注。使用该行上的 ✎（编辑名称／触发词）和 ✕（移除）。移除某个类型不会改动您笔记中的 [!…] 文本——它只是恢复为普通笔记的外观，直到您重新创建该类型为止。

您的自定义标注、颜色和图标会随这个宇宙（Universe）一起保存，因此它们会跟随您的库（Library）一同迁移。

### 重命名笔记会自动更新指向它的所有链接

当您重命名一条笔记时——在文件树中（右键点击 → 重命名），或直接编辑页面顶部的标题——Constellation 会改写每一条指向它的链接，链接绝不会悄无声息地失效。这由**设置 → 链接**下的**自动更新内部链接**开关控制；除非您关闭它，否则始终生效。更新期间，受影响的笔记上会短暂出现「正在更新链接…」的提示层。

**每一种链接形式都会更新**，不只是最简单的那种：普通链接（`[[笔记名称]]`）、带有您自定义显示文字的链接（`[[笔记名称|您希望显示的文字]]`）、承载关系的**类型化**链接（`[[supports::笔记名称]]`，以及带批注的 `[[supports::笔记名称|为何支持]]`），还有指向笔记*内部*的链接——指向某个标题（`[[笔记名称#某个标题]]`）或某个区块（`[[笔记名称^区块编号]]`）。只有名称会改变：关系类型、您的显示文字、您的批注，以及所指向的标题或区块，都会原样保留。此前，类型化链接和指向标题或区块的链接会被遗漏，仍然指着旧名称，而且不会有任何提示。 在通往笔记的路径上写出文件夹名的链接（`[[文件夹名/笔记名]]`）同样会更新，并且原样保留其文件夹——改动的是笔记的标题，而非它的位置。**还有一种情形尚未涵盖：** 若链接所写标题的大小写与笔记本身不同，它依然能够解析，但改名之后仍旧指着旧标题。

**覆盖您宇宙中的每一个知识库。**更新会到达当前打开的宇宙中**所有**知识库里的笔记，而不只是被重命名笔记所在的那一个——因此跨知识库的链接也能在重命名后保持完好。**已链接的（子）宇宙**中的笔记则被有意保留不动：那是一个独立的知识库，Constellation 不会改写它的笔记。

**如果有笔记未能更新，您会被告知。**偶尔某个文件被锁定、为只读，或正被其他程序占用。Constellation 不会报告一切顺利，而是列出这些笔记，并说明它们的链接仍指向旧名称，让您清楚该检查哪些内容。

**重命名文件夹不会改动任何链接**——这是刻意的设计。文件夹名称从不出现在链接内部，因此没有什么需要改写。

### 保存与恢复

Constellation 会在您输入时**自动保存**——没有"保存"按钮。当您停顿片刻后（以及每当您切换笔记或关闭标签页时），您的编辑就会写入 `.md` 文件。只有当笔记真正写入磁盘后，它才会被标记为"已保存"。

**关闭应用同样是一个保存点。** 当您关闭 Constellation 时，所有含有未保存输入的笔记都会在窗口关闭**之前**写入各自的文件——包括您在点击 ✕ 前最后一秒敲下的文字。正常关闭（没有未保存内容时）与以前一样瞬间完成；当有内容需要写入时，窗口可能会短暂停留片刻（最多五秒），以便您的笔记安全地写入磁盘。

如果某次保存**失败**——例如某个同步工具（iCloud / OneDrive / Syncthing）或杀毒软件短暂锁定了该文件——Constellation **不会**丢失您的工作：

- 顶部会出现一条横幅：*"无法保存 {note}——您的编辑是安全的，将会重试。"* 您输入的内容会保留在屏幕上，并安全地保存在内存中（以及一个即使重启也不会丢失的恢复缓冲区里）。
- Constellation 会**每隔几秒自动重试**，因此一旦文件解除锁定，您的编辑就会自行写入——即使您已经离开也没关系。
- 您也可以点击横幅上的**立即重试**来马上保存。笔记保存后，横幅便会消失。

您完全不必担心文件被锁定或短暂不可用会让您丢失任何编辑。

---


### 无法保存时，Constellation 现在会告诉你

同样的坦率也适用于笔记正文之外。若某个**属性**无法写入，属性面板会明确说明，并把你的更改保留在屏幕上，而不是悄悄丢弃。若某个**回顾优先级**无法保存，滑块会带着一行简短说明回到已保存的值，而不是停在你拖动的位置、仿佛一切正常。若某个**已保存的样式**无法写入，样式库会恢复原样，而不是显示一个磁盘上并不存在的样式。若某个**任务复选框**无法写入其笔记，勾选会被取消，并在列表上方出现一行说明。以往在这些地方的行为都是沉默——更改看起来被接受了，而你要么后来才发现，要么永远不会发现。

**两个同名文件都可以恢复**：若你从一个文件夹删除 `Notes.md`，接着又从另一个文件夹删除 `Notes.md`，第二个会以带编号的名称存放在第一个旁边——无论两次删除相隔多近，先删的那个都不会被替换。此外，回收站中的笔记不会出现在搜索结果和链接建议中；删除的笔记不会再回来。

## 4. 搜索

Constellation 内置基于 SQLite FTS5 的混合多语言搜索引擎，支持 BM25 排名、结构化查询过滤器和阿拉伯语优化规范化。搜索可通过侧边栏工具栏访问。

### 如何搜索

点击侧边栏工具栏中的搜索图标，或使用 `Ctrl+Shift+F` 激活搜索模式。输入查询后，结果会在短暂延迟（300毫秒）后显示。按 `Escape` 或点击 `×` 按钮清除搜索并返回文件树。

### 搜索语法

| 语法 | 示例 | 搜索内容 |
|------|------|----------|
| 自由文本 | `项目管理` | 标题或正文中包含这些词的笔记 |
| 标签过滤 | `#研究` | 带有 `#研究` 标签的笔记 |
| 属性过滤 | `status=active` | frontmatter 属性 `status` 等于 `active` 的笔记 |
| 维基链接过滤 | `links to [[气候]]` | 链接到 `[[气候]]` 的笔记 |
| 库范围 | `in:我的库` | 将结果限制在特定库中 |
| 组合 | `#研究 status=active 经济` | 所有过滤器同时应用 |

### 匹配类型徽章

每个搜索结果显示一个彩色徽章，表明匹配是如何找到的。徽章显示本地化字母以提高可访问性（色盲安全）：

| 徽章 | 颜色 | 含义 |
|------|------|------|
| **标** | 蓝色 | 标题匹配 - 搜索词出现在笔记名称中 |
| **内** | 绿色 | 内容匹配 - 搜索词出现在笔记正文中 |
| **语** | 紫色 | 语义匹配 - 概念上相关（需要嵌入模型） |
| **属** | 琥珀色 | 属性匹配 - 通过 frontmatter 属性过滤器找到 |
| **#** | 粉色 | 标签匹配 - 通过标签过滤器找到 |
| **维** | 浅蓝色 | 维基链接匹配 - 通过维基链接过滤器找到 |

徽章字母已针对所有 15 种支持的语言进行本地化。

### 固定结果（浏览结果）

点击某个结果后，搜索结果保持可见。打开的笔记在结果列表中高亮显示，以便您知道正在查看哪个结果。无需重新搜索，点击另一个结果即可导航到该结果。

要清除搜索，按 `Escape` 或点击 `×` 按钮。

### 键盘导航

| 按键 | 操作 |
|------|------|
| `向下箭头` | 选择下一个结果 |
| `向上箭头` | 选择上一个结果 |
| `Enter` | 打开选中的结果 |
| `Escape` | 清除搜索并返回文件树 |

### 搜索词高亮

从搜索结果打开笔记时，搜索词的所有出现位置都会在编辑器中高亮显示。这支持阿拉伯语变音符号感知匹配 - 搜索"ادارة"将高亮"إدارة"及所有变音符号变体。

### 搜索历史

搜索字段为空时点击它，可查看最近的搜索（最近 20 条查询）。每个条目显示查询文本和执行时间。点击任何条目可立即重新运行该搜索。使用底部的"清除历史"链接删除所有历史记录。

搜索历史本地存储在您的设备上，在应用重启之间保持不变。

### Search Hub

Search Hub 是全屏搜索体验。点击停靠栏中的放大镜图标打开它。两侧边栏折叠以提供最大空间。输入任何词条，Constellation 同时搜索所有位置，将结果分为 5 个类别：标题、内容、标签、属性和维基链接。每个类别都有一个可折叠的部分，带有计数徽章。点击任何结果在编辑器中打开，所有出现位置都会高亮显示。"返回 Search Hub" 按钮出现，让您无需重新搜索即可返回。

### 链接运算符

Constellation 支持 6 个链接拓扑搜索运算符：

| 语法 | 查找内容 |
|------|----------|
| `links to [[X]]` | 链接到 X 的笔记（反向链接） |
| `links from [[X]]` | X 链接到的笔记（外向链接） |
| `mutual [[X]]` | 与 X 互相链接的笔记（双向） |
| `mentions [[X]]` | 包含 X 名称但没有 [[维基链接]] 的笔记 |
| `orphans` | 没有任何传入或传出链接的笔记 |
| `links between [[X]] and [[Y]]` | 同时链接到 X 和 Y 的笔记 |

输入任何链接运算符时，`[[` 自动补全显示宇宙中的所有笔记。选择笔记后，输入 `#` 进行标题补全或 `|type:` 进行链接类型补全。

## 7. 索引

索引是跨所有库的综合术语词汇表——每个有意义的词汇，按字母顺序排列并附有出现次数。

### 打开索引

- **停靠按钮**：点击左侧停靠栏中的索引图标（书本）
- **命令面板**：`Ctrl+P` 然后输入 "Index"

### 多语言 NLP 管道

索引在建立索引之前通过语言感知管道处理文本：

- **阿拉伯语**：Lucene Light10 算法——移除变音符号、统一哈姆扎、去除定冠词（الـ）、移除语法后缀
- **希伯来语**：前缀移除（ב/ל/מ/ה/ו/כ/ש）
- **英语**：Porter 类词干提取（复数、动词形式、后缀）
- **法语/西班牙语/葡萄牙语/德语**：语言特定后缀移除
- **俄语/土耳其语/印地语/波斯语**：形态后缀移除

## 10. 属性和前置数据

笔记顶部可以包含 YAML 前置数据：

```yaml
---
tags: [project, active]
date: 2026-03-19
status: in-progress
---
```

Constellation 会自动检测属性类型：

| 类型 | 示例 |
|------|------|
| **文本** | `author: John` |
| **数字** | `priority: 5` |
| **日期** | `date: 2026-03-19` |
| **列表** | `tags: [a, b, c]` |
| **复选框** | `done: true` |
| **链接** | `related: [[Other Note]]` |

切换属性显示：**设置 > 编辑器 > 文档中的属性**（显示 / 隐藏 / 源码）。

### 列表的四种写法

像 `tags:` 或 `aliases:` 这样的列表可以有四种写法，含义完全相同。Constellation 都能读取，并显示同样的标签：

- **缩进式** —— `tags:` 下方写 `  - a`。这是 Constellation 自己写入的形式。
- **不缩进式** —— `tags:` 下方从最左侧开始写 `- a`。这同样是合法的 YAML，也是许多其他工具导出的形式，因此在导入的库中很常见。
- **写在一行** —— `tags: [a, b]`。
- **写在下一行** —— `tags:` 下方写 `  [a, b]`。

> [!important] 已在 0.1 中修复
> 不缩进的写法此前会被读成*空*列表。条目仍在文件里，但面板什么也不显示 —— 而只要新增一个标签，整个列表就会被替换，原有条目随之从文件中丢失。现在四种写法都能正确读取。同一缺陷还影响 `aliases:`（笔记别名的链接依靠它解析），以及构成连接图谱的 `supports:`、`contains:` 等带类型的链接。

### 修改属性后立即离开

属性修改会在你停止输入约 0.8 秒后保存。如果你在**右侧边栏**中修改属性，并在这段时间内点开一个链接，Constellation 会**丢弃**这次尚未保存的修改——它不会被带到你跳转到的那篇笔记上。

> [!important] 已在 0.1 中修复
> 在 0.1 之前，这次尚未保存的修改会被**应用到你刚跳转到的那篇笔记**上：只属于第一篇笔记的属性可能出现在第二篇上，而第二篇自己的值可能被覆盖——悄无声息，并写入磁盘。若想让修改确实生效，请在跳转前稍作停顿，或在笔记**内部**的属性区中编辑。

### 长文本块

`description: |` 后接缩进的若干行，可将多行文字作为一个值保存。Constellation 会以**只读**方式显示该行，并预览首行内容 —— 与嵌套字段同一条规则：无法安全改写的内容，就不改写。需要修改时，请直接编辑 `.md` 文件。

## 10b. 来源审阅 (Constellation 认知内容引擎 — CECE)

> *(翻译说明:V3-§10.F 章节的 AI 生成翻译；母语者审阅待定。)*

前置数据中最重要的两个属性 — `sources:` 和 `content_type:` — 描述了你*如何得知*某事以及它是*哪一类知识*。Constellation 的**认知内容引擎** (CECE) 使用六个分类器集成自动沿这两个轴对每条笔记进行分类。**来源审阅**面板是你审阅和修正这些分类的地方。

### 引擎做什么

当你对一条笔记进行分类时（右键单击 → "建议来源和内容类型"，或通过**设置 > 运行扫描**，或通过后台扫描开关自动），CECE 对笔记运行六个独立的分类器。每个分类器通过不同的透镜读取笔记，并对两个问题投票:

- **来源** (水平轴) — 这一知识*从何而来*?十一种可能的值:感知、推理、证言、大量传递、比较、假设、非感知、记忆、先天倾向、灵感、启示。加上*无法分类*。
- **内容类型** (垂直轴) — 这是*哪一类*知识?五个顶级分支:感官输入、符号实体、语义内容、认知状态、高阶构造。

两个轴是独立的。"我怀疑登月"这条笔记的来源是证言（有人报告了），内容类型是认知状态/怀疑（你的立场）。

引擎在**你的设备上**运行 — 任何笔记都不会离开 Constellation。

### 六个分类器

每个分类器是一个透镜。来源审阅卡片在每张卡片的右上角将它们显示为六个小的彩色圆点:

- **你的 frontmatter** (蓝色) — 以绝对权威采用你已经设置的内容
- **引用与结构** (玫瑰色) — 引用、块引、定理标记、定义短语
- **词干与词汇** (琥珀色) — 阿拉伯语词根分析 + 跨语言术语等效
- **已链接笔记** (青绿色) — 到其他已分类笔记的类型化 Living Links
- **相似笔记** (紫罗兰色) — 与你已分类笔记的嵌入相似度
- **AI 判断** (绿色) — 本地 LLM (Qwen3-4B；*尚未激活*，推迟到未来版本)

实心圆点表示该分类器发了言并同意综合结论。带环圆点表示发了言但持异议。虚线轮廓圆点表示保持沉默 (此透镜无信号)。

### 三种信任体制

分类器投票后，每个轴落入三种体制之一:

- **一致同意** — 所有发言的分类器都同意
- **多数赞成 (一项异议)** — 大多数同意；指出一名异议者
- **分裂** — 没有明确的多数；引擎拒绝猜测，要求你选择

每个轴独立获得自己的体制 — 一张卡片可以在水平轴一致同意 + 在垂直轴分裂等。

### Sibling Disambiguation

当一个轴处于分裂时，引擎将候选值作为**芯片**显示在提示下: *"选择最适合这条笔记的一个。"* 点击芯片 → 引擎将你的选择写入笔记的 frontmatter 并从队列中移除卡片。如果另一个轴已确定 (一致同意或多数赞成)，引擎*同时*写入该轴的值 — 当只有一个轴分裂时，一次点击完成两个轴。

### 推理追溯

每张卡片都有一个 *"▸ 为什么是这个分类?"* 切换。展开后显示每个发言分类器的一行，包含推理、自报告的信任度和友好的规则芯片 ("表面关键词匹配"、"阿拉伯语词根匹配 (CAE)"、"定义标记" 等) — 这些是每个分类器触发的具体规则。

在你的**前 50 次审阅**期间，每张卡片上的追溯都会自动展开 (一个*信任校准期*)，以便你可以建立何时信任引擎的直觉。之后，追溯在一致同意的卡片上折叠为按需显示。随时在**设置 > 智能 > CECE > 推理追溯可见性**中覆盖。

### 队列构成筛选器

在计数条上方，五个芯片根据每张卡片需要的决策类型对队列进行切片:

- **全部** — 完整队列
- **两个轴都需要你判断** — 两个轴都分裂
- **来源需要你判断** — 水平分裂 + 垂直确定
- **内容类型需要你判断** — 垂直分裂 + 水平确定
- **分类器已达成一致** — 没有轴分裂 (橡皮图章候选)

每个芯片显示其桶数。筛选器是渲染层切片器 — "全部接受"数学始终在完整队列上运行，无论哪个筛选器处于活动状态。

### 每张卡片的操作

- **接受** — 将引擎的综合结论作为两个轴的主要内容写入；移除卡片。更新每个分类器的可靠性。
- **编辑** — 打开两个轴的树选择器；手动选择。相同的可靠性更新。
- **拒绝** — 不写入清除卡片。
- **Sibling Disambiguation 芯片** — 仅在分裂卡片上。

### 按 Library 校准

**设置 > 智能 > CECE > 按 Library 校准**打开一个只读表，显示活动 Library 上每个分类器在每个轴上的准确度。不同的 Library 有不同的每分类器准确度 — Linguistic 在阿拉伯语为主的 Library 上表现出色，Graph 在密集链接的 Library 上表现出色。综合层使用此校准数据来加权投票。

分类器需要 **20 次修正**才能显示其准确度比率。低于该阈值时，标签显示为 *"(均匀)"* — 分类器贡献均匀加权的投票，直到累积足够的数据。

### 后台分类

默认情况下，CECE 仅在你要求时才对笔记进行分类 (右键单击或设置扫描按钮)。你可以在**设置 > 智能 > CECE > 后台分类**中选择自动分类:

- **笔记保存时** — 在你停止键入约 1.5 秒后对每条笔记进行分类 (利用现有的防抖保存；从不按每个键击触发；键入保持即时)
- **应用启动时** — 每次启动时扫描一次未分类的笔记

### 分类器 — 全页主页

同样的卡片也存在于一个名为**分类器** (the Cataloger) 的全页视图中,从**左侧停靠栏的层叠卡片图标**打开。它是同一个引擎和同一个队列,占据整个窗口而不是窄窄的边栏标签页 — 而且它增加了边栏标签页从未有过的两个控件:

- **分类笔记…** — 一个搜索框,让你按名称对*任意*笔记进行分类,无需先打开它。键入几个字母,选取笔记,一张新卡片就会出现在队列中。
- **生成全部摘要** — 在后台为每条缺少摘要的笔记预先计算笔记摘要(见下文),进度显示在状态栏中。

一个 **开始扫描** 按钮(与设置中相同的宇宙级扫描)和一个实时进度条让头部更完整。用 **(×)** 或 **Esc** 关闭分类器。(当 *分类笔记…* 搜索框打开时,第一次按 **Esc** 仅关闭那个搜索框。)

一个命名说明:**分类器** (the Cataloger) 是*房间*(全页视图);**分类器组件** (the catalogers) 是引擎内部对每张卡片投票的*六个透镜*。别把两者弄混。

### 笔记摘要

每张卡片的标题下方有一段简短的**摘要** — 几句话告诉你这条笔记讲的是什么,让你无需打开它就能分类。Constellation 始终优先采用*你*写的摘要,只有在你没写时才生成一段:

1. 一个 `summary:` / `description:` / `abstract:` / `excerpt:` **frontmatter 字段**,逐字使用。
2. 正文中的一个 `> [!summary]` / `[!abstract]` / `[!tldr]` **callout**,逐字使用。
3. 否则,一段**生成的**摘要 — 笔记最核心的三个句子,经抽取(绝非编造)并按原始顺序显示。

生成的摘要是**只读的** — Constellation 从不把摘要写回你的笔记 (File-Over-App),且一切都在**你的设备上**计算。如果你想让摘要存在文件里,自己写一段,Constellation 就会显示你的。

有关更深入的详细信息 (每个圆点状态、每个规则芯片、逐步演练)，请参阅帮助系统中的 **Source Review**、**The Cataloger** 和 **Note Summaries** 主题。

## 10c. 认知元数据

一小组可选的前置元数据字段,用于记录有关一篇笔记的知识是如何获得的、谁持有该立场、它属于哪个学科以及你最后一次修订观点的时间等更丰富的信息。在 MIG-022 §A 中为响应差距分析 (`docs/epistemic-content-gap-analysis.md`) 而添加。

这些字段 **全部可选**。没有它们的笔记照常工作。

### 快速参考

| Field | Type | 用途 |
|---|---|---|
| `held_by` | text | 这是谁的立场?(默认为 `user`;可以是 `"al-Shāfiʿī"`、`"Ḥanafī"` 等) |
| `domain` | list | 用于检索的学科标签 (`[fiqh, ʿibādāt]`) |
| `function` | text | 这篇笔记是干什么用的 (`reference` / `seed` / `actionable` / `shipped`) |
| `provenance_civilization` | text | 传统词汇 (`sunni-usuli` / `analytic-western` / `nyaya` 等) |
| `updated_at` | date | 你最后一次有意修订观点的时间(不同于文件系统 mtime) |
| `ikhtilāf` | list of objects | 结构化的学术分歧 (`[{school, position}, ...]`) |
| `warrant` | text | 等级标签(已解析但在 Warrant Research 工作流发布前不活跃) |
| `warrant_notes` | text | 支持 warrant 等级的自由文本(也不活跃) |

### 它们如何在 Properties 面板中出现

每个字段以适合类型的编辑器渲染:
- 文本字段 → 文本输入
- `domain` → 标签列表(Enter 添加,× 删除)
- `updated_at` → 日期选择器
- **`ikhtilāf` → 自定义小部件**:每行两个并排输入(school + position)加上每行的删除按钮,以及底部的"添加学派"按钮。该小部件从结构化 YAML 读写,因此往返时保留每个字段。

### `supersedes` 怎么处理?

`supersedes` 是 *笔记之间的关系*(这篇笔记替换了较早的笔记),而不是单个笔记的属性。Constellation 将其作为 **类型化链接** 处理,而不是 YAML 标量:

```markdown
This replaces my earlier analysis: [[old-note-id|supersedes]]
```

wikilink 上的 `|supersedes` 后缀使其成为 `supersedes` 类型的类型化链接 — 独特的板岩蓝灰胶囊,出现在 Backlinks + Outgoing Links 面板中,参与 Living Link Architecture。

### 这 *不是* 什么

这些新字段是 **模式** — 你可以填写的可识别词汇。CECE 当前不消费它们用于分类。未来的 MIG(Warrant Research 工作流、MIG-023 时间轴)将发布读取 `warrant`、`updated_at` 等的功能。

有关更深入的细节和工作示例,请参阅帮助系统中的 **Epistemic Metadata** 主题。

## 15. 日历

**日历**是一个整页的月视图，从**左侧停靠栏**（日历图标）打开。有笔记或有到期任务的日期会用彩色**圆点**标记。标题栏以您所选的日历显示当前月份；如果您设置了**辅助日历**，下方的副标题会显示该日历对应的范围（例如，公历的某个月会显示其对应的回历跨度，"Dhul-Hijjah 1447 – Muharram 1448 AH"）。

**点击某一天。** 每个日期单元格都可交互：

- **点击空白处（或日期数字）** → 打开（或创建）那一天的**每日笔记**。点击一个已经有每日笔记的日期只会**打开**它——绝不会创建副本。
- **点击圆点** → 打开对应的具体条目。**金色**圆点是每日笔记；**紫色**圆点是当天编辑过的另一篇笔记；**红色**圆点是当天到期的任务。（颜色可在 Style Setter → 日历 中设置主题。）如果某一天有多篇笔记或多个任务，点击圆点会显示一个小**列表**供您选择。
- **点击任务圆点** → 打开笔记并**滚动到该任务所在的行**，可立即编辑。在任务列表中，您还可以直接从日历**勾选任务的复选框来完成它**——已完成的任务会立即从列表中消失。只有自身带有 `📅 YYYY-MM-DD` 的任务才会出现在日历上（正是这个日期决定了它落在哪一天）。

**文化日历（八种）。** 在**设置 → 日历**中，您可以设置**日历系统**——**公历、回历（伊斯兰历）、波斯历（太阳回历）、希伯来历、印度历（萨卡历）、佛历、中国农历或韩国历**——整个月历网格都会随之切换，每个单元格同时显示所选日历的日期（大字）和公历日期（小字），并附带月相。每个月份标题会显示月份**名称、括号中的序号以及年份**——序号有助于辨认那些月份顺序不常见的日历。**中国农历和韩国历**是*阴阳历*：它们有时会插入一个**闰月**（闰六月 / 윤6월），日历会将其单独显示为一页，因此导航既不会跳过也不会重复。回历采用精确的天文引算引擎；圣月会被高亮，伊斯兰节日会被标记。您还可以选择**每周起始日**（周日/周一）并切换**周数列**。

**回历选项。** 在**设置 → 日历 → "回历（伊斯兰历）"**下方有两个额外的控制项：

- **计算方法**——**天文（朔月合相）**，依据真实的新月（最精确，默认值），或**表算（al-Tawfīqāt al-Ilhāmiyyah，灵感校正表）**，即古典的算术周期。
- **月份校正**——将某个回历月份的起始日微调 ±1 或 ±2 天，以匹配**当地的实际观月**。选择回历的年份和月份，选定一个偏移量，然后点击 **Set（设置）**；该校正会应用于该月份及其之后的每个月份。您的所有校正都会列出（每一项均可删除），并附带一个 **Clear all（全部清除）**按钮。

这两项设置（以及您的各项校正）都会**随宇宙一同保存**，因此可以跨设备同步。

**中国农历和韩国历的显示选项。** 韩国沿用中国农历，因此两者的日期完全相同——区分它们的是文字与年份。当其中任一历法作为您的主日历或辅助日历时，**设置 → 日历**会显示两个额外的控制项：一个是**年份显示**（中国农历：六十甲子 丙午年、纯年份、或两者并列；韩国历：**檀纪**纪年 단기 4359、年份、或六十甲子 병오년），另一个是**月份名称**——*本地文字*（五月 / 5월）或*音译*，即用您自己的语言写出该月份的读音（英文 "Wǔyuè / Owol"；阿拉伯文 "وُو-يوي / أوه-وُل"）。

**为日历设置样式。** 打开 **Style Setter**（左侧停靠栏，或**设置 → Style Setter**）并选择**日历**界面，即可重新设置每个部分的样式——每个元素都有自己的**颜色和文字大小**（日期数字、交叉参照日期、月份药丸标签、星期标题、周数、月相符号、今日高亮、网格线，以及笔记/任务/事件圆点），还有日历的**字体**。一个实时、全尺寸的预览会随您的编辑而更新；点击 **Keep（保留）**即可应用。

> **每日笔记的文件名始终保持公历格式**（`YYYY-MM-DD`），无论显示的是哪种日历——这样您的文件就能保持可移植性并正确排序。文化日期会显示在日历中（也可以记录到笔记的 frontmatter 中）。

日历为每日笔记提供完整支持：点击任意一天即可打开它，或运行 **"Daily Note（每日笔记）"** 命令（命令面板）跳转到今天。

**在笔记中记录文化日期。** 有两个可选启用的工具能把文化日期写入笔记的**属性**（文件名始终保持公历 `YYYY-MM-DD`）：

- **每日笔记回历戳记**——*设置 → 日历 → "在每日笔记中戳记回历日期。"* 开启后（仅当回历是您的**主日历或辅助日历**时可用），每一篇**新建**的每日笔记都会获得一行 `hijri:`，例如 `hijri: 1448-01-06`。已有的笔记绝不会被改动。
- **笔记属性中的 "+ Hijri"**——打开任意笔记的**属性**，将鼠标悬停在日期上，就会出现一个小巧的 **"+ Hijri"** 按钮（还有 "+ Jalali"、"+ Hebrew" 等——**您每选择一种非公历日历，就有一个对应按钮**）。点击它，Constellation 会读取笔记的公历日期并添加对应的值，例如 `jalali: 1405-03-30`。韩国历按钮写入的是**檀纪**年；中国农历/韩国历的**闰月**会用 `L` 标记（例如 `chinese: 2025-06L-17`）。如果笔记没有日期属性，则使用文件的创建日期。

## 16. 镜头与 Constellation Base

**镜头**是已保存的查询，它显示已筛选并已排序的笔记列表，连同您关心的属性一起呈现。Constellation 提供两种方式：

### Constellation Base — 嵌入式镜头块

您可以使用 ` ```base ` 代码块将镜头直接嵌入任何 Markdown 笔记的正文中：

````markdown
```base
schema: 1
view: list
dimensions: [note.name, note.created_at]
sort: [note.created_at, desc]
limit: 20
```
````

查看笔记时，代码块会被显示匹配笔记的交互式表格替换。在实时预览中，单击 **镜头** 标签可编辑该块。

**v1 中可用的维度：** `note.name`、`note.path`、`note.created_at`、`note.headline`。

**联邦：** 默认情况下，镜头块从活跃宇宙和每个链接的 cUniverse 中读取。在 YAML 中设置 `federation: active` 以限制为仅活跃宇宙。

### 完整标签页的 Base（表格视图）

打开一个 `.base` 文件，它会以一张可交互的表格填满整个标签页 —— 每篇笔记一行，每个属性一列。除了添加/移除/重新排序列和排序（点击列标题在升序 → 降序 → 关闭之间循环，或使用**排序**面板一次按多列排序）之外，表格还提供三种在其中查找一篇笔记的方式：

- **在本库中搜索** —— 标题栏中的搜索框会在你输入时即时筛选各行，既匹配一篇笔记的名称，*也*匹配每一个可见列的文本。筛选期间，计数徽章会显示 `匹配数 / 总数`（例如 `4/7684`）。它在每一种文字下都有效 —— 输入阿拉伯语即可找到阿拉伯语标题。即使有数千行，筛选也是瞬时的。
- **字母栏** —— 当一个库有 50 行或以上时，一条纤细的字母条会沿着表格边缘出现，它的字母由你实际笔记标题的首字母构成（因此英文显示 A–Z，阿拉伯语显示 أ ب ت …，任何其他文字也会显示相应的正确字母；在从右到左的界面中它会落在正确的一侧）。点击某个字母即可直接跳转到以它开头的第一篇笔记 —— 如果表格尚未按名称排序，会先按名称排序，再跳转。
- **右键点击某一行** —— 调出标准的笔记菜单：打开、在新选项卡中打开、加入书签、复制路径 / 复制名称、在文件树中显示、用默认应用打开、在系统资源管理器中显示、样式…（重命名、移动和删除在这里被刻意不提供 —— 请从文件树中进行这些操作。）

### 五幕 (Five Acts) — 内置镜头

侧边栏的 **Five Acts** 部分（在 Workspace Bases 上方）列出 Constellation 在 `{universe}/Five Acts/*.md` 中策划的宿主笔记。v1 包含一个：**Observation — Recent Captures**（最近捕获的 20 条笔记的联邦列表）。您可以自由编辑这些笔记 — Constellation 不会覆盖您的编辑。

### 经典镜头面板

旧版镜头面板（按标签、文件夹、属性筛选）仍可通过 **设置 → 面板 → 镜头** 使用。

### 结构（结构性链接）

**结构**面板显示当前打开的笔记位于某个更大的*作品*——一本书、一部剧本、一门课程、一张内容地图（Map of Content）——中的什么位置。它回答的问题与反向链接面板和正向链接面板不同。后者回答的是*"这个想法与另一个想法之间有什么关系？"*（即思考链接——supports、contradicts、causes……）。结构则回答*"这篇笔记在我正在创作的整部作品中处于什么位置？"*——书 → 部 → 章 → 场景。

这是一部作品的**创作脊柱**：目录、有序的大纲。它被刻意排除在所有思考、成熟度和连接度量**之外**——把一篇笔记放"在某本书之下"，绝不会改变这篇笔记的成熟度、它的连接数，或它在星图视图中的存在。目录属于创作行为，而不是有待评判的主张。

**两种结构性链接**（你永远只需要键入其中一端——Constellation 会替你推算出反向的另一端）：

- **`parent`** —— *这篇笔记*在某一个父级之下的位置（例如，一章声明它所属的部）。
- **`contains`** —— *这篇笔记*的有序子级列表（例如，一本书按阅读顺序列出它的各部）。

**创建结构性链接**——打开笔记的**属性**（右侧边栏中的"属性"标签页，或笔记顶部的属性区块）：

1. 点击 **+ Add property（添加属性）**，键入键名 `parent` 或 `contains`。
2. 在值中键入**目标笔记的名称**——只需名称即可，例如 `Part I - The Cartographer`。Constellation 会替你把它包装成 `[[link]]`；你**不需要**键入方括号。（如果你粘贴的名称已经带有方括号，它仍会被干净地存储为单层 `[[name]]`——绝不会变成双层包裹。）
3. 对于 `contains`，按你希望的阅读顺序，把每个子级各自添加为一个独立的小药丸（chip）——这个顺序就会成为大纲的顺序。

结构性链接**可以安全地重命名**：重命名一章之后，它在结构中的位置会自动跟随，因为链接指向的是笔记本身，而不是一段被冻结的文字。

**阅读结构面板**——打开右侧边栏中的**结构**标签页（就在反向链接之后）：

- 面板会以缩进大纲（青色项目符号）的形式显示**整部作品**，标题为 **OUTLINE（大纲）**，并附带后代笔记的计数——而不仅仅是当前打开笔记自己的子级。
- 你当前正在查看的笔记会在该大纲中被**高亮**显示（"你在这里"）。
- 顶部的**面包屑导航**显示沿脊柱向上的路径（例如 *The Atlas of Lost Places › Part I › Chapter 1*）。点击任意一个面包屑——或大纲中的任意一行——即可跳转到那篇笔记。
- 面板右上角有一个 **Whole work ⇄ This note（整部作品 ⇄ 这篇笔记）**切换开关，用于在整部作品与当前打开笔记自己的子树之间切换。它只在笔记确实有父级时才出现，这样两种视图才会有所不同。
- 如果结构意外地自我循环（笔记 A 的父级是 B，而 B 的父级又是 A），大纲会绘制出这条链，然后干净地停下，并在切断点标记一个小小的 **↻**。它绝不会卡死。

**解决冲突（Contested，有争议）。** 如果有两篇笔记都声称拥有同一个子级——一篇通过该子级自身的 `parent`，另一篇通过 `contains` 列表——面板会把那一行标记为 **Contested（有争议）**（一个琥珀色的 ⚠ 徽章，注明另一位声称者），而不是悄悄地丢弃它。两个一键按钮可以解决冲突：

- **Keep（保留）** —— 保留该子级自己声明的父级（这篇笔记放弃对该子级的声称）。
- **Move here（移到此处）** —— 接受这篇笔记作为父级（该子级的 `parent` 切换为这篇笔记）。

任一按钮都会直接更新笔记文件并刷新大纲。没有你的点击，绝不会有任何改动发生。

## 19. RTL 和阿拉伯语支持

Constellation 为阿拉伯语、希伯来语、波斯语、乌尔都语及其他 RTL 文字提供一流支持：

- **自动检测**：笔记方向根据内容自动检测
- **界面**：选择阿拉伯语/希伯来语时提供完整的 RTL 界面
- **编辑器**：完整的 RTL 文本编辑——光标移动、按单位选择、段落方向控制（详见下文）
- **星图视图**：阿拉伯语标签以正确的字体回退从右向左渲染
- **图例**：根据内容语言翻转圆点/文本顺序
- **文字字体**：在设置中可独立配置阿拉伯语、希伯来语和 CJK 字体

### 光标与方向键在阿拉伯语及双语文本中的行为

Constellation 的编辑器遵循与 Windows 版 Microsoft Word 相同的逻辑，您的肌肉记忆可以直接沿用：

- **方向键按*文本*的阅读顺序逐字符移动**——而不是按屏幕上的位置移动。在纯阿拉伯语或纯英语文本中，效果与您按下的箭头完全一致。在阿拉伯语与英语的接缝处（例如一句阿拉伯语中夹着一个英文单词），光标会按书写顺序干净利落地逐字符前进，并"跳"过接缝——这个跳跃是正确的行为，正是它避免了光标在交界处卡住的感觉。
- **Home** 移到该行的阅读*起点*——阿拉伯语行的**右**端；**End** 移到阅读*终点*——**左**端。在阿拉伯语行上按 **Enter**，新行的光标出现在**右侧**。
- **三击**选中段落的**文本**（不包括文本旁边的空白）。**双击**选中一个词。
- **阿拉伯语行末的拉丁单词**会保持清晰、稳定的光标位置，而不会迷失方向。

### 按单位选择与导航

每种文本单位都有快捷选择方式，在阿拉伯语、英语和混合笔记中完全一致：

- **词**——双击。**句子**——在句中任意位置 **Ctrl+单击**，或将光标置于句内后按 **Ctrl+Shift+S**。句子检测理解阿拉伯语标点：**؟ ۔ !** 和句号会结束一个句子，而阿拉伯语分号 **؛** 是句*内*的停顿——像 3.14 这样的小数永远不会截断句子。（Ctrl+单击取代了原先的"添加光标"手势。）
- **行**——**Ctrl+L**。**段落**（空行之间的文本块）——**Ctrl+Shift+L**，或三击。高亮紧贴文本——在阿拉伯语行上，选区止于文字本身，而不会延伸到左侧的空白区域。
- **一屏**——**Shift+Page Down/Up**。**全部**——**Ctrl+A**。
- **按段落移动**——**Ctrl+↓** 跳到下一段的开头，**Ctrl+↑** 跳到当前段的开头（再按一次跳到上一段）。加上 **Shift** 可逐段选择。

### 强制指定段落方向

有时自动检测的结果并非您想要的——比如一段以英文品牌名开头的阿拉伯语段落，或一段您希望按从右到左阅读的英文段落：

- **按下并松开右侧 Ctrl+Shift** → 光标所在的段落变为 **100% 从右到左**。**左侧 Ctrl+Shift** → **100% 从左到右**。（Microsoft Word 的惯例。）
- 它在**松开按键时**触发，中间不能按任何其他键——因此 Ctrl+Shift+S 等快捷键完全不受影响。
- 该覆盖是**硬性**的（胜过自动检测），作用于整个段落或选区跨越的每一个段落，并以一个不可见的方向字符保存在**文本内部**——重启和同步后依然有效，粘贴到 Word 或 Obsidian 时也随文本一起迁移。
- 一次 **Ctrl+Z** 即可撤销。Markdown 安然无恙：列表、标题、引用保留其标记；代码块、表格以及以 #标签*开头*的行被有意排除在外。

### 设置阿拉伯语

1. 前往**设置 > 通用 > 语言**，选择阿拉伯语
2. 可选择在**设置 > 通用 > 文字字体**中设置专用阿拉伯语字体
3. 包含阿拉伯语内容的笔记将自动以 RTL 方式渲染

### 阿拉伯语引擎覆盖

Constellation 的阿拉伯语引擎是一套五层形态分析器,它在每一次搜索、链接与索引条目之下运行。它懂得词根、词型、专有名词、外来语以及音位修复——因此查询 كاتب 会找到 كتبنا 与 كتاب,而 وائل 作为人名会原样保留,不会被肢解成 ائل。

设置中的 **阿拉伯语覆盖** 面板,就是您把自己的术语教给引擎的地方。每条覆盖都是一锤定音的答案——它胜过生成式 FST、级联以及启发式回退。

**何时使用覆盖:**
- 引擎不认识的人名、当地地名或领域特有术语
- 您 Universe 中独有的新造词或缩略语
- 希望保留某种特定拼写的外来语
- 任何您不认同引擎自动分析的情形

**分步操作:**

1. 打开 **设置**(齿轮图标或 `Ctrl + ,` / `Cmd + ,`),在侧边栏中选择 **阿拉伯语覆盖**。
2. 点击 **添加覆盖**。
3. 填写:
   - **表面形式** — 您输入的那个阿拉伯语词
   - **词元** — 引擎应返回的规范形式
   - **词根**(可选)— 若该词有古典词根,则为 3 或 4 个辅音
   - **模式**(可选)— 例如 `فاعل`
   - **词性** — 专有名词 / 名词 / 形容词 / 副词 / 动词 / 虚词 / 外来语 / 未知
   - **备注**(可选)— 为自己留一行上下文
4. 点击 **保存**。包含该表面形式的每条笔记被重新分词时,面板会显示 **重新索引中…**,完成后显示 **已重新索引 N 条笔记**。
5. 若要移除覆盖,点击该行的 **×**——同样的重新索引扫描会反向运行。

覆盖按 Universe 存储在 `<universe>/.constellation/arabic-overrides.json`——纯文本、字母顺序排序、原子写入。您可以将该文件纳入版本控制或在多设备间共享。

## 22. 认知引擎

认知引擎是 Constellation 内置的智能系统，用于分析笔记并发现想法之间隐藏的模式和关联。其核心理念：

> "数据的多少并不重要。重要的不是你存储了多少来源，而是你如何从中提炼知识，并将其连接成一个有意义的统一认知。"

认知引擎由九个集成工具组成：类型链接、知识层级、成熟度周期、张力检测器、来源链、外化引擎、复习脉搏、路径和多镜头视图。

---

### 17.1 类型链接

#### 是什么？

类型链接是携带关系类型的维基链接，用于描述两个笔记之间的关系性质。不是简单地写 `[[笔记]]`，而是写 `[[笔记|关系类型]]` 来表达连接的本质——它是派生的吗？矛盾的？扩展的？

#### 为什么重要？

普通链接只说"这里有连接"，却不说是什么连接。类型链接将你的笔记网络从一堆引用转变为真正的知识地图，使思维结构、依赖关系和推理链条清晰可见。

#### 如何使用

1. 在编辑器中打开笔记
2. 写带关系类型的维基链接：`[[目标笔记|derives-from]]`
3. 支持的类型：`derives-from`（派生自）、`supports`（支持）、`contradicts`（矛盾）、`extends`（扩展）、`exemplifies`（例证）、`questions`（质疑）
4. 也可以通过右侧边栏的笔记属性添加类型

#### 在哪里可见？

- **星图视图（GraphMind）**：节点之间带颜色和标签的连线
- **右侧边栏**："反向链接"标签页中显示每个链接的类型
- **来源标签页**：用于构建知识谱系树

---

### 17.2 知识层级

#### 是什么？

认知引擎自动将每个笔记分类到八个知识层级之一：快照、日志、主题、地图、框架、原则、信念、作品。分类基于笔记的结构、内容和链接数量。

#### 为什么重要？

了解每个笔记的类型揭示了你知识库中的知识平衡。你的大部分笔记是转瞬即逝的快照，还是已经演化为原则和框架？对内容本质的这种觉察，是从单纯的信息积累走向真正知识构建的第一步。

#### 如何使用

1. 分类自动进行——无需任何操作
2. 若要覆盖自动分类，在前置数据中添加 `stratum` 属性：
   ```yaml
   ---
   stratum: framework
   ---
   ```
3. 可用值：`snapshot`、`log`、`topic`、`map`、`framework`、`principle`、`conviction`、`artifact`

#### 在哪里可见？

- **右侧边栏**：笔记属性中的"层级"项
- **星图视图**：根据层级显示不同颜色的节点
- **设置 > 认知引擎**：启用/禁用自动分类

---

### 17.3 成熟度周期

#### 是什么？

引擎以四个阶段跟踪每个笔记的成熟度：**种子** → **幼苗** → **常青** → **经典**。每个笔记从种子开始，随着内容、链接和审查的增加逐步成长。

#### 为什么重要？

成熟度区分了原始想法和精炼知识。今天的种子如果得到足够关注，明天就可能成为参考经典。成熟度追踪帮助你识别值得进一步发展和关注的笔记。

#### 如何使用

1. 成熟度根据以下因素自动变化：字数、入链和出链数量、最后修改日期
2. 若要手动设置成熟度，在前置数据中添加 `maturity` 属性：
   ```yaml
   ---
   maturity: evergreen
   ---
   ```
3. 可用值：`seed`（种子）、`sapling`（幼苗）、`evergreen`（常青）、`canonical`（经典）

#### 在哪里可见？

- **右侧边栏**：标题旁的图标显示当前成熟阶段
- **星图视图**：以节点大小表示——笔记越成熟，节点越大
- **设置 > 认知引擎**：启用/禁用成熟度追踪

---

### 17.4 张力检测器

#### 是什么？

张力检测器检查关联笔记，当两个或多个笔记之间的主张或结论相互矛盾时向你发出警告。它依赖于 `contradicts` 类型链接的分析以及笔记间的主题相似性。

#### 为什么重要？

张力不一定是错误——它们是深度思考的邀请。当知识库中两个想法相互矛盾时，意味着你的理解在进化，或者存在值得探索的复杂性。检测张力防止你在不知不觉中在矛盾的基础上构建知识。

#### 如何使用

1. 在矛盾的笔记之间添加 `contradicts` 类型链接：`[[其他笔记|contradicts]]`
2. 引擎也会通过内容分析检测隐含的张力
3. 从侧边栏查看检测到的张力列表

#### 在哪里可见？

- **右侧边栏**：检测到矛盾时的"张力"标签页
- **星图视图**：矛盾节点之间的红色虚线
- **通知面板**：检测到新张力时的提醒

### 17.5 来源链

#### 是什么？

来源链追踪每个想法的起源——它从哪里来，由什么派生。使用 `[[笔记|derives-from]]` 链接构建谱系树，展示知识从原始来源到当前表述的演化路径。

#### 为什么重要？

了解想法的来源区分了接收的知识（来自书籍、文章、讲座）和发现的知识（你自己的结论和思考）。对知识源头的这种觉察帮助你评估想法的可靠性，并理解你的思维是如何随时间形成的。

#### 如何使用

1. 创建派生自某来源的笔记时添加链接：`[[原始来源|derives-from]]`
2. 可以构建多层级链条：笔记 ← 派生自 ← 派生自 ← 原始来源
3. 在前置数据中添加 `source-type: received` 来分类外部来源

#### 在哪里可见？

- **右侧边栏**："来源"标签页显示完整谱系树
- **星图视图**：链接上箭头的方向（从来源指向派生）
- **笔记属性**：基于来源链的"接收的"或"发现的"分类

### 17.6 外化引擎

#### 是什么？

一个渐进式形式化管道，追踪笔记从原始捕获到结晶洞察的成熟过程。每个笔记可以被分配四个阶段之一：

| 阶段 | 图标 | 含义 |
|------|------|------|
| 闪念 | 🌱 | 快速捕获，一闪而过的想法 |
| 文献 | 📖 | 用自己的话从来源重写 |
| 永久 | 🔗 | 原子化想法，一个概念，连接到你的图谱 |
| 综合 | ✨ | 结合多个永久笔记的原创洞察 |

#### 为什么重要？

大多数应用对所有笔记一视同仁。外化引擎使区别可见——你可以一目了然地看到你的库中有多少是原始捕获，有多少是真正的理解。

#### 如何使用

1. 在面包屑栏（编辑器上方），使用阶段下拉菜单选择一个阶段。
2. 或展开属性并使用那里的阶段下拉菜单。两者都会与文件树即时同步。
3. 要提升笔记，将下拉菜单从一个阶段更改为下一个。在专注模式下，点击底部的"提升为永久"。
4. 要移除阶段，从下拉菜单中选择"— 阶段 —"。

#### 在哪里可见？

- **面包屑栏**：带有表情符号 + 阶段名称的下拉菜单
- **属性面板**：当 `stage` 属性存在时显示下拉菜单
- **文件树**：笔记名称旁的表情符号图标
- **专注模式页脚**："提升为永久"按钮

### 17.7 复习脉搏

#### 这是什么？

复习脉搏是一个间隔重现系统，以递增的间隔将笔记重新带回您的注意力：最后一次复习后1天、3天、7天、14天、30天。它还监控带有 `#assumption` 或 `#model` 标签的笔记作为心智模型检查点，并维护一个"从未复习"队列，用于捕获但从未重新访问的笔记。

#### 为什么重要？

知识在没有重新访问的情况下会衰退。您今天写了一条笔记，三周后就忘记了它的存在。间隔重复是认知科学中对抗这种衰退最成熟的技术。复习脉搏将这一原理应用于您的实际笔记。

#### 如何使用

1. 点击左侧边栏中的**复习脉搏**标签页。您将看到三个部分：待复习、心智模型检查点（`#assumption` / `#model`）、和从未复习。
2. 点击任何笔记打开并阅读。
3. 选择三个操作之一：
   - **已复习**（勾选标记）— 按下一个间隔安排下次复习（1 → 3 → 7 → 14 → 30天）。
   - **推迟7天**（眼睛图标）— 不推进间隔，将笔记推迟7天。
   - **移除**（归档图标）— 永久从复习队列中移除笔记。
4. 打开命令面板输入 "Review due notes" 直接跳转到待复习笔记。

#### 在哪里可见？

- **左侧边栏**：复习脉搏标签页，带有待复习笔记数量的徽章
- **命令面板**："Review due notes" 命令用于快速访问

### 17.8 路径

#### 这是什么？

路径是笔记的命名有序序列——就像书的章节或知识导览的站点。通过在笔记的 frontmatter 中添加 `trail: true`，然后在笔记正文中按顺序列出维基链接来定义。

#### 为什么重要？

知识并不总是一张网。有时它是一条路径——学习序列、论证推进、叙事。路径明确地捕获这种顺序，为您的非线性库添加线性维度。

#### 如何使用

1. 创建一个 frontmatter 中包含 `trail: true` 的新笔记。
2. 在笔记正文中，按所需顺序列出维基链接。
3. 当打开属于某条路径的笔记时，面包屑栏显示路径名称和位置的指示器（例如"我的路径 2/5"）。箭头按钮可导航至上一条和下一条笔记。
4. 打开命令面板输入 "Open Trail" 查看所有路径。

#### 在哪里可见？

- **面包屑栏**：带有名称、位置和导航箭头的路径指示器
- **命令面板**："Open Trail" 命令列出所有路径

### 17.9 多镜头视图

#### 这是什么？

多镜头视图让您通过不同的分类方案查看您的库——无需更改文件夹结构或复制笔记。"镜头"是基于属性或标签重新组织笔记的虚拟分组。内置镜头："按阶段"（瞬时/文献/永久/综合）和"按主题"（按标签分组）。可以在设置中创建自定义镜头。

#### 为什么重要？

文件夹结构强制使用单一层次结构，但知识不适合放在一棵树中。多镜头视图让您在不移动文件的情况下在不同视角之间切换。相同的笔记，通过不同的组织镜头查看。

#### 如何使用

1. 在侧边栏中，找到文件树顶部的**镜头下拉菜单**（默认为"文件夹"）。
2. 选择镜头："按阶段"、"按主题"或自定义镜头。侧边栏立即重新组织。
3. 选择"文件夹"返回默认文件树。
4. 创建自定义镜头：打开**设置 > 知识管理**，点击**创建镜头**，命名并选择用于分组的 frontmatter 属性。
5. 或使用命令面板：输入 "Create Lens"。

#### 在哪里可见？

- **侧边栏下拉菜单**：文件树顶部的镜头选择器
- **设置 > 知识管理**：创建、编辑和删除自定义镜头
- **命令面板**："Create Lens" 命令

### 认知引擎设置

认知引擎的所有工具可在 **设置 > 认知引擎** 中配置：

- **层级分类** — 启用或禁用自动分类
- **成熟度追踪** — 启用或禁用成熟度生命周期追踪
- **类型链接** — 调整链接检测灵敏度阈值（0.0 – 1.0）
- **张力检测器** — 启用或禁用自动张力检测
- **手动覆盖** — 在前置数据中添加 `stratum` 和 `maturity` 属性以覆盖自动分类

## 23. 推荐连接

Constellation 用于*提炼*知识，而知识即连接。**推荐连接**会在你的知识库中找出与当前正在查看的笔记最相关的那些笔记——它本应连接、却尚未连接的"亲属"——并让你只需轻点一下，就把其中任意一则变成一条**类型链接**。它是"更多类似笔记"，但服务于思考。

**每条推荐都是有类型的。**当你采纳一条推荐时，Constellation 会问这两则笔记*如何*相关——支持、反驳、举例、源自，等等，或者只是单纯**关联**。有类型的链接是一段你日后可以阅读、检索、并加以质疑的推理；本功能绝不会批量添加链接，也绝不会悄无声息地添加一条无类型的链接。（参见**知识提炼**与**属性**。）

**它如何找出它们。**候选笔记**只来自你自己的知识库**，依据 Constellation 实时搜索索引、按最*独特*的共有词汇排序——那些稀有而有意味的词，而非常见词。每条推荐都会显示让它浮现的**共有词条**，向你解释它为什么会出现，因此你绝不会去接受一个黑箱式的猜测。

**五个地方，一份列表。**同一份推荐列表会出现在**回顾**（🕐，针对它标记为*孤立*或*脆弱*的笔记）、**反向链接标签页**（右侧边栏）、**360° 检视器**、**健康标签页**，以及**天空视图**（🌌——右键点击任意星星 →**推荐连接…**）。

**入向与出向——以及你为什么无需选择。**诊断类界面（**360° 检视器**与**健康标签页**）推荐**入向**连接——*哪些笔记应当指向**这里***。通用类界面（**反向链接标签页**与**天空视图**）推荐**出向**连接——*这则笔记应当指向**什么***。界面会挑选最契合其职责的方向；你来挑选笔记和类型。（未来的更新会让你自己切换方向。）

**如何使用。**在**推荐连接**标题下，你会看到一份相关笔记列表，按最相关在前的顺序排序，每一则都附有它的共有词条。点击某个候选笔记的**连接**按钮 → 在那个小小的**"它们有什么关系？"**菜单里选择关系类型 → 类型链接会被**即时**创建，该推荐随即从列表中消失。它随后便存在于笔记的**属性**之中，并出现在它的反向链接/出链里以及整个关系图中。如果没有一条真正合适，把它们留着就好——或者，在回顾中，把这则笔记标记为有意**独立**。推荐连接负责提议；做决定的是你。

**本地、私密、不阻塞。**推荐是仅从你的知识库按需计算的——没有任何内容离开你的设备——而且汇集推荐绝不会卡住你的打字（在它工作时，你会看到短暂的"正在查找相关笔记…"提示）。推荐内容、共有词条提示，以及各种关系类型，都会以你所选的语言显示，并且对于从右到左的文字，布局会正确镜像。

## 24. 认知色彩与右键菜单

### 属性样式（样式设计器）

打开**样式设计器**（设置 → 外观 → ✦ 打开样式设计器，或它自己的选项卡），选择**属性**类别，以重新设计一篇笔记前置数据中那些小标签的样式。两个元素：**属性标签**（普通的 `tags` 式药丸 — 标签背景、标签文字、标签圆角 0–20 px、高度 14–32 px）和**分类徽章**（背景、文字、圆角 0–20 px）。中央有一个实时预览随你编辑而更新；每个值都从今天的样子精确开始，因此在你触碰某个控件之前什么都不会变。单击 **Keep（保留）** 即可为此宇宙保存。

### 认知色彩（样式设计器）

**认知色彩**类别给你**每种认知状态一个共享颜色**，因此凡是显示该状态的界面都达成一致。五组：

- **成熟度** — 种子、幼苗、常青、权威、枯萎。
- **置信度** — 假设、证据、已确立、存争议。
- **来源** — 接收、发现、混合、无。
- **阶段** — 萌发、诞生、成长、成熟、休眠、归档。
- **匹配类别**（一条搜索结果为何匹配）— 标题、内容、标签、维基链接、属性、语义、结构化。

其行为是**按需统一**：在你挑选一种颜色之前什么都不会变。每个界面都把它当前的颜色保留为回退值，而一旦你在这里设置了某种状态的颜色，**每一个**显示该状态的界面 — 文件树、选项卡、笔记检视器、编辑器内的搜索高亮、匹配徽章，以及搜索结果高亮 — 都会立即对齐到你的颜色。让某种状态保持不动，它看起来就和之前一模一样。单击 **Keep（保留）** 即可保存。

### 右键菜单

Constellation 在三个地方为你提供上下文菜单，每个菜单只提供契合你点击之处的操作：

- **右键点击笔记正文** — 添加链接 / 添加外部链接；**格式 ▸**（粗体、斜体、下划线、删除线、高亮、行内代码、数学、切换注释、上标、下标、清除格式）；**段落 ▸**（项目符号/编号/任务列表、H1–H6、正文、块引用）；**插入 ▸**（脚注、表格、标注框、水平分隔线、代码块、数学块、图像）；剪切 / 复制 / 粘贴 / 粘贴为纯文本 / 全选；以及**样式…**（打开聚焦于**编辑器**类别的样式设计器）。
- **右键点击前置数据属性行** — 复制值、复制名称、移除属性、添加属性；接着是与正文相同的编辑菜单；以及打开聚焦于**属性**类别的样式设计器的**样式…**。
- **右键点击搜索结果** — 一个**安全**的子集：打开、在新选项卡中打开、在树中显示、复制链接、复制路径、加入书签、在资源管理器中显示、用默认应用打开，以及**样式…**（**认知色彩**类别）。按设计这里**没有重命名、移动或删除** — 搜索面板不保留分秒同步的文件树副本，因此破坏性操作保留在视图始终最新的文件树中。

每一个**样式…**入口都会落在你右键点击之物所属的类别上，因此你永远不必去四处寻找正确的控件。每一个菜单项、类别名称和状态标签，都会以你所选的界面语言显示，并为从右到左的布局镜像。
