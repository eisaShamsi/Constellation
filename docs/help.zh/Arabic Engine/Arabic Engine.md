# 阿拉伯语引擎

Constellation 使用一套为本应用从零构建的五层形态分析引擎来解析阿拉伯语文本。它并非现成词干提取器的移植版本,而是一件能够理解阿拉伯语词根、词型、专有名词、外来语以及您自己术语的原生工具。引擎本身无需任何配置；它在每一次搜索、每一条链接、每一个索引条目之下默默运行。您*可以*配置的部分——也是本帮助主题所涵盖的——是引擎唯一邀请您下达判断的地方:设置中的 **阿拉伯语引擎覆盖** 面板。

---

## 引擎为何存在

阿拉伯语是一门模板型语言。像 ك‑ت‑ب（「书写」）这样一个词根可以派生出数十个表面形式—— كاتب（作者)、مكتوب（已写)、كتاب（书)、يكتب（他写)、كتبنا（我们写了)——当您搜索时，这些形式理应都坍缩到同一个语义核心。一个幼稚的词干提取器要么会误伤这些形式（例如把 وائل 过度剥除成 ائل),要么干脆忽略它们之间的联系。Constellation 的引擎通过将每个阿拉伯语词严格按优先级顺序依次送入五层分析来避免这两种失败:

1. **第 0 层 — 用户覆盖**（这是您所掌控的一层)
2. **第 2 层 — 受保护列表**（约 1,200 个人工精选的专有名词、地名、外来语与功能词,任何情况下都不得触动)
3. **第 3 层 — 生成式 FST**（一个编译后的有限状态转换器,将约 7,000 个词根 × 158 个词型映射为完整的表面词汇)
4. **第 3b 层 — 级联**（音位修复:同化、弱根、哈姆扎落位)
5. **第 5 层 — 启发式**（优雅的回退——一个保守的词缀剥除器,仅在其他所有层都拒绝作答时才会启动)

当多于一层产生读法时,一个排序步骤（第 4 层)会挑出唯一最佳分析。排序会把您的覆盖置于一切之上。

## 功能:阿拉伯语引擎覆盖

### 它是什么

覆盖面板是设置中的一张小表格,您可以在此用自己的话告诉引擎如何分析某个特定的阿拉伯语表面形式。每条覆盖包含:

- **表面形式** — 您输入的阿拉伯语词原貌（例如 وائل)。
- **词元** — 引擎应返回的规范形式（例如 وائل)。
- **词根** — 可选。若该词有古典词根,则为三或四个辅音。
- **模式** — 可选。若您希望记录其形态模板,则为一个自由文本标签（例如 `فاعل`)。
- **词性** — 专有名词 / 名词 / 形容词 / 副词 / 动词 / 虚词 / 外来语 / 未知。
- **备注** — 可选。给未来的自己留一行上下文。

### 为何重要

每一张知识网络里,都会有一些引擎不可能从词典中知晓的术语:您自己的新造词、所在乡镇的人名、您领域内使用的缩略语、同事偏好某种特定拼写的外来语。没有覆盖,引擎就会对这些表面形式施加通用分析,您的搜索结果就会因一点细微差异而支离破碎。覆盖是一锤定音的答案——它胜过生成式 FST、级联以及启发式回退。第 4 层的排序赋予覆盖最高来源与 1.0 的置信度,因此它们绝不会被其他分析挤下去。

覆盖保存在 `<您的 Universe>/.constellation/arabic-overrides.json` 这一单个 JSON 文件中。该文件是纯文本,按字母顺序排序,通过 `.tmp` + 重命名对原子写入,因此中途断电也不会导致损坏。它属于您——您可以将其纳入版本控制、对比差异,或在多台设备之间共享。

### 如何使用

**第 1 步:打开面板**

点击右上角工具栏中的齿轮图标(或按 `Ctrl + ,` / `Cmd + ,`)打开设置。在左侧边栏中选择 **阿拉伯语覆盖**——它紧挨着 **语言**。若未看到,请滚动侧边栏。

**第 2 步:添加第一条覆盖**

点击 **添加覆盖**。一张包含六个字段(表面形式、词元、词根、模式、词性、备注)的表单会出现。按您在笔记中书写的原貌输入表面形式——引擎会在内部规范化变音符与 alef 变体,因此您不必刻意精确匹配。填入您希望返回的词元。若您不知道词根与模式,可留空;引擎仍会使用该覆盖。从下拉中选择一个词性,或保留为 **未知**。点击 **保存**。

**第 3 步:观察重新索引横幅**

一经保存,面板就会显示 **重新索引中…**,引擎会扫描当前 Universe 中所有包含该表面形式的笔记。每一条匹配到的笔记都会在新的覆盖裁决下被重新分词。扫描结束时——在典型 Universe 中通常不到一秒——横幅会变为 **已重新索引 N 条笔记**,并在三秒后自动消失。您无需重启应用,也无需重建任何索引。

**第 4 步:在搜索中验证**

打开搜索中心(`Ctrl + K` / `Cmd + K`)并输入该表面形式。匹配结果现在应当反映您所指定的词元:查询词元能找到表面形式,查询表面形式也能找到该词元的其他屈折形式。

**第 5 步:移除一条覆盖**

点击该覆盖行上的 **×** 按钮。条目会立即从磁盘上移除,同样的重新索引扫描会反向运行——先前包含该表面形式的笔记会在引擎的通用分析下被重新分词。横幅会报告所触及的笔记条数。

### 与受保护列表的交互

受保护列表(第 2 层)已经收纳了约 1,200 个常见表面形式,它们绝不可被剥除——像 وائل 这样的名字、فلسطين 这样的地名、إنترنت 这样的外来语。您无需亲自添加这些;引擎自带它们。请把覆盖面板用于那些对您的 Universe 而言*个人化*的表面形式:您自己的术语、当地人名、领域特有的外来语,或您不认同引擎自动读法的情形。

### 跨 Universe 的交互

每个 Universe 都有自己独立的覆盖文件。切换 Universe 会在内存中交换当前覆盖集——引擎会从新 Universe 的 `.constellation/` 文件夹重新加载 JSON。若文件缺失(全新 Universe),引擎会将覆盖集视为空集。若文件格式错误,引擎会记录一条警告并退回到空集,而非拒绝加载。

### 若您手动编辑该文件会怎样

您可以手动编辑。文件格式为:

```json
[
  {
    "surface": "وائل",
    "lemma": "وائل",
    "root": null,
    "pattern": null,
    "pos": "ProperNoun",
    "note": "Personal name — never strip"
  }
]
```

请按表面形式的字母顺序保持条目排序,以便产生对 git 友好的差异。引擎会在每次保存时重新排序,因此手工重排不会在界面驱动的编辑后保留下来。

## 术语表

- **表面形式** — 书写而成的阿拉伯语词,包括任何附着的附加成分(例如 الكتاب、بالكتاب、كتبنا)。
- **词元** — 一个词剥除屈折后的引文形式(例如 كتاب)。
- **词根** — 一族词所共享的 3 或 4 个辅音构成的语义核心(例如 ك‑ت‑ب)。
- **模式** — 与词根组合以产出表面形式的元音与词缀模板(例如 فاعل → كاتب)。
- **FST** — 一个有限状态转换器。引擎用它来高效地将词根 × 词型映射到完整的表面词汇。
- **级联** — 处理同化、弱辅音与哈姆扎落位的音位修复层。
- **覆盖** — 您对某个特定表面形式应如何分析所下达的裁决;胜过其他所有层。
