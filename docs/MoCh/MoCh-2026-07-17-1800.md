## 1. FM+ is born — and immediately fenced

Session opened on the handover: next action = **PJ-114**, the Focus-mode right-click menu. I read the orientation + handover, synced, and started concept-first.

**Boss steer #1 (interrupting my scouting):** *"I want to add a toggle switch for the Focus-mode-added functions; we will call it FM+, which the user can switch on to enable the extra features."*
→ Reframed the concept: FM+ as an **opt-in switch** resolving the tension between "add functions to Focus" and "Focus = minimal." Asked two forks; Boss chose **footer status-bar toggle** + **single master switch**.

**Boss steer #2 (interrupting again):** *"But, avoid having another NotePane version."*
→ The guardrail that shaped everything after: FM+ is a **thin affordance layer delegating to existing engines**, Focus stays parser-free, link detection stays a line-regex.

**Boss steer #3:** *"In FM+, I want to navigate to other notes via their links in Focus mode, not to exit to the NotePane."*
→ Expanded FM+ from a rename menu into *wander your library through links without leaving the calm room*. I flagged that this makes it `/migration`-class (it touches the save/open lifecycle — flush-before-navigate).

Design pass (Art Director & Team) → Boss picked: **Essentials+ menu · Mod-click + Mod-Enter follow · back/forward via existing keys**. Architect + Plan → **Plan approved**, build began.

## 2. Build cascade, and the Boss's eye

Steps §0.1 → §1.2 all passed. Along the way Boss caught things I'd have shipped:

- *"When I switched to the Arabic UI… the menu was truncated"* → the ⋯ menu RTL bug (a **pre-existing** bug, not mine). Boss later handed me the task directly: *"I want you to audit…"* — no, first: *"fix this."*

**Boss praise worth recording:** *"Wow. I am impressed, especially by how the FM+ disappears to remove the distraction from the user's way."*

## 3. The rejection that changed the project

The FM+ menu v1 shipped as Copy-link-text / Copy-path + clipboard. Boss:

> *"No. I don't like it at all. If we only have this so limited choices in the FM+, while there is a richer native ones, then we don't need it. Do some digging and give me more smart choices."*

He was right — my menu was strictly poorer than the native webview menu. A research dig reframed it: **native owns the clipboard; FM+ owns knowledge formulation.** I brought back a menu of typed links, extract-to-note, annotate, confidence.

Then the ruling that redirected everything:

> *"Remember, it is the NotePane that should have the full living-link, so we are not going to replicate it in the FM."*
> *"Stop. I want you to audit what we have in the NotePane today to see if we need to enrich it. Then, we will cross-check it with the FM+ to choose what is suitable."*

→ FM+ menu paused. NotePane audit commissioned.

## 4. NotePane elevated

The audit came back blunt: NotePane is a fine *Markdown* editor but **not a living-link editor** — 1 of 8 link properties settable, type/annotation reachable only through raw syntax.

**Boss, stating the principle:**

> *"What's more, the NotePane is the GATE to the knowledge cognition, it is the key to one's knowledge. If Constellation is going to be a unique, powerful, and smart PKM/PKF system, it will be through the NotePane capabilities. It is the starting point of one's cognitive journey, so we have to make sure it is well-equipped and well-instrumented."*

→ Registered as a **top-principal**. Vision + Five-Acts roadmap produced; Boss chose **"plan it first."**

**Boss rulings on Phase 1:** "**stretch it**" (four picks + housekeeping + supersedes + badge) · controls at **three depths** · tension **early** · and a refinement better than either option I offered: *"It shall be Minimal by default, but could be Richer by choice, through the Settings."*

Architect + Plan then overturned my assumptions (no LINK files exist; body text is the source of truth; a live indexer bug wipes confidence and resurrects archived links). Boss confirmed **edit the note text** (File-Over-App), **delete the 2,550 dead lines**, and **one continuous migration**.

## 5. "Enough guessing."

Boss reported two editor-experience issues: the caret jumping to the top when entering Focus (and not carrying back), and tables rendering as raw pipes. He chose: **fix the caret now**, **queue tables as their own work**.

I then shipped **two** caret fixes built on theories. Both failed. Boss:

> *"Still, Coming back is not working."*
> *"Enough guessing."*

I stopped, owned the violated rule (Reproduce-First), and built on-screen instrumentation instead. Boss chose *"Do it properly now."* One instrumented run produced the trace — my hand-off worked and was then **overwritten by the app's own cursor memory that I hadn't known existed**. Fix: delete mine, feed the existing one. Boss: *"It is working now."*

He also caught, from a screenshot, that my ⋯-menu rule was wrong in a fourth case (Latin UI + Arabic note → menu spilling over the file tree): *"While you at it, fix this."* Correct rule: anchor by the **note's** direction, always open into the note.

## 6. Close

Boss chose to continue to §3, then — once I surfaced honestly that §3's remaining half is ~120 localization strings — chose to **close out** with the full PCS.
