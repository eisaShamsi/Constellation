## 1. The Boss opened with a diagnosis, not just a request

Eisa handed over a detailed brief: the 15 locale files in `src/lib/i18n/` had drifted structurally, with
`ar.json` (3,999 keys) as the stated reference and every other locale short — ~196 keys for most, ~223 for
CJK, ~94 for `en`. The brief named specific missing clusters (`sight.v5.*`, `plurals.*`, `sources.description.*`),
named specific extra keys (`focusPane.promote`, `cece._translation_note`, the `_comment` keys), and set six
numbered deliverables: a union-based diff script, genuine translations (explicitly *not* English copy-paste),
resolution of the extras, correct CLDR plural categories per language, a vitest guard, and verification via
`npx vitest run` + `npx svelte-check --threshold error`. One hard constraint: **no component code changes**.

The brief also supplied the rationale — CLAUDE.md's standing order that all user-facing strings go through
`$t()` and all 15 locales move together, and the observation that the discipline had slipped.

## 2. Claude read the runtime before touching data — and two premises did not survive

Rather than act on the stated diagnosis, the first move was reading `src/lib/i18n/index.ts`. Two corrections
came back to the Boss immediately:

- **`en.json` is the severe direction, not the mild one.** `t()` falls back active-locale → en → *raw key*, so a
  key missing from a non-en locale renders English, but a key missing from **en** renders the literal key path
  in all 15 languages. en's 94 were the highest-impact set, not the lowest.
- **A missing plural category does not "break `$tn()` at runtime"** as the brief put it — `resolvePluralForm`
  falls back category → `other` → `one`, so it renders the *wrong grammatical form silently*. Worse than a
  crash, and the reason the defects had survived.

Then the larger correction, after checking `Intl.PluralRules` directly: **the `plurals.*` "gaps" were not drift
at all — they were correct CLDR.** `plurals.characters.two` exists only in ar/he because only Arabic and Hebrew
*have* a `two` category. Following the brief's union approach literally would have forced `two`/`few`/`many`
into English, where the runtime can never select them — permanently dead keys shipped in every file. Claude
reported this plainly and built the tool to govern ordinary keys by the union and `plurals.*` by
`Intl.PluralRules`.

## 3. The one question Claude asked

Investigation split the ~196 into two piles: **62 LIVE keys** (verified by grep, including dynamically-built
lookups like `$t('sources.description.' + s.source)` and `styleSetter.labels.<slug>` via `L()`), and **~40 DEAD
keys** — all `sight.v5.*`, whose component `SightV5.svelte` **does not exist on disk** and whose flag was retired
by MIG-028, while `engine.ts` states the standing policy that retired-engine key paths are kept as
architectural history.

Claude put the fork to the Boss rather than deciding unilaterally, since it was worth ~520 translated strings
either way:

> **Eisa's ruling:** *"Exempt dead, translate live."* — translate the 62 live keys into all 13 locales; leave
> `sight.v5.*` in en/ar as history behind a documented exemption; drop the true orphans.

## 4. What Claude found that the Boss had not asked about

Checking each locale against CLDR instead of against the union surfaced **three real defects nobody had filed**:

- **`ru` had no `other` category at all** — fractional counts fell back to `one` ("1.5 заметка").
- **`es`/`fr`/`pt` had no `many`** — exact millions took the wrong branch.
- **`ar` had no `zero`** — n=0 rendered "0 ملاحظة" instead of "لا ملاحظات".

All three fixed, and verified by simulating the runtime resolver end to end rather than trusting the test.

## 5. The guard caught a bug Claude then refused to fix

The new test immediately failed on something pre-existing: `styleSetter.labels.an` is `""` in he/ja/ko. That
turned out to be *deliberate* — those languages have no indefinite article, and the string is the article in the
Style Setter's bold-text sample. But `L()` treats `''` as a miss and falls back to English, so Japanese renders
**"An りんご"**.

Claude reported that **no locale-data value can fix this** (empty renders English; non-empty renders a word the
language doesn't have) and that the real fix is one line in `StyleSetter.svelte` — which the Boss's
"no component code" constraint ruled out. Rather than silently widen scope or silently drop the finding, it was
held behind a narrow allowlist with a stale-waiver test and **filed as PJ-194 for a ruling**.
