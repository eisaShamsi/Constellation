### 2. The architectural pivot (§2G.3i)

Mid-cascade, Eisa redirected at a higher altitude with a single sentence:

> "To zoom in and out with the mouse wheel, imagine the Sight page as a regular page; all its components and elements should be locked in place. The mouse wheel will act as a lens. When zooming in, you move the lens closer to the page surface. It means every component/element will be outside the lens's coverage if it is not within it."

Three rounds of "chart zooms while overlays stay anchored" implementation evaporated. The right model was: the entire Sight page is a single page; the wheel is a magnifying lens over it; everything scales together.

This invalidated the Pixi-side `chartContainer.scale` approach and the per-overlay manual transforms. Replaced with one `.sight-v3-zoom-wrapper` element wrapping canvas + chart overlays, with one CSS `transform: translate(panX, panY) scale(zoom)`. Pixi-side scale removed. Math simplified.

Lesson: when an implementation needs four rounds of patches for the same general bug (zoom feels off, close doesn't work, hit-test misses), the model is wrong, not the patches. Ask the user what they expect, then redesign. Cheaper than five more patches.

### 3. The close button mystery

Four full rounds of failed Svelte `onclick={...}` attempts:
- §2G.3g: explicit lambda `(e) => onClose()` + bumped z-index 10 → 100
- §2G.3h: removed the (theoretical) `onpointerdown stopPropagation` interference + bumped z-index → 1000
- §2G.3i (round 1): rewrite handler shape, type="button", :active feedback
- §2G.3i (round 2 — landed): bypassed Svelte event system entirely. `bind:this={closeBtn}` + raw `closeBtn.addEventListener('click', ...)` + defensive `pointerup` listener in onMount.

Hover style fired on every round. Click handler never did. Cause unclear without browser-level debugging access. The lesson: when a framework-level binding fails inexplicably and you can't reproduce it, drop one layer down. addEventListener is bulletproof.

## Patterns / lessons

1. **Two-Boss-test rounds is a red flag for "wrong model".** Three or more is "stop patching, ask what the user expects." Eisa's "lens" sentence in round 4 was the model fix. Should have asked sooner.

2. **The (X, Y, Z) grammar elevated Sight from chart to instrument.** This is the single most important architectural decision in the cascade. It's now codified in the visual spec doc v1.1 and locked.

3. **Close button bug class.** When Svelte event binding fails:
   - Try `bind:this` + `addEventListener` immediately. Don't iterate on Svelte syntax.
   - Hover styles working = DOM events reach the element. addEventListener WILL fire.

4. **CSS gotchas across the lens architecture:**
   - `position: fixed` becomes relative to nearest transformed ancestor (not viewport). Tooltip had to be moved OUT of the zoom wrapper.
   - `transform-origin` in pixel units is in element-local coords, not parent coords. Verify against the wrapper's bounding box.
   - `getBoundingClientRect` post-transform values automatically absorb both translate AND scale — inverse simplifies cleanly to `internal = visual_offset / zoom`.

5. **Repulsion + sqrt radial = uniform area density.** Combining (a) hash-based azimuth jitter, (b) sqrt(rank) radial mapping, and (c) wedge-bounded repulsion at MIN_DIST = 9 px gave the visual that finally read right. Each piece alone was insufficient.

6. **The orientation in-line discipline pays off.** After yesterday's "Have you SO's?" check-in, every commit today carried its orientation v-bump inline. Zero drift. The doc trail is current with reality. When a future session reads `v1.65`, they get the live truth.
