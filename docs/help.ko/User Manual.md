# Constellation 사용자 매뉴얼

**버전 0.1.0 | 2026년 3월**

Constellation은 Markdown 노트 라이브러리를 관리하기 위한 개인 지식 관리(PKM) 데스크톱 애플리케이션입니다. Tauri v2, SvelteKit, Rust로 구축되었으며, Windows, macOS, Linux에서 네이티브로 실행되고 아랍어 및 RTL을 완벽하게 지원합니다.

## 1. 시작하기

### 설치

[Constellation 릴리스 페이지](https://github.com/eisaShamsi/Constellation/releases)에서 최신 설치 프로그램을 다운로드하세요:

- **Windows**: `.exe` (NSIS) 또는 `.msi` 설치 프로그램
- **macOS**: `.dmg` 디스크 이미지
- **Linux**: `.AppImage` 또는 `.deb` 패키지

### 첫 실행

Constellation을 처음 열면 **유니버스 설정 마법사**가 다음 단계를 안내합니다:

1. **언어 선택** — 15개 언어 지원
2. **라이브러리 생성 또는 가져오기** — 기존 Markdown 파일 폴더를 지정하거나 새로 시작
3. **유니버스 이름 지정** — 유니버스는 모든 라이브러리의 컨테이너입니다

### 인터페이스 개요

| 요소 | 설명 |
|------|------|
| **사이드바 (리본)** | 탐색 버튼: 파일 트리, 검색, 스타 뷰, 캘린더, 템플릿, 설정 |
| **파일 트리** | 라이브러리 내 노트와 폴더 탐색 |
| **에디터** | Markdown 노트 읽기 및 편집 |
| **탭 바** | 여러 노트를 탭으로 열기 |
| **상태 바** | 단어 수, 글자 수, 읽기 시간 |

## 2. 유니버스와 라이브러리

### 유니버스란?

**유니버스**는 모든 라이브러리를 담는 최상위 컨테이너입니다. 작업 공간이나 라이브러리 모음이라고 생각하면 됩니다.

### 라이브러리란?

**라이브러리**는 Markdown(`.md`) 파일이 들어 있는 컴퓨터의 폴더입니다. 하나의 유니버스에 여러 라이브러리를 가질 수 있습니다. 예를 들어, 업무 노트용과 개인 노트용을 별도로 만들 수 있습니다.

### 라이브러리 관리

- **라이브러리 추가**: 설정 > 라이브러리 > 라이브러리 추가, 또는 폴더를 앱으로 드래그
- **라이브러리 제거**: 설정 > 라이브러리 > 라이브러리 이름 옆의 제거 버튼 클릭
- **라이브러리 설정**: 각 라이브러리에 고유한 외관 설정(글꼴, 색상)을 적용할 수 있습니다

### 자식 유니버스

유니버스 안에 유니버스를 중첩할 수 있습니다. **자식 유니버스**는 부모 유니버스가 참조하는 다른 유니버스 폴더입니다. 자식 유니버스의 노트는 스타 뷰에서 자신의 노트와 함께 표시되며, 라이브러리 간 링크는 점선으로 표시됩니다.

### 자동 재개

Constellation은 마지막으로 활성화된 유니버스를 기억하고 실행 시 자동으로 다시 엽니다. 유니버스가 이동되었거나 경로가 변경된 경우, Constellation이 이를 감지하고 자동으로 경로를 수정합니다.

### 포터블 유니버스

Constellation 유니버스는 완전히 이동 가능합니다. 유니버스 폴더를 다른 드라이브, USB 메모리, 또는 다른 컴퓨터 등 어디로든 이동할 수 있으며, Constellation은 다시 열 때 모든 내부 경로를 자동으로 감지하고 수정합니다.

유니버스를 이동하려면:
1. Constellation을 닫습니다
2. 유니버스 폴더를 새 위치로 이동하거나 복사합니다
3. Constellation을 엽니다 → 환영 화면이 표시됩니다 (이전 경로가 더 이상 유효하지 않음)
4. **기존 유니버스 열기**를 선택하고 새 위치를 지정합니다
5. 모든 노트와 라이브러리가 즉시 나타납니다 — 경로가 자동으로 수정됩니다

유니버스 폴더 구조는 Obsidian 모델을 따릅니다: 노트는 루트 폴더에 직접 배치되고, 설정은 `.constellation/`에 저장됩니다.

## 3. 노트 작성 및 편집

### 노트 작성

| 방법 | 동작 |
|------|------|
| **키보드** | `Ctrl+N` |
| **파일 트리** | 폴더 우클릭 > 새 노트 |
| **미션 컨트롤** | `Ctrl+P` > "새 노트" |

### 에디터 모드

Constellation은 **설정 > 에디터 > 에디터 유형**에서 선택할 수 있는 두 가지 에디터 모드를 제공합니다:

#### Markdown 에디터 (CodeMirror)

파워 유저를 위한 기본 에디터입니다. Markdown을 직접 작성할 수 있습니다:

- **실시간 미리보기** — 입력하면서 서식을 인라인으로 렌더링
- **소스 모드** — 원본 Markdown 구문 표시
- **서식 도구 모음** — 텍스트 선택 시 표시
- **슬래시 명령** — `/`를 입력하여 빠른 삽입
- **Wikilink 자동 완성** — `[[`를 입력하여 노트 링크
- **다중 커서** — `Alt+Click` 또는 `Ctrl+D`

#### 문서 에디터 (TipTap)

비주얼 도구 모음이 있는 WYSIWYG 워드프로세서 경험:

- 굵게, 기울임, 밑줄, 취소선, 강조
- 제목(H1~H3), 텍스트 정렬
- 글머리 기호 목록, 번호 매기기 목록, 작업 목록
- 인용문, 코드 블록, 수평선
- 표(삽입, 행과 열 추가/삭제)
- 링크와 이미지

두 에디터 모두 표준 Markdown 파일로 저장됩니다. 데이터 손실 없이 언제든지 전환할 수 있습니다.

### 콜아웃 (Callouts)

메모, 경고, 팁 등을 위한 스타일이 지정된 콜아웃 블록을 만들 수 있습니다:

```markdown
> [!note] 중요한 정보
> 콜아웃 내용이 여기에 들어갑니다.

> [!warning] 주의하세요
> 이 작업은 되돌릴 수 없습니다.

> [!tip]- 클릭하여 펼치기
> 접을 수 있는 콜아웃 내용.
```

지원되는 유형: `note`, `tip`, `warning`, `danger`, `success`, `question`, `failure`, `bug`, `example`, `quote`, `abstract`. 각 유형에는 고유한 색상과 아이콘이 있습니다. 유형 뒤에 `-`를 추가하면 접을 수 있게 됩니다(접힌 상태로 시작). `+`를 추가하면 펼쳐진 상태로 시작합니다.

### 하이라이트 구문

텍스트를 이중 등호로 감싸면 강조 표시할 수 있습니다:

```markdown
이것은 노트에서 ==강조된 텍스트==입니다.
```

실시간 미리보기에서 `==` 표시는 숨겨지고 텍스트가 노란색 배경으로 표시됩니다.

### 코드 블록

펜스 코드 블록은 배경색과 언어 레이블과 함께 표시됩니다:

````markdown
```javascript
const greeting = "Hello, world!";
```
````

언어 이름이 코드 블록 위에 배지로 표시됩니다.

### 이미지 삽입

노트에 이미지를 직접 삽입할 수 있습니다:

```markdown
![대체 텍스트](https://example.com/image.png)   — 외부 URL
![[photo.jpg]]                                    — 라이브러리의 로컬 파일
```

실시간 미리보기에서 이미지가 인라인으로 렌더링됩니다. 로컬 이미지는 라이브러리 폴더에 있어야 합니다. 외부 이미지는 인터넷 연결이 필요합니다.

### 표 도구 모음

커서가 markdown 표 안에 있을 때 플로팅 도구 모음이 나타납니다:

- **+ 행 / + 열** — 행 또는 열 추가
- **- 행 / - 열** — 행 또는 열 삭제
- **정렬** — 열별 왼쪽, 가운데, 오른쪽 정렬
- **정렬** — 현재 열 기준으로 오름차순 또는 내림차순 정렬
- **Tab / Shift+Tab** — 표 셀 간 이동

### 텍스트 서식 단축키

| 단축키 | 동작 |
|--------|------|
| `Ctrl+B` | 굵게 |
| `Ctrl+I` | 기울임 |
| `Ctrl+Shift+S` | 취소선 |
| `Ctrl+Shift+H` | 강조 |
| `Ctrl+K` | Wikilink 삽입 |
| `Ctrl+Z` | 실행 취소 |
| `Ctrl+Shift+Z` | 다시 실행 |

### 노트 링크

`[[`를 입력하면 노트 자동 완성이 열립니다. 노트 이름을 입력하고 제안 목록에서 선택하세요. 링크는 클릭 가능한 Wikilink로 표시됩니다: `[[노트 이름]]`.

특정 제목에 링크할 수도 있습니다: `[[노트 이름#제목]]`.

## 4. 검색

Constellation에는 SQLite FTS5 기반의 BM25 랭킹, 구조화된 쿼리 필터, 아랍어 최적화 정규화를 갖춘 하이브리드 다국어 검색 엔진이 포함되어 있습니다. 검색은 사이드바 도구 모음에서 접근할 수 있습니다.

### 검색 방법

사이드바 도구 모음의 검색 아이콘을 클릭하거나 `Ctrl+Shift+F`로 검색 모드를 활성화합니다. 쿼리를 입력하면 짧은 지연(300ms) 후 결과가 나타납니다. `Escape`를 누르거나 `×` 버튼을 클릭하면 검색이 지워지고 파일 트리로 돌아갑니다.

### 검색 구문

| 구문 | 예시 | 검색 대상 |
|------|------|-----------|
| 자유 텍스트 | `프로젝트 관리` | 제목이나 본문에 해당 단어가 포함된 노트 |
| 태그 필터 | `#연구` | `#연구` 태그가 있는 노트 |
| 속성 필터 | `status=active` | frontmatter 속성 `status`가 `active`인 노트 |
| 위키링크 필터 | `links to [[기후]]` | `[[기후]]`에 링크된 노트 |
| 라이브러리 범위 | `in:내라이브러리` | 결과를 특정 라이브러리로 제한 |
| 조합 | `#연구 status=active 경제` | 모든 필터를 함께 적용 |

### 매치 유형 배지

각 검색 결과에는 매치가 어떻게 발견되었는지 나타내는 색상 배지가 표시됩니다. 배지는 접근성을 위해 현지화된 글자를 표시합니다(색맹 안전):

| 배지 | 색상 | 의미 |
|------|------|------|
| **제** | 파란색 | 제목 매치 — 검색어가 노트 이름에 나타남 |
| **내** | 초록색 | 내용 매치 — 검색어가 노트 본문에 나타남 |
| **의** | 보라색 | 의미 매치 — 개념적으로 관련됨 (embedding 모델 필요) |
| **속** | 호박색 | 속성 매치 — frontmatter 속성 필터로 발견 |
| **#** | 분홍색 | 태그 매치 — 태그 필터로 발견 |
| **위** | 연한 파란색 | 위키링크 매치 — 위키링크 필터로 발견 |

배지 글자는 지원되는 15개 언어 모두에 대해 현지화되어 있습니다.

### 고정된 결과 (결과 간 탐색)

검색 결과는 하나를 클릭한 후에도 계속 표시됩니다. 열린 노트가 결과 목록에서 강조 표시되어 어떤 결과를 보고 있는지 확인할 수 있습니다. 다시 검색하지 않고 다른 결과를 클릭하여 탐색할 수 있습니다.

검색을 지우려면 `Escape`를 누르거나 `×` 버튼을 클릭합니다.

### 키보드 탐색

| 키 | 동작 |
|----|------|
| `아래 화살표` | 다음 결과 선택 |
| `위 화살표` | 이전 결과 선택 |
| `Enter` | 선택한 결과 열기 |
| `Escape` | 검색 지우고 파일 트리로 돌아가기 |

### 검색어 하이라이팅

검색 결과에서 노트를 열면 검색어의 모든 등장이 편집기에서 강조 표시됩니다. 아랍어 발음 부호 인식 매칭이 작동하여 "ادارة"를 검색하면 "إدارة"와 모든 발음 부호 변형이 강조됩니다.

### 검색 기록

검색 필드가 비어 있을 때 클릭하면 최근 검색(최근 20개 쿼리)이 표시됩니다. 각 항목에는 쿼리 텍스트와 수행 시간이 표시됩니다. 아무 항목이나 클릭하면 해당 검색이 즉시 다시 실행됩니다. 하단의 "기록 지우기" 링크를 사용하여 모든 기록을 삭제할 수 있습니다.

검색 기록은 기기에 로컬로 저장되며 앱 재시작 시에도 유지됩니다.

### Search Hub

Search Hub는 전체 화면 검색 경험입니다. 독 바의 돋보기 아이콘을 클릭하여 엽니다. 양쪽 사이드바가 접혀 최대 공간을 제공합니다. 아무 용어나 입력하면 Constellation이 동시에 모든 곳을 검색하여 결과를 5개 카테고리로 그룹화합니다: 제목, 내용, 태그, 속성, 위키링크. 각 카테고리에는 개수 배지가 있는 접을 수 있는 섹션이 있습니다. 아무 결과나 클릭하면 모든 발생이 강조 표시된 상태로 편집기에서 열립니다. "Search Hub로 돌아가기" 버튼이 나타나 다시 검색하지 않고 돌아갈 수 있습니다.

### 링크 연산자

Constellation은 6가지 링크 토폴로지 검색 연산자를 지원합니다:

| 구문 | 찾는 내용 |
|------|-----------|
| `links to [[X]]` | X로 링크하는 노트 (백링크) |
| `links from [[X]]` | X가 링크하는 노트 (발신 링크) |
| `mutual [[X]]` | X에 링크하고 X도 다시 링크하는 노트 (양방향) |
| `mentions [[X]]` | [[위키링크]] 없이 X의 이름을 포함하는 노트 |
| `orphans` | 수신 또는 발신 링크가 없는 노트 |
| `links between [[X]] and [[Y]]` | X와 Y 모두에 링크하는 노트 |

링크 연산자를 입력할 때 `[[` 자동완성이 유니버스의 모든 노트를 표시합니다. 노트를 선택한 후 제목 완성에는 `#`을, 링크 유형 완성에는 `|type:`을 입력하세요.

## 5. 스타 뷰 (GraphMind)

스타 뷰는 **GraphMind** 엔진(Pixi.js WebGL)을 사용하여 노트를 인터랙티브한 3D 그래프로 시각화합니다.

### 스타 뷰 열기

- 사이드바의 그래프 아이콘 클릭
- `Ctrl+G` 누르기
- 미션 컨트롤(`Ctrl+P`) > "스타 뷰"

### 탐색

| 입력 | 동작 |
|------|------|
| **클릭 + 드래그** | 그래프 이동 |
| **스크롤** | 확대/축소 |
| **노드 클릭** | 노트 열기 |
| **노드 우클릭** | 컨텍스트 메뉴(열기, 포커스, 고정, 숨기기) |
| **중간 클릭 + 드래그** | 3D 회전 |
| **W/A/S/D** | 3D 공간 비행 |
| **0** | 회전을 2D로 리셋 |
| **Ctrl+F** | 검색 및 강조 |
| **Space** | 포커스 모드 전환 |

### 레이아웃 모드

`Ctrl+L`을 눌러 전환:

- **유기적** — 클러스터가 자연스럽게 형성되는 힘 기반 레이아웃
- **계층형** — 위에서 아래로의 트리 레이아웃
- **시간순** — 생성 날짜 순으로 타임라인에 배치

### 포커스 모드

노드 우클릭 > **포커스**로 해당 이웃만 표시합니다. 조정 항목:

- **깊이**(1~5홉) — 표시할 연결 수준 수
- **방향**(↔/←/→) — 모든 링크, 수신만, 발신만

### 3D 탐색

중간 클릭 + 드래그로 회전합니다. W/A/S/D/Q/E로 스타 필드를 비행합니다. 코너의 XYZ 축 기즈모로 방향을 확인할 수 있습니다. `0`을 눌러 리셋합니다.

### 설정

기어 아이콘을 클릭하여 설정:

- **외관**: 노드 크기, 라벨 표시, 글꼴 크기, 링크 두께, 고립 노드 표시
- **물리**: 반발력, 링크 힘, 링크 거리
- **AI**: 시맨틱 링크 임계값(2단계)

### 범례

오른쪽 하단 범례에 라이브러리/폴더 색상이 체크박스와 함께 표시되어 표시/숨기기를 전환할 수 있습니다.

### 지식 계층

스타 뷰는 추상화 수준에 따라 노트를 8개의 지식 계층으로 자동 분류합니다:

| 계층 | 설명 |
|------|------|
| **스냅샷** | 빠르고 일시적인 메모 |
| **로그** | 날짜가 있는 이벤트 및 일기 항목 |
| **주제** | 하나의 아이디어에 대한 원자적 개념 |
| **지도** | 다른 주제를 연결하는 조직 노트 |
| **프레임워크** | 모델과 사고 틀 |
| **원칙** | 검증된 규칙과 공리 |
| **신념** | 핵심 가치와 믿음 |
| **산출물** | 완성된 최종 작품 |

계층은 노트의 프론트매터, 구조, 링크에서 자동으로 결정됩니다. 프론트매터에 `stratum` 속성을 추가하여 분류를 수동으로 재정의할 수 있습니다.

### 성숙 수명 주기

각 노트는 발전 정도를 반영하는 성숙 수명 주기를 거칩니다:

- **씨앗** — 초기 아이디어 또는 초안
- **묘목** — 노트가 형태를 갖추기 시작하고 일부 링크가 있음
- **상록** — 성숙하고 검토되었으며 잘 연결된 노트
- **정전** — 해당 분야의 최종적이고 권위 있는 참고 자료

성숙도는 링크 수, 검토 날짜, 편집 빈도에 따라 자동으로 업데이트됩니다. 프론트매터의 `maturity` 속성으로 수동 설정도 가능합니다.

## 6. 분할 보기

분할 보기를 사용하면 메인 창에서 여러 노트를 나란히 편집할 수 있습니다.

### 분할 보기 열기

- **명령 팔레트**: `Ctrl+P` 후 "Split View" 입력
- **키보드 단축키**: 지정된 단축키로 모드 전환
- **순환**: 끔 → 수직 (나란히) → 수평 (위아래) → 끔

### 분할 보기에서 편집

각 패널은 완전히 독립적인 편집기입니다:
- 전체 도구 모음 (굵게, 기울임, 제목, 정렬 등)
- 경로 탐색 (라이브러리 / 노트 이름)
- 속성 패널과 단계 드롭다운
- 저장 지원 (`Ctrl+S`로 포커스된 패널 저장)
- 제목 편집 및 파일 이름 변경

### 패널 크기 조정

패널 사이의 구분선을 드래그하여 크기를 조정합니다. 각 구분선은 독립적입니다 — 3개 이상의 노트가 열려 있을 때 다른 것에 영향을 주지 않고 인접한 쌍의 크기를 조정할 수 있습니다. 수직 및 수평 모드 모두에서 작동합니다.

### 포커스

아무 패널이나 클릭하여 포커스합니다. 포커스된 패널이 키보드 단축키를 받으며 오른쪽 사이드바 패널(속성, 백링크 등)에서 추적됩니다.

## 7. 인덱스

인덱스는 모든 라이브러리에 걸친 포괄적인 용어 사전입니다 — 모든 의미 있는 단어가 알파벳순으로 정렬되어 출현 횟수와 함께 표시됩니다.

### 인덱스 열기

- **도크 버튼**: 왼쪽 도크의 인덱스 아이콘(책) 클릭
- **명령 팔레트**: `Ctrl+P` 후 "Index" 입력

### 다국어 NLP 파이프라인

인덱스는 색인 전에 언어 인식 파이프라인을 통해 텍스트를 처리합니다:

- **아랍어**: Lucene Light10 알고리즘 — 타쉬킬 제거, 함자 통합, 정관사(الـ) 제거, 문법 접미사 제거
- **히브리어**: 접두사 제거 (ב/ל/מ/ה/ו/כ/ש)
- **영어**: Porter 유사 스테밍 (복수형, 동사형, 접미사)
- **프랑스어/스페인어/포르투갈어/독일어**: 언어별 접미사 제거
- **러시아어/터키어/힌디어/페르시아어**: 형태론적 접미사 제거
- **전체 15개 언어**: 불용어 필터링 (관사, 전치사, 접속사)

### 탐색

- **언어 탭**: 전체, 아랍어, 히브리어, 영어 또는 # (특수 문자) 간 전환
- **알파벳 바**: 문자를 클릭하여 해당 문자로 시작하는 용어를 필터링 — 용어 수가 업데이트되어 일치 항목 수를 표시
- **같은 문자를 다시 클릭**하면 필터가 지워지고 모든 용어가 표시됩니다
- **정렬 모드**: 알파벳순(기본) 또는 빈도순(가장 많은 것 먼저)

### 인덱스에서 편집

용어의 참조에서 노트를 클릭하면 인덱스 옆의 분할 미리보기 패널에서 열립니다. 미리보기 패널은 완전한 편집기입니다 — 편집, 저장, 속성 변경, 단계 승격이 가능합니다. 검색 용어가 노트에서 하이라이트되고 자동으로 스크롤됩니다.

`Ctrl+Click`으로 노트를 일반 탭으로 엽니다. 탭 바에 "인덱스로 돌아가기" 버튼이 나타납니다 — 클릭하면 인덱스에서 중단한 위치로 정확히 돌아갑니다.

### 세컨드 스크린 통합

세컨드 스크린이 열려 있을 때:
- **용어 클릭** → 세컨드 스크린이 해당 용어를 포함한 모든 노트를 분할 뷰로 표시 (노트 목록 + 편집기)
- **여러 용어를 Ctrl+Click** → 세컨드 스크린이 비교 모드를 표시하며 각 용어가 자체 열에 배치됩니다

## 8. Constellation Sight

Constellation Sight는 전체 지식 시스템을 중력 우물 그래프로 시각화합니다. **"내 지식은 어떤 모습이고, 얼마나 건강한가?"**라는 질문에 답합니다.

### Sight 열기

왼쪽 리본의 **Sight 버튼**(눈 아이콘)을 클릭합니다. 중력 우물 그래프가 나타납니다. 닫으려면 x를 클릭합니다.

### 중력 우물 그래프

노트는 중요도(중심성)에 따라 동심원 링으로 배열됩니다. 가장 많이 연결된 노트가 중심에, 주변 노트가 가장자리에 위치합니다. 각 링 내에서 노트는 라이브러리(사용자의 조직)별로 그룹화됩니다. 노드 색상 = 라이브러리.

| 요소 | 의미 |
|------|------|
| **큰 노드** | 높은 중심성 — 다양한 지식 영역을 연결 |
| **작은 노드** | 주변부 — 한 영역 내 |
| **노드 색상** | 라이브러리 소속 |
| **실선** | 두 노트 간의 링크 |
| **방향 화살표** | 링크 방향을 나타내는 작은 화살표 |
| **선 두께** | 신뢰도 수준 (굵음 = 확립됨, 얇음 = 가설) |

### 상호작용

- **단일 클릭**: 노드의 이웃을 하이라이트합니다(모든 연결된 노트). 나머지는 흐려집니다.
- **더블 클릭**: 에디터에서 노트를 엽니다.
- **빈 공간 클릭**: 하이라이트를 지웁니다.
- **스크롤**: 줌. **드래그**: 팬. **화면에 맞추기**: 도구 모음 버튼.

### Sight에서 검색

돋보기를 클릭합니다. 모든 연산자를 지원합니다: `links to [[X]]`, `links from [[X]]`, `mutual [[X]]`, `orphans`, `supports [[X]]`, `contradicts [[X]]`, `#tag`, 자유 텍스트 및 시맨틱 검색. 결과는 방향 색상으로 표시됩니다: 초록색(유입), 빨간색(유출).

### 분석 패널 (SightPanel)

그리드 아이콘을 클릭하여 사이드바를 엽니다. 표시 내용: 유니버스 건강 점수(0-100), 노트/링크/고아 카운터, 링크 유형 및 신뢰도 바, 상위 10 브리지, 지식 인사이트(가장 강력한 증거, 약한 기반, 긴장, 정체, 가장 많이 연결된, 지식 격차).

### 설정

톱니바퀴 아이콘: 링크 스트로크 두께, 불투명도 및 화살표 크기를 조정합니다. 설정은 세션 간에 유지됩니다.

### 8a. 노트별 전통 필드 (MIG-029)

Sight 좌상단의 전통 칩은 10개 인식론적 가족에 속하는 24개 학문 전통을 통해 돔을 다시 구성할 수 있게 해줍니다. 그 중 9개 전통(섹터형 / 동심원형 / 사다리형 형태를 가진 것들)에 대해, 각 노트는 frontmatter 필드를 통해 **명시적으로 분류**될 수 있습니다. 필드가 없는 노트는 각 전통별로 합리적인 기본 버킷에 들어갑니다; 필드가 있는 노트는 당신이 지정한 버킷에 들어갑니다.

노트의 YAML frontmatter에 필드를 추가하세요:

```yaml
---
masadir_source: sunnah
---
```

해당 전통의 칩으로 전환 → 노트가 기본값 대신 그 전통의 이름이 붙은 섹터에 들어갑니다.

**허용된 필드와 값:**

| 전통 | frontmatter 필드 | 허용된 값 | 부재 시 기본값 |
|---|---|---|---|
| **마사디르(masādir)** (수니파 우슐 알피크) | `masadir_source` | `quran` / `sunnah` / `ijma` / `qiyas` | `quran` |
| **프라마나(pramāṇa)** (인도 니야야) | `pramana_kind` | `pratyaksha` / `anumana` / `upamana` / `shabda` | `pratyaksha` |
| **이븐 루시드 부르한** | `burhan_kind` | `burhan` / `jadal` / `khataba` / `shir` | `shir` (가장 바깥 고리) |
| **파르데스(PaRDeS)** (유대교 해석학) | `pardes_level` | `peshat` / `remez` / `derash` / `sod` | `peshat` |
| **퍼스** (3 현상학적 범주) | `peirce_category` | `firstness` / `secondness` / `thirdness` | `firstness` |
| **하버마스** (3 인식 관심) | `habermas_interest` | `technical` / `practical` / `emancipatory` | `technical` |
| **맹자 사단** (4 도덕적 싹) | `mencian_sprout` | `ceyin` / `xiuwu` / `cirang` / `shifei` | `ceyin` |
| **묵가 삼표(三表, sān biǎo)** (3 표준) | `mohist_zone` | `ben` / `yuan` / `yong` | 해시로 3개 구역에 분산 |
| **한국 성리학** (사단칠정 논쟁) | `songnihak_cell` | `li-sa` / `li-chil` / `qi-chil` / `qi-sa` | `li-sa` |

**동작:**
- 전통이 인식하지 못하는 값(오타 또는 만들어낸 값)을 작성하면, 노트는 기본 버킷에 들어갑니다. 충돌도, 렌더링 오류도 없습니다.
- frontmatter 변경은 자동으로 전파됩니다 — 노트를 저장하세요 → 돔의 다음 렌더링이 변경을 반영합니다.
- 같은 필드는 그 이름이 붙은 전통만 읽습니다. 노트에 `masadir_source: sunnah`를 설정해도 PaRDeS나 퍼스로 전환할 때는 아무 영향이 없습니다 — 각 전통은 자신의 필드를 독립적으로 읽습니다.
- 이것이 돔의 공간 문법을 제어하는 가장 명시적인 방법입니다. 이 필드들이 없으면 기하학은 올바르지만 모든 노트가 같은 기본 버킷에 들어갑니다; 이 필드들이 있으면 칩이 분석적으로 의미있게 됩니다.

**노트별 필드가 없는 전통** (현재 다른 수단으로 모든 별을 버킷화함 — 폴더 / 라이브러리 / 해시):

- 아리스토텔레스적 (기본값, 재매핑 없음)
- 폴라니 (그라데이션 안개; 섹터화 없음)
- 후설, 롱지노, 샤티비 마카시드, 마이모니데스 예언론, 탈무드 13 미도트, 왕양명, 미뇰로 플루리버설, 두셀 트랜스모더니티, 말도나도-토레스, 아칸(위레두), 이븐 칼둔 우므란, 이부아니단다

(향후 마이그레이션에서 사용자 수요가 가시화됨에 따라 이 전통들에도 노트별 frontmatter 필드를 추가할 수 있습니다.)

## 9. 세컨드 스크린

세컨드 스크린은 현재 사이드바 모드에 맞춰 적응하는 모드 기반 동반 창입니다.

- **열기**: 사이드바의 세컨드 스크린 아이콘 클릭, 또는 `Ctrl+Shift+2`
- **자동 닫기**: 메인 창을 닫으면 세컨드 스크린도 자동으로 닫힙니다

### 모드 기반 동반자

세컨드 스크린은 메인 창의 활성 사이드바 모드에 따라 콘텐츠를 변경합니다:

| 메인 사이드바 모드 | 세컨드 스크린 표시 |
|---|---|
| **파일 탐색기** | 유니버스 대시보드 — 통계, 라이브러리 분석, 하위 유니버스, 태그, 최근 편집/열린 노트 |
| **내비게이터** | 노트 탐색을 위한 전체 내비게이터 보기 |
| **스카이 뷰** | 디렉토리 구조가 포함된 스카이 뷰 트리 |
| **스타 뷰** | 백링크, 포워드 링크, 태그, 로컬 그래프가 포함된 스타 뷰 동반자 |

### 유니버스 대시보드 (파일 탐색기 모드)

메인 창이 파일 탐색기 모드일 때 세컨드 스크린은 다음을 포함한 대시보드를 표시합니다:

- **통계 카드** — 유니버스 이름, 하위 유니버스 수, 총 라이브러리, 폴더, 노트 수
- **하위 유니버스** — 연결된 라이브러리와 폴더/노트 수를 포함한 각 하위 유니버스
- **라이브러리** — 색상 코드 통계 상자에 폴더/노트 수를 포함한 각 라이브러리
- **최근 편집** — 현재 세션에서 수정한 노트 (저장 시 추적)
- **최근 열기** — 현재 세션에서 열었지만 편집하지 않은 노트
- **태그** — 모든 라이브러리의 모든 태그를 수별로 정렬; 태그를 클릭하여 관련 노트 모두 보기

### 대시보드 연동

메인 창에서 대시보드가 활성화된 경우, 항목을 클릭하면 세컨드 스크린으로 전송됩니다:

- **최근 편집/열기**: 노트를 클릭하면 세컨드 스크린에서 전체 편집기로 열립니다
- **태그**: 태그를 클릭하면 해당 태그를 사용하는 모든 노트가 분할 보기로 표시됩니다 — 왼쪽에 노트 목록, 오른쪽에 전체 편집기

세컨드 스크린에서의 모든 편집 내용은 자동으로 메인 창에 동기화됩니다.

### 세컨드 스크린에서 노트 편집

세컨드 스크린은 전체 노트 편집을 지원합니다 — 메인 창처럼 입력, 저장, 이름 변경, 속성 변경이 가능합니다. 변경 사항은 메인 창과 자동으로 동기화됩니다.

### 설정 동기화

모든 시각적 설정이 세컨드 스크린에 즉시 전파됩니다 — 재시작 불필요:

- **언어**: 인터페이스 언어 변경이 즉시 적용
- **테마**: 라이트/다크/시스템 모드가 즉시 전환
- **글꼴**: 인터페이스 글꼴, 텍스트 글꼴, 모노 글꼴, 스크립트별 글꼴
- **글꼴 크기**: 인터페이스와 편집기 글꼴 크기 모두
- **편집기**: 읽기 쉬운 줄 너비, 줄 번호, 플로팅 도구 모음
- **강조 색상**: 테마 강조 색상 변경

## 10. 속성과 프론트매터

노트 상단에 YAML 프론트매터를 작성할 수 있습니다:

```yaml
---
tags: [project, active]
date: 2026-03-19
status: in-progress
---
```

Constellation은 속성 유형을 자동으로 감지합니다:

| 유형 | 예시 |
|------|------|
| **텍스트** | `author: John` |
| **숫자** | `priority: 5` |
| **날짜** | `date: 2026-03-19` |
| **목록** | `tags: [a, b, c]` |
| **체크박스** | `done: true` |
| **링크** | `related: [[Other Note]]` |

속성 표시 전환: **설정 > 에디터 > 문서 내 속성**(표시 / 숨김 / 소스).

## 10b. 소스 검토 (Constellation 인식적 콘텐츠 엔진 — CECE)

> *(번역 메모: V3-§10.F 챕터의 AI 생성 번역; 원어민 검토 대기 중.)*

프론트매터의 가장 중요한 속성 두 가지 — `sources:` 및 `content_type:` — 는 무엇을 *어떻게 알게 되었는지* 와 *어떤 종류의 지식인지* 를 설명합니다. Constellation의 **인식적 콘텐츠 엔진** (CECE)은 6개의 분류기 앙상블을 사용하여 이 두 축을 따라 모든 노트를 자동으로 분류합니다. **소스 검토** 패널은 이러한 분류를 검토하고 수정하는 곳입니다.

### 엔진이 하는 일

노트를 분류할 때(우클릭 → "소스 및 콘텐츠 유형 제안", 또는 **설정 > 스캔 실행**, 또는 백그라운드 스캔 토글을 통해 자동으로), CECE는 노트에 대해 6개의 독립적인 분류기를 실행합니다. 각각 다른 렌즈를 통해 노트를 읽고 두 가지 질문에 투표합니다:

- **소스** (수평축) — 이 지식은 어디서 *왔는가*? 11가지 가능한 값: 지각, 추론, 증언, 대량 전달, 비교, 가정, 비파악, 기억, 선천적 성향, 영감, 계시. 그리고 *분류 불가능*.
- **콘텐츠 유형** (수직축) — 이것은 *어떤 종류*의 지식인가? 5개의 최상위 분기: 감각 입력, 상징 개체, 의미 콘텐츠, 인식 상태, 고차 구성.

두 축은 독립적입니다. "달 착륙을 의심한다"는 노트는 소스에서 증언(누군가가 보고함)이고 콘텐츠 유형에서 인식 상태/의심(당신의 입장)입니다.

엔진은 **당신의 기기에서** 실행됩니다 — 어떤 노트도 Constellation을 떠나지 않습니다.

### 6개의 분류기

각 분류기는 하나의 렌즈입니다. 소스 검토 카드는 각 카드의 오른쪽 위 모서리에 6개의 작은 색상 점으로 표시합니다:

- **내 frontmatter** (파랑) — 이미 설정한 것을 절대적 권위로 채택
- **인용 및 구조** (장미) — 인용, 블록 인용, 정리 표시자, 정의 구문
- **어간 및 어휘** (호박) — 아랍어 어근 분석 + 교차 언어 용어 동등성
- **연결된 노트** (틸) — 다른 분류된 노트로의 타입 Living Links
- **유사한 노트** (보라) — 이미 분류된 노트와의 임베딩 유사도
- **AI 판단** (초록) — 로컬 LLM (Qwen3-4B; *아직 활성화되지 않음*, 향후 릴리스로 연기)

채워진 점은 해당 분류기가 발언했고 종합에 동의함을 의미합니다. 링이 있는 점은 발언했지만 반대했음을 의미합니다. 점선 윤곽 점은 침묵을 지켰음을 의미합니다 (이 렌즈에 신호 없음).

### 세 가지 신뢰 체제

분류기가 투표한 후, 각 축은 세 가지 체제 중 하나에 안착합니다:

- **만장일치** — 발언한 모든 분류기가 동의
- **강한 다수 (1건 반대)** — 대부분 동의; 1명의 반대자가 명명됨
- **분열** — 명확한 다수 없음; 엔진은 추측을 거부하고 당신에게 선택을 요청

각 축은 독립적으로 자체 체제를 가집니다 — 카드는 수평에서 만장일치 + 수직에서 분열일 수 있습니다.

### Sibling Disambiguation

축이 분열일 때, 엔진은 후보 값을 프롬프트 아래 **칩**으로 표시합니다: *"노트에 가장 잘 맞는 것을 선택하세요."* 칩 클릭 → 엔진은 당신의 선택을 노트의 frontmatter에 기록하고 카드를 큐에서 제거합니다. 다른 축이 정해져 있었다면(만장일치 또는 강한 다수), 엔진은 *동시에* 그 축의 값도 기록합니다 — 한 축만 분열일 때 한 번의 클릭으로 두 축을 모두 완료합니다.

### 추론 추적

각 카드에는 *"▸ 왜 이 분류인가?"* 토글이 있습니다. 확장하면 발언한 각 분류기에 대한 한 행이 표시되며, 추론, 자체 보고된 신뢰도, 친화적 규칙 칩 ("표면 키워드 일치", "아랍어 어근 일치 (CAE)", "정의 표시자" 등)이 포함됩니다 — 이는 각 분류기가 트리거한 특정 규칙입니다.

당신의 **첫 50번의 검토** 동안, 추적은 모든 카드에서 자동으로 확장됩니다 (*신뢰도 보정 기간*) 그래서 엔진을 언제 신뢰할지에 대한 직관을 키울 수 있습니다. 그 후 추적은 만장일치 카드에서 요청 시 표시되도록 축소됩니다. 언제든지 **설정 > 인텔리전스 > CECE > 추론 추적 표시**에서 재정의할 수 있습니다.

### 큐 구성 필터

카운트 스트립 위에 5개의 칩이 각 카드가 필요로 하는 결정 종류에 따라 큐를 슬라이스합니다:

- **전체** — 전체 큐
- **두 축 모두 결정 필요** — 두 축이 분열
- **소스 결정 필요** — 수평이 분열 + 수직이 정해짐
- **콘텐츠 유형 결정 필요** — 수직이 분열 + 수평이 정해짐
- **분류기가 동의함** — 어떤 축도 분열되지 않음 (러버 스탬프 후보)

각 칩은 버킷 카운트를 표시합니다. 필터는 렌더링 계층 슬라이서입니다 — "모두 승인" 수학은 어떤 필터가 활성화되어 있든 항상 전체 큐에서 작동합니다.

### 카드별 작업

- **수락** — 두 축에서 엔진의 종합을 기본으로 기록; 카드를 제거. 분류기별 신뢰성을 업데이트.
- **편집** — 두 축에 대한 트리 선택기를 엽니다; 수동으로 선택. 동일한 신뢰성 업데이트.
- **거부** — 기록 없이 카드를 지웁니다.
- **Sibling Disambiguation 칩** — 분열 카드에서만.

### 라이브러리별 보정

**설정 > 인텔리전스 > CECE > 라이브러리별 보정**은 활성 라이브러리에서 각 분류기의 축별 정확도를 표시하는 읽기 전용 테이블을 엽니다. 다른 라이브러리는 분류기별로 다른 정확도를 갖습니다 — Linguistic은 아랍어가 많은 라이브러리에서 뛰어나고, Graph는 밀집하게 연결된 라이브러리에서 뛰어납니다. 종합 계층은 이 보정 데이터를 사용하여 투표에 가중치를 부여합니다.

분류기의 정확도 비율이 표시되려면 **20번의 수정**이 필요합니다. 그 임계값 미만에서는 라벨이 *"(균일)"* 로 표시됩니다 — 충분한 데이터가 누적될 때까지 분류기는 균일하게 가중된 투표를 기여합니다.

### 백그라운드 분류

기본적으로 CECE는 당신이 요청할 때만 노트를 분류합니다 (우클릭 또는 설정 스캔 버튼). **설정 > 인텔리전스 > CECE > 백그라운드 분류**에서 자동 분류를 선택할 수 있습니다:

- **노트 저장 시** — 타이핑을 멈춘 후 약 1.5초 후에 각 노트를 분류 (기존의 디바운스된 저장을 활용; 키 입력마다 발사하지 않음; 타이핑은 즉각적으로 유지)
- **앱 시작 시** — 시작당 한 번씩 미분류 노트를 스캔

### 분류기 — 전체 페이지 홈

동일한 카드는 **분류기**라고 불리는 전체 페이지 뷰에도 살며, **왼쪽 독의 쌓인 카드 아이콘**에서 열립니다. 그것은 동일한 엔진이자 동일한 큐로, 좁은 사이드바 탭 대신 창 전체를 부여받습니다 — 그리고 사이드바 탭에는 결코 없던 두 가지 컨트롤을 더합니다:

- **노트 분류…** — *어떤* 노트든 먼저 열지 않고 이름으로 분류할 수 있는 검색 상자. 몇 글자를 입력하고, 노트를 고르면, 새 카드가 큐에 나타납니다.
- **모든 요약 생성** — 요약이 없는 모든 노트에 대해 (아래의) 노트 요약을 백그라운드에서 미리 계산하며, 진행 상황은 상태 표시줄에 표시됩니다.

**스캔 시작** 버튼(설정과 동일한 우주 전체 스캔)과 라이브 진행 스트립이 헤더를 마무리합니다. 분류기는 **(×)** 또는 **Esc**로 닫습니다. (*노트 분류…* 검색 상자가 열려 있을 때는, 첫 번째 **Esc**가 그 상자만 닫습니다.)

이름에 대한 메모: **분류기**는 *방*(전체 페이지 뷰)이고; **분류기들**은 엔진 내부에서 각 카드에 투표하는 *여섯 개의 렌즈*입니다. 둘을 혼동하지 마세요.

### 노트 요약

각 카드의 제목 아래에는 짧은 **요약**이 있습니다 — 노트가 무엇에 관한 것인지 알려주는 몇 문장으로, 노트를 열지 않고도 분류할 수 있게 합니다. Constellation은 항상 *당신이* 작성한 요약을 우선하며 작성하지 않았을 때만 하나를 생성합니다:

1. `summary:` / `description:` / `abstract:` / `excerpt:` **frontmatter 필드**, 그대로 사용됨.
2. 본문의 `> [!summary]` / `[!abstract]` / `[!tldr]` **콜아웃**, 그대로 사용됨.
3. 그 외에는 **생성된** 요약 — 노트의 가장 중심적인 세 문장으로, 추출되어(결코 지어내지 않음) 원래 순서로 표시됨.

생성된 요약은 **읽기 전용**입니다 — Constellation은 결코 그것을 노트에 다시 작성하지 않으며(File-Over-App), 모든 것은 **당신의 기기에서** 계산됩니다. 요약이 파일에 살기를 원한다면, 직접 하나를 작성하면 Constellation이 당신의 것을 대신 표시합니다.

더 깊은 세부 사항(각 점 상태, 각 규칙 칩, 클릭별 안내)에 대해서는 도움말 시스템의 **소스 검토**, **분류기**, 그리고 **노트 요약** 항목을 참조하세요.

## 10c. 인식론적 메타데이터

노트의 지식이 어떻게 획득되었는지, 누가 그 입장을 견지하는지, 어느 학문 분야에 속하는지, 마지막으로 견해를 수정한 시점이 언제인지에 대한 더 풍부한 정보를 기록하기 위한 소수의 선택적 프런트매터 필드. 갭 분석(`docs/epistemic-content-gap-analysis.md`)에 대한 응답으로 MIG-022 §A에 추가되었습니다.

이 필드들은 **모두 선택적**입니다. 이들 없이 노트는 변경 없이 작동합니다.

### 빠른 참조

| Field | Type | 목적 |
|---|---|---|
| `held_by` | text | 이는 누구의 입장인가? (기본값은 `user`; `"al-Shāfiʿī"`, `"Ḥanafī"` 등이 될 수 있음) |
| `domain` | list | 검색용 학문 분야 태그 (`[fiqh, ʿibādāt]`) |
| `function` | text | 이 노트는 무엇을 위한 것인가 (`reference` / `seed` / `actionable` / `shipped`) |
| `provenance_civilization` | text | 전통 어휘 (`sunni-usuli` / `analytic-western` / `nyaya` 등) |
| `updated_at` | date | 마지막으로 의도적으로 견해를 수정한 시점 (파일 시스템 mtime과 구별됨) |
| `ikhtilāf` | list of objects | 구조화된 학술적 불일치 (`[{school, position}, ...]`) |
| `warrant` | text | 등급 라벨 (Warrant Research 워크스트림이 출시될 때까지 파싱되지만 비활성) |
| `warrant_notes` | text | warrant 등급을 뒷받침하는 자유 텍스트 (또한 비활성) |

### Properties 패널에서 표시되는 방법

각 필드는 타입에 적합한 에디터로 렌더링됩니다:
- 텍스트 필드 → 텍스트 입력
- `domain` → 태그 목록 (Enter로 추가, ×로 제거)
- `updated_at` → 날짜 선택기
- **`ikhtilāf` → 사용자 정의 위젯**: 행당 두 개의 나란한 입력(school + position) + 행당 제거 버튼, 하단에 "학파 추가" 버튼. 위젯은 구조화된 YAML에서 읽고 쓰므로 왕복 시 모든 필드가 보존됩니다.

### `supersedes`는 어떤가?

`supersedes`는 단일 노트의 속성이 아닌 *노트 간의 관계*(이 노트가 이전 것을 대체함)입니다. Constellation은 이것을 YAML 스칼라가 아닌 **타입드 링크**로 처리합니다:

```markdown
This replaces my earlier analysis: [[old-note-id|supersedes]]
```

위키링크의 `|supersedes` 접미사는 이를 `supersedes` 종류의 타입드 링크로 만듭니다 — 별도의 슬레이트 블루-그레이 알약, Backlinks + Outgoing Links 패널에 표시, Living Link Architecture에 참여.

### 이것이 *아닌* 것

새 필드는 **스키마**입니다 — 채울 수 있는 인식된 어휘. CECE는 현재 분류를 위해 이를 소비하지 않습니다. 미래의 MIG(Warrant Research 워크스트림, MIG-023 시간 축)는 `warrant`, `updated_at` 등을 읽는 기능을 출시할 것입니다.

더 깊은 세부 사항과 작업 예제는 도움말 시스템의 **Epistemic Metadata** 항목을 참조하세요.

## 15. 캘린더

**캘린더**는 전체 화면 월 보기로, **왼쪽 독**(캘린더 아이콘)에서 엽니다. 노트나 마감 예정 작업이 있는 날에는 색이 있는 **점**이 표시됩니다. 헤더에는 선택한 캘린더 기준의 월이 표시되며, **보조 캘린더**를 설정해 두었다면 그 아래 부제목에 해당 캘린더의 대응 범위가 함께 표시됩니다(예: 그레고리력의 한 달에 그 히즈리력 범위 "Dhul-Hijjah 1447 – Muharram 1448 AH"가 표시됨).

**날짜 클릭하기.** 각 날짜 칸은 상호작용이 가능합니다:

- **빈 공간(또는 날짜 숫자)을 클릭** → 그날의 **데일리 노트**를 열거나 만듭니다. 이미 데일리 노트가 있는 날짜를 클릭하면 그냥 **열기**만 하며, 절대 중복을 만들지 않습니다.
- **점을 클릭** → 해당 항목을 엽니다. **금색** 점은 데일리 노트, **보라색** 점은 그날 편집된 다른 노트, **빨간색** 점은 그날 마감인 작업입니다. (색상은 스타일 세터 → 캘린더에서 테마로 바꿀 수 있습니다.) 한 날에 여러 노트나 작업이 있으면, 점을 클릭하면 골라서 열 수 있는 작은 **목록**이 나타납니다.
- **작업 점을 클릭** → 노트를 열되 **그 작업의 줄로 스크롤된 상태**로 바로 편집할 수 있게 합니다. 작업 목록에서는 캘린더에서 바로 **작업의 체크박스를 체크해 완료** 처리할 수도 있으며, 완료된 작업은 즉시 사라집니다. 자체적으로 `📅 YYYY-MM-DD`를 가진 작업만 캘린더에 나타납니다(그 날짜가 작업을 특정 날에 배치합니다).

**문화권 캘린더(여덟 가지).** **설정 → 캘린더**에서 **캘린더 체계**를 설정할 수 있습니다 — **그레고리력, 히즈리력(이슬람력), 태양 히즈리력(페르시아력), 히브리력, 인도력(사카력), 불기, 중국력, 또는 한국력** — 그러면 월 격자 전체가 그 체계로 전환되어, 각 칸에 선택한 캘린더 날짜(크게)와 그레고리력 날짜(작게)를 모두 표시하고 달의 위상도 함께 보여 줍니다. 각 월 헤더에는 그 달의 **이름, 괄호 안의 번호, 그리고 연도**가 표시됩니다 — 번호는 월 순서가 익숙하지 않은 캘린더에서 도움이 됩니다. **중국력과 한국력**은 *태음태양력*이라 가끔 **윤달**(闰六月 / 윤6월)을 끼워 넣는데, 캘린더는 이를 별도의 페이지로 보여 주므로 탐색 시 건너뛰거나 두 번 나오는 일이 없습니다. 히즈리력은 정밀한 천문 엔진을 사용하며, 신성한 달이 강조되고 이슬람 행사가 표시됩니다. **주 시작 요일**(일요일/월요일)을 선택하고 **주 번호 열**을 켜고 끌 수도 있습니다.

**히즈리력 옵션.** **설정 → 캘린더 → "히즈리력(이슬람력)"** 아래에는 추가 컨트롤이 두 가지 있습니다:

- **계산 방식** — 실제 초승달을 따르는 **천문 방식(삭, Lunar Conjunction)**(가장 정확하며 기본값), 또는 고전적 산술 주기인 **표 방식(al-Tawfīqāt al-Ilhāmiyyah, 영감받은 조정표)**.
- **월 보정** — **현지의 달 관측**에 맞추기 위해 히즈리력 한 달의 시작을 ±1일 또는 ±2일 조정합니다. 히즈리력 연도와 월을 고르고, 오프셋을 선택한 뒤 **설정**을 클릭하면, 그 보정이 해당 월과 그 이후 모든 월에 적용됩니다. 적용한 보정은 목록으로 표시되며(각각 제거 가능), **모두 지우기** 버튼이 있습니다.

두 설정(그리고 보정 내용)은 **유니버스와 함께** 저장되므로 여러 기기를 넘나들며 따라다닙니다.

**중국력·한국력 표시 옵션.** 한국은 중국 음력을 사용하므로 두 캘린더의 날짜는 동일합니다 — 둘을 구분하는 것은 문자와 연도입니다. 둘 중 하나가 주 캘린더나 보조 캘린더일 때, **설정 → 캘린더**에 추가 컨트롤이 두 가지 나타납니다: **연도 표시**(중국력: 육십갑자 丙午年, 평이한 연도, 또는 둘 다 / 한국력: **단기** 4359, 연도, 또는 육십갑자 병오년)와 **월 이름** — *고유 문자*(五月 / 5월) 또는 *발음 표기*, 즉 그 달의 발음을 사용자 자신의 언어로 적은 것(한국어 "Wǔyuè / Owol"; 아랍어 "وُو-يوي / أوه-وُل").

**캘린더 꾸미기.** **스타일 세터**(왼쪽 독, 또는 **설정 → 스타일 세터**)를 열고 **캘린더** 표면을 선택하면 모든 부분을 다시 꾸밀 수 있습니다 — 각 요소(날짜 숫자, 상호 참조 날짜, 월 알약, 요일 헤더, 주 번호, 달 글리프, 오늘 강조, 격자선, 그리고 노트/작업/행사 점)마다 자체 **색상과 글자 크기**를 가지며, 캘린더 **글꼴**도 설정합니다. 편집하는 동안 전체 크기의 실시간 미리보기가 갱신되며, **유지**를 클릭하면 적용됩니다.

> **데일리 노트 파일 이름은 표시되는 캘린더와 관계없이 항상 그레고리력**(`YYYY-MM-DD`)을 유지합니다 — 그래야 파일이 이식성을 유지하고 올바르게 정렬됩니다. 문화권 날짜는 캘린더에 표시되며(노트의 프런트매터에 기록할 수도 있습니다).

캘린더는 데일리 노트를 온전히 지원합니다: 아무 날이나 클릭해 열거나, **"데일리 노트"** 명령(명령 팔레트)을 실행해 오늘로 바로 이동하세요.

**노트에 문화권 날짜 기록하기.** 두 가지 선택형 도구가 노트의 **속성**에 문화권 날짜를 기록합니다(파일 이름은 항상 그레고리력 `YYYY-MM-DD`를 유지합니다):

- **데일리 노트 히즈리 스탬프** — *설정 → 캘린더 → "데일리 노트에 히즈리 날짜 스탬프 찍기."* 켜면(히즈리력이 **주 캘린더나 보조 캘린더**일 때만 사용 가능), 모든 **새** 데일리 노트에 `hijri:` 줄이 들어갑니다(예: `hijri: 1448-01-06`). 이미 가지고 있는 노트는 절대 건드리지 않습니다.
- **노트 속성의 "+ Hijri"** — 아무 노트의 **속성**을 열고 날짜 위에 마우스를 올리면 작은 **"+ Hijri"** 버튼이 나타납니다(여기에 더해 "+ Jalali", "+ Hebrew" 등 — **선택한 비그레고리력 캘린더마다 버튼 하나씩**). 클릭하면 Constellation이 노트의 그레고리력 날짜를 읽어 대응 값을 추가합니다(예: `jalali: 1405-03-30`). 한국력 버튼은 **단기** 연도를 적으며, 중국력/한국력의 **윤달**은 `L`로 표시됩니다(예: `chinese: 2025-06L-17`). 노트에 날짜 속성이 없으면 파일의 생성 날짜를 사용합니다.

## 16. 렌즈와 Constellation Base

**렌즈**는 관심 있는 속성과 함께 필터링되고 정렬된 노트 목록을 표시하는 저장된 쿼리입니다. Constellation에는 두 가지 방식이 있습니다:

### Constellation Base — 임베디드 렌즈 블록

` ```base ` 코드 블록을 사용하여 모든 Markdown 노트의 본문에 렌즈를 직접 임베드할 수 있습니다:

````markdown
```base
schema: 1
view: list
dimensions: [note.name, note.created_at]
sort: [note.created_at, desc]
limit: 20
```
````

노트를 볼 때, 코드 블록은 일치하는 노트를 보여주는 대화형 테이블로 대체됩니다. 라이브 프리뷰에서는 **렌즈** 칩을 클릭하여 블록을 편집할 수 있습니다.

**v1에서 사용 가능한 차원:** `note.name`, `note.path`, `note.created_at`, `note.headline`.

**페더레이션:** 기본적으로 렌즈 블록은 활성 우주와 연결된 각 cUniverse에서 읽습니다. 활성 우주로 제한하려면 YAML에서 `federation: active`를 설정하세요.

### 다섯 가지 행위 (Five Acts) — 내장 렌즈

### Style Settings

인터페이스의 모든 가시적 요소에 대한 세밀한 사용자 정의를 위한 전용 탭으로, 활성 테마에 실시간으로 적용됩니다.

- **색상** — 배경, 표면, 텍스트(일반/음소거/희미), 강조, 테두리, 상태 색상
- **타이포그래피** — 인터페이스/노트/코드 글꼴 크기, H1–H6 크기, 제목 굵기, 줄 높이, 단락 간격
- **레이아웃 및 모양** — 작은/중간/큰 모서리 반경, 테두리 너비, 그림자, 편집기 가독성 행 길이, 측면 여백
- **구성 요소** — 리본 도크, 사이드바 액션 툴바, 레이아웃 바(창 토글), 상단 바/탭 스트립, 상태 바, 오른쪽 사이드바(인스펙터), 파일 탐색기(우주 노트, 자식 우주, 라이브러리, 폴더, 노트), 버튼, 태그, 콜아웃 — 각각 독립적인 크기, 반경, 색상, 해당되는 경우 활성 상태 스타일
- **편집기** — 링크 색상/호버/장식, 인라인 코드 색상/배경/반경, 블록 인용 바 너비/색상, 커서 색상, 선택 배경

**가져오기/내보내기** — 탭 상단의 툴바:
- 클립보드에서 붙여넣기(원클릭)
- 가져오기/붙여넣기(병합 또는 교체 포함 텍스트 영역)
- 파일에서(.json)
- 복사(현재 값을 클립보드로)
- 내보내기(.json)

형식은 Obsidian의 Style Settings 플러그인과 정확히 일치하므로 Obsidian과 Constellation 간에 설정을 공유할 수 있습니다.

변경 사항은 활성 테마에 자동 저장됩니다; 내장 테마를 편집하는 경우, 원본을 수정하지 않고 변경 사항이 지속되도록 사용자 정의 테마에 자동 복제됩니다.

### 스타일 세터(Style Setter)

**스타일 세터**는 전체 화면 디자인 스튜디오입니다 — **설정 → 외관 → "✦ Open Style Setter"**에서 엽니다. 가운데에 실제 인터페이스가 표시되고, 어떤 부분(사이드바, 노트 제목, 제목, 링크, 노트 페이지)이든 클릭하면 해당 요소의 컨트롤이 오른쪽에 나타나며 미리보기가 즉시 업데이트됩니다. 테마 카드(Midnight / Daylight / Chocolate / Nord)는 전체 모양을 시드하고 — 디자인하는 동안 스튜디오 자체가 그 모양을 입습니다 — *서피스* 목록은 편집기뿐 아니라 앱 전반에 걸쳐 모양을 미리 봅니다. **"Apply to app"**은 강조 색상, 배경, 텍스트 색상 및 폰트를 실제 Constellation에 적용합니다; **"Esc"** 또는 **"✕"**는 세터만 닫고 설정은 닫지 않습니다. 적용은 현재로서는 세션 실시간 미리보기입니다 — 모양을 영구적인 이름이 지정된 Style로 저장하는 기능(재사용 및 이름 변경이 가능한 색상 스와치와 내보내기/가져오기 포함)은 곧 제공될 예정입니다.

### 아랍어 재정의

Universe별 패널로, 아랍어 엔진이 특정 표면형을 어떻게 해석할지 고정할 수 있습니다——사용자 자신의 신조어, 지역 이름, 분야 특유의 외래어, 또는 엔진의 자동 해석에 동의하지 않는 경우입니다. 각 재정의는 생성 FST, 캐스케이드, 휴리스틱 폴백을 모두 이깁니다. 재정의를 추가하거나 제거하면 해당 표면형을 포함하는 노트에 한정된 표적 재색인이 일어납니다——전체 재구축은 없습니다. 단계별 안내는 §19(「RTL 및 아랍어 지원」)를 참조하십시오.

## 19. RTL 및 아랍어 지원

Constellation은 아랍어, 히브리어, 페르시아어, 우르두어 및 기타 RTL 스크립트를 완벽하게 지원합니다:

- **자동 감지**: 노트 방향이 콘텐츠에서 자동으로 감지됩니다
- **인터페이스**: 아랍어/히브리어 언어 선택 시 완전한 RTL 인터페이스
- **에디터**: 올바른 커서 이동과 선택으로 RTL 텍스트 편집
- **스타 뷰**: 아랍어 라벨이 적절한 글꼴 폴백으로 오른쪽에서 왼쪽으로 렌더링
- **범례**: 콘텐츠 언어에 따라 점/텍스트 순서가 반전
- **스크립트 글꼴**: 설정에서 아랍어, 히브리어, CJK 글꼴을 개별적으로 설정 가능

### 아랍어 설정

1. **설정 > 일반 > 언어**에서 아랍어를 선택
2. 필요에 따라 **설정 > 일반 > 스크립트 글꼴**에서 전용 아랍어 글꼴 설정
3. 아랍어 콘텐츠가 포함된 노트는 자동으로 RTL로 렌더링됩니다

### 아랍어 엔진 재정의

Constellation의 아랍어 엔진은 5층 형태 분석기로, 모든 검색·링크·색인 항목 아래에서 동작합니다. 어근·패턴·고유명사·외래어·음운 복원을 이해합니다——그래서 كاتب에 대한 질의가 كتبنا와 كتاب을 찾고, وائل은 ائل로 훼손되지 않고 이름 그대로 보존됩니다.

설정의 **아랍어 재정의** 패널은 사용자 자신의 용어를 엔진에 가르치는 자리입니다. 각 재정의는 주권적인 답입니다——생성 FST, 캐스케이드, 휴리스틱 폴백을 이깁니다.

**재정의를 사용해야 할 때:**
- 엔진이 모르는 인명·지역 지명·분야 특유의 용어
- 사용자의 Universe에만 있는 신조어나 약어
- 특정 철자를 유지하고 싶은 외래어
- 엔진의 자동 분석이 사용자의 읽기와 어긋나는 모든 경우

**단계별 안내:**

1. **설정**을 엽니다(기어 아이콘 또는 `Ctrl + ,` / `Cmd + ,`)그리고 사이드바에서 **아랍어 재정의**를 선택합니다.
2. **재정의 추가**를 클릭합니다.
3. 입력합니다:
   - **표면형** — 사용자가 입력하는 그대로의 아랍어 단어
   - **표제어** — 엔진이 반환해야 할 기본형
   - **어근**(선택) — 단어에 고전 어근이 있는 경우 3 또는 4개의 자음
   - **패턴**(선택) — 예: `فاعل`
   - **품사** — 고유명사 / 명사 / 형용사 / 부사 / 동사 / 조사 / 외래 / 미정
   - **메모**(선택) — 자신을 위한 한 줄의 맥락
4. **저장**을 클릭합니다. 해당 표면형을 포함한 모든 노트가 재토큰화되는 동안 패널은 **재색인 중…**을 표시하고, 완료되면 **노트 N개 재색인됨**을 보여 줍니다.
5. 재정의를 제거하려면 그 행의 **×**를 클릭합니다 —— 같은 재색인 스윕이 역방향으로 실행됩니다.

재정의는 Universe별로 `<universe>/.constellation/arabic-overrides.json`에 저장됩니다 —— 평문, 알파벳 순 정렬, 원자적 기록입니다. 파일을 버전 관리에 넣거나 여러 기기 간에 공유할 수 있습니다.

## 21. 지식 맵

지식 맵은 전체 지식 유니버스의 구조, 밀도, 성숙도를 보여주는 방사형 선버스트 시각화입니다.

### 맵 열기

- **독 버튼**: 왼쪽 독에서 지식 맵 아이콘을 클릭
- **명령 팔레트**: `Ctrl+P` 후 "Constellation Map" 입력

### 표시 내용

- **중앙**: 유니버스 이름과 전체 노트 및 단어 수
- **첫 번째 링**: 라이브러리 (각각 라이브러리 색상으로 표시). 하위 유니버스가 있으면 여기에도 표시됩니다.
- **깊은 링**: 각 라이브러리 내 폴더와 하위 폴더
- **가장 바깥 세그먼트**: 개별 노트

### 색상 모드

드롭다운으로 세 가지 모드 전환:
- **성숙도**: 씨앗 (회색) → 묘목 (연두) → 상록 (초록) → 정전 (금색) → 시듦
- **계층**: L1 (파랑) → L8 (빨강) — 지식 복잡도 표시
- **라이브러리**: 모든 세그먼트가 상위 라이브러리 색상을 상속

### 드릴다운 탐색

폴더 세그먼트를 클릭하여 확대합니다. 브레드크럼 경로가 현재 위치를 보여줍니다. 브레드크럼 항목을 클릭하여 돌아가거나 Escape를 누릅니다. 노트 세그먼트를 클릭하면 편집기에서 열립니다.

### 맵으로 돌아가기

맵에서 노트를 연 후, 탭 바에 "맵으로 돌아가기" 버튼이 나타납니다. 클릭하면 이전 위치로 정확히 돌아갑니다 — 드릴다운 레벨이 유지됩니다.

## 22. 인지 엔진

> "데이터의 양은 중요하지 않습니다. 얼마나 많은 소스를 저장하느냐가 아니라, 그것들로부터 지식을 어떻게 형성하고 하나의 의미 있는 인식으로 연결하느냐가 중요합니다."

인지 엔진은 아홉 가지 통합 도구로 구성됩니다: 유형 링크, 지식 계층, 성숙 주기, 긴장 감지기, 출처 체인, 외재화 엔진, 리뷰 펄스, 트레일, 멀티 렌즈 뷰.

### 17.1 유형 링크

#### 무엇인가?

유형 링크는 두 노트 간의 관계 유형을 기술하는 위키링크입니다. 단순히 `[[노트]]`라고 쓰는 대신 `[[노트|관계유형]]`이라고 작성하여 연결의 본질을 표현합니다 — 파생된 것인가? 모순되는 것인가? 확장하는 것인가?

#### 왜 중요한가?

일반 링크는 "연결이 있다"고만 알려줄 뿐 어떤 연결인지는 말해주지 않습니다. 유형 링크는 노트 네트워크를 참조의 더미에서 사고 구조, 의존성, 추론을 시각화하는 진정한 지식 지도로 변환합니다.

#### 사용 방법

1. 편집기에서 노트를 엽니다
2. 관계 유형이 포함된 위키링크를 작성합니다: `[[대상 노트|derives-from]]`
3. 지원되는 유형: `derives-from`(파생), `supports`(지지), `contradicts`(모순), `extends`(확장), `exemplifies`(예시), `questions`(의문)
4. 오른쪽 사이드바의 노트 속성에서도 유형을 추가할 수 있습니다

#### 어디에서 볼 수 있나?

- **스타 뷰(GraphMind)**: 노드 간 색상과 라벨이 있는 선으로 표시
- **오른쪽 사이드바**: "백링크" 탭에서 각 링크의 유형 표시
- **출처 탭**: 지식 계보 트리 구축에 사용

---

### 17.2 지식 계층

#### 무엇인가?

인지 엔진은 각 노트를 8개의 지식 계층 중 하나로 자동 분류합니다: 스냅샷, 로그, 주제, 지도, 프레임워크, 원칙, 신념, 산출물. 분류는 노트의 구조, 내용, 링크 수를 기반으로 합니다.

#### 왜 중요한가?

각 노트의 유형을 아는 것은 라이브러리의 지식 균형을 드러냅니다. 노트 대부분이 일시적인 스냅샷인가, 아니면 원칙과 프레임워크로 발전했는가? 콘텐츠 본질에 대한 이 인식은 단순한 정보 수집이 아닌 진정한 지식 구축을 향한 첫걸음입니다.

#### 사용 방법

1. 분류는 자동으로 이루어집니다 — 별도의 조작이 필요 없습니다
2. 자동 분류를 재정의하려면 프론트매터에 `stratum` 속성을 추가합니다:
   ```yaml
   ---
   stratum: framework
   ---
   ```
3. 사용 가능한 값: `snapshot`, `log`, `topic`, `map`, `framework`, `principle`, `conviction`, `artifact`

#### 어디에서 볼 수 있나?

- **오른쪽 사이드바**: 노트 속성의 "계층" 항목
- **스타 뷰**: 계층에 따른 노드 색상 구분
- **설정 > 인지 엔진**: 자동 분류 활성화/비활성화

---

### 17.3 성숙 주기

#### 무엇인가?

엔진은 각 노트의 성숙도를 4단계로 추적합니다: **씨앗** → **묘목** → **상록** → **정전**. 모든 노트는 씨앗으로 시작하여 콘텐츠, 링크, 검토가 추가되면서 점차 성장합니다.

#### 왜 중요한가?

성숙도는 원시적 아이디어와 다듬어진 지식을 구별합니다. 오늘의 씨앗은 충분한 관심을 기울이면 내일의 레퍼런스가 될 수 있습니다. 성숙도 추적은 더 많은 발전과 관심이 필요한 노트를 식별하는 데 도움을 줍니다.

#### 사용 방법

1. 성숙도는 다음을 기반으로 자동 변경됩니다: 단어 수, 수신/발신 링크 수, 마지막 수정 날짜
2. 성숙도를 수동으로 설정하려면 프론트매터에 `maturity` 속성을 추가합니다:
   ```yaml
   ---
   maturity: evergreen
   ---
   ```
3. 사용 가능한 값: `seed`(씨앗), `sapling`(묘목), `evergreen`(상록), `canonical`(정전)

#### 어디에서 볼 수 있나?

- **오른쪽 사이드바**: 제목 옆 아이콘으로 현재 성숙 단계 표시
- **스타 뷰**: 노드 크기로 표현 — 성숙한 노트일수록 노드가 큼
- **설정 > 인지 엔진**: 성숙도 추적 활성화/비활성화

---

### 17.4 긴장 감지기

#### 무엇인가?

긴장 감지기는 연결된 노트를 검사하여 두 개 이상의 노트 간에 주장이나 결론이 상충할 때 경고합니다. `contradicts` 유형의 링크 분석과 노트 간 주제적 유사성에 기반하여 작동합니다.

#### 왜 중요한가?

긴장은 반드시 오류가 아닙니다 — 더 깊은 사고로의 초대입니다. 라이브러리에서 두 아이디어가 서로 모순될 때, 이해가 진화했거나 탐구할 가치가 있는 복잡성이 존재한다는 의미입니다. 긴장 감지는 무의식적으로 모순된 기반 위에 지식을 쌓는 것을 방지합니다.

#### 사용 방법

1. 상충하는 노트 간에 `contradicts` 유형 링크를 추가합니다: `[[다른 노트|contradicts]]`
2. 엔진은 콘텐츠 분석을 통해 암묵적 긴장도 감지합니다
3. 사이드바에서 감지된 긴장 목록을 확인합니다

#### 어디에서 볼 수 있나?

- **오른쪽 사이드바**: 모순이 감지되었을 때 "긴장" 탭
- **스타 뷰**: 상충하는 노드 간의 빨간 점선
- **알림 패널**: 새로운 긴장 감지 시 알림

---

### 17.5 출처 체인

#### 무엇인가?

출처 체인은 각 아이디어의 기원을 추적합니다 — 어디서 왔으며 무엇에서 파생되었는지. `[[노트|derives-from]]` 링크를 사용하여 원본 소스에서 현재 표현까지의 지식 발전 경로를 보여주는 계보 트리를 구축합니다.

#### 왜 중요한가?

아이디어의 출처를 아는 것은 수신된 지식(책, 기사, 강의에서)과 발견된 지식(자신의 결론과 성찰)을 구별합니다. 지식의 원천에 대한 이 인식은 아이디어의 신뢰성을 평가하고 시간이 지남에 따라 사고가 어떻게 형성되었는지 이해하는 데 도움을 줍니다.

#### 사용 방법

1. 소스에서 파생된 노트를 만들 때 링크를 추가합니다: `[[원본 소스|derives-from]]`
2. 다단계 체인 구축이 가능합니다: 노트 ← 파생 ← 파생 ← 원본 소스
3. 프론트매터에 `source-type: received`를 추가하여 외부 소스를 분류합니다

#### 어디에서 볼 수 있나?

- **오른쪽 사이드바**: "출처" 탭에서 전체 계보 트리 표시
- **스타 뷰**: 링크의 화살표 방향 (소스에서 파생으로)
- **노트 속성**: 출처 체인에 따른 "수신됨" 또는 "발견됨" 분류

### 17.6 외재화 엔진

#### 무엇인가?

노트가 원시 캡처에서 결정화된 통찰력으로 성숙하는 과정을 추적하는 점진적 형식화 파이프라인입니다. 각 노트에는 네 가지 단계 중 하나를 할당할 수 있습니다:

| 단계 | 아이콘 | 의미 |
|------|--------|------|
| 순간 | 🌱 | 빠른 캡처, 스쳐가는 생각 |
| 문헌 | 📖 | 출처에서 자신의 말로 다시 작성 |
| 영구 | 🔗 | 원자적 아이디어, 하나의 개념, 그래프에 연결 |
| 종합 | ✨ | 여러 영구 노트를 결합한 독창적 통찰 |

#### 왜 중요한가?

대부분의 앱은 모든 노트를 동일하게 취급합니다. 외재화 엔진은 그 차이를 시각적으로 보여줍니다 — 라이브러리에서 원시 캡처와 진정한 이해의 비율을 한눈에 볼 수 있습니다.

#### 사용 방법

1. 브레드크럼 바(편집기 위)에서 단계 드롭다운을 사용하여 단계를 선택합니다.
2. 또는 속성을 확장하고 거기서 단계 드롭다운을 사용합니다. 둘 다 파일 트리와 즉시 동기화됩니다.
3. 노트를 승격하려면 드롭다운을 한 단계에서 다음 단계로 변경합니다. 집중 모드에서는 하단의 "영구로 승격"을 클릭합니다.
4. 단계를 제거하려면 드롭다운에서 "— 단계 —"를 선택합니다.

#### 어디에서 볼 수 있나?

- **브레드크럼 바**: 이모지 + 단계 이름이 있는 드롭다운
- **속성 패널**: `stage` 속성이 존재할 때 드롭다운
- **파일 트리**: 노트 이름 옆에 이모지 아이콘
- **집중 모드 푸터**: "영구로 승격" 버튼

### 17.7 리뷰 펄스

#### 무엇인가?

리뷰 펄스는 확대되는 간격으로 노트를 다시 주의에 가져오는 간격 재표면 시스템입니다: 마지막 리뷰 후 1일, 3일, 7일, 14일, 30일. `#assumption`이나 `#model` 태그가 있는 노트를 멘탈 모델 체크포인트로 모니터링하고, 캡처했지만 한 번도 재방문하지 않은 노트를 위한 "리뷰한 적 없음" 대기열을 유지합니다.

#### 왜 중요한가?

지식은 재방문 없이 쇠퇴합니다. 오늘 노트를 작성하면 3주 후에는 존재 자체를 잊어버립니다. 간격 반복은 인지 과학에서 이 쇠퇴에 대항하는 가장 확립된 기법입니다. 리뷰 펄스는 이 원리를 실제 노트에 적용합니다.

#### 사용 방법

1. 왼쪽 사이드바에서 **리뷰 펄스** 탭을 클릭합니다. 세 개의 섹션이 보입니다: 리뷰 예정, 멘탈 모델 체크포인트 (`#assumption` / `#model`), 리뷰한 적 없음.
2. 노트를 클릭하여 열고 읽습니다.
3. 세 가지 작업 중 하나를 선택합니다:
   - **리뷰 완료** (체크 표시) — 다음 간격으로 다음 리뷰를 예약 (1 → 3 → 7 → 14 → 30일).
   - **7일 스누즈** (눈 아이콘) — 간격을 진행하지 않고 노트를 7일 연기.
   - **해제** (아카이브 아이콘) — 노트를 리뷰 대기열에서 영구 제거.
4. 명령 팔레트를 열고 "Review due notes"를 입력합니다.

#### 어디에서 볼 수 있나?

- **왼쪽 사이드바**: 대기 중인 노트 수를 보여주는 배지가 있는 리뷰 펄스 탭
- **명령 팔레트**: 빠른 접근을 위한 "Review due notes" 명령

### 17.8 트레일

#### 무엇인가?

트레일은 노트의 이름이 있는 순서화된 시퀀스입니다 — 책의 장이나 지식의 가이드 투어 정류장과 같습니다. 노트의 frontmatter에 `trail: true`를 추가하고, 노트 본문에 위키링크를 순서대로 나열하여 정의합니다.

#### 왜 중요한가?

지식이 항상 웹인 것은 아닙니다. 때로는 경로입니다 — 학습 시퀀스, 논증 진행, 서사. 트레일은 이 순서를 명시적으로 캡처하여 비선형 라이브러리에 선형 차원을 추가합니다.

#### 사용 방법

1. frontmatter에 `trail: true`가 있는 새 노트를 만듭니다.
2. 노트 본문에 원하는 순서대로 위키링크를 나열합니다.
3. 트레일에 속한 노트를 열면, 브레드크럼 바에 트레일 이름과 위치가 표시됩니다 (예: "내 트레일 2/5"). 화살표 버튼으로 이전 및 다음 노트로 이동합니다.
4. 명령 팔레트를 열고 "Open Trail"을 입력하면 모든 트레일이 표시됩니다.

#### 어디에서 볼 수 있나?

- **브레드크럼 바**: 이름, 위치, 탐색 화살표가 있는 트레일 표시기
- **명령 팔레트**: 모든 트레일을 나열하는 "Open Trail" 명령

### 17.9 멀티 렌즈 뷰

#### 무엇인가?

멀티 렌즈 뷰는 폴더 구조를 변경하거나 노트를 복제하지 않고 다양한 분류 체계로 라이브러리를 볼 수 있게 합니다. "렌즈"는 속성이나 태그를 기반으로 노트를 재구성하는 가상 그룹화입니다. 기본 렌즈: "단계별" (일시적/문헌/영구/통합) 및 "주제별" (태그별 그룹화). 설정에서 사용자 정의 렌즈를 만들 수 있습니다.

#### 왜 중요한가?

폴더 구조는 단일 계층을 강제하지만, 지식은 하나의 트리에 맞지 않습니다. 멀티 렌즈 뷰는 파일을 이동하지 않고 다양한 관점 간에 전환할 수 있게 합니다. 같은 노트를 다른 조직적 렌즈로 봅니다.

#### 사용 방법

1. 사이드바에서 파일 트리 상단의 **렌즈 드롭다운**을 찾습니다 (기본값 "폴더").
2. 렌즈를 선택합니다: "단계별", "주제별" 또는 사용자 정의 렌즈. 사이드바가 즉시 재구성됩니다.
3. 기본 파일 트리로 돌아가려면 "폴더"를 선택합니다.
4. 사용자 정의 렌즈를 만들려면: **설정 > 지식 관리**를 열고, **렌즈 만들기**를 클릭하고, 이름을 지정하고 그룹화할 frontmatter 속성을 선택합니다.
5. 또는 명령 팔레트를 사용합니다: "Create Lens"를 입력합니다.

#### 어디에서 볼 수 있나?

- **사이드바 드롭다운**: 파일 트리 상단의 렌즈 선택기
- **설정 > 지식 관리**: 사용자 정의 렌즈 만들기, 편집, 삭제
- **명령 팔레트**: "Create Lens" 명령

### 인지 엔진 설정

인지 엔진의 모든 도구는 **설정 > 인지 엔진**에서 구성할 수 있습니다:

- **계층 분류** — 자동 분류 활성화 또는 비활성화
- **성숙도 추적** — 성숙 수명 주기 추적 활성화 또는 비활성화
- **유형 링크** — 링크 감지 감도 임계값 조정 (0.0 – 1.0)
- **긴장 감지기** — 자동 긴장 감지 활성화 또는 비활성화
- **수동 재정의** — 프론트매터에 `stratum` 및 `maturity` 속성을 추가하여 자동 분류 재정의

## 23. 추천 연결

Constellation은 지식을 *형성하기* 위한 도구이며, 지식이란 곧 연결입니다. **추천 연결**은 지금 보고 있는 노트와 가장 관련이 깊은 노트 — 마땅히 연결되어야 하지만 아직 연결되지 않은 친척 — 를 이미 라이브러리 안에서 찾아 주고, 그중 어느 것이든 단 한 번의 클릭으로 **유형이 지정된 링크**로 바꿔 줍니다. "이런 노트는 어때요"의 사고(思考) 버전인 셈입니다.

**모든 추천은 유형을 갖습니다.** 추천을 받아들이면 Constellation은 두 노트가 *어떻게* 관련되는지 묻습니다 — 지지, 모순, 예시, 파생 등, 아니면 그냥 **연관**. 유형이 지정된 링크는 나중에 읽고, 검색하고, 따져 볼 수 있는 하나의 추론입니다. 이 기능은 링크를 무더기로 추가하지 않으며, 유형 없는 링크를 조용히 추가하는 일도 없습니다. (**지식 형성**과 **속성** 참고.)

**어떻게 찾아내나.** 후보는 **오직 사용자 본인의 라이브러리**에서만 나오며, Constellation의 실시간 검색 인덱스를 기준으로 가장 *변별력 있는* 공통 어휘 — 흔한 단어가 아니라 드물고 핵심을 짚는 단어 — 에 따라 순위가 매겨집니다. 각 추천에는 그것이 떠오른 이유를 설명해 주는 **공통 단어**가 표시되므로, 정체를 알 수 없는 추측을 받아들일 일이 없습니다.

**다섯 곳, 하나의 목록.** 같은 추천 목록이 **다시 보기**(🕐, *외톨이*나 *취약*으로 표시한 노트), **백링크 탭**(오른쪽 사이드바), **360° 인스펙터**, **건강 탭**, 그리고 **스타 뷰**(🌌 — 아무 별이나 우클릭 → **연결 제안…**)에 나타납니다.

**들어오는 연결 대 나가는 연결 — 그리고 왜 직접 고르지 않는가.** 진단용 화면(**360° 인스펙터**와 **건강 탭**)은 **들어오는** 연결을 추천합니다 — *어떤 노트가 **이곳을** 가리켜야 하는가*. 일반용 화면(**백링크 탭**과 **스타 뷰**)은 **나가는** 연결을 추천합니다 — *이 노트가 **무엇을** 가리켜야 하는가*. 방향은 화면이 그 역할에 맞게 정하고, 노트와 유형은 사용자가 정합니다. (앞으로의 업데이트에서는 방향을 직접 전환할 수 있게 됩니다.)

**사용 방법.** **추천 연결** 제목 아래에 관련 노트가 가장 가까운 것부터 순위대로 나열되며, 각 노트마다 공통 단어가 함께 표시됩니다. 후보의 **연결** 버튼을 클릭 → 작은 **"어떻게 관련되나요?"** 메뉴에서 관계 유형을 고르면 → 유형 링크가 **즉시** 생성되고 그 추천은 목록에서 사라집니다. 그 링크는 이제 노트의 **속성** 안에 자리 잡고, 노트의 백링크/나가는 링크와 그래프 전반에 나타납니다. 정말로 맞는 것이 없다면 그냥 두거나, 다시 보기에서 노트를 의도적인 **독립 노트**로 표시하세요. 추천 연결은 제안할 뿐, 결정은 사용자의 몫입니다.

**로컬, 비공개, 비차단.** 추천은 요청할 때마다 오직 사용자의 라이브러리에서만 계산되며 — 아무것도 기기를 떠나지 않습니다 — 추천을 모으는 동안에도 타이핑이 멈추는 일이 없습니다(작업 중에는 짧은 "관련 노트를 찾는 중…" 표시가 보입니다). 추천, 공통 단어 힌트, 관계 유형은 모두 사용자가 선택한 언어로 표시되며, 오른쪽에서 왼쪽으로 쓰는 문자에서는 올바르게 좌우 대칭으로 바뀝니다.
