# Source Review

> **번역 참고:** 이 도움말 항목은 `help.uConstellation.World/Source Review/Source Review.md`에 있는 정식 영어판에서 AI가 생성한 번역입니다. 원어민 검토는 대기 중입니다. 수정 사항은 프로젝트 저장소를 통해 제출해 주세요.

*(Constellation 인식적 콘텐츠 엔진 — CECE)*

Source Review 패널은 Constellation이 **Constellation 인식적 콘텐츠 엔진**(CECE)에서 생성된 분류를 검토해 달라고 요청하는 곳입니다. 큐의 각 카드에는 노트와 해당 노트가 당신의 지식 분류 체계에 어떻게 부합하는지에 대한 엔진의 해석이 표시됩니다. "수락", "편집", "거부"하거나 "형제 모호성 해소" 칩을 선택하면 — 시간이 지남에 따라 엔진은 당신의 라이브러리의 형태를 학습합니다.

이 항목은 Source Review 카드의 모든 부분, 색이 있는 점의 의미, 엔진을 신뢰해야 할 시점, 그리고 끝없이 스크롤하지 않고 수백 개의 카드를 탐색하는 방법을 설명합니다.

> **두 곳, 하나의 패널.** 여기서 설명하는 카드는 오른쪽 사이드바의 **Source Review** 탭과 전체 페이지 **분류기** 뷰(왼쪽 독의 쌓인 카드 아이콘) 양쪽에 모두 나타납니다. 그것들은 동일한 패널이자 동일한 엔진입니다. 분류기는 큐에 창 전체와 노트 선택기, 그리고 "모든 요약 생성" 버튼을 부여합니다 — **분류기** 항목을 참조하세요. 아래의 모든 내용은 어느 곳에 있는 카드에든 적용됩니다.

---

## CECE가 실제로 하는 일

노트를 분류할 때(우클릭 → "Source와 콘텐츠 유형 제안" 또는 설정 → 스캔 실행 버튼을 통해) CECE는 노트에 대해 **6개의 독립적인 분류기**를 실행합니다. 각 분류기는 자체 렌즈(frontmatter, 인용, 어간, 연결된 노트, 유사한 노트, AI 판단)를 통해 노트를 읽고 두 가지 질문에 대해 투표합니다:

- **Source(수평축)**: 이 지식은 *어디에서* 왔는가? 예: 증언(누군가 내게 말했다), 지각(내가 보았다), 추론(내가 도출했다), 계시(성스러운 텍스트), 그 외 8가지.
- **콘텐츠 유형(수직축)**: 이것은 *어떤 종류*의 지식인가? 예: 인식적 상태(의심 / 확신 / 믿음), 의미적 내용(개념 / 명제 / 사실 / 이론), 감각 입력, 상징적 실체, 고차 구성물(세계관 / 교리).

두 축은 **독립적**입니다. "나는 달 착륙을 의심한다"라는 노트는 source 축에서 증언(누군가 보고했다)이고 콘텐츠 유형 축에서 인식적 상태/의심(그것에 대한 사용자의 입장)입니다.

분류기들이 투표한 후, **종합 레이어**가 그들의 투표를 축당 단일 분류로 결합하며, 세 가지 신뢰도 체제 중 하나로 표시됩니다:

- **만장일치** — 발언한 모든 분류기가 동의함
- **강한 다수** — 대부분이 동의했고, 한 명이 반대함(카드에 반대자의 이름이 표시됨)
- **의견 분산** — 명확한 다수가 없음; 엔진은 "할당을 거부"하고 *당신*에게 선택하도록 요청함

모든 것은 **당신의 기기에서** 실행됩니다. 노트가 Constellation을 떠나는 일은 결코 없습니다.

## 두 축을 평이한 언어로

### Source — *이 지식은 어디에서 왔는가?*

11개의 가능한 값과 *분류 불가*:

- **지각** — 직접적인 감각 관찰
- **추론** — 전제로부터의 추론(연역, 귀납, 유추)
- **증언** — 다른 사람의 보고(인용, 참조, 참조된 출처)
- **집단 전달** — 많은 독립적인 목격자에 의한 수렴된 보고(순니파의 *al-tawatur*)
- **비교** — 알려진 사례와의 유추에 의한 지식(법적 *qiyās*, 과학적 유추)
- **공준** — 최선의 설명에 대한 추론(*arthapatti*)
- **비파악** — 부재의 지식
- **기억** — 과거 경험의 회상
- **선천적 성향** — 경험 이전의 앎(*fitrah*)
- **영감** — 신비적 또는 창조적 파악(*kashf*)
- **계시** — 성스러운 텍스트 또는 예언적 전달(*al-wahy*)
- **분류 불가** — 이 분류에서 옵트 아웃

### 콘텐츠 유형 — *이것은 어떤 종류의 지식인가?*

5개의 최상위 분기와 하위 분기:

- **감각 입력** — 원시 신호(시각, 청각, 화학, …)
- **상징적 실체** — 기호, 상징, 코드
- **의미적 내용** — 개념, 명제, 사실, 아이디어, 정보
- **인식적 상태** — 의심, 믿음, 의견, 확신, 지식, 환상
- **고차 구성물** — 이론, 교리, 세계관, 패러다임

두 축 모두 각 최상위 값 아래에 여러 정제 계층이 있습니다(예: *epistemic-states/knowledge/by-content/propositional*은 잎입니다).

## 6개의 분류기

각 분류기는 CECE가 노트를 읽는 하나의 *렌즈*입니다. Source Review 카드는 우측 상단 모서리에 **6개의 작은 색이 있는 점**으로 표시됩니다. 점에 마우스를 올리면 이름 + 상태가 표시됩니다.

| 점 | 분류기 | 무엇을 읽는가 |
|---|---|---|
| 🔵 파란색 | **내 frontmatter**(사용자 권위) | 이미 설정한 `sources:` 및 `content_type:` 필드. 노트를 직접 분류한 경우 이 렌즈는 *절대적 권위*를 가집니다 — 종합은 당신의 선택을 채택하고 다른 것들을 건너뜁니다. |
| 🌹 장미색 | **인용 및 구조**(구조적) | 인용, 블록 인용, 코드 블록, 정리 마커, 정의 구절("X의 개념은 …로 정의됩니다"), 그림 참조. 노트의 구조적 형태를 읽습니다. |
| 🟡 호박색 | **어간 및 어휘**(언어적) | 아랍어 어근 분석(CAE), 표면 키워드 매칭, 교차 언어 용어 등가성(Bridge). 순수 임베딩이 놓치는 아랍어 인식 분류를 포착합니다. |
| 🟢 청록색 | **연결된 노트**(그래프) | 다른 분류된 노트에 대한 타입이 있는 Living Links(`[[Note\|supports]]`, `[[Note\|contradicts]]` 등). 이웃들이 클러스터를 이룰 때 이웃들로부터 분류를 상속합니다. |
| 🟣 보라색 | **유사한 노트**(의미적) | 이미 분류된 노트에 대한 임베딩 유사도(k-Nearest-Neighbor). 이 노트의 콘텐츠 벡터가 분류된 노트들과 클러스터를 이룰 때 합의를 가져옵니다. |
| 🟢 녹색 | **AI 판단**(추론) | 문법 제약 추론을 실행하는 로컬 LLM(Qwen3-4B Q5_K_M). *아직 활성화되지 않음* — 모델 배선은 후속 릴리스로 연기되었습니다. 오늘은 모든 카드에서 이 점이 침묵 상태로 유지됩니다. |

### 점 상태

- **채워짐** — 발언함 + 종합에 동의
- **링** — 발언함 + 종합에 반대(이 렌즈는 다른 것을 선택함)
- **점선 윤곽** — 침묵(이 노트에 대해 이 렌즈에 신호 없음)

점 클러스터는 한눈에 보는 앙상블 건강 지표입니다. 6개의 점이 모두 채워진 카드는 엔진의 가능한 가장 강력한 분류입니다(드뭄). 한두 개의 링이 있는 카드는 그 추론을 정직하게 보여줍니다 — 렌즈들이 동의하지 않은 것입니다.

## 세 가지 신뢰도 체제

분류기들이 투표한 후 CECE는 각 축에 세 체제 중 하나로 라벨을 붙입니다:

- **만장일치** — 발언한 모든 분류기가 동일한 주요 값을 선택함. 카드에 특별한 알약 표시가 없습니다.
- **강한 다수(1건 반대)** — 대부분이 동의함; 반대자 한 명이 이름으로 표시됩니다. 카드 헤더에 보라색 "강한 다수" 알약 표시가 있습니다.
- **의견 분산** — 명확한 다수가 없음. 카드에는 금색 "분류기 의견이 갈림 — 당신의 결정이 필요함" 알약 표시, **금색 왼쪽 테두리**, 그리고 선택할 칩이 있는 형제 모호성 해소 양식이 있습니다.

각 축은 독립적으로 자체 체제를 받습니다. 카드는 수평에서 만장일치 + 수직에서 의견 분산일 수 있습니다(또는 그 반대). 헤더 알약 표시는 두 축에 걸친 최악의 체제를 요약합니다.

## 형제 모호성 해소 (Sibling Disambiguation)

축의 의견이 갈리면 CECE는 추측을 거부하고 대신 후보 값들을 프롬프트 아래에 **라디오 칩**으로 표시합니다:

> *"분류기들이 이 후보들 사이에서 의견이 갈렸습니다. 노트에 가장 잘 맞는 것을 선택하세요:"*

칩을 클릭하면 → 엔진은 그 선택을 노트의 frontmatter에 작성하고, 카드를 큐에서 제거하며, 라이브러리별 신뢰도 데이터를 업데이트합니다.

다른 축이 정해져 있던 경우(만장일치 또는 강한 다수), CECE는 그 축의 값도 *동시에* 작성합니다 — 따라서 한 번의 칩 클릭으로 두 축이 모두 완료되며, 선택한 것만이 아닙니다. 같은 카드는 결코 두 번 묻지 않습니다.

두 축 모두 의견이 갈리면 축당 하나의 칩을 선택합니다(두 번 클릭).

## 추론 추적

각 카드에는 **"▸ 왜 이 분류인가?"** 토글이 있습니다(열려 있으면 "▾ 추론 숨기기"). 펼치면 발언한 분류기당 한 행씩 표시됩니다:

- 점 클러스터와 일치하는 **렌즈 색상 점**
- **분류기 라벨**(예: "어간 및 어휘")
- 대괄호 안의 **자체 보고된 신뢰도**: `[high]` `[medium]` `[low]`
- 무엇이 발동했는지를 설명하는 **한 줄 추론**(예: *"언어적 일치: 수직 → semantic-contents/concept (가중치 0.80)"*)
- 추론 아래의 **친근한 규칙 칩**: `Surface keyword match`, `Side-channel preference rule`, `Arabic root match (CAE)` — 이것들은 각 분류기가 트리거한 특정 규칙입니다

**처음 50회 검토** 동안 추적은 모든 카드에서 자동으로 펼쳐져 엔진을 신뢰해야 할 시점에 대한 직관을 키울 수 있습니다. 그 후, 추적은 만장일치 카드에서는 요청 시로 접히고, 강한 다수 + 의견 분산 카드에서는 자동 펼침 상태로 유지됩니다(불일치가 정보적인 경우).

설정 → Intelligence → CECE → 추론 추적 표시에서 언제든지 이 기본값을 재정의할 수 있습니다:

- **항상 표시** — 모든 카드에서 열림
- **불일치 시에만 (기본값)** — 의견 분산 + 강한 다수 카드에서 열림, 처음 50회 검토 포함
- **항상 숨김** — 펼치려면 수동 클릭 필요

## 큐 구성 필터

카운트 스트립 위에는 각 카드가 당신에게 필요한 결정의 종류에 따라 큐를 분할하는 **5개의 칩**이 있습니다:

| 칩 | 표시 |
|---|---|
| **전체** *(기본값)* | 전체 큐 |
| **두 축 모두 결정 필요** | 수평과 수직 모두 의견이 갈린 카드 |
| **Source 결정 필요** | 수평이 의견이 갈리고 + 수직이 정해진 카드 |
| **콘텐츠 유형 결정 필요** | 수직이 의견이 갈리고 + 수평이 정해진 카드 |
| **분류기가 동의함** | 어떤 축도 의견이 갈리지 않은 카드 — 빠른 도장 찍기 후보 |

각 칩은 그 버킷의 개수를 표시합니다(예: *"Source 결정 필요 (43)"*). 빈 버킷은 흐려지고 비활성화됩니다. 칩을 클릭하면 표시되는 카드가 다시 렌더링됩니다; 카운트 스트립과 모두 승인 계산은 활성 필터에 관계없이 항상 **전체** 큐에 대해 작동하므로 항상 실제 합계를 볼 수 있습니다.

이 필터는 큐에 수백 장의 카드가 있을 때 건초더미 속 바늘 문제를 해결합니다. 먼저 모든 도장 찍기 후보를 정리하고 싶나요? **분류기가 동의함**을 클릭한 다음 **모두 승인**을 클릭합니다. 가장 어려운 사례에 집중하고 싶나요? **두 축 모두 결정 필요**를 클릭합니다.

## 각 카드 아래의 노트 요약

각 카드의 제목 아래에는 짧은 **요약** 줄이 있습니다 — 노트가 무엇에 관한 것인지 알려주는 몇 문장으로, 노트를 열지 않고도 어떻게 분류할지 결정할 수 있게 합니다. Constellation은 항상 *당신이* 작성한 요약(`summary:` / `description:` / `abstract:` / `excerpt:` frontmatter 필드, 또는 본문의 `> [!summary]` / `[!abstract]` / `[!tldr]` 콜아웃)을 표시하며, 작성하지 않았을 때만 하나를 생성합니다. 생성된 요약은 추출적이며 — 노트 자체의 가장 중심적인 문장 — 결코 당신의 파일에 다시 작성되지 않습니다. 전체 세부 사항은 **노트 요약** 항목에 있습니다.

## 카드별 작업

모든 카드 하단에는 4가지 작업이 있습니다(의견 분산 카드에서는 모호성 해소가 수락/편집을 대체하므로 3가지):

- **수락** — 엔진의 종합된 주요 값을 두 축 모두에 대해 노트의 frontmatter에 작성하고 카드를 큐에서 제거합니다. 분류기별 신뢰도를 업데이트합니다.
- **편집** — 두 축 모두에 대한 트리 선택기를 엽니다; 값을 수동으로 선택합니다. 동일한 신뢰도 업데이트.
- **거부** — 아무것도 작성하지 않고 카드를 지웁니다. 나중에 다시 분류하면 엔진이 다시 제안합니다. (거부는 신뢰도를 업데이트하지 않습니다 — 사용자가 "이 중 어느 것도 원하지 않는다"는 것은 피드백 신호로서 모호합니다.)
- **형제 모호성 해소 칩** — 의견 분산 카드에서 후보 칩 중 하나를 클릭합니다. 선택한 값을 작성합니다(다른 축이 정해져 있었다면 자동으로 작성).

---

## 신뢰 보정 기간

CECE 분류 카드의 처음 **50회 검토**는 *신뢰 보정 기간*입니다. 이 기간 동안 추론 추적은 모든 카드에서 자동으로 펼쳐지며(체제와 관계없이), 패널 상단의 조용한 배너가 상기시킵니다: *"{N}개의 카드를 더 검토할 때까지 추론 추적을 표시합니다 — 분류기를 언제 신뢰해야 할지 배우는 데 도움이 됩니다."*

50회 검토 후 배너는 사라지고 추적은 기본 요청 시 동작으로 접힙니다. 항상 열거나 항상 닫고 싶으면 설정에서 재정의할 수 있습니다.

보정 기간의 요점: CECE는 당신이 수정할 때마다 더 좋아지는 확률적 시스템입니다(라이브러리별 신뢰도). 처음 50회 검토 동안 각 분류기가 *왜* 그렇게 투표했는지 보면 이 특정 라이브러리의 콘텐츠에 대해 그 결론이 신뢰할 만한 시점에 대한 자신만의 직관을 형성할 수 있습니다.

---

## 라이브러리별 보정

설정 → Intelligence → CECE → **라이브러리별 보정**은 활성 라이브러리에서 각 분류기의 축별 정확도를 보여주는 읽기 전용 테이블을 엽니다:

```
분류기              수평           수직
─────────         ──────         ────
내 frontmatter    12/12 (100%)   4/4 (100%)
인용              18/22 (82%)    6/8 (75%)
어간              24/28 (86%)    20/26 (77%)
연결된 노트        3/4 (균일)     2/3 (균일)
유사한 노트        14/19 (74%)    12/19 (63%)
AI 판단           — (실행 안 됨)  — (실행 안 됨)
```

숫자는 정답 / 총 개수입니다. 백분율은 분류기가 해당 라이브러리 × 축에서 20건 이상의 수정을 한 후에 표시됩니다(안정적인 정확도 데이터의 임계값). 임계값 미만에서는 라벨에 **(균일)**이 표시됩니다 — 충분한 데이터가 누적될 때까지 분류기는 균일하게 가중된 투표에 기여합니다.

다른 라이브러리는 분류기별 정확도가 크게 다를 수 있습니다. 언어적 분류기는 아랍어가 많은 라이브러리에서 뛰어나고; 그래프 분류기는 밀집하게 연결된 라이브러리에서 뛰어납니다. 종합 레이어는 라이브러리별 보정 데이터를 사용하여 투표에 가중치를 부여합니다 — 따라서 *이* 라이브러리에서 70%의 시간 동안 틀렸던 분류기는 다음 종합 라운드에서 투표가 하향 가중됩니다.

## 백그라운드 분류

Source Review 큐는 두 가지 방식으로 증가할 수 있습니다:

1. **수동**(기본값) — 노트를 우클릭 → "Source와 콘텐츠 유형 제안" 또는 설정 → 분류 스캔 실행을 트리거합니다.
2. **백그라운드** — 설정 → Intelligence → CECE → 백그라운드 분류. 두 가지 모드:
   - **노트 저장 시** — 입력을 멈춘 후 약 1.5초 후에 각 노트를 자동 분류합니다(기존 디바운스된 저장을 활용; 키 입력마다 발생하지 않음).
   - **앱 시작 시** — 시작당 한 번 분류되지 않은 노트를 스캔합니다.

백그라운드 분류는 기본적으로 **꺼짐**입니다. 두 백그라운드 모드 모두 백그라운드 스레드에서 실행되고 진행 이벤트를 발생시킵니다; 입력은 즉각적으로 유지됩니다; Source Review 패널 헤더에서 취소할 수 있습니다.

## 일반적인 워크플로우

**"방금 CECE를 설치했어요 — 어디서 시작하나요?"**
Source Review 패널을 엽니다. 파일 트리에서 5-10개의 노트를 우클릭 → "Source와 콘텐츠 유형 제안"을 선택해 큐를 시드합니다. 카드를 한 번에 하나씩 클릭합니다. 처음 50회 검토 동안 추론 추적이 자동으로 펼쳐집니다 — 읽으세요. 5-10개의 카드 후에는 당신의 콘텐츠에서 어떤 분류기가 신뢰할 만한지 보이기 시작할 것입니다.

**"제 큐에 1,200장의 카드가 있어요 — 어디에 집중해야 하나요?"**
필터 칩을 사용하세요. **분류기가 동의함**(도장 찍기 후보)으로 시작 → 모두 승인을 클릭하여 그것들을 정리합니다. 그런 다음 **Source 결정 필요** + **콘텐츠 유형 결정 필요**로 각 한 가지 결정이 필요한 의견 분산 사례를 처리합니다. **두 축 모두 결정 필요**가 가장 어려운 세트입니다; 마지막에 남겨두세요.

**"수락 vs 거부 vs 편집 vs 모호성 해소를 언제 해야 할지 어떻게 알 수 있나요?"**
- **수락** — 종합된 주요 값이 노트에 대한 당신의 해석과 일치할 때.
- **거부** — 어떤 제안도 맞지 않을 때(예: 엔진이 노트에 대해 당신이 알고 있는 무언가를 놓쳤을 때).
- **편집** — 어떤 제안에도 없는 값을 원할 때.
- **형제 모호성 해소 칩** — 카드의 의견이 갈리고 후보 중 하나가 정확할 때.

**"어떤 분류기를 가장 신뢰하는지 어떻게 볼 수 있나요?"**
설정 → Intelligence → CECE → 라이브러리별 보정을 엽니다. 테이블에는 이 라이브러리에서 한 수정에 걸친 분류기별 정확도가 표시됩니다.

## 관련 항목

- **분류기** — 이 카드들의 전체 페이지 홈으로, 노트 선택기("노트 분류…")와 "모든 요약 생성" 버튼이 있습니다.
- **노트 요약** — 각 카드 아래의 요약 줄이 어떻게 생산되는지, 그리고 항상 당신 자신의 말을 우선하는 작성자 우선 우선순위.
- **인지 엔진** — CECE가 부합하는 더 넓은 지식 형성 철학.
- **속성** — CECE가 작성하는 `sources:` 및 `content_type:` frontmatter 필드.
- **지식 계층** — Source × 콘텐츠 유형이 Universe / Library / Folder / Note 구조에 어떻게 부합하는지.

## 우측 사이드바와 Cataloger — 서로 다른 두 곳

우측 사이드바의 **Source Review** 탭과 전체 페이지인 **Cataloger** 는 이제 **서로 다른 화면**입니다:

- **우측 사이드바 → Source Review** 는 **현재 열려 있는 노트**의 대기 중인 제안을 보여줍니다 — 그 노트의 카드와 카드별 *수락 / 편집 / 거부*.
- **Cataloger** (쌓인 카드 아이콘, 왼쪽 도크)는 **우주 전체**의 검토 대기열 — 결정을 기다리는 모든 노트 — 을 일괄 **모두 승인 / 모두 거부** 도구 및 필터 칩과 함께 보여줍니다. 이 일괄 도구는 *오직* 여기에만 있으며, 개별 노트 옆에는 절대 나타나지 않습니다.

Cataloger의 텍스트 크기는 **Style Setter → Cataloger → Text size** 에서 조절할 수 있습니다.
