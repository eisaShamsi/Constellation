# Руководство пользователя Constellation

**Версия 0.1.0 | Март 2026**

Constellation — это настольное приложение для управления личными знаниями (PKM), предназначенное для работы с библиотеками заметок в формате Markdown. Создано на основе Tauri v2, SvelteKit и Rust, работает нативно на Windows, macOS и Linux с полной поддержкой арабского языка и RTL.

## 1. Начало работы

### Установка

Скачайте последнюю версию установщика со [страницы релизов Constellation](https://github.com/eisaShamsi/Constellation/releases):

- **Windows**: установщик `.exe` (NSIS) или `.msi`
- **macOS**: образ диска `.dmg`
- **Linux**: `.AppImage` или пакет `.deb`

### Первый запуск

При первом открытии Constellation **Мастер настройки Вселенной** проведёт вас через следующие шаги:

1. **Выберите язык** — поддерживается 15 языков
2. **Создайте или импортируйте библиотеку** — укажите существующую папку с Markdown-файлами или начните с нуля
3. **Назовите вашу вселенную** — вселенная является контейнером для всех ваших библиотек

### Обзор интерфейса

| Элемент | Описание |
|---------|----------|
| **Боковая панель (лента)** | Кнопки навигации: дерево файлов, поиск, Sky View, календарь, шаблоны, настройки |
| **Дерево файлов** | Просмотр заметок и папок в библиотеках |
| **Редактор** | Чтение и редактирование Markdown-заметок |
| **Панель вкладок** | Открытие нескольких заметок во вкладках |
| **Строка состояния** | Количество слов, символов, время чтения |

## 2. Вселенная и библиотеки

### Что такое Вселенная?

**Вселенная** — это контейнер верхнего уровня, содержащий все ваши библиотеки. Представьте её как рабочее пространство или коллекцию библиотек.

### Что такое Библиотека?

**Библиотека** — это папка на вашем компьютере, содержащая файлы Markdown (`.md`). В одной вселенной может быть несколько библиотек — например, одна для рабочих заметок, другая для личных.

### Управление библиотеками

- **Добавить библиотеку**: Настройки > Библиотеки > Добавить библиотеку, или перетащите папку в приложение
- **Удалить библиотеку**: Настройки > Библиотеки > нажмите кнопку удаления рядом с названием библиотеки
- **Настройки библиотеки**: Каждая библиотека может иметь собственные настройки внешнего вида (шрифты, цвета)

### Дочерние вселенные

Вселенные можно вкладывать друг в друга. **Дочерняя вселенная** — это папка другой вселенной, на которую ссылается родительская. Заметки из дочерних вселенных отображаются в Sky View вместе с вашими собственными заметками, а межбиблиотечные ссылки показываются пунктирными линиями.

### Автоматическое открытие

Constellation запоминает последнюю активную вселенную и автоматически открывает её при запуске. Если вселенная была перемещена или её путь изменился, Constellation обнаруживает это и автоматически исправляет путь.

### Портативные вселенные

Вселенные Constellation полностью портативны. Вы можете переместить папку вселенной в любое место — на другой диск, USB-накопитель или другой компьютер — и Constellation автоматически обнаружит и исправит все внутренние пути при повторном открытии.

Чтобы переместить вселенную:
1. Закройте Constellation
2. Переместите или скопируйте папку вселенной в новое расположение
3. Откройте Constellation → появится экран приветствия (старый путь больше недействителен)
4. Выберите **Открыть существующую вселенную** и укажите новое расположение
5. Все заметки и библиотеки появятся мгновенно — пути исправляются автоматически

Структура папок вселенной следует модели Obsidian: заметки хранятся непосредственно в корневой папке, конфигурация находится в `.constellation/`.

## 3. Создание и редактирование заметок

### Создание заметки

| Способ | Действие |
|--------|----------|
| **Клавиатура** | `Ctrl+N` |
| **Дерево файлов** | Правый клик по папке > Новая заметка |
| **Mission Control** | `Ctrl+P` > "New note" |

### Режимы редактора

Constellation предлагает два режима редактора, выбираемых в разделе **Настройки > Редактор > Тип редактора**:

#### Markdown-редактор (CodeMirror)

Редактор по умолчанию для опытных пользователей. Пишите Markdown напрямую:

- **Живой предпросмотр** — отображает форматирование прямо при наборе текста
- **Режим исходного кода** — показывает необработанный синтаксис Markdown
- **Панель форматирования** — появляется при выделении текста
- **Слэш-команды** — введите `/` для быстрых вставок
- **Автодополнение Wikilink** — введите `[[` для связывания заметок
- **Множественные курсоры** — `Alt+Click` или `Ctrl+D`

#### Документный редактор (TipTap)

WYSIWYG-редактор с визуальной панелью инструментов:

- Полужирный, курсив, подчёркивание, зачёркивание, выделение
- Заголовки (H1–H3), выравнивание текста
- Маркированные списки, нумерованные списки, списки задач
- Цитаты, блоки кода, горизонтальные линии
- Таблицы (вставка, добавление/удаление строк и столбцов)
- Ссылки и изображения

Оба редактора сохраняют файлы в стандартном формате Markdown. Переключаться между ними можно в любой момент без потери данных.

### Выноски (Callouts)

Создавайте стилизованные блоки выносок для заметок, предупреждений, советов и других указаний:

```markdown
> [!note] Важная информация
> Содержимое выноски размещается здесь.

> [!warning] Будьте осторожны
> Это действие нельзя отменить.

> [!tip]- Нажмите для раскрытия
> Сворачиваемое содержимое выноски.
```

Поддерживаемые типы: `note`, `tip`, `warning`, `danger`, `success`, `question`, `failure`, `bug`, `example`, `quote`, `abstract`. Каждый тип имеет свой цвет и значок. Добавьте `-` после типа, чтобы сделать его сворачиваемым (начинает свёрнутым), или `+` (начинает развёрнутым).

### Синтаксис выделения

Оберните текст двойными знаками равенства для выделения:

```markdown
Это ==выделенный текст== в вашей заметке.
```

В режиме живого просмотра метки `==` скрываются, и текст отображается с жёлтым фоном.

### Блоки кода

Ограждённые блоки кода отображаются с цветом фона и меткой языка:

````markdown
```javascript
const greeting = "Hello, world!";
```
````

Название языка отображается в виде бейджа над блоком кода.

### Встраивание изображений

Встраивайте изображения непосредственно в свои заметки:

```markdown
![Альтернативный текст](https://example.com/image.png)   — внешний URL
![[photo.jpg]]                                              — локальный файл из библиотеки
```

В режиме живого просмотра изображения отображаются в строке. Локальные изображения должны находиться в папке вашей библиотеки. Внешние изображения требуют подключения к интернету.

### Панель инструментов таблицы

Когда курсор находится внутри markdown-таблицы, появляется плавающая панель инструментов с:

- **+ Строка / + Столбец** — добавить строки или столбцы
- **- Строка / - Столбец** — удалить строки или столбцы
- **Выравнивание** — выравнивание по левому краю, по центру или по правому краю для каждого столбца
- **Сортировка** — сортировка строк по возрастанию или убыванию по текущему столбцу
- **Tab / Shift+Tab** — навигация между ячейками таблицы

### Сочетания клавиш для форматирования текста

| Сочетание | Действие |
|-----------|----------|
| `Ctrl+B` | Полужирный |
| `Ctrl+I` | Курсив |
| `Ctrl+Shift+S` | Зачёркивание |
| `Ctrl+Shift+H` | Выделение |
| `Ctrl+K` | Вставить wikilink |
| `Ctrl+Z` | Отменить |
| `Ctrl+Shift+Z` | Повторить |

### Связывание заметок

Введите `[[`, чтобы открыть автодополнение заметок. Начните вводить название заметки и выберите из предложений. Ссылки отображаются как кликабельные wikilink-ссылки: `[[Note Name]]`.

Также можно ссылаться на конкретные заголовки: `[[Note Name#Heading]]`.

## 4. Поиск

Constellation включает гибридный многоязычный поисковый движок на базе SQLite FTS5 с ранжированием BM25, структурированными фильтрами запросов и оптимизированной нормализацией для арабского языка. Поиск доступен из панели инструментов боковой панели.

### Как искать

Нажмите на значок поиска на боковой панели или используйте `Ctrl+Shift+F` для активации режима поиска. Введите запрос, и результаты появятся после короткой задержки (300мс). Нажмите `Escape` или кнопку `×`, чтобы очистить поиск и вернуться к дереву файлов.

### Синтаксис поиска

| Синтаксис | Пример | Что находит |
|-----------|--------|-------------|
| Свободный текст | `управление проектами` | Заметки, содержащие эти слова в заголовке или тексте |
| Фильтр по тегу | `#исследование` | Заметки с тегом `#исследование` |
| Фильтр по свойству | `status=active` | Заметки со свойством frontmatter `status` равным `active` |
| Фильтр по вики-ссылке | `links to [[Климат]]` | Заметки со ссылкой на `[[Климат]]` |
| Область библиотеки | `in:МояБиблиотека` | Ограничивает результаты определённой библиотекой |
| Комбинированный | `#исследование status=active экономика` | Все фильтры применяются одновременно |

### Значки типа совпадения

Каждый результат поиска отображает цветной значок, указывающий, как было найдено совпадение. Значок показывает локализованную букву для доступности (безопасно для дальтоников):

| Значок | Цвет | Значение |
|--------|------|----------|
| **Н** | Синий | Совпадение по названию — поисковый запрос найден в имени заметки |
| **С** | Зелёный | Совпадение по содержимому — поисковый запрос найден в тексте заметки |
| **С** | Фиолетовый | Семантическое совпадение — концептуально связано (требуется модель эмбеддингов) |
| **С** | Янтарный | Совпадение по свойству — найдено через фильтр свойства frontmatter |
| **#** | Розовый | Совпадение по тегу — найдено через фильтр тега |
| **В** | Светло-голубой | Совпадение по вики-ссылке — найдено через фильтр вики-ссылки |

Буквы значков локализованы для всех 15 поддерживаемых языков.

### Закреплённые результаты (навигация по результатам)

Результаты поиска остаются видимыми после нажатия на один из них. Открытая заметка подсвечивается в списке результатов, чтобы вы видели, какой результат просматриваете. Нажмите на другой результат для перехода к нему без повторного поиска.

Чтобы очистить поиск, нажмите `Escape` или кнопку `×`.

### Навигация с клавиатуры

| Клавиша | Действие |
|---------|----------|
| `Стрелка вниз` | Выбрать следующий результат |
| `Стрелка вверх` | Выбрать предыдущий результат |
| `Enter` | Открыть выбранный результат |
| `Escape` | Очистить поиск и вернуться к дереву файлов |

### Подсветка поискового запроса

При открытии заметки из результатов поиска все вхождения поискового запроса подсвечиваются в редакторе. Это работает с распознаванием арабских диакритических знаков — поиск "ادارة" подсветит "إدارة" и все диакритические варианты.

### История поиска

Нажмите на поле поиска, когда оно пустое, чтобы увидеть последние запросы (последние 20 запросов). Каждая запись показывает текст запроса и время выполнения. Нажмите на любую запись, чтобы мгновенно повторить поиск. Используйте ссылку "Очистить историю" внизу для удаления всей истории.

История поиска хранится локально на вашем устройстве и сохраняется между перезапусками приложения.

### Search Hub

Search Hub — это полноэкранный поисковый интерфейс. Нажмите на значок лупы в панели дока, чтобы открыть его. Обе боковые панели сворачиваются для максимального пространства. Введите любой термин, и Constellation ищет везде одновременно, группируя результаты в 5 категорий: Заголовки, Содержимое, Теги, Свойства и Вики-ссылки. Каждая категория имеет сворачиваемый раздел со счётчиком. Нажмите на любой результат, чтобы открыть его в редакторе с подсветкой всех вхождений. Появляется кнопка "Вернуться в Search Hub", чтобы вернуться без повторного поиска.

### Операторы ссылок

Constellation поддерживает 6 операторов поиска по топологии ссылок:

| Синтаксис | Что находит |
|-----------|-------------|
| `links to [[X]]` | Заметки, ссылающиеся на X (обратные ссылки) |
| `links from [[X]]` | Заметки, на которые ссылается X (исходящие ссылки) |
| `mutual [[X]]` | Заметки, связанные с X, и X ссылается обратно (двунаправленные) |
| `mentions [[X]]` | Заметки, содержащие имя X без [[вики-ссылки]] |
| `orphans` | Заметки без входящих или исходящих ссылок |
| `links between [[X]] and [[Y]]` | Заметки, ссылающиеся на X и Y |

При вводе любого оператора ссылок автозаполнение `[[` показывает все заметки во вселенной. После выбора заметки введите `#` для завершения заголовков или `|type:` для завершения типа ссылки.

## 5. Sky View (GraphMind)

Sky View визуализирует ваши заметки в виде интерактивного 3D-графа на основе движка **GraphMind** (Pixi.js WebGL).

### Открытие Sky View

- Нажмите на значок графа в боковой панели
- Нажмите `Ctrl+G`
- Mission Control (`Ctrl+P`) > "Sky View"

### Навигация

| Ввод | Действие |
|------|----------|
| **Клик + перетаскивание** | Перемещение графа |
| **Прокрутка** | Увеличение/уменьшение |
| **Клик по узлу** | Открыть заметку |
| **Правый клик по узлу** | Контекстное меню (Открыть, Фокус, Закрепить, Скрыть) |
| **Средняя кнопка + перетаскивание** | Вращение в 3D |
| **W/A/S/D** | Полёт в 3D-пространстве |
| **0** | Сброс вращения к 2D |
| **Ctrl+F** | Поиск и выделение |
| **Space** | Переключение режима фокуса |

### Режимы компоновки

Нажмите `Ctrl+L` для переключения между:

- **Органический** — силовая компоновка, при которой кластеры формируются естественно
- **Иерархический** — древовидная компоновка сверху вниз
- **Хронологический** — заметки располагаются по дате создания на временной шкале

### Режим фокуса

Правый клик по узлу > **Фокус**, чтобы видеть только его окружение. Настройте:

- **Глубина** (1–5 переходов) — сколько уровней связей показывать
- **Направление** (↔/←/→) — все ссылки, только входящие или только исходящие

### 3D-навигация

Зажмите среднюю кнопку мыши и перетаскивайте для вращения. Используйте W/A/S/D/Q/E для полёта по звёздному полю. Индикатор осей XYZ в углу показывает вашу ориентацию. Нажмите `0` для сброса.

### Настройки

Нажмите на значок шестерёнки:

- **Внешний вид**: Размер узлов, видимость меток, размер шрифта, толщина связей, показать изолированные
- **Физика**: Сила отталкивания, сила связей, расстояние связей
- **AI**: Порог семантических связей (Фаза 2)

### Легенда

Легенда в правом нижнем углу показывает цвета библиотек/папок с флажками для переключения видимости.

### Страты знаний

Sky View автоматически классифицирует ваши заметки по восьми стратам знаний в зависимости от уровня абстракции:

| Страта | Описание |
|--------|----------|
| **Снимок** | Быстрые, мимолётные заметки |
| **Журнал** | Датированные события и дневниковые записи |
| **Тема** | Атомарные концепции об одной идее |
| **Карта** | Организационные заметки, связывающие другие темы |
| **Фреймворк** | Модели и мыслительные рамки |
| **Принцип** | Проверенные правила и аксиомы |
| **Убеждение** | Базовые ценности и убеждения |
| **Артефакт** | Завершённые, окончательные работы |

Страта определяется автоматически на основе frontmatter, структуры и ссылок заметки. Вы можете переопределить классификацию вручную, добавив свойство `stratum` в frontmatter.

### Жизненный цикл зрелости

Каждая заметка проходит жизненный цикл зрелости, отражающий степень её развития:

- **Семя** — Начальная идея или черновой набросок
- **Саженец** — Заметка начинает обретать форму и имеет несколько ссылок
- **Вечнозелёная** — Зрелая, проверенная и хорошо связанная заметка
- **Каноническая** — Окончательный, авторитетный справочник в своей области

Уровень зрелости обновляется автоматически на основе количества ссылок, даты ревизии и частоты редактирования. Вы также можете установить его вручную через свойство `maturity` в frontmatter.

## 6. Разделённый вид

Разделённый вид позволяет редактировать несколько заметок рядом в главном окне.

### Открытие разделённого вида

- **Палитра команд**: `Ctrl+P`, затем введите "Split View"
- **Горячая клавиша**: Используйте назначенное сочетание для переключения между режимами
- **Цикл**: Выкл → Вертикальный (рядом) → Горизонтальный (сверху и снизу) → Выкл

### Редактирование в разделённом виде

Каждая панель — это полностью независимый редактор с:
- Полной панелью инструментов (жирный, курсив, заголовки, выравнивание и т.д.)
- Навигацией по хлебным крошкам (библиотека / название заметки)
- Панелью свойств и выпадающим списком стадий
- Поддержкой сохранения (`Ctrl+S` сохраняет текущую панель)
- Редактированием заголовка и переименованием файла

### Изменение размера панелей

Перетащите разделитель между панелями, чтобы изменить их размер. Каждый разделитель независим — при 3 и более открытых заметках вы можете изменить размер любой соседней пары, не затрагивая остальные. Работает как в вертикальном, так и в горизонтальном режимах.

### Фокус

Щёлкните по любой панели, чтобы сфокусироваться на ней. Панель в фокусе получает горячие клавиши и отслеживается панелями правой боковой панели (Свойства, Обратные ссылки и т.д.).

## 7. Индекс

Индекс — это всеобъемлющий глоссарий терминов по всем вашим библиотекам — каждое значимое слово, отсортированное по алфавиту с количеством упоминаний.

### Открытие Индекса

- **Кнопка дока**: Нажмите на значок Индекса (книга) в левом доке
- **Палитра команд**: `Ctrl+P`, затем введите "Index"

### Многоязычный NLP-конвейер

Индекс обрабатывает текст через языково-зависимый конвейер перед индексацией:

- **Арабский**: Алгоритм Lucene Light10 — удаляет ташкиль, унифицирует хамзу, удаляет определённый артикль (الـ), удаляет грамматические суффиксы
- **Иврит**: Удаление префиксов (ב/ל/מ/ה/ו/כ/ש)
- **Английский**: Стемминг типа Porter (множественное число, глагольные формы, суффиксы)
- **Французский/Испанский/Португальский/Немецкий**: Удаление суффиксов, специфичных для языка
- **Русский/Турецкий/Хинди/Персидский**: Удаление морфологических суффиксов
- **Все 15 языков**: Фильтрация стоп-слов (артикли, предлоги, союзы)

### Навигация

- **Вкладки языков**: Переключайтесь между Все, Арабский, Иврит, Английский или # (специальные символы)
- **Алфавитная панель**: Щёлкните по букве, чтобы отфильтровать термины, начинающиеся с этой буквы — счётчик терминов обновляется, показывая количество совпадений
- **Щёлкните по той же букве ещё раз**, чтобы сбросить фильтр и показать все термины
- **Режимы сортировки**: По алфавиту (по умолчанию) или по частоте (самые частые первыми)

### Редактирование из Индекса

Щёлкните по любой заметке в ссылках термина, чтобы открыть её в панели предварительного просмотра рядом с Индексом. Панель предварительного просмотра — это полноценный редактор — вы можете редактировать, сохранять, изменять свойства и повышать стадию. Поисковый термин выделяется в заметке и автоматически прокручивается к нему.

Нажмите `Ctrl+Клик`, чтобы открыть заметку как обычную вкладку. Кнопка «Вернуться к Индексу» появляется на панели вкладок — нажмите её, чтобы вернуться точно туда, где вы остановились в Индексе.

### Интеграция со Вторым экраном

Когда Второй экран открыт:
- **Щёлкните по термину** → Второй экран показывает все заметки, содержащие этот термин, в разделённом виде (список заметок + редактор)
- **Ctrl+Клик по нескольким терминам** → Второй экран показывает режим сравнения с каждым термином в отдельной колонке

## 8. Constellation Sight

Constellation Sight визуализирует всю вашу систему знаний в виде графа гравитационного колодца. Он отвечает на вопрос: **"Как выглядят мои знания и насколько они здоровы?"**

### Открытие Sight

Нажмите на **кнопку Sight** (значок глаза) в левой ленте. Появится граф гравитационного колодца. Нажмите x для закрытия.

### Граф гравитационного колодца

Заметки расположены в концентрических кольцах по важности (центральности). Наиболее связанные заметки находятся в центре; периферийные — на краях. Внутри каждого кольца заметки сгруппированы по библиотеке (вашей организации). Цвет узла = библиотека.

| Элемент | Значение |
|---------|----------|
| **Большой узел** | Высокая центральность — соединяет различные области знаний |
| **Маленький узел** | Периферийный — внутри одной области |
| **Цвет узла** | Принадлежность к библиотеке |
| **Сплошная линия** | Связь между двумя заметками |
| **Стрелки направления** | Маленькие стрелки, показывающие направление связи |
| **Толщина линии** | Уровень уверенности (толстая = установлено, тонкая = гипотеза) |

### Взаимодействие

- **Одиночный клик** по узлу: выделяет его окружение (все связанные заметки). Всё остальное затемняется.
- **Двойной клик**: открывает заметку в редакторе.
- **Клик по пустому пространству**: снимает выделение.
- **Прокрутка**: масштабирование. **Перетаскивание**: панорамирование. **По размеру экрана**: кнопка на панели инструментов.

### Поиск в Sight

Нажмите на лупу. Поддерживает все операторы: `links to [[X]]`, `links from [[X]]`, `mutual [[X]]`, `orphans`, `supports [[X]]`, `contradicts [[X]]`, `#tag`, свободный текст и семантический поиск. Результаты показывают направленные цвета: зелёный (входящий), красный (исходящий).

### Панель аналитики (SightPanel)

Нажмите на значок сетки, чтобы открыть боковую панель. Показывает: оценку Здоровья Вселенной (0-100), счётчики заметок/связей/сирот, полосы типов связей и уверенности, топ-10 мостов и Знаниевые инсайты (сильнейшие доказательства, слабые основания, напряжения, стагнирующие, наиболее связанные, пробелы в знаниях).

### Настройки

Значок шестерёнки: настройте толщину штриха связи, прозрачность и размер стрелки. Настройки сохраняются между сессиями.

### 8a. Поля традиции для каждой заметки (MIG-029)

Чип традиции в левом верхнем углу Sight позволяет переосмыслить купол через 24 научные традиции, распределённые на 10 эпистемических семейств. Для девяти из этих традиций (секторных / концентрических / лесенчатых форм) каждая заметка может быть **явно классифицирована** через поле во frontmatter. Заметки без этого поля попадают в разумную корзину по умолчанию для данной традиции; заметки С этим полем попадают в ту корзину, которую вы назвали.

Добавьте поле в YAML-frontmatter заметки:

```yaml
---
masadir_source: sunnah
---
```

Переключитесь на чип этой традиции → ваша заметка попадёт в её именованный сектор вместо значения по умолчанию.

**Разрешённые поля и значения:**

| Традиция | Поле frontmatter | Разрешённые значения | По умолчанию при отсутствии |
|---|---|---|---|
| **масадир (masādir)** (суннитское uṣūl al-fiqh) | `masadir_source` | `quran` / `sunnah` / `ijma` / `qiyas` | `quran` |
| **прамана (pramāṇa)** (индийская Nyāya) | `pramana_kind` | `pratyaksha` / `anumana` / `upamana` / `shabda` | `pratyaksha` |
| **Бурхан Ибн Рушда** | `burhan_kind` | `burhan` / `jadal` / `khataba` / `shir` | `shir` (внешнее кольцо) |
| **PaRDeS** (еврейская герменевтика) | `pardes_level` | `peshat` / `remez` / `derash` / `sod` | `peshat` |
| **Пирс** (3 фанероскопические категории) | `peirce_category` | `firstness` / `secondness` / `thirdness` | `firstness` |
| **Хабермас** (3 познавательных интереса) | `habermas_interest` | `technical` / `practical` / `emancipatory` | `technical` |
| **Менцианские ростки** (4 моральных ростка) | `mencian_sprout` | `ceyin` / `xiuwu` / `cirang` / `shifei` | `ceyin` |
| **Моистские саньбяо (sān biǎo)** (3 стандарта) | `mohist_zone` | `ben` / `yuan` / `yong` | распределено по хэшу на 3 зоны |
| **Корейский Сонъ-нихак** (дебаты Четырёх-Семи) | `songnihak_cell` | `li-sa` / `li-chil` / `qi-chil` / `qi-sa` | `li-sa` |

**Поведение:**
- Если вы напишете значение, которое традиция не распознаёт (опечатка или изобретённое), заметка попадает в корзину по умолчанию. Нет сбоев, нет ошибок отрисовки.
- Изменения frontmatter распространяются автоматически — сохраните заметку → следующая отрисовка купола отразит изменение.
- То же поле читается только своей именованной традицией. Установка `masadir_source: sunnah` на заметке не имеет эффекта, когда вы переключаетесь на PaRDeS или Пирса — каждая традиция читает своё собственное поле независимо.
- Это самый явный способ контролировать пространственную грамматику купола. Без этих полей геометрия правильна, но каждая заметка по умолчанию попадает в одну и ту же корзину; с ними чип становится аналитически значимым.

**Традиции без полей для каждой заметки** (в настоящее время группируют все звёзды другими средствами — папка / библиотека / хэш):

- Аристотелевская (по умолчанию, без переразметки)
- Полани (градиентный туман; без секторизации)
- Гуссерль, Лонжино, Макасид аш-Шатиби, Пророчество по Маймониду, 13 талмудических миддот, Ван Янмин, Плюриверсальное Миньоло, Трансмодерн Дусселя, Мальдонадо-Торрес, Акан Виреду, ‘Умран Ибн Халдуна, Ибуанидаанда

(Будущие миграции могут добавить поля frontmatter для каждой заметки и для этих традиций по мере появления спроса пользователей.)

## 9. Второй экран

Второй экран — это режимное окно-компаньон, которое адаптируется к текущему режиму боковой панели.

- **Открыть**: Нажмите на значок второго экрана в боковой панели или `Ctrl+Shift+2`
- **Автозакрытие**: При закрытии главного окна второй экран закрывается автоматически

### Режимный компаньон

Второй экран меняет своё содержимое в зависимости от активного режима боковой панели в главном окне:

| Режим боковой панели | Второй экран показывает |
|---|---|
| **Проводник** | Панель управления Вселенной — статистика, разбивка по библиотекам, дочерние вселенные, теги, недавно отредактированные/открытые заметки |
| **Навигатор** | Полный вид Навигатора для просмотра заметок |
| **Вид неба** | Дерево Вида неба со структурой каталогов |
| **Sky View** | Компаньон Sky View с обратными ссылками, прямыми ссылками, тегами и локальным графом |

### Панель управления Вселенной (Режим Проводника)

Когда главное окно находится в режиме Проводника, второй экран отображает панель управления с:

- **Карточки статистики** — Название вселенной, количество дочерних вселенных, общее количество библиотек, папок и заметок
- **Дочерние вселенные** — Каждая дочерняя вселенная с привязанными библиотеками и количеством папок/заметок
- **Библиотеки** — Каждая библиотека с количеством папок/заметок в цветных блоках статистики
- **Недавно отредактированные** — Заметки, изменённые в текущей сессии (отслеживается при сохранении)
- **Недавно открытые** — Заметки, которые вы открыли, но не редактировали в текущей сессии
- **Теги** — Все теги по всем библиотекам, отсортированные по количеству; щёлкните тег, чтобы увидеть все заметки с ним

### Взаимодействие с панелью

Когда панель управления активна в главном окне, нажатие на элементы отправляет их на второй экран:

- **Недавно отредактированные/открытые**: Нажмите на заметку, чтобы открыть её как полный редактор на втором экране
- **Теги**: Нажмите на тег, чтобы показать все заметки с ним в разделённом виде — список заметок слева, полный редактор справа

Все изменения на втором экране автоматически синхронизируются с главным окном.

### Редактирование заметок на втором экране

Второй экран поддерживает полное редактирование заметок — набирайте текст, сохраняйте, переименовывайте и изменяйте свойства так же, как в главном окне. Изменения автоматически синхронизируются с главным окном.

### Синхронизация настроек

Все визуальные настройки мгновенно передаются на второй экран — перезапуск не требуется:

- **Язык**: Изменения языка интерфейса применяются немедленно
- **Тема**: Светлый/тёмный/системный режим переключается мгновенно
- **Шрифты**: Шрифт интерфейса, текстовый шрифт, моноширинный шрифт и шрифты для конкретных скриптов
- **Размер шрифта**: Размеры шрифтов интерфейса и редактора
- **Редактор**: Читаемая длина строки, номера строк, плавающая панель инструментов
- **Цвет акцента**: Изменения цвета акцента темы

## 10b. Обзор Источника (Constellation Epistemic Content Engine — CECE)

> *(Примечание о переводе: машинный перевод раздела V3-§10.F; ожидается проверка носителем языка.)*

Два самых важных свойства frontmatter — `sources:` и `content_type:` — описывают, *как вы пришли к знанию* чего-либо и *какого рода это знание*. **Epistemic Content Engine** (CECE) Constellation автоматически классифицирует каждую заметку по этим двум осям, используя ансамбль из 6 каталогизаторов. Панель **Обзор Источника** — это место, где вы проверяете и исправляете эти классификации.

### Что делает движок

Когда вы классифицируете заметку (правый клик → «Предложить источники и тип контента», или через Настройки > Запустить сканирование, или автоматически через переключатель фонового сканирования), CECE запускает шесть независимых каталогизаторов против заметки. Каждый читает заметку через свою линзу и голосует по двум вопросам:

- **Источник** (горизонтальная ось) — откуда *пришло* это знание? Одиннадцать возможных значений: восприятие, вывод, свидетельство, массовая передача, сравнение, постулирование, неосознавание, память, врождённая склонность, вдохновение, откровение. Плюс *неклассифицируемое*.
- **Тип контента** (вертикальная ось) — какого *рода* это знание? Пять основных ветвей: сенсорные входы, символические сущности, семантическое содержание, эпистемические состояния, конструкции высшего порядка.

Две оси независимы. Заметка «Я сомневаюсь в высадке на Луну» — это свидетельство (кто-то сообщил об этом) по источнику + эпистемические состояния/сомнение (ваша позиция) по типу контента.

Движок работает **на вашем устройстве** — ни одна заметка никогда не покидает Constellation.

### Шесть каталогизаторов

Каждый каталогизатор — это линза. Карточка Обзора Источника показывает их как шесть маленьких цветных точек в правом верхнем углу каждой карточки:

- **Ваш frontmatter** (синий) — принимает то, что вы уже задали, с абсолютным авторитетом
- **Цитаты и структура** (розовый) — цитаты, блок-цитаты, маркеры теорем, фразы определений
- **Корни слов и лексика** (янтарный) — анализ арабских корней + межъязыковая эквивалентность терминов
- **Связанные заметки** (бирюзовый) — типизированные Living Links к другим классифицированным заметкам
- **Похожие заметки** (фиолетовый) — сходство по эмбеддингам с уже классифицированными вами заметками
- **Суждение ИИ** (зелёный) — локальный LLM (Qwen3-4B; *пока не активен*, отложен до будущей версии)

Заполненная точка означает, что этот каталогизатор высказался и согласен с синтезом. Точка с кольцом означает, что он высказался, но не согласился. Точка с пунктирным контуром означает, что он молчал (нет сигнала в этой линзе).

### Три режима доверия

После того как каталогизаторы проголосовали, каждая ось попадает в один из трёх режимов:

- **Единогласно** — все высказавшиеся каталогизаторы согласились
- **Сильное большинство (одно несогласие)** — большинство согласилось; один несогласный назван
- **Разделено** — нет чёткого большинства; движок отказывается гадать и просит вас выбрать

Каждая ось получает свой собственный режим независимо — карточка может быть Единогласной по горизонтали + Разделённой по вертикали и т. д.

### Sibling Disambiguation

Когда ось Разделена, движок выводит значения-кандидаты как **чипы** под подсказкой: *«Выберите, какой лучше всего подходит к заметке.»* Кликните по чипу → движок записывает этот выбор во frontmatter заметки и убирает карточку из очереди. Если ДРУГАЯ ось была решена (Единогласно или Сильное большинство), движок *также* записывает значение этой оси одновременно — один клик завершает обе оси, когда только одна была Разделена.

### Трасса рассуждений

У каждой карточки есть переключатель *«▸ Почему такая классификация?»*. При его раскрытии показывается одна строка на каждый высказавшийся каталогизатор с обоснованием, самооценкой уверенности и дружелюбными чипами правил («Совпадение поверхностного ключевого слова», «Совпадение арабского корня (CAE)», «Маркер определения» и т. д.) — это конкретные правила, которые сработали у каждого каталогизатора.

Во время ваших **первых 50 проверок** трасса автоматически раскрывается на каждой карточке (это *период калибровки доверия*), чтобы вы могли выработать интуицию, когда доверять движку. После этого трассы сворачиваются до показа по требованию на Единогласных карточках. Переопределите в любой момент в **Настройки > Интеллект > CECE > Видимость трассы рассуждений**.

### Фильтр состава очереди

Над полосой счётчика пять чипов нарезают очередь по типу решения, требуемого от каждой карточки:

- **Все** — полная очередь
- **Обе оси требуют вашего решения** — обе оси Разделены
- **Источник требует вашего решения** — горизонтальная Разделена + вертикальная решена
- **Тип контента требует вашего решения** — вертикальная Разделена + горизонтальная решена
- **Каталогизаторы согласились** — ни одна ось не Разделена (кандидаты на штамповку)

Каждый чип показывает счётчик своего сегмента. Фильтр — это нарезатель слоя рендеринга — математика «Принять Все» всегда работает с полной очередью, независимо от того, какой фильтр активен.

### Действия для карточки

- **Принять** — записать синтез движка как первичный по обеим осям; убрать карточку. Обновляет надёжность по каталогизатору.
- **Редактировать** — открывает древовидный селектор для обеих осей; выберите вручную. То же обновление надёжности.
- **Отклонить** — очищает карточку без записи.
- **Чип Sibling Disambiguation** — только на Разделённых карточках.

### Калибровка по Библиотеке

**Настройки > Интеллект > CECE > Калибровка по Библиотеке** открывает таблицу только для чтения, показывающую точность каждого каталогизатора по оси в активной Библиотеке. Разные Библиотеки имеют разную точность по каталогизатору — Лингвистический отлично работает на Библиотеках с большим количеством арабского, Граф отлично работает на плотно связанных. Слой синтеза использует эти данные калибровки для взвешивания голосов.

Каталогизатору требуется **20 исправлений**, прежде чем будет показано его соотношение точности. Ниже этого порога метка читается как *«(равномерно)»* — каталогизатор вносит голоса с равномерным весом, пока не накопится достаточно данных.

### Фоновая классификация

По умолчанию CECE классифицирует заметки только тогда, когда вы об этом просите (правый клик или кнопка сканирования в Настройках). Вы можете включить автоматическую классификацию в **Настройки > Интеллект > CECE > Фоновая классификация**:

- **При сохранении заметки** — классифицировать каждую заметку через ~1,5 секунды после того, как вы прекратите печатать (использует существующее сохранение с задержкой; никогда не срабатывает на каждое нажатие клавиши; ввод остаётся мгновенным)
- **При запуске приложения** — сканировать неклассифицированные заметки один раз за запуск

### Классификатор — полностраничный дом

Те же карточки также живут в полностраничном виде под названием **Классификатор**, открываемом из **иконки стопки карточек в доке слева**. Это тот же движок и та же очередь, которым отдано всё окно вместо узкой вкладки боковой панели — и он добавляет два элемента управления, которых у вкладки боковой панели никогда не было:

- **Классифицировать заметку…** — поле поиска, которое позволяет классифицировать *любую* заметку по имени, не открывая её сначала. Введите несколько букв, выберите заметку — и свежая карточка появится в очереди.
- **Создать все сводки** — предварительно вычисляет сводку заметки (см. ниже) для каждой заметки, у которой её нет, в фоне, с прогрессом в строке состояния.

Кнопка **Запустить сканирование** (то же общевселенское сканирование, что и в Настройках) и живая полоса прогресса дополняют заголовок. Закройте Классификатор через **(×)** или **Esc**. (Когда поле поиска *Классифицировать заметку…* открыто, первое **Esc** закрывает только это поле.)

Замечание об именах: **Классификатор** — это *комната* (полностраничный вид); **каталогизаторы** — это *шесть линз* внутри движка, которые голосуют по каждой карточке. Не путайте эти два понятия.

### Сводки заметок

Под заголовком каждой карточки располагается короткое **Резюме** — несколько предложений, говорящих вам, о чём заметка, чтобы вы могли классифицировать её, не открывая. Constellation всегда предпочитает сводку, которую написали *вы*, и генерирует свою только тогда, когда вы этого не сделали:

1. Поле **frontmatter** `summary:` / `description:` / `abstract:` / `excerpt:`, используемое дословно.
2. **Callout** `> [!summary]` / `[!abstract]` / `[!tldr]` в теле, используемый дословно.
3. Иначе — **сгенерированная** сводка: три самых центральных предложения заметки, извлечённые (а не придуманные) и показанные в исходном порядке.

Сгенерированные сводки доступны **только для чтения** — Constellation никогда не записывает их обратно в вашу заметку (File-Over-App), и всё вычисляется **на вашем устройстве**. Если вы хотите, чтобы сводка жила в файле, напишите её сами, и Constellation покажет вашу.

Для более детальных сведений (каждый статус точки, каждый чип правила, пошаговые сценарии) см. темы **Обзор Источника**, **Классификатор** и **Сводки заметок** в системе помощи.

## 10c. Эпистемические метаданные

Небольшой набор необязательных полей frontmatter для записи более богатой информации о том, как было получено знание заметки, кто придерживается позиции, к какой дисциплине она относится и когда вы в последний раз пересмотрели свою точку зрения. Добавлено в MIG-022 §A в ответ на gap-анализ (`docs/epistemic-content-gap-analysis.md`).

Эти поля **все необязательны**. Заметки без них работают без изменений.

### Краткий справочник

| Field | Type | Назначение |
|---|---|---|
| `held_by` | text | Чья это позиция? (по умолчанию `user`; может быть `"al-Shāfiʿī"`, `"Ḥanafī"` и т.д.) |
| `domain` | list | Дисциплинарные теги для извлечения (`[fiqh, ʿibādāt]`) |
| `function` | text | Для чего эта заметка (`reference` / `seed` / `actionable` / `shipped`) |
| `provenance_civilization` | text | Словарь традиции (`sunni-usuli` / `analytic-western` / `nyaya` и т.д.) |
| `updated_at` | date | Когда вы в последний раз обдуманно пересматривали свою точку зрения (отличается от mtime файловой системы) |
| `ikhtilāf` | list of objects | Структурированное научное несогласие (`[{school, position}, ...]`) |
| `warrant` | text | Метка градации (парсится, но инертна, пока не выйдет рабочий поток Warrant Research) |
| `warrant_notes` | text | Свободный текст, поддерживающий градацию warrant (также инертно) |

### Как они отображаются на панели Properties

Каждое поле отображается с подходящим для типа редактором:
- Текстовые поля → текстовый ввод
- `domain` → список тегов (Enter для добавления, × для удаления)
- `updated_at` → выбор даты
- **`ikhtilāf` → специальный виджет** с двумя расположенными рядом полями ввода в каждой строке (school + position) плюс кнопкой удаления для каждой строки и кнопкой «Добавить школу» внизу. Виджет читает из и записывает в структурированный YAML, поэтому при переходах туда-обратно сохраняется каждое поле.

### А что насчёт `supersedes`?

`supersedes` — это *отношение между заметками* (эта заметка заменяет более раннюю), а не свойство одной заметки. Constellation обрабатывает это как **типизированную ссылку**, а не YAML-скаляр:

```markdown
This replaces my earlier analysis: [[old-note-id|supersedes]]
```

Суффикс `|supersedes` на викилинке делает его типизированной ссылкой вида `supersedes` — отдельная пилюля грифельного сине-серого цвета, отображается в панелях Backlinks + Outgoing Links, участвует в Living Link Architecture.

### Чем это НЕ является

Новые поля — это **схема**, распознаваемый словарь, который вы можете заполнять. CECE в настоящее время не потребляет их для классификации. Будущие MIG (рабочий поток Warrant Research, временная ось MIG-023) выпустят функции, читающие `warrant`, `updated_at` и подобные.

Для более глубоких деталей и проработанного примера см. раздел **Epistemic Metadata** в системе справки.

## 17. Настройки

Откройте настройки через значок шестерёнки в боковой панели или `Ctrl+,`.

### Общие

- Язык (15 языков)
- Тема (Светлая / Тёмная)
- Шрифт интерфейса, шрифт текста, моноширинный шрифт, размер шрифта
- Тема шрифтов — предустановленные комбинации шрифтов (Печатная машинка, Классическая, Современная и др.) для быстрого переключения
- **Темы** — выберите из шести встроенных тем, создайте пользовательские темы (редактор пяти цветов), импортируйте темы из реестра сообщества Obsidian (200+ тем) или импортируйте файл темы `.json`. Удалите любую пользовательскую тему кнопкой ✕ при наведении.

### Style Settings

Отдельная вкладка для тонкой настройки каждого видимого элемента интерфейса, применяемая в реальном времени к активной теме.

- **Цвета** — фон, поверхности, текст (обычный/приглушённый/слабый), акцент, границы, цвета состояний
- **Типографика** — размеры шрифтов интерфейса/заметки/кода, размеры H1–H6, вес заголовков, межстрочные интервалы, расстояние между абзацами
- **Макет и форма** — малый/средний/большой радиусы углов, ширина границ, тени, читаемая длина строки редактора, боковые поля
- **Компоненты** — лента-док, боковая панель действий, панель макета (переключатели панелей), верхняя панель/полоса вкладок, строка состояния, правая боковая панель (инспектор), проводник файлов (заметки Вселенной, дочерние вселенные, библиотеки, папки, заметки), кнопки, теги, callouts — каждое с независимым размером, радиусом, цветом и стилем активного состояния, где применимо
- **Редактор** — цвет/hover/оформление ссылки, цвет/фон/радиус строчного кода, ширина/цвет полосы цитаты, цвет курсора, фон выделения

**Импорт / Экспорт** — панель инструментов в верхней части вкладки:
- Вставить из буфера обмена (один клик)
- Импорт / Вставить (текстовое поле с Объединить или Заменить)
- Из файла (.json)
- Копировать (текущие значения в буфер обмена)
- Экспорт (.json)

Формат точно соответствует плагину Style Settings в Obsidian, поэтому вы можете делиться настройками между Obsidian и Constellation.

Изменения автосохраняются в активную тему; если вы редактируете встроенную тему, она автоматически клонируется в ваши пользовательские темы, чтобы изменения сохранялись без изменения оригинала.

### Переопределения арабского

Панель на уровне Вселенной, где вы закрепляете, как арабский движок анализирует конкретные поверхностные формы — ваши собственные новообразования, локальные названия, заимствования из вашей области или случаи, когда вы не согласны с автоматическим прочтением движка. Каждое переопределение побеждает генеративный FST, каскад и эвристический резерв. Добавление или удаление переопределения запускает адресную переиндексацию только тех заметок, которые содержат затронутую поверхностную форму — без полной перестройки. См. §19 («Поддержка RTL и арабского языка») для пошагового руководства.

### Редактор

- Тип редактора (Markdown / Документный)
- Представление по умолчанию (Чтение / Редактирование)
- Режим живого предпросмотра
- Номера строк, направляющие отступов, проверка орфографии
- Автоматическое закрытие скобок, умные списки

### Библиотеки

- Добавление/удаление библиотек
- Индивидуальные настройки внешнего вида библиотек
- Расположение папки вложений

### Обновления

- Проверка обновлений
- Токен GitHub для обновлений из приватного репозитория

## 19. Поддержка RTL и арабского языка

Constellation обеспечивает первоклассную поддержку арабского, иврита, персидского, урду и других RTL-скриптов:

- **Автоопределение**: Направление заметки определяется автоматически по содержимому
- **Интерфейс**: Полный RTL-интерфейс при выборе арабского/иврита
- **Редактор**: Редактирование RTL-текста с правильным перемещением курсора и выделением
- **Sky View**: Арабские метки отображаются справа налево с корректным запасным шрифтом
- **Легенда**: Элементы меняют порядок точки/текста в зависимости от языка содержимого
- **Шрифты скриптов**: Настройте арабские, ивритские и CJK-шрифты независимо в настройках

### Настройка для арабского языка

1. Перейдите в **Настройки > Общие > Язык** и выберите арабский
2. По желанию задайте отдельный арабский шрифт в **Настройки > Общие > Шрифты скриптов**
3. Заметки с арабским содержимым будут автоматически отображаться в режиме RTL

### Переопределения арабского движка

Арабский движок Constellation — это пятислойный морфологический анализатор, работающий под каждым поиском, ссылкой и записью индекса. Он понимает корни, шаблоны, имена собственные, заимствования и фонологические ремонты — поэтому запрос к كاتب находит كتبنا и كتاب, но وائل остаётся целым как имя, а не искажается до ائل.

Панель **Переопределения арабского** в настройках — это место, где вы обучаете движок своей собственной терминологии. Каждое переопределение — суверенный ответ: оно побеждает генеративный FST, каскад и эвристический резерв.

**Когда использовать переопределения:**
- Личные имена, местные географические названия или термины из вашей области, которых движок не знает
- Новообразования или аббревиатуры, уникальные для вашей Вселенной
- Заимствования, где вы хотите сохранить определённое написание
- Любой случай, когда автоматический анализ движка расходится с тем, как вы читаете слово

**Пошагово:**

1. Откройте **Настройки** (значок шестерёнки или `Ctrl + ,` / `Cmd + ,`) и выберите **Переопределения арабского** в боковой панели.
2. Нажмите **Добавить переопределение**.
3. Заполните:
   - **Поверхностная форма** — арабское слово в том виде, как вы его вводите
   - **Лемма** — каноническая форма, которую должен возвращать движок
   - **Корень** (необязательно) — 3 или 4 согласных, если у слова есть классический корень
   - **Шаблон** (необязательно) — например, `فاعل`
   - **Часть речи** — Имя собственное / Существительное / Прилагательное / Наречие / Глагол / Частица / Иностранное / Неизвестно
   - **Заметка** (необязательно) — строка контекста для вас самих
4. Нажмите **Сохранить**. Панель показывает **Переиндексация…**, пока каждая заметка, содержащая поверхностную форму, заново токенизируется, затем **Переиндексировано заметок: N** по завершении.
5. Чтобы удалить переопределение, нажмите **×** в его строке — тот же обход переиндексации выполняется в обратную сторону.

Переопределения хранятся по Вселенным в `<universe>/.constellation/arabic-overrides.json` — обычный текст, отсортированный по алфавиту, атомарно записанный. Вы можете хранить файл в системе контроля версий или передавать его между устройствами.

## 21. Карта знаний

Карта знаний — это радиальная визуализация (sunburst), которая показывает структуру, плотность и зрелость всей вашей вселенной знаний.

### Открытие Карты

- **Кнопка дока**: Нажмите на значок Карты знаний в левой панели
- **Палитра команд**: `Ctrl+P`, затем введите "Constellation Map"

### Что вы видите

- **Центр**: Имя вашей Вселенной с общим количеством заметок и слов
- **Первое кольцо**: Библиотеки (каждая в своём цвете). Если у вашей вселенной есть дочерние вселенные, они тоже отображаются здесь.
- **Глубокие кольца**: Папки и подпапки внутри каждой библиотеки
- **Внешние сегменты**: Отдельные заметки

### Цветовые режимы

Переключайтесь между тремя режимами через выпадающее меню:
- **Зрелость**: семя (серый) → росток (светло-зелёный) → вечнозелёный (зелёный) → канонический (золотой) → увядающий
- **Страта**: L1 (синий) → L8 (красный) — показывает сложность знаний
- **Библиотека**: все сегменты наследуют цвет родительской библиотеки

### Навигация с углублением

Нажмите на сегмент папки для увеличения. Хлебные крошки показывают ваш путь. Нажмите на любой элемент крошек для возврата или нажмите Escape. Нажмите на сегмент заметки, чтобы открыть её в редакторе.

### Возврат к Карте

После открытия заметки из Карты в панели вкладок появляется кнопка "Вернуться к Карте". Нажмите её, чтобы вернуться точно туда, где вы были — уровень углубления сохраняется.

## 22. Когнитивный движок

Когнитивный движок — это встроенная интеллектуальная система Constellation, которая анализирует ваши заметки и выявляет скрытые закономерности и связи между идеями. Его ключевая философия:

> «Количество ваших данных не имеет значения. Важно не то, сколько источников вы храните, а то, как вы формируете из них своё знание и связываете его в единое осмысленное понимание.»

Когнитивный движок состоит из девяти интегрированных инструментов: Типизированные ссылки, Страты знаний, Жизненный цикл зрелости, Детектор напряжений, Цепочка происхождения, Движок экстернализации, Пульс обзора, Маршруты и Мультилинзовые виды.

---

### 17.1 Типизированные ссылки

#### Что это?

Типизированные ссылки — это вики-ссылки, несущие тип отношения, описывающий характер связи между двумя заметками. Вместо простого `[[заметка]]` вы пишете `[[заметка|тип-отношения]]`, чтобы выразить суть связи — является ли она производной? Противоречит? Расширяет?

#### Почему это важно?

Обычная ссылка говорит лишь «есть связь», но не говорит какая. Типизированные ссылки превращают вашу сеть заметок из нагромождения ссылок в настоящую карту знаний, делающую видимыми структуры мышления, зависимости и цепочки рассуждений между идеями.

#### Как использовать

1. Откройте заметку в редакторе
2. Напишите вики-ссылку с типом отношения: `[[Целевая заметка|derives-from]]`
3. Поддерживаемые типы: `derives-from` (производная от), `supports` (поддерживает), `contradicts` (противоречит), `extends` (расширяет), `exemplifies` (иллюстрирует), `questions` (ставит под вопрос)
4. Также можно добавить типы через свойства заметки на правой боковой панели

#### Где отображается?

- **Sky View (GraphMind)**: В виде цветных подписанных линий между узлами
- **Правая боковая панель**: Во вкладке «Обратные ссылки» с указанием типа каждой ссылки
- **Вкладка «Происхождение»**: Используется для построения древа генеалогии знаний

---

### 17.2 Страты знаний

#### Что это?

Когнитивный движок автоматически классифицирует каждую заметку в одну из восьми страт: Снимок, Журнал, Тема, Карта, Фреймворк, Принцип, Убеждение, Артефакт. Классификация основана на структуре, содержании и количестве ссылок заметки.

#### Почему это важно?

Знание типа каждой заметки раскрывает баланс знаний в вашей библиотеке. Большинство ваших заметок — мимолётные снимки или они развились в принципы и фреймворки? Это осознание природы контента — первый шаг к построению настоящего знания, а не просто накоплению информации.

#### Как использовать

1. Классификация происходит автоматически — ничего делать не нужно
2. Для переопределения автоматической классификации добавьте свойство `stratum` во frontmatter:
   ```yaml
   ---
   stratum: framework
   ---
   ```
3. Доступные значения: `snapshot`, `log`, `topic`, `map`, `framework`, `principle`, `conviction`, `artifact`

#### Где отображается?

- **Правая боковая панель**: В разделе свойств заметки под «Страта»
- **Sky View**: В виде различных цветов узлов по стратам
- **Настройки > Когнитивный движок**: Для включения/отключения автоматической классификации

---

### 17.3 Жизненный цикл зрелости

#### Что это?

Движок отслеживает уровень зрелости каждой заметки в четыре этапа: **Семя** → **Саженец** → **Вечнозелёная** → **Каноническая**. Каждая заметка начинается как семя и постепенно растёт с добавлением контента, ссылок и ревизий.

#### Почему это важно?

Зрелость отличает сырую идею от отшлифованного знания. Сегодняшнее семя может стать завтрашним эталоном, если уделить ему достаточно внимания. Отслеживание зрелости помогает выявить заметки, заслуживающие дальнейшего развития и внимания.

#### Как использовать

1. Зрелость изменяется автоматически на основе: количества слов, числа входящих и исходящих ссылок, даты последнего изменения
2. Для ручной установки зрелости добавьте свойство `maturity` во frontmatter:
   ```yaml
   ---
   maturity: evergreen
   ---
   ```
3. Доступные значения: `seed` (Семя), `sapling` (Саженец), `evergreen` (Вечнозелёная), `canonical` (Каноническая)

#### Где отображается?

- **Правая боковая панель**: Иконка рядом с заголовком показывает текущий этап зрелости
- **Sky View**: В виде размера узла — чем зрелее заметка, тем крупнее узел
- **Настройки > Когнитивный движок**: Для включения/отключения отслеживания зрелости

---

### 17.4 Детектор напряжений

#### Что это?

Детектор напряжений проверяет связанные заметки и предупреждает, когда утверждения или выводы в двух или более заметках противоречат друг другу. Он опирается на анализ типизированных ссылок `contradicts` и тематическое сходство между заметками.

#### Почему это важно?

Напряжения — это не обязательно ошибки, а приглашения к более глубокому размышлению. Когда две идеи в вашей библиотеке противоречат друг другу, это означает, что ваше понимание эволюционировало или существует сложность, достойная исследования. Обнаружение напряжений защищает вас от неосознанного построения знания на противоречивых основаниях.

#### Как использовать

1. Добавьте типизированную ссылку `contradicts` между противоречащими заметками: `[[Другая заметка|contradicts]]`
2. Движок также обнаруживает неявные напряжения через анализ контента
3. Просмотрите список обнаруженных напряжений на боковой панели

#### Где отображается?

- **Правая боковая панель**: Во вкладке «Напряжения» при обнаружении противоречий
- **Sky View**: В виде красных пунктирных линий между конфликтующими узлами
- **Панель уведомлений**: Оповещения при обнаружении нового напряжения

---

### 17.5 Цепочка происхождения

#### Что это?

Цепочка происхождения отслеживает истоки каждой идеи — откуда она пришла и из чего была выведена. Она использует ссылки `[[заметка|derives-from]]` для построения генеалогического древа, показывающего путь развития знания от первоисточника до текущей формулировки.

#### Почему это важно?

Знание происхождения своих идей отличает полученное знание (из книг, статей, лекций) от открытого знания (ваши собственные выводы и размышления). Это осознание источника знаний помогает оценить надёжность идей и понять, как формировалось ваше мышление со временем.

#### Как использовать

1. При создании заметки, производной от источника, добавьте ссылку: `[[Оригинальный источник|derives-from]]`
2. Возможно построение многоуровневых цепочек: заметка ← производная от ← производная от ← первоисточник
3. Классифицируйте внешние источники, добавив `source-type: received` во frontmatter

#### Где отображается?

- **Правая боковая панель**: Вкладка «Происхождение» показывает полное генеалогическое древо
- **Sky View**: В виде направления стрелок на ссылках (от источника к производной)
- **Свойства заметки**: Классификация как «полученная» или «открытая» на основе цепочки происхождения

### 17.6 Движок экстернализации

#### Что это?

Поэтапный конвейер формализации, отслеживающий созревание заметок от сырых записей до кристаллизованных идей. Каждой заметке можно назначить одну из четырёх стадий:

| Стадия | Значок | Значение |
|--------|--------|----------|
| Мимолётная | 🌱 | Быстрая запись, мимолётная мысль |
| Литература | 📖 | Переписано из источника своими словами |
| Постоянная | 🔗 | Атомарная идея, одна концепция, связанная с графом |
| Синтез | ✨ | Оригинальное озарение, объединяющее несколько постоянных заметок |

#### Почему это важно?

Большинство приложений относятся ко всем заметкам одинаково. Движок экстернализации делает различие видимым — вы можете сразу увидеть, какая часть библиотеки является сырыми записями, а какая — подлинным пониманием.

#### Как использовать

1. В панели навигации (над редактором) используйте выпадающий список стадий для выбора стадии.
2. Или разверните Свойства и используйте выпадающий список стадий там. Оба мгновенно синхронизируются с деревом файлов.
3. Для продвижения заметки измените выпадающий список с одной стадии на следующую. В режиме фокуса нажмите «Повысить до Постоянной» внизу.
4. Для удаления стадии выберите «— Стадия —» из выпадающего списка.

#### Где отображается?

- **Панель навигации**: выпадающий список с эмодзи + название стадии
- **Панель свойств**: выпадающий список при наличии свойства `stage`
- **Дерево файлов**: значок эмодзи рядом с именем заметки
- **Нижняя панель режима фокуса**: кнопка «Повысить до Постоянной»

### 17.7 Пульс обзора

#### Что это?

Пульс обзора — это система интервального повторного появления, которая возвращает заметки в поле вашего внимания через увеличивающиеся интервалы: 1 день, затем 3, затем 7, затем 14, затем 30 дней после последнего обзора. Также отслеживает заметки с тегами `#assumption` или `#model` как контрольные точки ментальных моделей и поддерживает очередь «Никогда не просматривались» для захваченных, но ни разу не пересмотренных заметок.

#### Почему это важно?

Знание угасает без повторного обращения. Вы пишете заметку сегодня, а через три недели забываете о её существовании. Интервальное повторение — наиболее подтверждённая техника в когнитивной науке для борьбы с этим угасанием. Пульс обзора применяет этот принцип к вашим реальным заметкам.

#### Как использовать

1. Нажмите на вкладку **Пульс обзора** в левой боковой панели. Вы увидите три раздела: Ожидают обзора, Контрольные точки ментальных моделей (`#assumption` / `#model`), и Никогда не просматривались.
2. Нажмите на любую заметку, чтобы открыть и прочитать её.
3. Выберите одно из трёх действий:
   - **Просмотрена** (галочка) — планирует следующий обзор через следующий интервал (1 → 3 → 7 → 14 → 30 дней).
   - **Отложить на 7 дней** (значок глаза) — откладывает заметку на 7 дней без продвижения интервала.
   - **Убрать** (значок архива) — навсегда удаляет заметку из очереди обзора.
4. Откройте палитру команд и введите "Review due notes" для быстрого перехода к ожидающим заметкам.

#### Где отображается?

- **Левая боковая панель**: Вкладка Пульс обзора со счётчиком ожидающих заметок
- **Палитра команд**: Команда "Review due notes" для быстрого доступа

### 17.8 Маршруты

#### Что это?

Маршруты — это именованные упорядоченные последовательности заметок, подобные главам книги или остановкам на экскурсии по вашим знаниям. Определяются добавлением `trail: true` в frontmatter заметки и перечислением вики-ссылок по порядку в теле заметки.

#### Почему это важно?

Знание — это не всегда сеть. Иногда это путь — последовательность обучения, развитие аргумента, повествование. Маршруты фиксируют этот порядок явно, добавляя линейное измерение в вашу нелинейную библиотеку.

#### Как использовать

1. Создайте новую заметку с `trail: true` в frontmatter.
2. В теле заметки перечислите вики-ссылки в нужном порядке.
3. При открытии заметки, принадлежащей маршруту, в навигационной панели появляется индикатор с названием маршрута и позицией (например, «Мой маршрут 2/5»). Кнопки со стрелками позволяют перейти к предыдущей и следующей заметке.
4. Откройте палитру команд и введите "Open Trail", чтобы увидеть все маршруты.

#### Где отображается?

- **Навигационная панель**: Индикатор маршрута с названием, позицией и стрелками навигации
- **Палитра команд**: Команда "Open Trail" показывает все маршруты

### 17.9 Мультилинзовые виды

#### Что это?

Мультилинзовые виды позволяют просматривать вашу библиотеку через различные схемы классификации — без изменения структуры папок или дублирования заметок. «Линза» — это виртуальная группировка, которая реорганизует заметки на основе свойства или тега. Встроенные линзы: «По стадии» (Мимолётная/Литературная/Постоянная/Синтез) и «По теме» (группировка по тегам). Пользовательские линзы можно создать в Настройках.

#### Почему это важно?

Структуры папок навязывают единственную иерархию, но знание не умещается в одно дерево. Мультилинзовые виды позволяют переключаться между разными перспективами без перемещения файлов. Те же заметки, через разные организационные линзы.

#### Как использовать

1. В боковой панели найдите **выпадающий список линз** вверху дерева файлов (по умолчанию «Папки»).
2. Выберите линзу: «По стадии», «По теме» или пользовательскую линзу. Боковая панель мгновенно реорганизуется.
3. Выберите «Папки» для возврата к стандартному дереву файлов.
4. Для создания пользовательской линзы: откройте **Настройки > Управление знаниями**, нажмите **Создать линзу**, назовите её и выберите свойство frontmatter для группировки.
5. Или используйте палитру команд: введите "Create Lens".

#### Где отображается?

- **Выпадающий список в боковой панели**: Переключатель линз вверху дерева файлов
- **Настройки > Управление знаниями**: Создание, редактирование и удаление пользовательских линз
- **Палитра команд**: Команда "Create Lens"

### Настройки когнитивного движка

Все инструменты когнитивного движка настраиваются в **Настройки > Когнитивный движок**:

- **Классификация страт** — Включить или отключить автоматическую классификацию
- **Отслеживание зрелости** — Включить или отключить отслеживание жизненного цикла зрелости
- **Типизированные ссылки** — Настроить порог чувствительности обнаружения ссылок (0.0 – 1.0)
- **Детектор напряжений** — Включить или отключить автоматическое обнаружение напряжений
- **Ручное переопределение** — Добавьте свойства `stratum` и `maturity` в frontmatter для переопределения автоматической классификации
