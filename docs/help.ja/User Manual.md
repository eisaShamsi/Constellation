# Constellation ユーザーマニュアル

**バージョン 0.1.0 | 2026年3月**

Constellation は、Markdown ノートライブラリを管理するためのパーソナルナレッジマネジメント（PKM）デスクトップアプリケーションです。Tauri v2、SvelteKit、Rust で構築されており、Windows、macOS、Linux 上でネイティブに動作し、アラビア語および RTL を完全サポートしています。

## 1. はじめに

### インストール

[Constellation リリースページ](https://github.com/eisaShamsi/Constellation/releases) から最新のインストーラーをダウンロードしてください：

- **Windows**: `.exe`（NSIS）または `.msi` インストーラー
- **macOS**: `.dmg` ディスクイメージ
- **Linux**: `.AppImage` または `.deb` パッケージ

### 初回起動

Constellation を初めて開くと、**ユニバースセットアップウィザード**が以下の手順を案内します：

1. **言語を選択** — 15言語対応
2. **ライブラリを作成またはインポート** — 既存の Markdown ファイルフォルダを指定するか、新しく作成
3. **ユニバースに名前を付ける** — ユニバースはすべてのライブラリのコンテナです

### インターフェース概要

| 要素 | 説明 |
|------|------|
| **サイドバー（リボン）** | ナビゲーションボタン：ファイルツリー、検索、スタービュー、カレンダー、テンプレート、設定 |
| **ファイルツリー** | ライブラリ内のノートとフォルダを閲覧 |
| **エディター** | Markdown ノートの閲覧と編集 |
| **タブバー** | 複数のノートをタブで開く |
| **ステータスバー** | 文字数、単語数、読了時間 |

## 2. ユニバースとライブラリ

### ユニバースとは？

**ユニバース**は、すべてのライブラリを格納するトップレベルのコンテナです。ワークスペースやライブラリコレクションと考えてください。

### ライブラリとは？

**ライブラリ**は、Markdown（`.md`）ファイルを含むコンピュータ上のフォルダです。1つのユニバースに複数のライブラリを持つことができます。例えば、仕事用ノートと個人用ノートを別々のライブラリにできます。

### ライブラリの管理

- **ライブラリを追加**: 設定 > ライブラリ > ライブラリを追加、またはフォルダをアプリにドラッグ
- **ライブラリを削除**: 設定 > ライブラリ > ライブラリ名の横にある削除ボタンをクリック
- **ライブラリ設定**: 各ライブラリに独自の外観設定（フォント、色）を適用できます

### 同期と外部からの変更

Constellation は **File Over App** の原則に従います — あなたのノートはディスク上の素の `.md` ファイルであり、アプリはそれらの変更を監視しています。アプリを開いている間に、Constellation の *外部* からノートが追加されたり変更されたりした場合 — 別のデバイスからの Obsidian 同期、`git pull`、クラウド同期ツール（iCloud / Syncthing / OneDrive）、あるいはライブラリフォルダに直接ドロップしたファイルなど — Constellation は **再起動なし** で、約1秒以内に、それを**自動的に**取り込みます：

- そのノートが**ファイルツリー**に表示されます。
- **スタージャンプ（クイックオープン、`Ctrl+O`）**、**検索**、**インデックス**、**バックリンク**、そしてライブラリの**ノート数**から見つけられるようになります — すべてが自動的に更新されます。
- アプリの外部でフォルダ名を変更した場合でも、そのノートは新しい場所で引き続き見つけられ、古いエントリは整理されます。
- 大量の一括処理（多数のノートの `git pull` や初回同期）はバックグラウンドでインデックス化されます — 検索が追いつく間も、入力は瞬時のままです。

特に何かをする必要はありません：Constellation は、ディスク上でファイルが変化するのに合わせて検索インデックスを常に同期させ続けます。*（ひとつだけ補足：アプリの **外部** でフォルダ名を変更すると、そのノートのレビュースケジュールとリンク重みの履歴はリセットされます — ノートのテキスト自体はそのまま保持されます。Constellation の **内部** でフォルダ名を変更した場合は、すべてが保持されます。）*

**変更されたノートが現在タブで開かれている場合**、Constellation はそれを安全に最新の状態へと更新します — あなたの作業が黙って上書きされることは決してありません：

- そのノートに**未保存の変更がない**場合、開いているノートはひっそりと再読み込みされて外部での編集内容を表示します。そのため、次にキーを入力すると、その編集は新しいバージョンの上で続きます。*（以前は、開いているノートが古いテキストを表示し続け、次に入力した一文字が外部の編集を黙って上書きしてしまうことがありました — これはもう起こりません。）*
- そのノートに**未保存の編集がある**まさにその瞬間に外部からの変更が届いた場合 — これは正真正銘の競合です — Constellation があなたの未保存の作業に手を触れることは決してありません。**あなたの**バージョンをエディターに保持したまま、届いた外部バージョンをノートの隣に**サイドコピー**として書き出し（`<note>.conflict-<timestamp>.md.txt` という名前なので、何も失われることはありません）、次のバナーを表示します：*「{note} への外部からの編集は、別のコピーとして保持されました — あなたのバージョンは変更されていません。」* **「コピーを表示」**をクリックすると、そのサイドコピーのあるフォルダが開き、必要に応じて手作業でマージできます。サイドコピーは何もしない（不活性な）`.txt` ファイルです — サイドバーや検索に現れることはなく、別の同期を引き起こすこともありません。

### 子ユニバース

ユニバースの中にユニバースをネストできます。**子ユニバース**は、親ユニバースから参照される別のユニバースフォルダです。子ユニバースのノートは、スタービューで自分のノートと一緒に表示され、ライブラリ間のリンクは破線で示されます。

### 自動再オープン

Constellation は最後にアクティブだったユニバースを記憶し、起動時に自動的に再オープンします。ユニバースが移動されたりパスが変更された場合、Constellation はそれを検出してパスを自動的に修正します。

### ポータブルユニバース

Constellation のユニバースは完全にポータブルです。ユニバースフォルダを別のドライブ、USBメモリ、または別のコンピュータなど、任意の場所に移動でき、Constellation は再度開いた際にすべての内部パスを自動的に検出して修正します。

ユニバースを移動するには：
1. Constellation を閉じる
2. ユニバースフォルダを新しい場所に移動またはコピーする
3. Constellation を開く → ウェルカム画面が表示される（古いパスは無効）
4. **既存のユニバースを開く**を選択し、新しい場所を指定する
5. すべてのノートとライブラリが即座に表示される — パスは自動修正されます

ユニバースのフォルダ構造は Obsidian モデルに従います：ノートはルートフォルダに直接配置され、設定は `.constellation/` に格納されます。

## 3. ノートの作成と編集

### ノートの作成

| 方法 | 操作 |
|------|------|
| **キーボード** | `Ctrl+N` |
| **ファイルツリー** | フォルダを右クリック > 新規ノート |
| **ミッションコントロール** | `Ctrl+P` > 「新規ノート」 |

### 再起動時のタブ復元

これまでは、Constellation を閉じるとどのノートを開いていたかは忘れられ、起動のたびに白紙の状態から始まっていました。現在は、開いていたタブ、アクティブだったタブ、そしてウィンドウが分割されていたかどうかをアプリが記憶し、次回の起動時に自動的に元へ戻します。机の上は、あなたが離れたときのままです。

- この記憶は**ユニバースごと**に保持され、タブを開く・閉じる・並べ替えるたびに約1秒後にひっそりと更新されます。クラッシュや強制終了で失われるのは、最大でも直前1秒分の*タブ配置*だけです — ノートの内容が失われることは決してありません（内容の保護は、これとは別の以前からある仕組みが担っています）。
- アプリを閉じている間に移動または削除されたノートは単にスキップされ、残りのタブはそのまま戻ってきます。
- オフにするには：**設定 > エディター > 再起動時にタブを復元**。オフにすると保存されたセッションも削除されます — オフとは*記憶をやめる*ということです。
- 名前付き**ワークスペース**には影響しません：ワークスペースは、あなたが意図して手動で保存したスナップショットのままです。この機能はあくまで、常に更新され続ける「最後の状態」にすぎません。
- 既知の制限：分割ビューでは、分割そのものは復元されますが、どのタブが左右どちら側にあったかはまだ記憶されません。

### エディターモード

Constellation には、**設定 > エディター > エディタータイプ**で選択できる2つのエディターモードがあります：

#### Markdown エディター（CodeMirror）

パワーユーザー向けのデフォルトエディターです。Markdown を直接記述できます：

- **ライブプレビュー** — 入力中にフォーマットをインラインでレンダリング
- **ソースモード** — 生の Markdown 構文を表示
- **フォーマットツールバー** — テキスト選択時に表示
- **スラッシュコマンド** — `/` を入力してクイック挿入
- **Wikilink 自動補完** — `[[` を入力してノートをリンク
- **マルチカーソル** — `Alt+Click` または `Ctrl+D`

#### ドキュメントエディター（TipTap）

ビジュアルツールバーを備えた WYSIWYG ワープロ体験：

- 太字、斜体、下線、取り消し線、ハイライト
- 見出し（H1～H3）、テキスト揃え
- 箇条書き、番号付きリスト、タスクリスト
- 引用、コードブロック、水平線
- テーブル（挿入、行と列の追加/削除）
- リンクと画像

両方のエディターは標準 Markdown ファイルとして保存されます。データを失うことなくいつでも切り替えできます。

### コールアウト (Callouts)

メモ、警告、ヒントなどのスタイル付きコールアウトブロックを作成できます：

```markdown
> [!note] 重要な情報
> コールアウトの内容をここに記述します。

> [!warning] 注意
> この操作は元に戻せません。

> [!tip]- クリックして展開
> 折りたたみ可能なコールアウトの内容。
```

対応タイプ: `note`、`tip`、`warning`、`danger`、`success`、`question`、`failure`、`bug`、`example`、`quote`、`abstract`。各タイプには独自の色とアイコンがあります。タイプの後に `-` を追加すると折りたたみ可能になります（折りたたまれた状態で開始）。`+` で展開された状態で開始します。

#### コールアウトのカスタマイズ — 色、アイコン、独自のタイプ

コールアウトの色とアイコンは自由に変更でき、独自のコールアウトタイプを作ることもできます。スタイルセッター（ドックの 🎨 ボタン）を開き、エディターカテゴリを選んでから「コールアウト」をクリックします。中央に1つのコールアウトマネージャーが開き、各コールアウトが色・アイコン・名前を示す1行として表示されます。

- 組み込みコールアウトの色を変える。その行の色スウォッチをクリックします。小さなパレットが開き、保存済みの色（クリックすると適用）と、新しい色を選ぶための「カスタム…」ピッカーが表示されます。選んだ色は次回のためにパレットにも追加されます。組み込みタイプの色変更は、スタイルセッターで「保持／適用」を押したときに保存されます。
- 組み込みコールアウトのアイコンを変える。その行のアイコンをクリックします。絵文字＆アイコンライブラリが開くので、好きな絵文字やベクターアイコンを選びます。すぐにどこでも、そのコールアウトの色で変更されます。小さな ↺ が表示され、そのアイコンだけを元に戻せます。
- 組み込みをリセットする。マネージャー上部の「↺ この要素をリセット」ボタンで、組み込みコールアウトの色とアイコンをすべて既定値に戻します。（独自のコールアウトはそのまま残ります — それらは個別に削除してください。）
- 独自のコールアウトタイプを作る。区切り線の下に追加行があります。名前（例: Decision、または فكرة）、トリガーワード（入力する [!word] — アラビア語を含むあらゆる言語が使えます）を入力し、色とアイコンを選んで「追加」をクリックします。これで、どのノートでも > [!decision]（または > [!فكرة]）と入力するとあなたのコールアウトが表示されます。トリガーの後にタイトルを入力しない場合、コールアウトのヘッダーにはコールアウトの名前が太字で表示されます。
- 独自のコールアウトを編集／削除する。その行の ✎（名前／トリガーを編集）と ✕（削除）を使います。タイプを削除しても、ノート内の [!…] テキストはそのまま残ります — タイプを作り直すまでは、単に通常のノートの見た目に戻るだけです。

独自のコールアウト、色、アイコンはこの Universe とともに保存されるので、ライブラリと一緒に持ち運べます。

### ハイライト構文

テキストを二重イコールで囲むとハイライトできます：

```markdown
これはノート内の==ハイライトされたテキスト==です。
```

ライブプレビューでは、`==` マークは非表示になり、テキストが黄色い背景で表示されます。

### コードブロック

フェンス付きコードブロックは背景色と言語ラベル付きで表示されます：

````markdown
```javascript
const greeting = "Hello, world!";
```
````

言語名がコードブロックの上にバッジとして表示されます。

### 画像の埋め込み

ノートに画像を直接埋め込むことができます：

```markdown
![代替テキスト](https://example.com/image.png)   — 外部 URL
![[photo.jpg]]                                     — ライブラリ内のローカルファイル
```

ライブプレビューでは、画像がインラインで表示されます。ローカル画像はライブラリフォルダー内にある必要があります。外部画像にはインターネット接続が必要です。

### テーブルツールバー

カーソルが markdown テーブル内にあるとき、フローティングツールバーが表示されます：

- **+ 行 / + 列** — 行または列を追加
- **- 行 / - 列** — 行または列を削除
- **配置** — 列ごとに左揃え、中央揃え、右揃え
- **ソート** — 現在の列で昇順または降順にソート
- **Tab / Shift+Tab** — テーブルセル間を移動

### テキストフォーマットショートカット

| ショートカット | 操作 |
|----------------|------|
| `Ctrl+B` | 太字 |
| `Ctrl+I` | 斜体 |
| `Ctrl+Shift+S` | 取り消し線 |
| `Ctrl+Shift+H` | ハイライト |
| `Ctrl+K` | Wikilink を挿入 |
| `Ctrl+Z` | 元に戻す |
| `Ctrl+Shift+Z` | やり直し |

### ノートのリンク

`[[` を入力するとノート自動補完が開きます。ノート名を入力し、候補から選択してください。リンクはクリック可能な Wikilink として表示されます：`[[ノート名]]`。

特定の見出しにリンクすることもできます：`[[ノート名#見出し]]`。

### 保存と復旧

Constellation は入力中に**自動的に保存**します — 保存ボタンはありません。編集内容は、入力を止めた少し後に（また、ノートを切り替えたときやタブを閉じたときにも）`.md` ファイルへ書き込まれます。ノートが「保存済み」と表示されるのは、実際にディスクへ書き込まれた後だけです。

万一、保存に**失敗**した場合 — たとえば同期ツール（iCloud / OneDrive / Syncthing）やウイルス対策ソフトが一時的にファイルをロックしたとき — でも、Constellation があなたの作業を**失うことはありません**：

- 画面上部にバナーが表示されます：*「{note} を保存できませんでした — 編集内容は安全に保持され、再試行されます。」* 入力した内容は画面に残ったまま、メモリ内（および再起動後も残る復旧バッファ内）に安全に保持されます。
- Constellation は**数秒ごとに自動で再試行**するため、ファイルのロックが解けさえすれば、その場を離れていても編集内容はひとりでに書き込まれます。
- バナー上の**「再試行」**をクリックして、すぐに保存することもできます。ノートが保存されると、バナーは消えます。

ファイルがロックされたり一時的に利用できなくなったりして編集内容が失われる、といった心配をする必要は一切ありません。

### ファイルエクスプローラー（ファイルツリー）

サイドバーの**ファイルエクスプローラー**は、ライブラリのノートとフォルダをそのまま階層ツリーで表示します。ノートを開くだけでなく、ファイルの探索・整理をここで完結できるよう、フィルター、並べ替え、複数選択、一括操作を備えています。

（以前は「ノートナビゲーター（リストモード）」と呼ばれる、別の一覧表示モードがありました。このモードは廃止され、そのファイル管理機能はすべてファイルエクスプローラーに統合されています。ツリー表示と組織図表示が現在のモードです。）

#### フィルター（名前で絞り込み）

ツリー上部のフィルターボックスに文字を入力すると、**名前が一致するノートとフォルダだけ**が表示に残ります。

- 絞り込みは**名前のみ**が対象です。ノートの本文は検索しません（本文検索は「検索」または Search Hub の役割です）。
- フィルターは**すべてのライブラリ**を横断します。折りたたまれているライブラリも自動的に読み込まれて一致箇所が展開表示され、フィルターをクリアすると元の折りたたみ状態に戻ります。
- フィルターボックスを空にすると、通常のツリー表示に戻ります。

#### 並べ替え（ソート）

ツリーを8種類の順序で並べ替えられます。**フォルダは常に先頭にまとめて**表示されます。

| 並べ替え | 説明 |
|----------|------|
| 名前（A→Z） | 名前の昇順 |
| 名前（Z→A） | 名前の降順 |
| 更新日時（新しい順） | 最近更新したものが上 |
| 更新日時（古い順） | 古い更新のものが上 |
| 作成日時（新しい順） | 最近作成したものが上 |
| 作成日時（古い順） | 古い作成のものが上 |
| サイズ（大きい順） | ファイルサイズの大きいものが上 |
| サイズ（小さい順） | ファイルサイズの小さいものが上 |

#### 複数選択

複数のノートやフォルダをまとめて扱えます。

- **`Ctrl`（macOS では `⌘`）+ クリック** — 対象の選択をオン／オフに切り替えます。
- **`Shift` + クリック** — 直前にクリックした項目から範囲選択します。
- **通常のクリック** — これまで通りノートを開きます（選択ではなく開く操作）。
- **`Escape`** — すべての選択を解除します。
- 選択された行はハイライト表示されます。

#### 一括操作バー

1つ以上を選択すると、選択件数と操作を示す**一括操作バー**が表示されます。

- **タグを追加** — 選択したすべてのノートにタグを付与します。
- **移動** — 選択した項目を別のフォルダへ移動します。
- **削除** — 選択した項目を削除します（ゴミ箱経由で、復元可能）。

各操作は、単一ノートに対して行うときと同じ安全な処理を経由します。読み取り専用の子ユニバースのノートは、一括操作の対象から自動的に除外されます。

## 4. 検索

Constellation には、SQLite FTS5 ベースの BM25 ランキング、構造化クエリフィルター、アラビア語最適化正規化を備えたハイブリッド多言語検索エンジンが搭載されています。検索はサイドバーツールバーからアクセスできます。

### 検索方法

サイドバーツールバーの検索アイコンをクリックするか、`Ctrl+Shift+F` で検索モードを有効にします。クエリを入力すると、短いディレイ（300ms）の後に結果が表示されます。`Escape` を押すか `×` ボタンをクリックすると、検索がクリアされファイルツリーに戻ります。

### 検索構文

| 構文 | 例 | 検索対象 |
|------|-----|---------|
| フリーテキスト | `プロジェクト管理` | タイトルまたは本文にそれらの単語を含むノート |
| タグフィルター | `#研究` | `#研究` タグが付いたノート |
| プロパティフィルター | `status=active` | frontmatter プロパティ `status` が `active` のノート |
| ウィキリンクフィルター | `links to [[気候]]` | `[[気候]]` にリンクしているノート |
| ライブラリ範囲 | `in:マイライブラリ` | 結果を特定のライブラリに限定 |
| 組み合わせ | `#研究 status=active 経済` | すべてのフィルターを同時に適用 |

### マッチタイプバッジ

各検索結果には、マッチがどのように見つかったかを示す色付きバッジが表示されます。バッジにはアクセシビリティのためにローカライズされた文字が表示されます（色覚対応）：

| バッジ | 色 | 意味 |
|--------|-----|------|
| **タ** | 青 | タイトルマッチ — 検索語がノート名に含まれている |
| **コ** | 緑 | コンテンツマッチ — 検索語がノート本文に含まれている |
| **セ** | 紫 | セマンティックマッチ — 概念的に関連（embeddingモデルが必要） |
| **プ** | 琥珀 | プロパティマッチ — frontmatter プロパティフィルターで検出 |
| **#** | ピンク | タグマッチ — タグフィルターで検出 |
| **ウ** | 水色 | ウィキリンクマッチ — ウィキリンクフィルターで検出 |

バッジ文字はサポートされている全15言語でローカライズされています。

### ピン留め結果（結果間のナビゲーション）

検索結果はクリック後も表示されたままです。開いたノートは結果リストでハイライトされ、どの結果を表示しているか確認できます。再検索せずに別の結果をクリックしてナビゲートできます。

検索をクリアするには、`Escape` を押すか `×` ボタンをクリックします。

### キーボードナビゲーション

| キー | アクション |
|------|-----------|
| `下矢印` | 次の結果を選択 |
| `上矢印` | 前の結果を選択 |
| `Enter` | 選択した結果を開く |
| `Escape` | 検索をクリアしてファイルツリーに戻る |

### 検索語のハイライト

検索結果からノートを開くと、検索語のすべての出現箇所がエディタでハイライトされます。アラビア語のダイアクリティカルマーク対応マッチングが機能し、「ادارة」を検索すると「إدارة」とすべてのダイアクリティカルバリエーションがハイライトされます。

### 検索履歴

検索フィールドが空の時にクリックすると、最近の検索（過去20件）が表示されます。各エントリにはクエリテキストと実行時間が表示されます。任意のエントリをクリックするとその検索を即座に再実行します。下部の「履歴をクリア」リンクですべての履歴を削除できます。

検索履歴はデバイスにローカル保存され、アプリの再起動間で保持されます。

### Search Hub

Search Hubはフルスクリーンの検索体験です。ドックバーの虫眼鏡アイコンをクリックして開きます。両方のサイドバーが折りたたまれ、最大限のスペースが確保されます。任意の用語を入力すると、Constellationが同時にすべての場所を検索し、結果を5つのカテゴリに分類します：タイトル、コンテンツ、タグ、プロパティ、ウィキリンク。各カテゴリにはカウントバッジ付きの折りたたみ可能なセクションがあります。任意の結果をクリックすると、すべての出現箇所がハイライトされた状態でエディタで開きます。「Search Hubに戻る」ボタンが表示され、再検索せずに戻ることができます。

### リンクオペレーター

Constellationは6つのリンクトポロジー検索オペレーターをサポートしています：

| 構文 | 何を見つけるか |
|------|---------------|
| `links to [[X]]` | Xにリンクしているノート（バックリンク） |
| `links from [[X]]` | Xがリンクしているノート（アウトゴーイングリンク） |
| `mutual [[X]]` | Xにリンクし、Xもリンクバックするノート（双方向） |
| `mentions [[X]]` | [[ウィキリンク]]なしでXの名前を含むノート |
| `orphans` | 受信リンクも送信リンクもないノート |
| `links between [[X]] and [[Y]]` | XとYの両方にリンクするノート |

リンクオペレーターを入力する際、`[[`オートコンプリートがユニバース内のすべてのノートを表示します。ノートを選択した後、見出し補完には`#`を、リンクタイプ補完には`|type:`を入力してください。

## 5. スタービュー (GraphMind)

スタービューは、**GraphMind** エンジン（Pixi.js WebGL）を使用して、ノートをインタラクティブな3Dグラフとして可視化します。

### スタービューを開く

- サイドバーのグラフアイコンをクリック
- `Ctrl+G` を押す
- ミッションコントロール（`Ctrl+P`）> 「スタービュー」

### ナビゲーション

| 入力 | 操作 |
|------|------|
| **クリック＋ドラッグ** | グラフをパン |
| **スクロール** | ズームイン/アウト |
| **ノードをクリック** | ノートを開く |
| **ノードを右クリック** | コンテキストメニュー（開く、フォーカス、ピン留め、非表示） |
| **中クリック＋ドラッグ** | 3D回転 |
| **W/A/S/D** | 3D空間を飛行 |
| **0** | 回転を2Dにリセット |
| **Ctrl+F** | 検索＆ハイライト |
| **Space** | フォーカスモード切替 |

### レイアウトモード

`Ctrl+L` を押して切り替え：

- **オーガニック** — クラスターが自然に形成される力学モデルレイアウト
- **階層型** — トップダウンのツリーレイアウト
- **時系列** — 作成日順にタイムライン上に配置

### フォーカスモード

ノードを右クリック > **フォーカス**で、その近傍のみを表示します。調整項目：

- **深さ**（1～5ホップ）— 表示する接続レベル数
- **方向**（↔/←/→）— 全リンク、受信のみ、送信のみ

### 3D ナビゲーション

中クリック＋ドラッグで回転。W/A/S/D/Q/E でスターフィールドを飛行。コーナーの XYZ 軸ギズモで方向を確認できます。`0` を押してリセット。

### 設定

歯車アイコンをクリックして設定：

- **外観**: ノードサイズ、ラベル表示、フォントサイズ、リンクの太さ、孤立ノードの表示
- **物理**: 反発力、リンク力、リンク距離
- **AI**: セマンティックリンクしきい値（フェーズ2）

### 凡例

右下の凡例に、ライブラリ/フォルダの色がチェックボックス付きで表示され、表示/非表示を切り替えられます。

### 知識階層

スタービューは、抽象度に基づいてノートを8つの知識階層に自動分類します：

| 階層 | 説明 |
|------|------|
| **スナップショット** | 素早い、一時的なメモ |
| **ログ** | 日付付きの出来事や日記 |
| **トピック** | 1つのアイデアに関するアトミックな概念 |
| **マップ** | 他のトピックをつなぐ整理用ノート |
| **フレームワーク** | モデルや思考の枠組み |
| **原則** | 検証されたルールや公理 |
| **信条** | 基本的な価値観や信念 |
| **成果物** | 完成した最終的な作品 |

階層はノートのフロントマター、構造、リンクから自動的に決定されます。フロントマターに `stratum` プロパティを追加して、手動で分類を上書きできます。

### 成熟ライフサイクル

各ノートは、その発展度を反映する成熟ライフサイクルを経ます：

- **種** — 初期のアイデアや下書き
- **苗** — ノートが形を取り始め、いくつかのリンクを持つ
- **常緑** — 成熟し、レビュー済みで、十分にリンクされたノート
- **正典** — その分野における最終的で権威ある参照

成熟度はリンク数、レビュー日、編集頻度に基づいて自動的に更新されます。フロントマターの `maturity` プロパティで手動設定も可能です。

## 7. インデックス

インデックスは、すべてのライブラリを横断する包括的な用語集です — すべての意味のある単語がアルファベット順に出現回数とともに表示されます。

### インデックスを開く

- **ドックボタン**: 左ドックのインデックスアイコン（本）をクリック
- **コマンドパレット**: `Ctrl+P` で "Index" と入力

### 多言語NLPパイプライン

インデックスはインデックス作成前に言語対応パイプラインでテキストを処理します：

- **アラビア語**: Lucene Light10アルゴリズム — タシュキール除去、ハムザ統一、定冠詞（الـ）除去、文法接尾辞除去
- **ヘブライ語**: 接頭辞除去（ב/ל/מ/ה/ו/כ/ש）
- **英語**: Porter系ステミング（複数形、動詞形、接尾辞）
- **フランス語/スペイン語/ポルトガル語/ドイツ語**: 言語固有の接尾辞除去
- **ロシア語/トルコ語/ヒンディー語/ペルシア語**: 形態論的接尾辞除去
- **全15言語**: ストップワードフィルタリング（冠詞、前置詞、接続詞）

### ブラウジング

- **言語タブ**: すべて、アラビア語、ヘブライ語、英語、#（特殊文字）を切り替え
- **アルファベットバー**: 文字をクリックしてその文字で始まる用語をフィルタリング — 用語数が更新され一致数を表示
- **同じ文字をもう一度クリック**するとフィルターがクリアされすべての用語が表示されます
- **ソートモード**: アルファベット順（デフォルト）または頻度順（最も多いものから）

### インデックスからの編集

用語の参照内の任意のノートをクリックすると、インデックスの横に分割プレビューペインで開きます。プレビューペインはフルエディターです — 編集、保存、プロパティの変更、ステージの昇格が可能です。検索用語はノート内でハイライトされ、自動的にスクロールされます。

`Ctrl+Click` でノートを通常のタブとして開きます。タブバーに「インデックスに戻る」ボタンが表示されます — クリックするとインデックスで中断した場所に正確に戻ります。

### セカンドスクリーン統合

セカンドスクリーンが開いている場合：
- **用語をクリック** → セカンドスクリーンがその用語を含むすべてのノートを分割ビューで表示（ノートリスト + エディター）
- **複数の用語をCtrl+Click** → セカンドスクリーンが比較モードを表示し、各用語が独自の列に配置されます

## 8. Constellation Sight

Constellation Sight は、ナレッジシステム全体を重力井戸グラフとして可視化します。**「自分の知識はどのように見えるか、そしてどれくらい健全か？」**という問いに答えます。

### Sight を開く

左リボンの **Sight ボタン**（目のアイコン）をクリックします。重力井戸グラフが表示されます。閉じるには x をクリックします。

### 重力井戸グラフ

ノートは重要度（中心性）に基づいて同心円状のリングに配置されます。最も接続の多いノートが中心に、周辺的なノートが端に位置します。各リング内では、ノートはライブラリ（組織構造）ごとにグループ化されます。ノードの色 = ライブラリ。

| 要素 | 意味 |
|------|------|
| **大きなノード** | 高い中心性 — 異なる知識領域を橋渡し |
| **小さなノード** | 周辺的 — 一つの領域内 |
| **ノードの色** | ライブラリの所属 |
| **実線** | 2つのノート間のリンク |
| **方向矢印** | リンクの方向を示す小さな矢印 |
| **線の太さ** | 信頼度レベル（太い = 確立済み、細い = 仮説） |

### インタラクション

- **シングルクリック**: ノードの近傍をハイライト（接続されたすべてのノート）。それ以外は薄暗くなります。
- **ダブルクリック**: エディタでノートを開きます。
- **空白をクリック**: ハイライトをクリア。
- **スクロール**: ズーム。**ドラッグ**: パン。**画面に合わせる**: ツールバーボタン。

### Sight での検索

虫眼鏡をクリックします。すべてのオペレーターをサポート: `links to [[X]]`、`links from [[X]]`、`mutual [[X]]`、`orphans`、`supports [[X]]`、`contradicts [[X]]`、`#tag`、フリーテキスト、セマンティック検索。結果は方向色で表示: 緑（内向き）、赤（外向き）。

### 分析パネル (SightPanel)

グリッドアイコンをクリックしてサイドバーを開きます。表示内容: ユニバース健全性スコア（0-100）、ノート/リンク/孤児カウンター、リンクタイプと信頼度バー、トップ10ブリッジ、ナレッジインサイト（最も強い証拠、弱い基盤、緊張、停滞、最も接続が多い、知識ギャップ）。

### 設定

歯車アイコン: リンクストロークの太さ、不透明度、矢印サイズを調整。設定はセッション間で保持されます。

### 8a. ノートごとの伝統フィールド（MIG-029）

Sight の左上の伝統チップを使うと、10 の認識論的家族に分類された 24 の学術伝統を通してドームを再構成できます。これらの伝統のうち 9 つ(扇形 / 同心円形 / はしご状の形をもつもの)については、ノートごとに frontmatter フィールドで**明示的に分類**できます。フィールドがないノートは、その伝統に応じた合理的なデフォルトのバケットに収まります；フィールドがあるノートは、あなたが指定したバケットに収まります。

ノートの YAML frontmatter にフィールドを追加します:

```yaml
---
masadir_source: sunnah
---
```

その伝統のチップに切り替える → あなたのノートはデフォルトではなく、指定された扇区に収まります。

**許可されたフィールドと値:**

| 伝統 | frontmatter フィールド | 許可された値 | 不在時のデフォルト |
|---|---|---|---|
| **マサーディル(masādir)**(スンナ派ウスール・アル=フィクフ) | `masadir_source` | `quran` / `sunnah` / `ijma` / `qiyas` | `quran` |
| **プラマーナ(pramāṇa)**(インドのニヤーヤ学派) | `pramana_kind` | `pratyaksha` / `anumana` / `upamana` / `shabda` | `pratyaksha` |
| **イブン・ルシュドのブルハーン** | `burhan_kind` | `burhan` / `jadal` / `khataba` / `shir` | `shir`(最外環) |
| **פַּרְדֵּ"ס(PaRDeS)**(ユダヤ教解釈学) | `pardes_level` | `peshat` / `remez` / `derash` / `sod` | `peshat` |
| **パース**(3 つの現象学的カテゴリ) | `peirce_category` | `firstness` / `secondness` / `thirdness` | `firstness` |
| **ハーバーマス**(3 つの知識関心) | `habermas_interest` | `technical` / `practical` / `emancipatory` | `technical` |
| **孟子の四端**(4 つの道徳的萌芽) | `mencian_sprout` | `ceyin` / `xiuwu` / `cirang` / `shifei` | `ceyin` |
| **墨家の三表(sān biǎo)**(3 つの基準) | `mohist_zone` | `ben` / `yuan` / `yong` | ハッシュで 3 つのゾーンに分散 |
| **朝鮮性理学**(四七論争) | `songnihak_cell` | `li-sa` / `li-chil` / `qi-chil` / `qi-sa` | `li-sa` |

**動作:**
- 伝統が認識しない値(タイプミスや創作)を書いた場合、ノートはデフォルトのバケットに収まります。クラッシュも、レンダリングの不具合もありません。
- frontmatter の変更は自動的に伝播します — ノートを保存する → ドームの次のレンダリングが変更を反映します。
- 同じフィールドは、それを名前にもつ伝統によってのみ読み取られます。ノートに `masadir_source: sunnah` を設定しても、PaRDeS やパースに切り替えた時には何の効果もありません — 各伝統は自分のフィールドを独立して読みます。
- これがドームの空間文法を制御する最も明示的な方法です。これらのフィールドがなければ、幾何学は正しいけれども、すべてのノートが同じデフォルトのバケットに収まります；あれば、チップは分析的に意味のあるものになります。

**ノートごとのフィールドを持たない伝統**(現在、すべての星点を他の手段でバケット分けしている — フォルダ / ライブラリ / ハッシュ):

- アリストテレス的(デフォルト、再マッピングなし)
- ポランニー(グラデーションの霧;扇区化なし)
- フッサール、ロンギーノ、シャーティビーのマカースィド、マイモニデスの預言論、タルムード13ミッドット、王陽明、ミニョロのプルリバーサル、ドゥッセルのトランスモダニティ、マルドナド-トーレス、アカン(ウィレドゥ)、イブン・ハルドゥーンのウムラーン、イブアニダンダ

(将来の移行では、ユーザーの需要が出てきた際に、これらの伝統にもノートごとの frontmatter フィールドを追加する可能性があります。)

## 9. セカンドスクリーン

セカンドスクリーンは、現在のサイドバーモードに適応するモードベースのコンパニオンウィンドウです。

- **開く**: サイドバーのセカンドスクリーンアイコンをクリック、または `Ctrl+Shift+2`
- **自動終了**: メインウィンドウを閉じると、セカンドスクリーンも自動的に閉じます

### モードベースのコンパニオン

セカンドスクリーンは、メインウィンドウのアクティブなサイドバーモードに基づいてコンテンツを変更します：

| メインサイドバーモード | セカンドスクリーンの表示 |
|---|---|
| **ファイルエクスプローラー** | ユニバースダッシュボード — 統計、ライブラリの内訳、子ユニバース、タグ、最近編集/開いたノート |
| **ナビゲーター** | ノートをブラウズするための完全なナビゲータービュー |
| **スカイビュー** | ディレクトリ構造付きスカイビューツリー |
| **スタービュー** | バックリンク、フォワードリンク、タグ、ローカルグラフ付きスタービューコンパニオン |

### ユニバースダッシュボード（ファイルエクスプローラーモード）

メインウィンドウがファイルエクスプローラーモードの時、セカンドスクリーンは以下を含むダッシュボードを表示します：

- **統計カード** — ユニバース名、子ユニバース数、ライブラリ・フォルダ・ノートの合計
- **子ユニバース** — リンクされたライブラリとフォルダ/ノート数を含む各子ユニバース
- **ライブラリ** — 色分けされた統計ボックスにフォルダ/ノート数を含む各ライブラリ
- **最近編集** — 現在のセッションで変更したノート（保存時に追跡）
- **最近開いた** — 現在のセッションで開いたが編集していないノート
- **タグ** — ライブラリ全体のすべてのタグを数順でソート；タグをクリックして関連するすべてのノートを表示

### ダッシュボード連携

メインウィンドウでダッシュボードがアクティブな場合、アイテムをクリックするとセカンドスクリーンに送信されます：

- **最近編集/開いた**: ノートをクリックすると、セカンドスクリーンでフルエディターとして開きます
- **タグ**: タグをクリックすると、そのタグを使用するすべてのノートがスプリットビューで表示されます — 左側にノートリスト、右側にフルエディター

セカンドスクリーンでのすべての編集は、自動的にメインウィンドウに同期されます。

### セカンドスクリーンでのノート編集

セカンドスクリーンはフルノート編集をサポートします — メインウィンドウと同様に入力、保存、名前変更、プロパティ変更が可能です。変更は自動的にメインウィンドウに同期されます。

### 設定の同期

すべての視覚設定がセカンドスクリーンに即座に反映されます — 再起動不要：

- **言語**: インターフェース言語の変更が即座に適用
- **テーマ**: ライト/ダーク/システムモードが即座に切り替え
- **フォント**: インターフェースフォント、テキストフォント、等幅フォント、スクリプト固有フォント
- **フォントサイズ**: インターフェースとエディターの両方のフォントサイズ
- **エディター**: 読みやすい行幅、行番号、フローティングツールバー
- **アクセントカラー**: テーマのアクセントカラーの変更

## 10b. ソースレビュー (Constellation 認識的コンテンツエンジン — CECE)

> *(翻訳メモ: V3-§10.F 章のAI生成翻訳; ネイティブスピーカーによるレビュー待ち。)*

フロントマターの最も重要なプロパティのうち2つ — `sources:` と `content_type:` — は、何かを *どのように知ったか* と *どのような種類の知識か* を記述します。Constellation の **認識的コンテンツエンジン** (CECE) は、6 つの分類器のアンサンブルを使用して、これら 2 つの軸に沿ってすべてのノートを自動的に分類します。**ソースレビュー** パネルは、これらの分類をレビューして修正する場所です。

### エンジンが行うこと

ノートを分類するとき (右クリック → 「ソースとコンテンツタイプを提案」、または **設定 > スキャンを実行**、またはバックグラウンドスキャントグルで自動的に)、CECE はノートに対して 6 つの独立した分類器を実行します。それぞれが異なるレンズを通してノートを読み、2 つの質問に投票します:

- **ソース** (水平軸) — この知識は *どこから来た* のか? 11 種類の値: 知覚、推論、証言、大量伝達、比較、仮定、非把握、記憶、生得的素質、霊感、啓示。プラス *分類不能*。
- **コンテンツタイプ** (垂直軸) — これは *どのような種類* の知識か? 5 つの最上位ブランチ: 感覚入力、シンボリックエンティティ、意味的内容、認識的状態、より高次の構造体。

2 つの軸は独立しています。「月着陸を疑う」というノートは、ソースでは証言 (誰かが報告した) で、コンテンツタイプでは認識的状態/疑い (あなたの立場) です。

エンジンは **あなたのデバイス上で** 実行されます — ノートが Constellation を出ることはありません。

### 6 つの分類器

各分類器は 1 つのレンズです。ソースレビューカードは、各カードの右上隅にある 6 つの小さなカラードットとしてそれらを表示します:

- **あなたの frontmatter** (青) — すでに設定したものを絶対的な権威として採用
- **引用と構造** (バラ色) — 引用、ブロック引用、定理マーカー、定義フレーズ
- **語幹と語彙** (琥珀色) — アラビア語語根分析 + 言語横断的な用語等価
- **リンクされたノート** (ティール) — 他の分類済みノートへのタイプ付き Living Links
- **類似ノート** (バイオレット) — すでに分類されたノートへの埋め込み類似度
- **AI判断** (緑) — ローカル LLM (Qwen3-4B; *まだアクティブではない*、将来のリリースに延期)

塗りつぶされたドットは、その分類器が発言し、統合に同意したことを意味します。リング付きドットは、発言したが異議を唱えたことを意味します。破線アウトラインのドットは、沈黙を保ったことを意味します (このレンズで信号なし)。

### 3 つの信頼度レジーム

分類器が投票した後、各軸は 3 つのレジームのいずれかに収まります:

- **全会一致** — 発言したすべての分類器が同意
- **強い多数 (1 件の異議)** — ほとんどが同意; 1 名の異議者が指名される
- **分裂** — 明確な多数派なし; エンジンは推測を拒否し、あなたに選択を求める

各軸は独立してそのレジームを取得します — カードは水平で全会一致 + 垂直で分裂などになることがあります。

### Sibling Disambiguation

軸が分裂しているとき、エンジンは候補値を **チップ** としてプロンプトの下に表示します: *「ノートに最も合うものを選んでください。」* チップをクリック → エンジンはあなたの選択をノートの frontmatter に書き込み、カードをキューから削除します。もう一方の軸が確定していた場合 (全会一致または強い多数)、エンジンは *同時に* その軸の値も書き込みます — 1 つの軸だけが分裂していたとき、1 クリックで両軸が完了します。

### 推論履歴

各カードには *「▸ なぜこの分類なのか?」* トグルがあります。展開すると、発言した各分類器ごとに 1 行が表示され、推論、自己申告された信頼度、フレンドリーなルールチップ (「表面キーワードの一致」、「アラビア語語根の一致 (CAE)」、「定義マーカー」など) が含まれます — これらは各分類器がトリガーした特定のルールです。

最初の **50 件のレビュー** 中、すべてのカードで履歴が自動展開されます (*信頼度キャリブレーション期間*) ので、エンジンを信頼するタイミングについての直感を養うことができます。その後、履歴は全会一致のカードでオンデマンドに折りたたまれます。**設定 > インテリジェンス > CECE > 推論履歴の表示** でいつでもオーバーライドできます。

### キュー構成フィルター

カウントストリップの上に、5 つのチップが各カードが必要とする決定の種類によってキューをスライスします:

- **すべて** — 完全なキュー
- **両方の軸で判断が必要** — 両軸が分裂
- **ソースの判断が必要** — 水平が分裂 + 垂直が確定
- **コンテンツタイプの判断が必要** — 垂直が分裂 + 水平が確定
- **分類器が同意** — どの軸も分裂していない (ラバースタンプ候補)

各チップはバケットカウントを表示します。フィルターはレンダリング層のスライサーです — 「すべて承認」の計算は、どのフィルターがアクティブであっても常に完全なキューで動作します。

### カードごとのアクション

- **承認** — エンジンの統合を両軸でプライマリとして書き込み; カードを削除。分類器ごとの信頼性を更新。
- **編集** — 両軸のツリーピッカーを開く; 手動で選択。同じ信頼性更新。
- **拒否** — 書き込まずにカードをクリア。
- **Sibling Disambiguation チップ** — 分裂カードのみ。

### ライブラリごとのキャリブレーション

**設定 > インテリジェンス > CECE > ライブラリごとのキャリブレーション** は、アクティブなライブラリで各分類器の軸ごとの精度を表示する読み取り専用テーブルを開きます。異なるライブラリは分類器ごとに異なる精度を持ちます — Linguistic はアラビア語が多いライブラリで優れ、Graph は密にリンクされたライブラリで優れています。統合層はこのキャリブレーションデータを使用して投票を重み付けします。

分類器の精度比が表示されるには **20 件の修正** が必要です。そのしきい値以下では、ラベルは *「(均一)」* と表示されます — 分類器は十分なデータが蓄積されるまで均一に重み付けされた投票を行います。

### バックグラウンド分類

デフォルトでは、CECE はあなたが要求した時のみノートを分類します (右クリックまたは設定スキャンボタン)。**設定 > インテリジェンス > CECE > バックグラウンド分類** で自動分類を選択できます:

- **ノート保存時** — 入力を停止してから約 1.5 秒後に各ノートを分類 (既存のデバウンスされた保存に乗ります; キーストロークごとに発火することはありません; 入力は瞬時のままです)
- **アプリ起動時** — 起動ごとに 1 回、未分類のノートをスキャン

### 分類器 — フルページのホーム

同じカードは、**左ドックの積み重なったカードのアイコン** から開く **分類器** と呼ばれるフルページビューにも存在します。これは同じエンジンと同じキューで、狭いサイドバータブの代わりにウィンドウ全体が与えられたものです — さらにサイドバータブにはなかった 2 つのコントロールが加わります:

- **ノートを分類…** — *任意の* ノートを、先に開かずに名前で分類できる検索ボックス。数文字を入力してノートを選ぶと、新しいカードがキューに表示されます。
- **すべての要約を作成** — 要約を持たないすべてのノートのノート要約(下記参照)を、バックグラウンドで、進捗をステータスバーに表示しながら事前計算します。

**スキャン開始** ボタン(設定と同じ宇宙全体のスキャン)とライブの進行ストリップがヘッダーを締めくくります。分類器は **(×)** または **Esc** で閉じます。(*ノートを分類…* 検索ボックスが開いているときは、最初の **Esc** はそのボックスだけを閉じます。)

命名についての注記:**分類器** は *部屋*(フルページビュー)です;**複数の分類器** はエンジン内で各カードに投票する *6 つのレンズ* です。この 2 つを混同しないでください。

### ノートの要約

各カードのタイトルの下には、短い **要約** があります — ノートが何についてのものかを伝える数文の文章で、ノートを開かずに分類できます。Constellation は常に *あなた* が書いた要約を優先し、あなたが書いていないときだけ生成します:

1. `summary:` / `description:` / `abstract:` / `excerpt:` **frontmatter フィールド**、そのまま使用。
2. 本文の `> [!summary]` / `[!abstract]` / `[!tldr]` **コールアウト**、そのまま使用。
3. それ以外の場合は **生成された** 要約 — ノートの最も中心的な 3 文を抽出し(決して考案せず)、元の順序で表示。

生成された要約は **読み取り専用** です — Constellation はそれをあなたのノートに書き戻すことは決してなく(File-Over-App)、すべては **あなたのデバイス上で** 計算されます。要約をファイルの中に存在させたい場合は、自分で書けば Constellation はあなたのものを代わりに表示します。

より深い詳細 (各ドットのステータス、各ルールチップ、クリックバイクリックウォークスルー) については、ヘルプシステムの **ソースレビュー**、**分類器**、**Note Summaries** トピックを参照してください。

## 10c. エピステミックメタデータ

ノートの知識がどのように獲得されたか、誰がその立場を保持しているか、どの分野に属するか、いつ最後に見解を改訂したかについて、より豊かな情報を記録するための、少数のオプションのフロントマターフィールド。MIG-022 §A でギャップ分析(`docs/epistemic-content-gap-analysis.md`)に応じて追加されました。

これらのフィールドは **すべてオプション** です。これらを持たないノートはそのまま動作します。

### クイックリファレンス

| Field | Type | 目的 |
|---|---|---|
| `held_by` | text | これは誰の立場か?(デフォルトは `user`; `"al-Shāfiʿī"`、`"Ḥanafī"` などになりうる) |
| `domain` | list | 検索のための学問領域タグ(`[fiqh, ʿibādāt]`) |
| `function` | text | このノートは何のためか(`reference` / `seed` / `actionable` / `shipped`) |
| `provenance_civilization` | text | 伝統の語彙(`sunni-usuli` / `analytic-western` / `nyaya` など) |
| `updated_at` | date | 最後に意図的に見解を改訂した時(ファイルシステムの mtime とは区別される) |
| `ikhtilāf` | list of objects | 構造化された学術的不一致(`[{school, position}, ...]`) |
| `warrant` | text | グレードラベル(Warrant Research ワークストリームが完成するまでパースされるが不活性) |
| `warrant_notes` | text | warrant グレードを支持する自由テキスト(これも不活性) |

### プロパティパネルでの表示方法

各フィールドは型に適したエディタでレンダリングされます:
- テキストフィールド → テキスト入力
- `domain` → タグリスト(Enter で追加、× で削除)
- `updated_at` → 日付選択
- **`ikhtilāf` → カスタムウィジェット**:1 行ごとに 2 つの並列入力(school + position)、各行に削除ボタン、下部に「学派を追加」ボタン。ウィジェットは構造化された YAML から読み取り、書き込みます。ラウンドトリップではすべてのフィールドが保持されます。

### `supersedes` についてはどうか?

`supersedes` は *ノート間の関係* (このノートが以前のものを置き換える)であり、単一ノートのプロパティではありません。Constellation はこれを YAML スカラーではなく **型付きリンク** として扱います:

```markdown
This replaces my earlier analysis: [[old-note-id|supersedes]]
```

ウィキリンクの `|supersedes` サフィックスは、それを `supersedes` 種別の型付きリンクにします — 専用のスレートブルーグレーピル、Backlinks + Outgoing Links パネルに表示、Living Link Architecture に参加。

### これは何で *ない* か

新しいフィールドは **スキーマ** — 入力できる認識された語彙です。CECE は現在、分類のためにこれらを消費しません。将来の MIG (Warrant Research ワークストリーム、MIG-023 時間軸) は `warrant`、`updated_at` などを読む機能を出荷します。

より深い詳細と完成した例については、ヘルプシステムの **Epistemic Metadata** トピックを参照してください。

- **Markdown フォルダ** — `.md` ファイルの任意のフォルダをインポート
- **その他の形式** — HTML、テキストファイル

**設定 > インポーター**でインポートを開始します。

## 15. カレンダー

**カレンダー**は全画面の月表示で、**左ドック**（カレンダーアイコン）から開きます。ノートや期限付きタスクがある日には、色付きの**ドット**が付きます。ヘッダーには、選択したカレンダーでの月が表示されます。**副カレンダー**を設定している場合は、その下のサブタイトルに、そのカレンダーで対応する範囲が表示されます（例えばグレゴリオ暦の月には、対応するヒジュラ暦の範囲「ズー・アル＝ヒッジャ 1447 – ムハッラム 1448 AH」が表示されます）。

**日付をクリックする。** それぞれの日のセルは操作できます。

- **空いている部分（または日付の数字）をクリック** → その日の**デイリーノート**を開きます（なければ作成します）。すでにデイリーノートがある日付をクリックした場合は、その**ノートを開くだけ**で、重複は作成されません。
- **ドットをクリック** → その項目を開きます。**金色**のドットはデイリーノート、**紫色**のドットはその日に編集された別のノート、**赤色**のドットはその日が期限のタスクです。（色は Style Setter → カレンダー でテーマ設定できます。）1つの日に複数のノートやタスクがある場合は、ドットをクリックすると選べるように小さな**リスト**が表示されます。
- **タスクのドットをクリック** → そのタスクの行までスクロールした状態でノートが開き、すぐに編集できます。タスクリストでは、カレンダーから直接**タスクのチェックボックスをオンにして完了**することもできます。完了したタスクはすぐに一覧から消えます。カレンダーに表示されるのは、自身に `📅 YYYY-MM-DD` を持つタスクだけです（この日付によってどの日に配置されるかが決まります）。

**文化暦（8種類）。** **設定 → カレンダー**で**暦の体系**を設定できます。選べるのは**グレゴリオ暦、ヒジュラ暦（イスラム暦）、太陽ヒジュラ暦（ペルシャ暦）、ヘブライ暦、インド暦（サカ暦）、仏暦、中国暦、韓国暦**で、選ぶと月のグリッド全体がそれに切り替わり、各セルに選択した暦の日付（大きく）とグレゴリオ暦の日付（小さく）の両方、そして月相が表示されます。各月のヘッダーには、月の**名前、括弧内の番号、そして年**が表示されます。番号は、月の並び順に馴染みのない暦で役立ちます。**中国暦と韓国暦**は*太陰太陽暦*で、ときどき**閏月**（闰六月 / 윤6월）が挿入されます。カレンダーはこれを独立したページとして表示するため、移動の際にスキップされたり二重になったりしません。ヒジュラ暦は正確な天文計算エンジンを使用し、聖月が強調表示され、イスラムの行事が記されます。また、**週の始まり**（日曜/月曜）を選んだり、**週番号の列**を切り替えたりできます。

**ヒジュラ暦のオプション。** **設定 → カレンダー →「ヒジュラ暦（イスラム暦）」**には、2つの追加コントロールがあります。

- **計算方法** — 真の新月に従う**天文計算（朔（さく）合）**（最も正確で、既定値）か、古典的な計算サイクルである**表式（al-Tawfīqāt al-Ilhāmiyyah、霊感的補正表）**。
- **月の補正** — **現地での月の目視観測**に合わせて、ヒジュラ暦の月の始まりを ±1 または ±2 日ずらします。ヒジュラ暦の年と月を選び、オフセットを選んで**Set**をクリックすると、その月とそれ以降のすべての月に補正が適用されます。設定した補正は一覧で表示され（それぞれ削除可能）、**Clear all**ボタンもあります。

両方の設定（および補正）は**ユニバースとともに**保存されるため、お使いのデバイス間で引き継がれます。

**中国暦・韓国暦の表示オプション。** 韓国は中国の太陰暦を使用するため、両者の日付は同一です。違いは文字（スクリプト）と年の表し方です。どちらかを主カレンダーまたは副カレンダーにしている場合、**設定 → カレンダー**に2つの追加コントロールが表示されます。**年の表示**（中国暦：干支 丙午年、単純な年、またはその両方／韓国暦：**檀紀（Dangi）**の 단기 4359、年、または干支 병오년）と、**月名**（*ネイティブ文字*（五月 / 5월）か、*音写*、つまりその月の発音を自分の言語で書いたもの（英語「Wǔyuè / Owol」／アラビア語「وُو-يوي / أوه-وُل」））です。

**カレンダーのスタイル設定。** **Style Setter**（左ドック、または**設定 → Style Setter**）を開いて**カレンダー**サーフェスを選ぶと、すべての部分を再スタイルできます。各要素はそれぞれ独自の**色と文字サイズ**を持ちます（日付の数字、相互参照の日付、月のピル、曜日ヘッダー、週番号、月のグリフ、今日のハイライト、グリッド線、ノート／タスク／行事のドット）。さらにカレンダーの**フォント**も設定できます。編集に合わせてフルサイズのライブプレビューが更新されます。**Keep**をクリックすると適用されます。

> **デイリーノートのファイル名は、表示している暦に関わらず常にグレゴリオ暦のまま**（`YYYY-MM-DD`）です。これにより、ファイルは可搬性を保ち、正しく並び替えられます。文化暦の日付はカレンダーに表示され（また、ノートのフロントマターに記録することもできます）。

カレンダーはデイリーノートを十分に支えます。任意の日をクリックして開くか、**「Daily Note」**コマンド（コマンドパレット）を実行して今日へ移動できます。

**ノートに文化暦の日付を記録する。** オプトイン式の2つのツールが、ノートの**プロパティ**に文化暦の日付を書き込みます（ファイル名は常にグレゴリオ暦 `YYYY-MM-DD` のままです）。

- **デイリーノートへのヒジュラ暦スタンプ** — *設定 → カレンダー →「デイリーノートにヒジュラ暦の日付をスタンプする」*。オンにすると（ヒジュラ暦を**主または副**カレンダーにしている場合のみ利用可能）、**新規の**デイリーノートすべてに `hijri:` の行が付きます（例：`hijri: 1448-01-06`）。既存のノートは一切変更されません。
- **ノートのプロパティ内の「+ Hijri」** — 任意のノートの**プロパティ**を開き、日付にカーソルを合わせると、小さな**「+ Hijri」**ボタンが表示されます（さらに「+ Jalali」「+ Hebrew」なども表示されます。**選択したグレゴリオ暦以外の暦ごとに1つのボタン**です）。クリックすると、Constellation はノートのグレゴリオ暦の日付を読み取って対応する値を追加します（例：`jalali: 1405-03-30`）。韓国暦のボタンは**檀紀（Dangi）**の年を書き込みます。中国暦／韓国暦の**閏月**は `L` で示されます（例：`chinese: 2025-06L-17`）。ノートに日付プロパティがない場合は、ファイルの作成日が使われます。

## 16. レンズとConstellation Base

**レンズ**は、対象のプロパティとともにフィルタ済み・ソート済みのノート一覧を表示する保存済みクエリです。Constellationには2つの方法があります：

### Constellation Base — 埋め込みレンズブロック

任意のMarkdownノートの本文に、` ```base `コードブロックを使ってレンズを直接埋め込めます：

````markdown
```base
schema: 1
view: list
dimensions: [note.name, note.created_at]
sort: [note.created_at, desc]
limit: 20
```
````

ノートを表示すると、コードブロックは該当するノートを表示するインタラクティブなテーブルに置き換えられます。ライブプレビューでは、**レンズ**チップをクリックしてブロックを編集できます。

**v1で利用可能なディメンション：** `note.name`, `note.path`, `note.created_at`, `note.headline`.

**フェデレーション：** デフォルトでは、レンズブロックはアクティブな宇宙とリンクされた各cUniverseから読み込みます。アクティブな宇宙のみに制限するには、YAMLで`federation: active`を設定してください。

### タブ全体のベース

`.base`ファイルを開くと、インタラクティブなテーブルとしてタブいっぱいに表示されます。テーブルの中でノートを見つけるための操作は次のとおりです：

- **このベースを検索** — ヘッダーの検索ボックスが、入力に合わせて行を絞り込みます。ノートの名前*と*、表示中のすべての列のテキストに一致します。絞り込んでいる間、カウントバッジには`一致件数 / 全体`が表示されます（例：`4/7684`）。あらゆるスクリプトで検索でき — アラビア語を入力すればアラビア語のタイトルが見つかります。数千行あっても絞り込みは瞬時です。
- **文字レール** — 50 行以上あるベースでは、テーブルの端に細い文字の帯が現れます。これは実際のノートのタイトルの頭文字から作られます（英語なら A–Z、アラビア語なら أ ب ت…、そのほかのスクリプトにも正しい文字を表示します）。文字をクリックすると、その文字で始まる最初のノートへ一気にジャンプします — テーブルがまだ名前で並べ替えられていない場合は、まず名前で並べ替えてからジャンプします。
- **行を右クリック** — 標準のノートメニューが開きます：開く、新しいタブで開く、ブックマーク、パス / 名前をコピー、ファイルツリーで表示、既定のアプリで開く、システムのエクスプローラーで表示、スタイル…（名前の変更・移動・削除は、ここではあえて提供していません — それらはファイルツリーから行ってください。）

### 五幕（Five Acts）— 組み込みレンズ

サイドバーの**Five Acts**セクション（Workspace Basesの上）には、Constellationがキュレートしたホストノートが`{universe}/Five Acts/*.md`に表示されます。v1には1つ含まれます：**Observation — Recent Captures**（直近キャプチャされた20件のノートのフェデレーション一覧）。これらのノートは自由に編集できます — Constellationはあなたの編集を上書きしません。

### クラシックレンズパネル

以前のレンズパネル（タグ、フォルダ、プロパティによるフィルタリング）は**設定 → パネル → レンズ**から引き続き利用できます。

---

### 構造（構造リンク）

**構造**パネルは、開いているノートがより大きな*作品*——書籍、脚本、講座、Map of Content——のどこに位置するかを示します。これは Backlinks パネルや Outgoing Links パネルとは異なる問いに答えます。それらのパネルは*「このアイデアは別のアイデアとどう関係するか?」*（思考リンク——supports、contradicts、causes…）に答えます。構造は*「このノートは、私が組み立てている作品全体のどこに位置するか?」*——書籍 → パート → 章 → シーン——に答えます。

これは作品の**構成上の背骨**です。すなわち目次であり、順序づけられたアウトラインです。これはあらゆる思考・成熟・接続の指標から意図的に**外されて**います——あるノートを「書籍の下」に置いても、そのノートの成熟度、接続数、スカイビューでの表示が変わることは決してありません。目次はオーサーシップ（執筆の判断）であって、評価されるべき主張ではないからです。

**2 種類の構造リンク**（あなたが入力するのは常に片側だけ——もう片側は Constellation が割り出します）：

- **`parent`** — *このノートの*ひとつの親の下での位置（例：ある章が、自分の属するパートを宣言する）。
- **`contains`** — *このノートの*順序づけられた子の一覧（例：書籍が、自分のパートを読む順に並べる）。

**構造リンクを作成する** — ノートの**プロパティ**を開きます（右サイドバーのプロパティタブ、またはノート上部のプロパティブロック）：

1. **+ プロパティを追加**をクリックし、キーに `parent` または `contains` を入力します。
2. 値に、**対象ノートの名前**——名前だけ、例えば `Part I - The Cartographer`——を入力します。Constellation がそれを `[[link]]` に包んでくれるので、角かっこを入力する必要は**ありません**。（すでに角かっこの付いた名前を貼り付けても、二重に包まれることなく単一の `[[name]]` としてきれいに保存されます。）
3. `contains` の場合は、読ませたい順に、子をそれぞれ独立したチップとして追加します——その順序がアウトラインの順序になります。

構造リンクは**安全にリネームできます**：章をリネームしても、リンクは凍結されたテキストではなくノート自体を指しているため、構造上の位置は自動的に追従します。

**構造パネルを読む** — 右サイドバーの**構造**タブを開きます（Backlinks のすぐ後ろ）：

- パネルは**作品全体**を字下げされたアウトライン（ティール色の箇条書き）として表示し、見出しに**OUTLINE**と子孫の件数が付きます——開いているノート自身の子だけではありません。
- 現在表示しているノートはそのアウトライン内で**ハイライト**表示されます（「現在地」）。
- 上部の**パンくず**が背骨をたどる経路を示します（例：*The Atlas of Lost Places › Part I › Chapter 1*）。任意のパンくず——またはアウトラインの任意の行——をクリックすると、そのノートへ移動します。
- **作品全体 ⇄ このノート**のトグル（パネル右上）が、作品全体と、開いているノート自身のサブツリーだけとを切り替えます。これはノートに実際に親がある場合にのみ表示されます（その場合のみ 2 つのビューが異なるためです）。
- 構造がうっかり自分自身に巡回してしまった場合（ノート A の親が B、かつ B の親が A）、アウトラインはその連鎖を描いたあときれいに停止し、切断点に小さな**↻**を付けます。決してハングしません。

**競合の解消（Contested）。** 2 つのノートが同じ子を主張した場合——一方は子自身の `parent` を通じて、もう一方は `contains` の一覧を通じて——パネルはどちらかを黙って取り下げるのではなく、その行を**Contested**（もう一方の主張者の名前を示す黄色の ⚠ バッジ）として指摘します。ワンクリックのボタンが 2 つあり、これを解消します：

- **Keep** — 子自身が宣言した親を保持します（このノートは子への主張を取り下げます）。
- **Move here** — このノートを親として受け入れます（子の `parent` がこのノートに切り替わります）。

どちらのボタンもノートファイルを直接更新し、アウトラインを再描画します。あなたのクリックなしに変更されることは決してありません。

## 17. 設定

サイドバーの歯車アイコンまたは `Ctrl+,` で設定にアクセスします。

### 一般

- 言語（15言語）
- テーマ（ライト / ダーク）
- インターフェースフォント、テキストフォント、等幅フォント、フォントサイズ
- フォントテーマ — プリセットフォントの組み合わせ（タイプライター、クラシック、モダンなど）で素早く切り替え
- **テーマ** — 6つの組み込みテーマから選択、カスタムテーマを作成（5色エディタ）、Obsidianコミュニティレジストリからテーマをインポート（200以上のテーマ）、または `.json` テーマファイルをインポート。ホバー時の✕ボタンで任意のカスタムテーマを削除。

### Style Settings

インターフェースのすべての可視要素の細かなカスタマイズ専用タブで、アクティブなテーマにライブ適用されます。

- **色** — 背景、サーフェス、テキスト（通常/ミュート/淡い）、アクセント、ボーダー、状態色
- **タイポグラフィ** — インターフェース/ノート/コードフォントサイズ、H1–H6サイズ、見出しウェイト、行の高さ、段落間隔
- **レイアウトと形状** — 小/中/大の角の半径、ボーダー幅、シャドウ、エディタの読みやすい行長、サイド余白
- **コンポーネント** — リボンドック、サイドバーアクションツールバー、レイアウトバー（ペイントグル）、トップバー/タブストリップ、ステータスバー、右サイドバー（インスペクタ）、ファイルエクスプローラー（ユニバースノート、子ユニバース、ライブラリ、フォルダ、ノート）、ボタン、タグ、コールアウト — それぞれ独立したサイズ、半径、色、該当する場合はアクティブ状態スタイル
- **エディタ** — リンクの色/ホバー/装飾、インラインコードの色/背景/半径、ブロック引用バーの幅/色、カーソルの色、選択背景

**インポート/エクスポート** — タブ上部のツールバー：
- クリップボードから貼り付け（ワンクリック）
- インポート/貼り付け（マージまたは置換付きテキストエリア）
- ファイルから（.json）
- コピー（現在の値をクリップボードへ）
- エクスポート（.json）

形式はObsidianのStyle Settingsプラグインと完全に一致するため、ObsidianとConstellation間で設定を共有できます。

変更はアクティブなテーマに自動保存されます；組み込みテーマを編集する場合、オリジナルを変更することなく変更が保持されるよう、自動的にカスタムテーマにクローンされます。

### スタイルセッター（Style Setter）

**スタイルセッター**は、フルページのデザインスタジオです — **設定 → 外観 → 「✦ Open Style Setter」**から開きます。中央に実際のインターフェースが表示され、任意の部分（サイドバー、ノートタイトル、見出し、リンク、ノートページ）をクリックすると、その要素のコントロールが右側に表示され、プレビューが即座に更新されます。テーマカード（Midnight / Daylight / Chocolate / Nord）は見た目全体を設定し — デザイン中はスタジオ自体もそのテーマをまといます — *サーフェス*リストはエディタだけでなくアプリ全体にわたって見た目をプレビューします。**「Apply to app」**でアクセント、背景、テキストの色、フォントが実際のConstellationに反映されます；**「Esc」**または**「✕」**はセッターのみを閉じ、設定は閉じません。適用は現時点ではセッションのライブプレビューです — 見た目を恒久的な名前付きStyleとして保存すること（再利用・名前変更可能なカラースウォッチとエクスポート/インポートを含む）は近日対応予定です。

### アラビア語オーバーライド

Universe ごとのパネルで、アラビア語エンジンが特定の表層形をどう解析するかを固定できます——自分の造語、地元の人名、分野固有の外来語、あるいはエンジンの自動的な読みに同意しない場合などです。各オーバーライドは生成 FST、カスケード、ヒューリスティック・フォールバックに優先します。オーバーライドの追加や削除は、その表層形を含むノートに限って対象化された再インデックスを発火します——全面再構築は起きません。ステップバイステップの手順は §19(「RTL とアラビア語サポート」)を参照してください。

### エディター

- エディタータイプ（Markdown / ドキュメント）
- デフォルトビュー（閲覧 / 編集）
- ライブプレビューモード
- 行番号、インデントガイド、スペルチェック
- 括弧の自動ペアリング、スマートリスト

### ライブラリ

- ライブラリの追加/削除
- ライブラリごとの外観設定
- 添付ファイルフォルダの場所

### アップデート

- アップデートの確認
- プライベートリポジトリ更新用の GitHub トークン

## 19. RTL とアラビア語サポート

Constellation は、アラビア語、ヘブライ語、ペルシア語、ウルドゥー語、その他の RTL スクリプトをファーストクラスでサポートしています：

- **自動検出**: ノートの方向はコンテンツから自動的に検出されます
- **インターフェース**: アラビア語/ヘブライ語を選択すると完全な RTL インターフェース
- **エディター**: 正しいカーソル移動と選択による RTL テキスト編集
- **スタービュー**: アラビア語ラベルは適切なフォントフォールバックで右から左にレンダリング
- **凡例**: コンテンツ言語に基づいてドット/テキストの順序が反転
- **スクリプトフォント**: 設定でアラビア語、ヘブライ語、CJK フォントを個別に設定可能

### アラビア語の設定

1. **設定 > 一般 > 言語**でアラビア語を選択
2. 必要に応じて**設定 > 一般 > スクリプトフォント**で専用のアラビア語フォントを設定
3. アラビア語コンテンツを含むノートは自動的に RTL でレンダリングされます

### アラビア語エンジン・オーバーライド

Constellation のアラビア語エンジンは五層の形態解析器であり、あらゆる検索・リンク・索引エントリの下で動作します。語根、語型、固有名詞、外来語、音韻的修復を理解しているため—— كاتب のクエリは كتبنا と كتاب を見つけ、一方で وائل は ائل へと壊されることなく名前のまま保たれます。

設定内の **アラビア語オーバーライド** パネルは、あなた自身の用語をエンジンに教える場所です。各オーバーライドは主権的な答えであり——生成 FST、カスケード、ヒューリスティック・フォールバックに優先します。

**オーバーライドを使う場面:**
- エンジンが知らない人名・地元の地名・分野特有の用語
- あなたの Universe に固有の造語や頭字語
- 特定の綴りを保ちたい外来語
- エンジンの自動解析があなたの読みと食い違うあらゆる場合

**ステップごとの手順:**

1. **設定** を開き(歯車アイコン、または `Ctrl + ,` / `Cmd + ,`)、サイドバーで **アラビア語オーバーライド** を選択します。
2. **オーバーライドを追加** をクリックします。
3. 次を入力します:
   - **表層形** — あなたが入力するアラビア語の語
   - **レンマ** — エンジンが返すべき基本形
   - **語根**(任意)— 古典的な語根がある場合は 3 または 4 つの子音
   - **語型**(任意)— 例 `فاعل`
   - **品詞** — 固有名詞 / 名詞 / 形容詞 / 副詞 / 動詞 / 助詞 / 外来 / 不明
   - **メモ**(任意)— 自分のための一行の文脈
4. **保存** をクリックします。表層形を含むすべてのノートが再トークン化されている間、パネルは **再インデックス中…** を表示し、完了すると **N 件のノートを再インデックスしました** と表示します。
5. オーバーライドを削除するには、その行の **×** をクリックします——同じ再インデックス走査が逆方向に実行されます。

オーバーライドは Universe ごとに `<universe>/.constellation/arabic-overrides.json` に保存されます——プレーンテキスト、アルファベット順ソート、原子的書き込みです。このファイルはバージョン管理に入れたり、複数デバイス間で共有したりできます。

## 21. ナレッジマップ

ナレッジマップは、知識ユニバース全体の構造、密度、成熟度を表示するラジアルサンバースト視覚化です。

### マップを開く

- **ドックボタン**: 左ドックのナレッジマップアイコンをクリック
- **コマンドパレット**: `Ctrl+P` で「Constellation Map」と入力

### 表示内容

- **中心**: ユニバース名と合計ノート数・単語数
- **最初のリング**: ライブラリ（各ライブラリの色で表示）。子ユニバースがある場合はここにも表示されます。
- **深いリング**: 各ライブラリ内のフォルダとサブフォルダ
- **最外部セグメント**: 個別ノート

### カラーモード

ドロップダウンで3つのモードを切り替え:
- **成熟度**: 種（灰色）→ 苗（薄緑）→ 常緑（緑）→ 正典（金）→ 枯れ
- **階層**: L1（青）→ L8（赤）— 知識の複雑さを表示
- **ライブラリ**: すべてのセグメントが親ライブラリの色を継承

### ドリルダウンナビゲーション

フォルダセグメントをクリックしてズームイン。パンくずリストでパスを確認。パンくずアイテムをクリックして戻るか、Escapeキーを押します。ノートセグメントをクリックしてエディタで開きます。

### マップに戻る

マップからノートを開いた後、タブバーに「マップに戻る」ボタンが表示されます。クリックすると元の場所に戻ります — ドリルダウンレベルが保持されます。

## 22. 認知エンジン

認知エンジンは、Constellation に組み込まれたインテリジェンスシステムで、ノートを分析し、アイデア間の隠れたパターンや関係を発見します。その根底にある哲学：

> 「データの量は問題ではありません。大切なのは、いくつのソースを保存するかではなく、そこからどのように知識を練り上げ、ひとつの意味ある認識へとつなげるかです。」

認知エンジンは9つの統合ツールで構成されています：タイプ付きリンク、知識階層、成熟ライフサイクル、テンション検出器、来歴チェーン、外在化エンジン、レビューパルス、トレイル、マルチレンズビュー。

---

### 17.1 タイプ付きリンク

#### これは何か？

タイプ付きリンクは、2つのノート間の関係の種類を記述するウィキリンクです。単に `[[ノート]]` と書く代わりに、`[[ノート|関係タイプ]]` と書くことで、つながりの本質を表現します——派生しているのか？矛盾しているのか？拡張しているのか？

#### なぜ重要か？

通常のリンクは「つながりがある」とだけ伝え、どのようなつながりかは示しません。タイプ付きリンクは、ノートのネットワークを参照の山から、思考構造・依存関係・推論を可視化する本物のナレッジマップへと変えます。

#### 使い方

1. エディタでノートを開く
2. 関係タイプ付きのウィキリンクを書く：`[[対象ノート|derives-from]]`
3. 対応タイプ：`derives-from`（由来）、`supports`（支持）、`contradicts`（矛盾）、`extends`（拡張）、`exemplifies`（例示）、`questions`（疑問）
4. 右サイドバーのノートプロパティからもタイプを追加可能

#### どこに表示されるか？

- **スタービュー（GraphMind）**：ノード間の色付きラベル付き線として
- **右サイドバー**：「バックリンク」タブにリンクタイプの表示付き
- **来歴タブ**：知識の系譜ツリー構築に使用

---

### 17.2 知識階層

#### これは何か？

認知エンジンは各ノートを8つの知識階層のいずれかに自動分類します：スナップショット、ログ、トピック、マップ、フレームワーク、原則、信条、成果物。分類はノートの構造、内容、リンク数に基づきます。

#### なぜ重要か？

各ノートの種類を知ることで、ライブラリ内の知識バランスが明らかになります。ノートの大半は一時的なスナップショットですか？それとも原則やフレームワークに発展していますか？コンテンツの本質への意識は、単なる情報収集ではなく真の知識構築への第一歩です。

#### 使い方

1. 分類は自動的に行われます——何もする必要はありません
2. 自動分類を上書きするには、フロントマターに `stratum` プロパティを追加：
   ```yaml
   ---
   stratum: framework
   ---
   ```
3. 使用可能な値：`snapshot`、`log`、`topic`、`map`、`framework`、`principle`、`conviction`、`artifact`

#### どこに表示されるか？

- **右サイドバー**：ノートプロパティの「階層」の下
- **スタービュー**：階層に応じたノードの色分け
- **設定 > 認知エンジン**：自動分類の有効/無効

---

### 17.3 成熟ライフサイクル

#### これは何か？

エンジンは各ノートの成熟度を4段階で追跡します：**種** → **苗** → **常緑** → **正典**。すべてのノートは種として始まり、コンテンツ、リンク、レビューの追加とともに徐々に成長します。

#### なぜ重要か？

成熟度は、生のアイデアと洗練された知識を区別します。今日の種は、十分な注意を払えば明日のリファレンスになり得ます。成熟度トラッキングは、さらなる発展と注意に値するノートの特定を助けます。

#### 使い方

1. 成熟度は以下に基づいて自動的に変化：語数、入出リンク数、最終更新日
2. 成熟度を手動設定するには、フロントマターに `maturity` プロパティを追加：
   ```yaml
   ---
   maturity: evergreen
   ---
   ```
3. 使用可能な値：`seed`（種）、`sapling`（苗）、`evergreen`（常緑）、`canonical`（正典）

#### どこに表示されるか？

- **右サイドバー**：タイトル横のアイコンで現在の成熟段階を表示
- **スタービュー**：ノードサイズとして——成熟したノートほどノードが大きい
- **設定 > 認知エンジン**：成熟度トラッキングの有効/無効

---

### 17.4 テンション検出器

#### これは何か？

テンション検出器は、関連するノートを検査し、2つ以上のノート間で主張や結論が矛盾している場合に警告します。`contradicts` タイプのリンク分析とノート間のテーマ的類似性に基づいて動作します。

#### なぜ重要か？

テンションは必ずしもエラーではありません——より深い思考への招待です。ライブラリ内の2つのアイデアが矛盾する場合、それは理解が進化したか、探求に値する複雑さが存在することを意味します。テンション検出は、矛盾した基盤の上に無意識に知識を積み上げることを防ぎます。

#### 使い方

1. 矛盾するノート間に `contradicts` タイプリンクを追加：`[[別のノート|contradicts]]`
2. エンジンはコンテンツ分析による暗黙のテンションも検出
3. サイドバーから検出されたテンションのリストを確認

#### どこに表示されるか？

- **右サイドバー**：矛盾が検出された場合の「テンション」タブ
- **スタービュー**：矛盾するノード間の赤い点線
- **通知パネル**：新しいテンション検出時のアラート

---

### 17.5 来歴チェーン

#### これは何か？

来歴チェーンは各アイデアの起源を追跡します——どこから来たのか、何から派生したのか。`[[ノート|derives-from]]` リンクを使用して、元のソースから現在の定式化に至るまでの知識の発展経路を示す系譜ツリーを構築します。

#### なぜ重要か？

アイデアの出所を知ることは、受信した知識（書籍、記事、講義から）と発見した知識（自分自身の結論と考察）を区別します。知識のソースへの意識は、アイデアの信頼性を評価し、時間の経過とともに思考がどのように形成されたかを理解するのに役立ちます。

#### 使い方

1. ソースから派生したノートを作成する際にリンクを追加：`[[元のソース|derives-from]]`
2. 多段階チェーンの構築が可能：ノート ← 由来 ← 由来 ← 元のソース
3. フロントマターに `source-type: received` を追加して外部ソースを分類

#### どこに表示されるか？

- **右サイドバー**：「来歴」タブに完全な系譜ツリーを表示
- **スタービュー**：リンク上の矢印の方向（ソースから派生へ）
- **ノートプロパティ**：来歴チェーンに基づく「受信」または「発見」分類

### 17.6 外在化エンジン

#### これは何か？

ノートが生のキャプチャから結晶化された洞察へと成熟する過程を追跡する段階的な形式化パイプラインです。各ノートには4つのステージのいずれかを割り当てることができます：

| ステージ | アイコン | 意味 |
|----------|----------|------|
| 一時的 | 🌱 | 素早いキャプチャ、一時的な思いつき |
| 文献 | 📖 | ソースから自分の言葉で書き直したもの |
| 永続 | 🔗 | アトミックなアイデア、1つのコンセプト、グラフに接続 |
| 統合 | ✨ | 複数の永続ノートを組み合わせたオリジナルの洞察 |

#### なぜ重要か？

ほとんどのアプリはすべてのノートを同じように扱います。外在化エンジンはその違いを可視化します — ライブラリのどれだけが生のキャプチャで、どれだけが真の理解なのかを一目で確認できます。

#### 使い方

1. ブレッドクラムバー（エディタの上）で、ステージドロップダウンを使用してステージを選択します。
2. またはプロパティを展開してそこのステージドロップダウンを使用します。どちらもファイルツリーと即座に同期します。
3. ノートを昇格するには、ドロップダウンを1つのステージから次のステージに変更します。フォーカスモードでは、下部の「永続に昇格」をクリックします。
4. ステージを削除するには、ドロップダウンから「— ステージ —」を選択します。

#### どこに表示されるか？

- **ブレッドクラムバー**：絵文字 + ステージ名のドロップダウン
- **プロパティパネル**：`stage` プロパティが存在する場合のドロップダウン
- **ファイルツリー**：ノート名の横に絵文字アイコン
- **フォーカスモードフッター**：「永続に昇格」ボタン

### 17.7 レビューパルス

#### これは何か？

レビューパルスは、拡大する間隔でノートを再浮上させるシステムです：最終レビューから1日、3日、7日、14日、30日後にノートを注意に戻します。`#assumption`や`#model`タグのついたノートをメンタルモデルチェックポイントとして監視し、キャプチャしたが一度も再訪していないノートの「未レビュー」キューも管理します。

#### なぜ重要か？

知識は再訪なしに衰退します。今日ノートを書いて、3週間後にはその存在を忘れています。間隔反復は認知科学でこの衰退と戦う最も確立された技法です。レビューパルスはこの原理を実際のノートに適用します。

#### 使い方

1. 左サイドバーの**レビューパルス**タブをクリックします。3つのセクションが表示されます：レビュー予定、メンタルモデルチェックポイント（`#assumption` / `#model`）、未レビュー。
2. ノートをクリックして開き、読みます。
3. 3つのアクションから選択します：
   - **レビュー済み**（チェックマーク）— 次の間隔で次のレビューをスケジュール（1 → 3 → 7 → 14 → 30日）。
   - **7日スヌーズ**（目のアイコン）— 間隔を進めずにノートを7日延期。
   - **却下**（アーカイブアイコン）— ノートをレビューキューから永久に削除。
4. コマンドパレットを開いて "Review due notes" と入力します。

#### どこに表示されるか？

- **左サイドバー**：レビューパルスタブに予定ノートのバッジカウント
- **コマンドパレット**：クイックアクセス用の "Review due notes" コマンド

### 17.8 トレイル

#### これは何か？

トレイルは、ノートの名前付き順序付きシーケンスです — 本の章や知識のガイドツアーの停留所のようなものです。ノートのfrontmatterに`trail: true`を追加し、ノート本文にウィキリンクを順番にリストすることで定義します。

#### なぜ重要か？

知識は常にウェブではありません。時にはパスです — 学習シーケンス、議論の進行、物語。トレイルはその順序を明示的にキャプチャし、非線形ライブラリに線形の次元を追加します。

#### 使い方

1. frontmatterに`trail: true`を含む新しいノートを作成します。
2. ノート本文に、希望の順序でウィキリンクをリストします。
3. トレイルに属するノートを開くと、ブレッドクラムバーにトレイル名と位置が表示されます（例：「マイトレイル 2/5」）。矢印ボタンで前後のノートに移動できます。
4. コマンドパレットを開いて "Open Trail" と入力すると、全トレイルが表示されます。

#### どこに表示されるか？

- **ブレッドクラムバー**：名前、位置、ナビゲーション矢印付きのトレイルインジケーター
- **コマンドパレット**："Open Trail" コマンドで全トレイルを一覧

### 17.9 マルチレンズビュー

#### これは何か？

マルチレンズビューは、フォルダ構造を変更したりノートを複製したりすることなく、異なる分類スキームでライブラリを表示できます。「レンズ」はプロパティやタグに基づいてノートを再編成する仮想的なグループ化です。組み込みレンズ：「ステージ別」（一時的/文献/永続/統合）と「トピック別」（タグによるグループ化）。設定でカスタムレンズを作成できます。

#### なぜ重要か？

フォルダ構造は単一の階層を強制しますが、知識は一つの木には収まりません。マルチレンズビューは、ファイルを移動せずに異なる視点を切り替えることができます。同じノートを、異なる組織的レンズで表示します。

#### 使い方

1. サイドバーで、ファイルツリーの上部にある**レンズドロップダウン**を見つけます（デフォルトは「フォルダ」）。
2. レンズを選択：「ステージ別」、「トピック別」、またはカスタムレンズ。サイドバーが即座に再編成されます。
3. デフォルトのファイルツリーに戻るには「フォルダ」を選択します。
4. カスタムレンズを作成するには：**設定 > ナレッジマネジメント**を開き、**レンズを作成**をクリックし、名前を付けてグループ化するfrontmatterプロパティを選択します。
5. またはコマンドパレットを使用："Create Lens" と入力します。

#### どこに表示されるか？

- **サイドバードロップダウン**：ファイルツリーの上部にあるレンズセレクター
- **設定 > ナレッジマネジメント**：カスタムレンズの作成、編集、削除
- **コマンドパレット**："Create Lens" コマンド

### 認知エンジンの設定

認知エンジンの全ツールは **設定 > 認知エンジン** で設定可能です：

- **階層分類** — 自動分類を有効/無効にする
- **成熟度トラッキング** — 成熟ライフサイクルの追跡を有効/無効にする
- **タイプ付きリンク** — リンク検出の感度しきい値を調整（0.0 ～ 1.0）
- **テンション検出器** — 自動テンション検出を有効/無効にする
- **手動上書き** — フロントマターに `stratum` と `maturity` プロパティを追加して自動分類を上書き

## 23. 関連ノート

Constellation は知識を*練り上げる*ためのものであり、知識とはつながりです。**関連ノート**は、いま見ているノートと最も関係の深いノートを、すでにあなたのライブラリにあるものの中から見つけ出します——本来リンクすべきなのに、まだつながっていない親類たちです——そして、そのどれでもワンクリックで**タイプ付きリンク**に変えます。これは「これに似たノート」の、思考のための版です。

**すべての提案がタイプ付きです。** 提案を受け入れると、Constellation は2つのノートが*どう*関連しているかを尋ねます——支持、矛盾、例示、派生、等々、あるいは単なる**連想**。タイプ付きリンクは、後から読み返し、検索し、問い直すことのできる、ひとつの推論です。この機能は、リンクをまとめて一括追加することも、タイプのないリンクを黙って追加することも決してありません。（**ナレッジ・フォーミュレーション**および**プロパティ**を参照してください。）

**どのように見つけるか。** 候補は**あなた自身のライブラリの中だけ**から選ばれ、Constellation の常時更新される検索インデックスに照らして、最も*特徴的な*共有語彙——ありふれた言葉ではなく、珍しく内容を物語る言葉——でランク付けされます。それぞれの提案には、なぜそれが浮かび上がったのかを説明する**共通の語**が表示されるので、中身の見えない当て推量を受け入れさせられることはありません。

**5か所、ひとつのリスト。** 同じ提案リストが、**レビュアー**（🕐、*孤立ノート*または*脆いノート*として指摘されたノートに対して）、**バックリンクタブ**（右サイドバー）、**360° インスペクター**、**ヘルスタブ**、そして**スカイビュー**（🌌——任意の星を右クリック → **関連ノートを提案…**）に表示されます。

**被リンク方向と発リンク方向 — そして、なぜあなたが選ばなくてよいのか。** 診断のための場所（**360° インスペクター**と**ヘルスタブ**）は**被リンク方向**のつながりを提案します——*どのノートが**ここを**指すべきか*。一般的な場所（**バックリンクタブ**と**スカイビュー**）は**発リンク方向**のつながりを提案します——*このノートが**何を**指すべきか*。方向はその役割に合わせて表示場所が選び、ノートとタイプはあなたが選びます。（今後のアップデートで、方向を自分で切り替えられるようになる予定です。）

**使い方。** **関連ノート**という見出しの下に、近いものから順にランク付けされた関連ノートが、それぞれの共通の語とともに並びます。候補の**リンク**ボタンをクリックし → 小さな**「どう関連していますか？」**メニューで関係のタイプを選ぶと → タイプ付きリンクが**即座に**作成され、その提案はリストから外れます。リンクはその後、ノートの**プロパティ**に収まり、被リンク・発リンクやグラフ全体に現れます。どれも本当には当てはまらないなら、そのまま放っておいてください——あるいはレビュアーで、ノートを意図的な**独立ノート**として印を付けてください。関連ノートは提案するだけ——決めるのはあなたです。

**ローカルで、プライベートで、入力を妨げません。** 提案は要求に応じてあなたのライブラリだけから計算され——何ひとつ端末の外には出ません——それをまとめる処理が入力を妨げることもありません（処理中は「関連するノートを探しています…」と短く表示されます）。提案も、共通の語のヒントも、関係のタイプもすべて、あなたが選んだ言語で表示され、右から左へ書く文字のために正しく反転します。

## 24. 認知の色と右クリックメニュー

### プロパティのスタイル設定（スタイルセッター）

**スタイルセッター**（設定 → 外観 → ✦ スタイルセッターを開く、または独立したタブ）を開き、**プロパティ**カテゴリーを選ぶと、ノートのフロントマター内の小さなタグを再装飾できます。2つの要素：**プロパティタグ**（通常の `tags` スタイルのチップ — タグの背景、タグのテキスト、タグの角丸 0〜20 px、高さ 14〜32 px）と**分類ピル**（背景、テキスト、角丸 0〜20 px）。中央のライブプレビューが編集に応じて更新されます。すべての値はいま現在の見た目とまったく同じ状態から始まるため、コントロールに触れるまで何も変わりません。**Keep** をクリックすると、このユニバースに保存されます。

### 認知の色（スタイルセッター）

**認知の色**カテゴリーは、**認知状態ごとに1つの共有色**を提供し、その状態を表示するすべてのサーフェスが一致するようにします。5つのセット：

- **成熟度** — 種、若木、常緑、正典、枯れかけ。
- **確信** — 仮説、証拠、確立、係争中。
- **由来** — 受容、発見、混合、なし。
- **ステージ** — 閃き、誕生、成長、成熟、休眠、保管。
- **一致カテゴリー**（検索結果がなぜ一致したか） — タイトル、本文、タグ、ウィキリンク、プロパティ、セマンティック、構造化。

その動作は**オンデマンドで統一**です：色を選ぶまで何も変わりません。各サーフェスは現在の色をフォールバックとして保持し、ここで状態の色を設定した瞬間、その状態を表示する**すべて**のサーフェス — ファイルツリー、タブ、ノートインスペクタ、エディタ内の検索ハイライト、一致バッジ、検索結果のハイライト — が一斉にあなたの色に切り替わります。状態に触れずに残せば、以前とまったく同じ見た目のままです。**Keep** をクリックして保存します。

### 右クリックメニュー

Constellationは3つの場所でコンテキストメニューを提供し、それぞれクリックした場所に合う操作だけを提示します：

- **ノート本文を右クリック** — リンクを追加 / 外部リンクを追加；**書式 ▸**（太字、斜体、下線、取り消し線、ハイライト、インラインコード、数式、コメントの切り替え、上付き、下付き、書式をクリア）；**段落 ▸**（箇条書き / 番号付き / タスクリスト、H1〜H6、本文、引用）；**挿入 ▸**（脚注、表、コールアウト、水平線、コードブロック、数式ブロック、画像）；切り取り / コピー / 貼り付け / プレーンテキストとして貼り付け / すべて選択；そして**スタイル…**（**エディタ**カテゴリーでスタイルセッターを開く）。
- **フロントマターのプロパティ行を右クリック** — 値をコピー、名前をコピー、プロパティを削除、プロパティを追加；続いて本文と同じ編集メニュー；そして**スタイル…**（**プロパティ**カテゴリーでスタイルセッターを開く）。
- **検索結果を右クリック** — **安全な**サブセット：開く、新しいタブで開く、ツリーで表示、リンクをコピー、パスをコピー、ブックマーク、エクスプローラーで表示、既定のアプリで開く、そして**スタイル…**（**認知の色**カテゴリー）。設計上、ここには**名前変更・移動・削除がありません** — 検索パネルはファイルツリーの一瞬一瞬の最新コピーを保持しないため、破壊的な操作は、ビューが常に最新であるファイルツリーに留められます。

各**スタイル…**項目は、右クリックしたものに応じたカテゴリーに着地するので、正しいコントロールを探し回る必要は決してありません。すべてのメニュー項目、カテゴリー名、状態ラベルは、あなたが選んだインターフェース言語で表示され、右から左へ書くレイアウトでは反転します。
