# 分類器

> *「各ノートを知識の種類と出典で分類します。」*

**分類器** は分類のための宇宙全体のホームです。左ドックから開くフルページビューで、Constellation の知識分類体系を通してノートを読むために必要なものをすべて 1 か所に集めます:ライブラリ全体をスキャンするコントロール、任意のノートをオンデマンドで分類する方法、ノートの要約を作成するボタン、そして各提案を承認・編集・却下・曖昧性解消するライブのレビューキューです。

右サイドバーの **Source Review** パネルを使ったことがあれば、すでにカードはご存じでしょう。分類器は同じエンジンと同じカードを、狭いサイドバータブから昇格させ、ウィンドウ全体を与えたものです — さらにサイドバータブにはなかった 2 つのもの:ノートピッカーと「すべての要約を作成」ボタンが加わります。

---

## 「分類器」と「複数の分類器」 — 名前についての一言

この 2 つの名前は意図的に似ていますが、別のものを意味します:

- **分類器**(このビュー)は *場所* です — 分類が行われるフルページの部屋。
- **複数の分類器**(エンジン内のもの)は *6 つのレンズ* です — frontmatter、引用、語幹、リンクされたノート、類似ノート、AI 判断 — それぞれがノートを読んで投票します。6 つのうち 5 つは今日アクティブです;6 つ目(AI 判断)は構築済みですがまだオンになっていません。

つまり:あなたは **分類器** を開き、その中で **複数の分類器** が読み取りを行います。6 レンズの仕組みは **Source Review** トピックで完全に説明されています — このトピックは部屋についてです。

---

## これは何ですか?

分類器は 1 つの質問に答えます:**「私の宇宙の各ノートはどう分類されているか — そして何がまだ私の判断を必要としているか?」**

上から下に積み重ねられた 4 つのものを中心に構築されています:

1. **3 つのアクションを持つヘッダー** — *ノートを分類…*、*すべての要約を作成*、*スキャン開始*。
2. **進行ストリップ** — ライブラリのスキャンが実行中のときのみ表示され、進捗状況を示します。
3. **レビューキュー** — Source Review パネルと同じ 承認 / 編集 / 却下 / 曖昧性解消 カード、ただし全幅で表示。
4. **各カードの下のノート要約** — ノートを開かずに判断できるよう、ノートを平易な言葉で短く要約したもの(下記の *ノートの要約*、および専用の **Note Summaries** トピックを参照)。

すべて **あなたのデバイス上で** 実行されます。ノートが Constellation を離れることはありません。

---

## なぜ重要ですか?

分類は、Constellation が `.md` ファイルの山を *形作られた* 知識体系に変える方法です — 各ノートを 2 つの軸(知識がどこから来たか、どんな種類の知識か)に配置します。その形こそが **Constellation Sight**、**Epistemic Metadata** パネル、そして分類体系を考慮した検索を動かすものです。

しかし分類は決定の多い作業です。何百もの未分類ノートがあるとき、薄いサイドバータブから — 一度に 1 ノートずつ、特定のノートを呼び出す方法もなく — それを行うのは遅いものです。分類器は、その作業を *腰を据えて行えるもの* にするために存在します:一度開いて、画面全体を与え、1 つの集中したセッションでライブラリを処理する。ノートピッカーは任意のノートを名前で引き込めます;要約は部屋を離れずにカードを判断できます;スキャンコントロールはキューを一括でシードします。

## 開き方

1. **左ドック**(ウィンドウの端にあるアイコンの縦の帯)で、**積み重なったカードのアイコン** — 上下に重なった 3 枚の小さなカード — をクリックします。Sight の目や Nervous System のニューロンといった他のワークスペースアイコンの中にあります。
2. 分類器は **フルページビュー** として開き、コンテンツ領域を引き継ぎます。
3. 閉じるには:ヘッダー右上の **(×)** をクリックするか、**Esc** を押します。元いた場所に戻ります。

> **Esc に関する注記:** *ノートを分類…* の検索ポップオーバーが開いている場合、**Esc** を押すとそのポップオーバーだけが閉じ、分類器は開いたままになります。(ポップオーバーを閉じた状態で)もう一度 **Esc** を押すと、分類器自体が閉じます。

## 表示内容

### ヘッダー — 3 つのアクション

分類器の上部には、3 つのコントロールが横に並んでいます:

| コントロール | 何をするか |
|---|---|
| **ノートを分類…** | 小さな検索ボックスを開きます。任意のノートのタイトルの数文字を入力し、結果から選ぶと、エンジンがその場で分類します — ノートを先に開く必要はありません。新しい提案が下のキューに表示されます。 |
| **すべての要約を作成** | まだ要約を持たないすべてのノートに対して、短い要約を事前計算します。バックグラウンドで静かに実行されます;進捗はウィンドウ下部のステータスバーに表示されます;いつでもキャンセルできます。(**Note Summaries** トピックで詳述。) |
| **スキャン開始** | エンジンを **アクティブなライブラリ全体** に対して一度に実行し、まだ分類されていないすべてのノートに対して提案をキューに入れます。実行中、ボタンは *実行中…* と表示され、ヘッダーの下に進行ストリップが現れます。 |

### 進行ストリップ

ヘッダーの直下に、**ライブラリのスキャンが実行中のときのみ** 薄いストリップが現れます。何件のノートが処理されたかを示し、スキャンの完了を見守ることができます。スキャンが実行されていないときはストリップは隠れ、キューがヘッダーのすぐ下に位置します。

### レビューキュー

分類器の大部分は **レビューキュー** です — Source Review パネルで見るのと同じカード、ただし全幅です。各カードには、ノート、ノートがあなたの分類体系にどう収まるかのエンジンの読み取り(Source × コンテンツタイプ)、6 つの小さな分類器ドット、そして取れるアクションが表示されます:

- **承認** — エンジンの提案をノートに書き込み、カードをクリアします。
- **編集** — ツリーから値を自分で選びます。
- **却下** — 何も書き込まずにカードをクリアします。
- **曖昧性解消** — 「分裂」したカードで、候補チップから正しい値を選びます。

カードの完全な仕組み — 色付きドット、確信度レジーム、兄弟曖昧性解消、キューフィルターチップ、「すべて承認」、ライブラリごとのキャリブレーション — は **Source Review** トピックに記載されています。分類器はそのパネルをそのまま使用します;カードについてはサイドバーとフルページビューの間で何も変わりません。

### 各カードの下のノート要約

各カードのタイトルの下には、短い **要約** 行があります — ノートが何についてのものかを伝える数文の文章で、ノートを開かずにカードを判断できます。これは **Note Summary Creator (NSC)** によって生成されます;次のセクションと **Note Summaries** トピックを参照してください。

## 単一ノートの分類 — ノートピッカー

*ノートを分類…* ボタンは単純な問題を解決します:サイドバータブでは、現在開いているノートしか分類できませんでした。分類器には「開いているノート」がないため、任意のノートを名前で呼び出す方法を提供します。

**1 つのノートを分類するには:**

1. **ノートを分類…** をクリックします。プレースホルダー *ノートを検索…* を持つ検索ボックスが降りてきます。
2. ノートのタイトルを入力し始めます。少し間を置いた後、一致するノートがリストに表示されます(最大 10 件)。
3. 必要なノートをクリックします。エンジンがそれを分類し、ポップオーバーが閉じ、そのノートの新しいカードが下のキューに表示されます。
4. 何かがうまくいかない場合(まれなエンジンエラー)、メッセージがポップオーバー内に表示されるので、分類が実行されなかったことがわかります。

ノートを開く必要はなく、キュー内の場所を失うこともありません。これは、頭にある特定のノートを分類する最速の方法です。

## 分類器内のノート要約 (NSC)

キュー内のすべてのカードには、タイトルの下に表示されるノートの短い **要約** が付いています。要約は **Note Summary Creator (NSC)** によって生成され、1 つの確固たるルールに従います:**あなたが要約を書いていれば、エンジンはあなたのものを使う;あなたが書いていないときだけ生成する。**

優先順位は次のとおりです:

1. **あなたの frontmatter 要約** — ノートのプロパティにある `summary:`、`description:`、`abstract:`、または `excerpt:` フィールド。あなたが書いたとおりに正確に使用されます。
2. **あなたの要約コールアウト** — ノート本文にある `> [!summary]`、`> [!abstract]`、または `> [!tldr]` ブロック。発音区別符号もすべて含め、あなたが書いたとおりに正確に使用されます。
3. **生成された要約** — 上記のいずれも書いていない場合のみ。Constellation はノートを読み、最も中心的な文を見つけ、上位 3 文を元の順序で表示します。

エンジンは **生成された要約をあなたのノートに書き戻すことは決してありません** — あなたの `.md` ファイルが信頼できる情報源であり、分類器はそれらを *読む* だけです。

**すべての要約を作成** ボタンは、ライブラリ全体の要約をバックグラウンドで事前計算するため、スクロールしながら埋まるのではなく、カードが即座に要約を表示します。完全な詳細 — 生成された要約がどう作られるか、要約が間違って見える場合の対処法を含む — は **Note Summaries** トピックにあります。

## 分類器が *行わない* こと

- **デフォルトでバックグラウンドで自動的に分類しません。** スキャンはあなたが *開始する* ものです。(設定 → インテリジェンス → CECE にオプションのバックグラウンドモードがあり、デフォルトはオフです — **Source Review** を参照。)
- **クラウドサービスを呼び出しません。** 5 つのアクティブな分類器はヒューリスティックでローカルです。6 つ目のレンズ(AI 判断、ローカル言語モデル)は設計に組み込まれていますがまだオンになっていないため、今日はすべてのカードで沈黙したままです。
- **ノートの文言を変更しません。** カードを承認すると、分類 *プロパティ*(`sources:` および `content_type:` frontmatter フィールド)が書き込まれます。あなたの文章を編集することは決してなく、生成された要約をファイルに書き込むこともありません。

## 一般的なワークフロー

**「分類器を初めて開きました — どこから始めればよいですか?」**
**スキャン開始** をクリックして、ライブラリ内のすべての未分類ノートに対して提案をキューに入れます。進行ストリップが埋まるのを見守ります。次にキューを下に処理し、エンジンが正しく分類したものを承認し、分裂したものを曖昧性解消します。各カードの下の要約で素早く判断できます。

**「ライブラリ全体ではなく、特定の 1 つのノートを分類したいです。」**
**ノートを分類…** をクリックし、タイトルを入力してクリックします。カードがキューに表示されます。それを承認するか編集します。

**「カードが要約を表示するのに少し時間がかかります。」**
**すべての要約を作成** を一度クリックします。バックグラウンドですべてのノートの要約を事前計算します(進捗はステータスバーに)。完了後、要約は即座に表示されます。

**「キューに何百ものカードがあります — どう集中すればよいですか?」**
キューの上のフィルターチップを使用します(**Source Review** に記載):*分類器が同意* と *すべて承認* で簡単なものをクリアし、それから分裂したカードに取り組みます。

## 関連トピック

- **Source Review** — カードそのもの:6 つの分類器、色付きドット、確信度レジーム、兄弟曖昧性解消、キューフィルター、「すべて承認」、ライブラリごとのキャリブレーション。分類器はこのパネルを埋め込みます。
- **Note Summaries** — 各カードの下の要約行がどう生成されるか、作者優先の優先順位、そして *すべての要約を作成* のバックフィル。
- **認知エンジン** — 分類が収まる、より広い知識形成哲学。
- **Epistemic Metadata** — 分類が書き込む `sources:` および `content_type:` プロパティと、その読み方。
- **Constellation Sight** — Source × コンテンツタイプの分類が動かす空間ビュー。
