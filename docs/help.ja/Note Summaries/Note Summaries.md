# ノートの要約

> *あなたが要約を書いていれば、Constellation はあなたのものを使います。あなたが書いていないときだけ生成し、そのときでさえファイルには書き込みません。*

**ノートの要約** はノートの短い要約です — ノートが何についてのものかを一目で伝える数文の文章。要約は **Note Summary Creator (NSC)** によって生成されます。3 つの場所で目にします:**分類器** / **Source Review** キューの各カードのタイトルの下(背後のノートを開かずにカードをどう分類するかを判断する場所)、**検索結果** の各ヒットの下にうっすらしたイタリック行として(なぜ一致したかを示すスニペットの横で、ノートが *何についてか* を伝えます)、そして **エディタ** でノートを開いたときにノート本文の上に細い帯として(読み書きの最中にノートの要点が文脈に残るように)。

このトピックでは、要約がどこから来るのか、機械のものより *あなたの* 言葉を常に優先する厳格な優先順位、生成された要約がどう作られるのか、そしてライブラリ全体の要約を一度に事前計算する方法を説明します。

---

## 要約が存在する理由

何百ものカードのレビューキューを処理しているとき、タイトルだけでは、ノートが実際に何を述べているかを思い出すのに十分でないことがよくあります。各ノートを開いて記憶を新たにすると、流れが途切れます。タイトルの下の一目でわかる要約がそれを解決します:3 文を読み、ノートを思い出し、判断を下し、次に進む。

しかし要約は作者性の小さな行為でもあります。すでにノートを自分の言葉で — `summary:` フィールドや `> [!summary]` コールアウトで — 蒸留しているなら、機械の推測ではなく *それ* が表示されるべき要約です。したがって Constellation の要約に対する第一のルールは、あなたの文章への敬意についてのルールです:**あなたのものが勝つ。**

---

## 要約がどこから来るのか — 優先順位

任意のノートについて、Constellation はこのリストを下にたどり、存在する最初のもので止まることで要約を選びます:

1. **あなたの frontmatter 要約。** ノートのプロパティに `summary:`、`description:`、`abstract:`、または `excerpt:` フィールド(この順序でチェック)が含まれている場合、そのテキストは **あなたが書いたとおりに正確に** 使用されます。
2. **あなたの要約コールアウト。** ノート本文に `> [!summary]`、`> [!abstract]`、または `> [!tldr]` コールアウトが含まれている場合、そのテキストは **あなたが書いたとおりに正確に** 使用されます — 発音区別符号や句読点を含め、そのまま保持されます。
3. **生成された要約。** 上記のいずれも書いていない場合のみ、Constellation は要約を生成します — ノートを読み、その最も中心的な文を抽出することによって(下記参照)。
4. **冒頭テキストのフォールバック。** エンジンが文に分割できないノート(例えば、明確な文の句読点がないスクリプトのテキスト)については、ランク付けされた要約の代わりにノートの冒頭の数行を表示します。

> **最も重要な唯一のルール:** ステップ 1 と 2 は、あなたが書いた要約が *決して* 上書きされないことを意味します。要約したと思っていたノートに生成された要約が表示される場合、それはエンジンが探す場所にあなたの要約を見つけられなかったことを意味します — あなたの frontmatter フィールドが上記の 4 つの名前のいずれかであること、またはあなたのコールアウトが上記の 3 つのタイプのいずれかであることを確認してください。

## 生成された要約がどう作られるか

Constellation が要約を生成しなければならないとき(あなたが書かなかったため)、それは **抽出型** の要約を行います — 新しい文章を考案するのではなく、すでにノートにある文を選択します。この手法は確立されたもの(TextRank, Mihalcea & Tarau 2004)です:

1. **文に分割する。** ノート本文は、文の境界に関する Unicode 標準を使って文に分割されるため、言語やスクリプトを越えて機能します。
2. **各文の意味を読む。** 各文は、コンパクトなオンデバイスモデルを使って小さな数値の「意味の指紋」(埋め込み)に変換されます。
3. **中心性でランク付けする。** 最も *他の多くの* 文と意味が似ている文が最高得点になります — これらがノート全体を最もよく代表する文です。
4. **上位 3 文を順序どおりに取る。** 最高ランクの 3 文は **ノートに現れる順序で** 表示されるため、要約が順序が乱れることなく自然に読めます。

非常に長いノートは丁寧に処理されます — エンジンは本文をどれだけスキャンするか、何文をランク付けするかに上限を設けるため、巨大なノートの要約がアプリを遅くしたりクラッシュのリスクを冒したりすることは決してありません。

抽出型であるため、生成された要約は常にあなたが実際に書いた文で構成されます。あなたの口に言葉を入れることは決してありません。

---

## 要約は読み取り専用 — File-Over-App

Constellation は **生成された要約をあなたのノートに書き戻すことは決してありません。** あなたの `.md` ファイルが信頼できる情報源です;カードに表示される要約はその場で計算され、ファイルのテキストや frontmatter に保存されるのではなく、別個にキャッシュされます。

これは意図的なものであり、Constellation の *File-Over-App* 原則に従います:アプリはあなたのファイルへの窓であり、それらを静かに変更するエディタではありません。要約をノートの *中に* 存在させたい場合は、自分で書いてください(`summary:` フィールドまたは `[!summary]` コールアウト) — そうすれば、上記の優先順位ルールにより、Constellation はあなたのものを表示し、生成を止めます。

すべては **あなたのデバイス上で** 計算されます。要約のためにノートのテキストがどこかに送信されることは決してありません。

## 要約はどこに表示され、どう埋まるか

要約は Constellation 全体で、ノートが現れるどこでも表示されます:

- **分類器 / Source Review キュー** — 各カードのタイトルの下(元々の表示場所 — *分類器* を参照)。
- **検索結果** — 各ヒットの下、スニペットの下にうっすらしたイタリック行。スニペットは結果がクエリと一致した *理由* を示し;要約行はそのノートが *何について* かを示します。両者があれば、何も開かずに結果を流し読みできます。
- **エディタ** — ノートを開いたときにノート本文の上に表示される細く控えめな帯で、読み書きの最中にノートの要点が文脈に残ります。要約がまだ存在しないとき(まったく新しいノート、または要約が計算中のノート)、帯は自分自身を隠します。

デフォルトでは要約は **遅延的かつ丁寧に** 埋まります:カードがビューにスクロールしてくると、検索結果が現れると、またはノートを開くと、Constellation は欠落している要約を一度に数件ずつ計算し、ライブラリの分類スキャンが実行中はいつでも一時停止して、両者がリソースを競合しないようにします。これによりアプリは応答性を保ちます — 要約が表示される前にカード / 結果 / 開いたノートが一瞬見え、その後すぐに要約がポップインすることがあります。

すべての要約を前もって準備しておきたい場合 — すべての場所で要約が即座に表示されるように — は、**すべての要約を作成** を使用します。

## すべての要約を作成 — ライブラリ全体の事前計算

**すべての要約を作成** ボタン(**分類器** ヘッダー内)は、**まだ最新のものを持たないすべてのノート** に対して要約を事前計算するため、スクロールしながら埋まるのではなく、カードが即座に要約を表示します。

**使い方:**

1. **分類器**(左ドックの積み重なったカードのアイコン)を開きます。
2. ヘッダーの **すべての要約を作成** をクリックします。ボタンが *ノートの要約を作成中…* に変わります。
3. 進捗はウィンドウ下部の **ステータスバー** に表示されます — 実行中も作業を続けられます。
4. 早めに止めるには、ステータスバーの進行ストリップにある **キャンセル** コントロールを使用します。部分的な実行で問題ありません;次回は止まった場所から続きます。

知っておくとよいいくつかのこと:

- **あなたが要求したときのみ** 実行されます — 自動的に開始することは決してないため、アプリの起動を遅くすることは決してありません。
- 別のスレッドで **バックグラウンドで** 実行されます;入力とナビゲーションは瞬時のままです。
- **再開可能** です — キャンセルしたり、実行中にアプリを閉じたりしても、次の実行は最初からやり直すのではなく、止まった場所から続きます。
- **欠落している、または古い** 要約のみを計算します — 要約がすでに最新のノートはスキップされるため、2 回目の実行は高速です。

## あなた自身の要約が使われることを確認する

カードでは、要約は単一の **要約** ラベルの下に表示されます — カードはテキストがあなたから来たのかエンジンから来たのかをバッジで示しません。それを決めるのは上記の優先順位です:ノートが frontmatter フィールドのいずれか、または要約コールアウトのいずれかを持っている場合、Constellation は *それ* を表示し、決して生成しません。

したがって、機械が選んだように読める要約をノートが表示している場合、そのノートは frontmatter 要約も要約コールアウトも持っておらず — 修正方法はそれを追加することです:

- ノートの frontmatter に `summary:`(または `description:` / `abstract:` / `excerpt:`)フィールドを追加する、**または**
- 本文に `> [!summary]`(または `[!abstract]` / `[!tldr]`)コールアウトを追加する。

そのノートの要約が次に計算されるとき — 次にカードが読み込まれるとき、または **すべての要約を作成** を実行した後 — あなたの言葉が引き継ぎます。

## 一般的なワークフロー

**「ノートが機械の要約を表示しているが、私が書いた。」**
Constellation は探す場所であなたの要約を見つけませんでした。あなたの frontmatter フィールドが `summary`、`description`、`abstract`、または `excerpt` という名前であること、**または** あなたのコールアウトが `[!summary]`、`[!abstract]`、または `[!tldr]` であることを確認してください。それから分類器を再度開く(または *すべての要約を作成* をクリックする)と更新されます。

**「分類器を開いた瞬間に、すべてのカードに要約を表示させたい。」**
**すべての要約を作成** を一度クリックして、完了させます。その後、要約は事前計算され、即座に表示されます。

**「要約をディスク上のノート自体の一部にしたい。」**
自分で書いてください — `summary:` frontmatter フィールドまたは `> [!summary]` コールアウトを追加します。Constellation はあなたのバージョンを表示し(生成を止め)、あなたの言葉は他のどのアプリも読めるファイルの中に存在します。
