*(Constellation 認識的コンテンツエンジン — CECE)*

Source Review パネルは、Constellation が **Constellation 認識的コンテンツエンジン**(CECE)によって生成された分類のレビューを依頼する場所です。キュー内の各カードには、ノートと、そのノートがあなたの知識分類体系にどう収まるかについてのエンジンの読み取り結果が表示されます。「承認」「編集」「却下」または「兄弟曖昧性解消」チップを選択することで、時間とともにエンジンはあなたのライブラリの形を学習していきます。

このトピックでは、Source Review カードのすべての部分、色付きドットの意味、エンジンを信頼すべき時期、そして何百ものカードを延々とスクロールせずにナビゲートする方法について説明します。

> **2 つの場所、1 つのパネル。** ここで説明するカードは、右サイドバーの **Source Review** タブと、フルページの **分類器** ビュー(左ドックの積み重なったカードのアイコン)の両方に表示されます。それらは同じパネルであり同じエンジンです。分類器はキューにウィンドウ全体に加えてノートピッカーと「すべての要約を作成」ボタンを与えます — **分類器** トピックを参照してください。以下のすべては、どちらの場所のカードにも適用されます。

## CECE が実際に行うこと

ノートを分類すると(右クリック →「ソースとコンテンツタイプを提案」、または設定 → スキャン実行ボタン)、CECE はノートに対して **6 つの独立した分類器** を実行します。各分類器は独自のレンズ(frontmatter、引用、語幹、リンクされたノート、類似ノート、AI 判断)を通してノートを読み取り、2 つの質問について投票します:

- **Source(水平軸)**:この知識は *どこから* 来たのか?例:証言(誰かが教えてくれた)、知覚(私が見た)、推論(私が導出した)、啓示(聖典)、その他 8 種。
- **コンテンツタイプ(垂直軸)**:これは *どんな種類* の知識か?例:認識的状態(疑い / 確信 / 信念)、意味的内容(概念 / 命題 / 事実 / 理論)、感覚入力、象徴的実体、高次構築物(世界観 / 教義)。

2 つの軸は **独立** しています。「私は月面着陸を疑う」というノートは、ソース軸では証言(誰かが報告した)、コンテンツタイプ軸では認識的状態 / 疑い(それに対するユーザーの立場)です。

分類器が投票した後、**統合層** がそれらの投票を軸ごとに 1 つの分類にまとめ、3 つの確信度レジームのいずれかを付与します:

- **全会一致** — 発言したすべての分類器が同意した
- **強い多数** — ほとんどが同意し、1 件が異議を唱えた(カードに異議者の名前が表示される)
- **意見が分かれた** — 明確な多数がない;エンジンは「割り当てを拒否」し、*あなた* に選ぶよう求める

すべて **あなたのデバイス上で** 実行されます。ノートが Constellation を離れることはありません。

## 2 つの軸を平易な言葉で

### Source — *この知識はどこから来たのか?*

11 の可能な値 + *分類不能*:

- **知覚** — 一次的な感覚観察
- **推論** — 前提からの推論(演繹、帰納、類推)
- **証言** — 他者の報告(引用、参照、参照されたソース)
- **集合的伝達** — 多くの独立した目撃者による収束的報告(スンニ派の *al-tawatur*)
- **比較** — 既知の事例への類推による知識(法的 *qiyās*、科学的類推)
- **公準** — 最良の説明への推論(*arthapatti*)
- **非把握** — 不在の知識
- **記憶** — 過去の経験の想起
- **生得的傾向** — 経験以前の認識(*fitrah*)
- **インスピレーション** — 神秘的または創造的把握(*kashf*)
- **啓示** — 聖典または預言的伝達(*al-wahy*)
- **分類不能** — この分類をオプトアウトする

### コンテンツタイプ — *これはどんな種類の知識か?*

5 つのトップレベルの枝とサブブランチ:

- **感覚入力** — 生信号(視覚、聴覚、化学、…)
- **象徴的実体** — 記号、シンボル、コード
- **意味的内容** — 概念、命題、事実、アイデア、情報
- **認識的状態** — 疑い、信念、意見、確信、知識、錯覚
- **高次構築物** — 理論、教義、世界観、パラダイム

両方の軸には、各トップレベル値の下にいくつかの精緻化レイヤーがあります(例:*epistemic-states/knowledge/by-content/propositional* は葉ノードです)。

## 6 つの分類器

各分類器は CECE がノートを読むための 1 つの *レンズ* です。Source Review カードは右上隅に **6 つの小さな色付きドット** として表示されます。任意のドットにカーソルを合わせると、名前 + ステータスが表示されます。

| ドット | 分類器 | 何を読み取るか |
|---|---|---|
| 🔵 青 | **あなたの frontmatter**(ユーザー権威) | あなたが既に設定した `sources:` および `content_type:` フィールド。ノートを自分で分類した場合、このレンズは *絶対的権威* を持ちます — 統合はあなたの選択を採用し、他をスキップします。 |
| 🌹 ローズ | **引用と構造**(構造的) | 引用、ブロック引用、コードブロック、定理マーカー、定義句(「X の概念は…として定義される」)、図の参照。ノートの構造的な形を読み取ります。 |
| 🟡 アンバー | **語幹と語彙**(言語的) | アラビア語の語根分析(CAE)、表面キーワードマッチング、言語横断的な用語等価性(Bridge)。純粋な埋め込みでは見逃すアラビア語対応の分類を捉えます。 |
| 🟢 ティール | **リンクされたノート**(グラフ) | 他の分類済みノートへの型付き Living Links(`[[Note\|supports]]`、`[[Note\|contradicts]]` など)。近隣ノートがクラスターを形成すると、近隣ノートから分類を継承します。 |
| 🟣 バイオレット | **類似ノート**(意味的) | あなたの既に分類済みのノートに対する埋め込み類似度(k-Nearest-Neighbor)。このノートのコンテンツベクトルが分類済みノートとクラスターを形成すると、コンセンサスを取り込みます。 |
| 🟢 グリーン | **AI 判断**(推論) | 文法制約付き推論を実行するローカル LLM(Qwen3-4B Q5_K_M)。*まだアクティブではありません* — モデル配線は後のリリースに延期されています。今日のすべてのカードでこのドットは沈黙したままです。 |

### ドットのステータス

- **塗りつぶし** — 発言した + 統合に同意
- **リング** — 発言した + 統合に異議を唱えた(このレンズは異なるものを選んだ)
- **破線アウトライン** — 沈黙(このノートに対してこのレンズに信号がない)

ドットクラスターは、一目でわかるアンサンブルの健全性インジケーターです。6 つのドットがすべて塗りつぶされたカードは、エンジンの最強の分類です(まれ)。1 つまたは 2 つのリング状ドットを持つカードは、その推論を正直に示しています — レンズが意見を異にしたのです。

## 3 つの確信度レジーム

分類器が投票した後、CECE は各軸を 3 つのレジームのいずれかでラベル付けします:

- **全会一致** — 発言したすべての分類器が同じ主要値を選んだ。カードには特別なピルはありません。
- **強い多数(1 件の異議)** — ほとんどが同意した;1 人の異議者が名前で表示されます。カードのヘッダーに紫色の「強い多数」ピルがあります。
- **意見が分かれた** — 明確な多数がない。カードには金色の「分類器の意見が分かれました — あなたの判断が必要です」ピル、**金色の左ボーダー**、そしてあなたが選択するためのチップ付き兄弟曖昧性解消フォームがあります。

各軸は独立して独自のレジームを取得します。カードは水平で全会一致 + 垂直で意見が分かれることがあります(またはその逆)。ヘッダーピルは、両軸にわたる最悪のレジームを要約します。

## 兄弟曖昧性解消(Sibling Disambiguation)

軸の意見が分かれている場合、CECE は推測を拒否し、代わりに候補値を **ラジオチップ** としてプロンプトの下に表示します:

> *「分類器がこれらの候補の間で意見が分かれました。ノートに最も合うものを選んでください:」*

チップをクリックすると → エンジンはその選択をノートの frontmatter に書き込み、カードをキューから削除し、ライブラリごとの信頼性データを更新します。

もう一方の軸が確定していた場合(全会一致または強い多数)、CECE は *同時に* その軸の値も書き込みます — つまり、1 回のチップクリックで両方の軸が完了し、選択した方だけではありません。同じカードが二度尋ねることはありません。

両方の軸の意見が分かれている場合は、軸ごとに 1 つのチップを選択します(2 回クリック)。

## 推論履歴

各カードには **「▸ なぜこの分類なのか?」** トグル(または開いている場合は「▾ 推論を非表示」)があります。展開すると、発言した分類器ごとに 1 行が表示されます:

- ドットクラスターと一致する **レンズ色のドット**
- **分類器ラベル**(例:「語幹と語彙」)
- 角括弧内の **自己申告された確信度**:`[high]` `[medium]` `[low]`
- 何が起動したかを説明する **1 行の推論**(例:*「言語的一致:垂直 → semantic-contents/concept(重み 0.80)」*)
- 推論の下にある **わかりやすいルールチップ**:`Surface keyword match`、`Side-channel preference rule`、`Arabic root match (CAE)` など — これらは各分類器がトリガーした特定のルールです

**最初の 50 回のレビュー** の間、エンジンを信頼すべき時期の直感を養えるよう、履歴はすべてのカードで自動的に展開されます。その後、履歴は全会一致のカードではオンデマンドに折りたたまれ、強い多数 + 意見が分かれたカードでは自動展開されたままになります(意見の不一致が情報的な場合)。

設定 → インテリジェンス → CECE → 推論履歴の表示で、いつでもこのデフォルトを上書きできます:

- **常に表示** — すべてのカードで開く
- **不一致時のみ(デフォルト)** — 意見が分かれた + 強い多数のカードで開く、最初の 50 回のレビューも含む
- **常に非表示** — 展開には手動クリックが必要

## キュー構成フィルター

カウントストリップの上に **5 つのチップ** があり、各カードがあなたから必要とする決定の種類によってキューをスライスします:

| チップ | 表示するもの |
|---|---|
| **すべて** *(デフォルト)* | キュー全体 |
| **両方の軸で判断が必要** | 水平 と 垂直 の両方が意見が分かれているカード |
| **Source の判断が必要** | 水平が意見が分かれていて + 垂直が確定しているカード |
| **コンテンツタイプの判断が必要** | 垂直が意見が分かれていて + 水平が確定しているカード |
| **分類器が同意** | どちらの軸も意見が分かれていないカード — 迅速なゴム印承認候補 |

各チップにはバケットのカウントが表示されます(例:*「Source の判断が必要(43)」*)。空のバケットは薄暗くなり、無効になります。チップをクリックすると、表示されているカードが再レンダリングされます;カウントストリップと「すべて承認」の計算は、アクティブなフィルターに関係なく常に **キュー全体** に対して動作するため、常に真の合計を確認できます。

このフィルターは、キューに何百ものカードがある場合の干し草の山の中の針問題を解決します。最初にすべてのゴム印承認候補をクリアしたいですか?**分類器が同意** をクリックしてから **すべて承認** をクリックします。最も難しいケースに集中したいですか?**両方の軸で判断が必要** をクリックします。

## 各カードの下のノート要約

各カードのタイトルの下には、短い **要約** 行があります — ノートが何についてのものかを伝える数文の文章で、ノートを開かずにどう分類するか判断できます。Constellation は常に *あなた* が書いた要約(`summary:` / `description:` / `abstract:` / `excerpt:` frontmatter フィールド、または本文の `> [!summary]` / `[!abstract]` / `[!tldr]` コールアウト)を表示し、あなたが書いていないときだけ生成します。生成された要約は抽出型 — ノート自身の最も中心的な文 — であり、決してあなたのファイルに書き戻されることはありません。完全な詳細は **Note Summaries** トピックにあります。

## カードごとのアクション

すべてのカードには下部に 4 つのアクションがあります(意見が分かれたカードでは、曖昧性解消が「承認 / 編集」に置き換わるため 3 つ):

- **承認** — エンジンの統合された主要値を両方の軸でノートの frontmatter に書き込み、カードをキューから削除します。分類器ごとの信頼性を更新します。
- **編集** — 両方の軸のツリーピッカーを開きます;値を手動で選択します。同じ信頼性更新。
- **却下** — 何も書き込まずにカードをクリアします。後で再分類すると、エンジンは再提案します。(却下は信頼性を更新しません — ユーザーが「これらのいずれも望まない」というのはフィードバック信号としてあいまいです。)
- **兄弟曖昧性解消チップ** — 意見が分かれたカードで、候補チップの 1 つをクリックします。選択された値を書き込みます(他の軸が確定していた場合は自動的に書き込みます)。

## 信頼度キャリブレーション期間

CECE 分類カードの最初の **50 回のレビュー** は、*信頼度キャリブレーション期間* です。この期間中、推論履歴はすべてのカードで自動展開され(レジームに関係なく)、パネル上部の控えめなバナーが思い出させます:*「あと {N} 枚のカードをレビューするまで推論履歴を表示しています — 分類器をいつ信頼すべきか学ぶのに役立ちます。」*

50 回のレビュー後、バナーは消え、履歴はデフォルトのオンデマンド動作に折りたたまれます。常に開いたままにしたい、または常に閉じたままにしたい場合は、設定で上書きできます。

キャリブレーション期間のポイント:CECE は、修正するたびに改善される確率的なシステムです(ライブラリごとの信頼性)。最初の 50 回のレビュー中に各分類器が *なぜ* そのように投票したかを見ることで、この特定のライブラリのコンテンツに対してその結論が信頼できるときの独自の直感を養うことができます。

## ライブラリごとのキャリブレーション

設定 → インテリジェンス → CECE → **ライブラリごとのキャリブレーション** は、アクティブなライブラリ上での各分類器の軸ごとの精度を示す読み取り専用テーブルを開きます:

```
分類器               水平            垂直
─────────           ──────          ────
あなたの frontmatter  12/12 (100%)    4/4 (100%)
引用                 18/22 (82%)     6/8 (75%)
語幹                 24/28 (86%)     20/26 (77%)
リンクされたノート    3/4 (均一)      2/3 (均一)
類似ノート           14/19 (74%)     12/19 (63%)
AI 判断              — (実行されていない) — (実行されていない)
```

数値は正解 / 合計のカウントです。パーセンテージは、分類器がそのライブラリ × 軸で 20 件以上の修正を持った後に表示されます(安定した精度データのしきい値)。しきい値未満では、ラベルは **(均一)** と表示されます — 十分なデータが蓄積されるまで、分類器は均一に重み付けされた投票を寄与します。

ライブラリが異なれば、分類器ごとの精度も大きく異なる場合があります。言語的分類器はアラビア語が多いライブラリで優れています;グラフ分類器は密にリンクされたライブラリで優れています。統合層はライブラリごとのキャリブレーションデータを使用して投票に重み付けします — そのため、*この* ライブラリで 70% 間違っていた分類器は、次の統合ラウンドで投票が下方重み付けされます。

## バックグラウンド分類

Source Review キューは 2 つの方法で増えることができます:

1. **手動**(デフォルト) — ノートを右クリック →「ソースとコンテンツタイプを提案」、または設定 → 分類スキャンの実行をトリガーします。
2. **バックグラウンド** — 設定 → インテリジェンス → CECE → バックグラウンド分類。2 つのモード:
   - **ノート保存時** — 入力を停止してから約 1.5 秒後に各ノートを自動分類します(既存のデバウンスされた保存を使用;キーストロークごとには発火しません)。
   - **アプリ起動時** — 起動ごとに 1 回未分類のノートをスキャンします。

バックグラウンド分類はデフォルトで **オフ** です。両方のバックグラウンドモードはバックグラウンドスレッドで実行され、進行イベントを発行します;入力は瞬時のままです;Source Review パネルのヘッダーからキャンセルできます。

## 一般的なワークフロー

**「CECE をインストールしたばかりです — どこから始めればよいですか?」**
Source Review パネルを開きます。ファイルツリーから 5〜10 個のノートを右クリック →「ソースとコンテンツタイプを提案」してキューをシードします。カードを 1 つずつクリックします。最初の 50 回のレビュー中、推論履歴は自動展開されます — 読んでください。5〜10 枚のカードの後、あなたのコンテンツでどの分類器が信頼できるかが見え始めます。

**「キューに 1,200 枚のカードがあります — どこに集中すべきですか?」**
フィルターチップを使用します。**分類器が同意**(ゴム印承認候補)から始めます → 「すべて承認」をクリックしてクリアします。次に **Source の判断が必要** + **コンテンツタイプの判断が必要** で、各 1 つの決定が必要な分かれたケースを処理します。**両方の軸で判断が必要** は最も難しいセットです;最後に残しておきましょう。

**「いつ承認 / 却下 / 編集 / 曖昧性解消すべきかをどう知るのですか?」**
- **承認** — 統合された主要値があなたのノートの読み取りと一致するとき。
- **却下** — どの提案も合わないとき(例:エンジンがノートについて知っている何かを見逃した)。
- **編集** — 提案にない値が必要なとき。
- **兄弟曖昧性解消チップ** — カードの意見が分かれていて、候補の 1 つが正しいとき。

**「最も信頼している分類器をどう確認するのですか?」**
設定 → インテリジェンス → CECE → ライブラリごとのキャリブレーションを開きます。テーブルには、このライブラリで行った修正全体にわたる分類器ごとの精度が表示されます。

- **認知エンジン** — CECE が組み込まれているより広い知識形成哲学。
- **プロパティ** — CECE が書き込む `sources:` および `content_type:` frontmatter フィールド。
- **知識階層** — Source × コンテンツタイプが Universe / Library / Folder / Note 構造にどう収まるか。

## 右サイドバーとカタロガー — 2つの異なる場所

右サイドバーの **ソースレビュー** タブと、フルページの **カタロガー** は、今では**異なるサーフェス**になっています。

- **右サイドバー → ソースレビュー** は、**開いているノート**の保留中の提案を表示します。そのノート自身のカードと、カードごとの *承認 / 編集 / 却下* です。
- **カタロガー**（積み重なったカードのアイコン、左ドック）は、**ユニバース全体**のレビューキューを表示します。決定を待っているすべてのノートと、一括の **すべて承認 / すべて却下** ツール、そしてフィルターチップが揃っています。これらの一括ツールは*ここにのみ*あり、個々のノートの横には決して現れません。

カタロガーのテキストサイズは、**スタイルセッター → カタロガー → 文字サイズ** で変更できます。
